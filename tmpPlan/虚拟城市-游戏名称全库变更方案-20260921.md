# 虚拟城市游戏名称全库变更方案（2026-09-21）

## 1. 目标与边界

将第 7 款游戏的对外名称由「财商流游戏」统一改为「虚拟城市」，覆盖：

- 游戏大厅、导航菜单、游戏页面、创建房间弹窗、规则文档、自动化测试说明等所有用户可见文案。
- 后端日志、错误信息、Agent 提示词、配置注释、路径注释等所有服务端可见文案。
- `lag_docs/财商流游戏/` 知识库目录、文件名与文档内容。
- 根目录自动化脚本、测试说明、测试产物命名约定与已归档方案文档。
- `python-generate-image-tool` 中资产生成脚本文案。

本次仅做名称与路径文案收敛，**不改**以下稳定技术契约，避免引入无关回归：

- `game_kind = wealth`、REST/WS 路由 `/wealth`、CSS/TS/Go 包名与 `Wealth*` 标识符。
- 数据库表、字段、协议 frame type、房间类型枚举。
- `python-generate-image-tool` 输出文件名与目录名（除非其中直接包含旧中文名称）。

## 2. 现状盘点

- 旧知识库目录：`lag_docs/财商流游戏/`，需 `git mv` 为 `lag_docs/虚拟城市/`。
- 全库文本命中旧名称的文件约 190 个，其中 `lag_docs` 子仓库约 133 个。
- 文件名直接包含旧名称的文件约 66 个，包含知识库文档、测试报告、截图与 `tmpPlan` 历史方案。
- 前端命中的用户文案集中在 `zh-CN.ts`、`wealthKeys.ts`、`WealthLobbyPage.tsx`、`WealthGamePage.tsx`、`WealthCreateRoomModal.tsx`、`public/rules/wealth.md`。
- 后端命中文案分布在 wealth 引擎、Agent、服务层、WS 层、errcode 与配置示例。
- `LsmAgentGame.conf.example` 的 `profession_docs_path` 指向旧知识库路径，必须同步指向新路径；本地真实 `LsmAgentGame.conf` 不能提交。
- `lag_docs` 与 `python-generate-image-tool` 为子仓库；若存在变更需分别中文提交并推送，再更新主仓库 gitlink。

## 3. 实施方案

### 阶段 A：文档与知识库

1. 在 `lag_docs` 子仓库执行 `git mv 财商流游戏 虚拟城市`。
2. 将该子仓库所有文本文件中的 `财商流游戏` 精确替换为 `虚拟城市`。
3. 使用 `git mv` 重命名子仓库内文件名包含旧名称的文档。
4. 更新 `lag_docs/README.md` 的主题索引与所有相对链接。
5. 检查 Markdown 单文件行数，确保规则文件不超过 800 行；新增方案文档保持小体量。

### 阶段 B：前端

1. 替换 `ClientWeb/src` 与 `ClientWeb/public` 中所有旧名称：
   - 导航、大厅、页面标题、创建房间弹窗、Agent 标识、注释和规则文案。
   - 多语言注释与中文语言包中的游戏名。
2. 不改路由、组件名、store key、i18n key 和 CSS 类，保证构建与运行兼容。
3. 检查创建房间弹窗与大厅入口在新名称下是否存在硬编码宽度、截断或测试选择器依赖。

### 阶段 C：后端与配置

1. 替换 `ServerGo/` 中日志、错误、提示词、注释里的旧名称。
2. 更新 `LsmAgentGame.conf.example` 的文档路径和配置注释。
3. 保持 `game_kind=wealth` 与所有 API/WS 协议不变。
4. 特别检查职业卡 loader 的默认路径，确保运行时按新目录读取。
5. 目录与文件重命名会改变职业卡索引的字典序，从而使真实池固定抽样命中既有生成器 YAML 瑕疵；本次在解析前增加内存态 frontmatter 净化层，兼容 `key:\n[]`、未闭合 `src_line` 与重复根字段，不批量改写 75k 原始档案。

### 阶段 D：根目录与自动化资产

1. 更新根目录测试脚本、公共脚本和测试说明中的名称与报告 glob。
2. 用 `git mv` 重命名 `tmpPlan`、`TestReport`、`AutoTestScreenshots` 等已跟踪或本地产物中的旧名称文件。
3. 更新 `python-generate-image-tool` 两个资产脚本中的旧名称并单独提交子仓库。
4. 全库复查：除 `.git`、`node_modules`、构建产物与二进制历史外，不允许再出现旧名称。

## 4. 验证方案

按依赖顺序执行：

1. `rg -n '财商流游戏'` 全库复查，目标为 0 命中。
2. `rg -n '虚拟城市'` 确认大厅、页面、规则、配置与知识库均已接线。
3. 后端：在 `ServerGo/` 执行 `go build -o LsmAgentGame main.go` 与 `go test ./...`。
4. 前端：在 `ClientWeb/` 执行 `npx tsc --noEmit` 与 `npm run build`。
5. 运行 `./rebuild_restart_app.sh`，确认服务重编译并启动成功。
6. 使用服务日志或 HTTP 探针确认 HTTPS 进程仍在预期端口提供服端；若本地已有测试工具链可用，再抽查大厅/创建房间文案。
