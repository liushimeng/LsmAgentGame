# 创建狼人杀房间窗口布局优化方案

> **任务**: 修复 `创建狼人杀房间 · 13 人` 弹窗在不同 AI 玩家数 + 难度档位下的布局跑偏、
> AI 解说 / 法官模型按钮显示不全、中间留白等问题。
> **日期**: 2026-08-17
> **版本**: §20260817-02
> **前置**: §20260808-01 ROW1/ROW2 横向合并 + §20260812-01 4 列紧凑布局
> **后置**: §20260817-02 多档位自适应重构(本文档)

---

## 1. 问题陈述

### 1.1 用户反馈(2026-08-17 报告)

打开 `创建狼人杀房间 · 13 人` 弹窗后:

1. **AI 数量滑块拖到 1~12 之间的任何非 0/13 值时**,ROW2 的「我的角色 / 法官模式 / Agent 难度 / 右侧列」四列布局在窄屏/中屏视口下会发生以下问题之一:
   - **跑偏**:`Agent 难度` 的 4 个 radio(🟢 简单 / 🔵 普通 / 🟠 困难 / 🔴 地狱)文字标签在英文视口会被换行或截断。
   - **显示不全**:`法官模型` 下拉框被挤窄到 100~140px 范围,长模型名(如「Qwen 3.7-Plus-and-Max」)只能显示前 8 字符,选择器右侧 50% 区域是空白。
   - **AI 解说 radio 显示不全**: `🎯 专业严谨` / `🎭 娱乐吐槽` 风格 radio 在 commentaryEnabled=true 时横向溢出右侧列。
2. **中间留白明显**: 当 agentCount=0(全人类房)时,ROW2 退化为 `--row--1` (180px + 1fr),但因为 `align-items: start`,右列只是 `1fr` 空白,无任何内容填充,视觉上「中间空了一大块」。
3. **难度档位 4 个 radio 标签对比强烈但缺乏视觉分组**: 简单/普通/困难/地狱 用 emoji 颜色区分,但 4 个 radio 是同一种颜色背景,密集排在一行时用户难以快速定位当前选中档。
4. **座位行高不一致**: agentCount=1~3 时座位区只有 1~3 行,`min-height: 96px` 把座位列表撑高成 96px,视觉上「数据太少却空了一大块」。
5. **i18n 文案宽度差异**:
   - `zh-CN` 难度档「🟢 简单」4 字 + emoji 11 字符
   - `en` 难度档「🟢 Easy」6 字符
   - `ja` 难度档「🟢 イージー」9 字符
   - 三语种在 4 档同行时最小列宽 88px(ja イージー档刚好)、3 档可用列宽时 ja 会折行。

### 1.2 复现路径

| 场景 | 复现条件 | 现象 |
|---|---|---|
| 4 列窄列 | agentCount=1~12, 视口 1200~1400px | 「法官模型」select 缩成 130px,「Qwen 3.7-Plus-and-Max」截断 |
| 难度档 4 同行 | agentCount=1~12, 视口 700~1200px | ja 「イージー」 radio 文字竖排 |
| 全人类空列 | agentCount=0 | ROW2 右列无内容,留白 |
| AI 解说启用 | commentaryEnabled=true | 风格 radio 横向溢出右侧列 |
| 座位行高 | agentCount=1~3 | 列表 96px 硬下限,下方空 50~80px |

### 1.3 影响面

- **用户能感知**: 弹窗看起来「不规整」「不专业」,配置体验劣化。
- **不影响功能**: 提交逻辑、座位分配、法官模型、Agent 难度档、座位角色偏好均按 §20260808-01 / §20260812-01 落地,无功能回归。
- **可访问性**: 难度档 radio 在 ja 文案下文字竖排,WCAG 文字宽度失败。
- **多语种**: 三语种均受影响,英文受影响最小(短文案),ja 受影响最大(中文字符宽度更宽)。

## 3. 根因分析

### 3.1 ROW2 4 列布局(§20260812-01)的本质

```css
.ww-create-modal__row--4 {
  grid-template-columns: 160px auto auto minmax(0, 1fr);
  gap: 12px;
  align-items: start;
}
```

- `160px` = 「我的角色」label + select 固定宽
- `auto` × 2 = 法官模式 + Agent 难度 各自按内容宽
- `minmax(0, 1fr)` = 右侧列(法官模型 + AI 解说)

### 3.2 三处具体问题

#### 3.2.1 `auto` 列在 ja 文案下撑爆剩余空间

`auto` 列的内容宽 = `min-content`(子项最长不可断行宽度)。ja 难度档「🟢 イージー」(9 字符 + 11 像素 emoji) + radio 13px + gap 4px ≈ 80px,4 档 × 80 + 3 gaps = 320px。法官模式「Agent ジャッジ」+ radio = 110px。两列 `auto` 共 430px,加上 160 + 12×3 gap = 606px, 760px 卡片减 32px padding = 728px 内容宽,**右侧列只剩 728 - 606 = 122px** — 不够放下法官模型 select (默认 200px+),且「Qwen 3.7-Plus-and-Max」会截断。

#### 3.2.2 `align-items: start` + `1fr` 右列 ≠ 视觉填满

`align-items: start` 让所有列从顶端对齐,右侧 1fr 列与法官模式/难度顶部对齐,但其内容只占顶部 30~50%,下方 50% 留白。**视觉上「右列空」**。

#### 3.2.3 agentCount=0 时 ROW2 是 `--row--1`,但 `grid-template-columns: 180px minmax(0, 1fr)` + 仅 1 个子项(label 180px) → 右列空。

#### 3.2.4 座位区 `min-height: 96px` 是死值

`flex: 1 1 auto; min-height: 96px;` — 即使 agentCount=1 只有 24px 内容,也会被撑到 96px 产生 72px 留白。

### 3.3 难度档视觉分组缺失

4 个 radio 同一行 + 同一颜色背景 = 用户需逐个扫读才能定位选中项。**4 档语义递进**(新手→专家)天然适合**视觉分组**:
- 简单/普通:绿/蓝(冷色,稳)
- 困难/地狱:橙/红(暖色,险)

## 4. 设计方案

### 4.1 总体策略

**「列宽契约 + 内容自适应 + 视觉分组」三管齐下**:

1. **列宽契约**: ROW2 改为 4 列**有最小宽度**的 grid,任何子项收缩都有下限,不再用 `auto` 撑破布局。
2. **内容自适应**:
   - 法官模型 select: 默认宽度契约给到 ≥ 220px,长模型名展开为 tooltip。
   - AI 解说风格: 不再与法官模型塞同一列,改为 ROW3 独立行(只在 commentaryEnabled 时折叠展开)。
3. **视觉分组**: 难度档 4 个 radio 加渐变底色 + 当前选中项光晕,无需逐项扫读。
4. **空态填补**:
   - agentCount=0 时把 ROW2 改为「`我的角色` 居中 + 右侧附『全人类房,无 AI,无法官,纯人类推理』说明文字」,填满右列。
   - 座位区 min-height 改为「`max(0, 13*24 - 7*24) = 24px`」,低于 1 行不撑高,大于 1 行时按 `flex: 1 1 auto` 弹性。

### 4.2 ROW2 4 列布局重构

#### 4.2.1 列宽契约

```css
.ww-create-modal__row--4 {
  /* 4 列最小宽度契约,任何视口下都不会撑破 760px 卡片。 */
  grid-template-columns:
    minmax(140px, 160px)   /* 我的角色 */
    minmax(120px, 0.7fr)   /* 法官模式 */
    minmax(180px, 1fr)     /* Agent 难度(4 档 同行) */
    minmax(220px, 1.1fr);  /* 法官模型 */
  gap: 12px;
  align-items: start;
}
```

- 难度档列最小 180px = 4 × 38px + 3 × 6px = 170px,加 10px buffer 正好放下 4 档 radio。
- 法官模型列最小 220px = 长模型名宽度足够,不再用 `auto` 撑爆。
- 总最小宽 140+120+180+220 = 660px + 36px gap + 32px padding = 728px,**760px 卡片内有 32px 余量**。

#### 4.2.2 难度档 4 档同行布局

`minmax(180px, 1fr)` 容纳 4 档,各档 `min-width: 38px` 内部不可再折。`flex-wrap: wrap` 仍保留,窄于 180px 时折为 2×2。

#### 4.2.3 法官模型 select 永远有 ≥ 220px

即使右侧列其他子项变窄,法官模型 select 仍能完整显示「Qwen 3.7-Plus-and-Max」。

### 4.3 难度档视觉分组(新增)

4 档难度 radio 加渐变背景 + 选中光晕:

```css
.ww-create-modal__difficulty-mode {
  /* 4 档用不同底色暗示递进,选中态加 box-shadow 光晕。 */
  border-radius: 6px;
  padding: 2px 6px;
  transition: background 120ms, box-shadow 120ms;
}

.ww-create-modal__difficulty-mode--easy   { background: rgba(46, 160, 67, 0.10); }
.ww-create-modal__difficulty-mode--normal { background: rgba(56, 139, 253, 0.10); }
.ww-create-modal__difficulty-mode--hard   { background: rgba(217, 119, 6, 0.12); }
.ww-create-modal__difficulty-mode--hell   { background: rgba(207, 34, 46, 0.12); }

.ww-create-modal__difficulty-mode:has(input:checked) {
  font-weight: 700;
  box-shadow: 0 0 0 2px var(--ww-accent, #8b5cf6);
  background: rgba(139, 92, 246, 0.18); /* 选中态统一紫色高亮 */
}
```

`:has()` 在 Chrome 105+ / Firefox 121+ / Safari 15.4+ 全面支持,无回归风险。

### 4.4 AI 解说下放到 ROW3(独立行)

**当前问题**: AI 解说(开关 + 风格 radio)与法官模型挤在右列 1fr,启用了再展开 pro/fun radio 时**把法官模型下挤成 50% 高度**。

**新方案**: 把 AI 解说下放为**独立可折叠行**,只占 24px 高度(开关一行 + 折叠指示符),点击展开后才显示 pro/fun radio。**关闭时完全不影响其他行布局**。

```css
.ww-create-modal__row--commentary {
  display: grid;
  grid-template-columns: 160px 1fr;
  gap: 12px;
  align-items: center;
  /* 默认折叠,只 24px 高。 */
  min-height: 24px;
}

.ww-create-modal__row--commentary[data-open="true"] {
  min-height: 56px;
}
```

### 4.5 全人类房 ROW2 填满右列

```tsx
{agentCount === 0 && (
  <div className="ww-create-modal__row--1">
    <label>...我的角色...</label>
    <div className="ww-create-modal__empty-state">
      全人类房:无 AI,无法官,纯人类推理。
    </div>
  </div>
)}
```

```css
.ww-create-modal__empty-state {
  display: flex;
  align-items: center;
  font-size: 12.5px;
  opacity: 0.7;
  padding: 0 4px;
  border-left: 2px solid rgba(255, 255, 255, 0.10);
  height: 100%;
  min-height: 27px;
}
```

### 4.6 座位区弹性高度修正

```css
.ww-create-modal__seats {
  display: flex;
  flex-direction: column;
  gap: 4px;
  /* 删掉旧的 min-height: 96px,改为按内容自然高度。 */
  flex: 1 1 auto;
  min-height: 0;
  max-height: 100%;
  overflow-y: auto;
  border: 1px solid rgba(255, 255, 255, 0.06);
  border-radius: 6px;
  padding: 6px;
}
```

`min-height: 0` + `flex: 1 1 auto` — 内容 1 行时高度=24px,内容 13 行时弹性增长,外层 `.ww-create-modal__body` 已设 `overflow-y: auto` 兜底。

### 4.7 响应式断点保留 + 微调

| 断点 | 现有 | 新增 |
|---|---|---|
| ≤ 700px | ROW1/ROW2 全降单列 | 保留,新增 ROW3 commentary 也降单列 |
| ≤ 520px | 座位行降 3 列 + 角色跨列 | 保留,新增 ROW2 右列折叠 |

## 8. 教训(留档)

1. **「auto 列在多语种下撑爆布局」是 grid 经典陷阱** — 用 `minmax(MIN, FR)` 取代 `auto`,为每列定最小宽度契约。
2. **「空态留白」需要主动设计** — 不仅是数据为空时显示占位,布局上的「空」也要主动填,否则用户会问「这里为什么是空的」。
3. **死值 `min-height` 是布局杀手** — 座位区 96px 写死导致 1 行时留白 70px,改为 `min-height: 0` + `flex: 1 1 auto`。
4. **「4 档 radio」用视觉分组** — 不仅语义递进(简单→地狱),视觉也应分组(冷→暖),让用户「一眼能定位」而非「逐个扫读」。
5. **断点 700px / 520px 是实测反推的,不要凭直觉** — 已在 §20260808-01 沉淀,本节保留并强调。
6. **AI 解说"折叠"是关键 UX 决策** — 默认关闭时仅 24px,不影响布局;启用后才展开,布局压力最小化。
