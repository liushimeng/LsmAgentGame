# 德州扑克游戏界面优化处理方案 - 20260819-02

> 状态: 已实施
> 范围: 德州扑克观战流程修复 + 菜单归类复核
> 关联: §20260819-02 (7858d33 首轮修复) / §87 (验证缺陷仍存在) / §130 (声明未接线)

## 0. 背景与结论

用户报告两项问题:

1. **菜单归类**: 德州扑克已加入 Agent 功能,应从「传统游戏」移到「AGENT 游戏」分组。
2. **观战卡死**: 无论开局与否,点击「观战」进入后主界面始终显示「观战中…」,无法退出,流程卡死。

**经实测验证(2026-08-20 16:44-16:51 实机复现)**:

- 需求 1 在 7858d33 + 86b1b95 已完成(后端 category / HomePage / GamesPage / GameCard /
  AppSidebar / i18n 三语言全链路就位),本轮仅复核无回归,**无代码改动**。
- 需求 2 **真实缺陷仍在**:7858d33 的修复只覆盖「房间凭空创建空壳」一种死法;
  实机复现出**服务器重启后 DB 房间成为孤儿**这一主场景,观战者 REST 成功 + WS 404,
  前端把 WS 错误帧吞进 console(违反 §7.1),UI 永久停留在「观战中…」。

### 0.1 实机复现记录

```
16:44:27  REST 创建房间 c1692fda(2 Agent + 人类房主),in-memory 房间建立,hand started
16:46:59  服务进程重启(并行 Agent 会话触发 rebuild) -> in-memory 房间全部丢失
16:48:11  REST POST /api/rooms/c1692fda/spectate -> 200 OK (DB 行还在)
16:48:12  WS game.spectate -> game.error 30001 "room does not exist"
```

对照实验:纯人类房间(无 Agent、REST 创建)观战正常 -- 因为 CreateRoomWithAgents 的
SyncSeat 会即时建立 in-memory 房间;**只有「重启丢内存」这条路是坏的**。

## 1. 缺陷清单(按严重度)

### P0-1 观战重启恢复缺失 -- SpectateGame 404 + 无 hydrator(根因)

`ServerGo/game/texasholdem/room.go:967 SpectateGame`: in-memory 房间缺失时直接返回
`ErrRoomNotFound`。而 REST `SpectateRoom` 查 DB 返回成功。前后端对「房间是否存在」
判定不一致,观战者必然卡在中间态。

**跨游戏对照**(本次审计的核心证据):

| 游戏 | SpectateGame 内存缺失行为 | 重启恢复 |
|------|--------------------------|---------|
| 狼人杀 | 懒创建 + `SetHydrator` 从 DB 恢复全座位 + 满员 force-start | ✅ BUG-WEREWOLF-P0-7 |
| 象棋/国际象棋/军棋/斗地主 | 懒创建(空房间,观战者看到空桌,能退出) | ❌(但无 Agent,自然收敛) |
| **德州扑克** | **404 拒绝** | **❌** |

狼人杀的 `SetHydrator` + `restoreBotsLocked` + `SeatsForRoom`(room_service.go:335,
返回人类+Agent 全座位)就是为同一问题设计的既有基建,德州扑克一行都没接。

### P0-2 前端 game.error 吞进 console(违反 §7.1)

`ClientWeb/src/hooks/useTexasHoldem.ts:39-43`: `game.error` 仅 `console.error`。
对照 `useWerewolf.ts:166` 已正确 `reportGlobalError`。5 款游戏 4 个 hook 违规
(xiangqi/doudizhu/texasholdem),但本轮只修德扑(§13 单一职责,其余游戏留待各自任务)。

后果: P0-1 场景下,WS 错误帧到达前端后 UI 无任何反馈,与「观战中…」spinner 合谋
构成「永久卡死」的用户体验。15s joinTimeout banner 是唯一逃生门,但文案误导
(「可能房间已被解散」-- 实际房间在 DB 里活得好好的)。

### P1-3 观战「等待中」与「加载中」UI 不可区分

`TexasHoldemGamePage.tsx:126` `isWaiting = !gameState || !gameState.ready`:
观战者进入未开局房间(<2 人入座, ready=false)时,看到的是与「正在加载」完全相同的
「观战中…」+ spinner。观战者无法分辨「数据在路上」与「牌局还没开」。
玩家侧的 `texasholdem.waiting`(等待玩家入座)文案对观战者更有信息量,但被
`texasholdem.spectating` 覆盖。

### P1-4 boot 孤儿清理不覆盖德州扑克

`room_orphan_cleanup.go:176` `WHERE r.game_kind = 'werewolf'`:重启后德扑 Agent 房间
永久滞留 DB(大厅一直显示,REST 观战一直"成功")。`zombieAbandonedCandidate`
(room_service_janitor.go:290)同样只扫 werewolf,注释「其它 4 款游戏以分钟计自然
收敛」的假设已被德扑 Agent(纯 bot 局可无限打)打破。

## 2. 修复方案

### 2.1 P0-1 后端 -- SpectateGame 懒创建 + 座位 hydrator(仿狼人杀 P0-7)

**`ServerGo/game/texasholdem/room.go`**:

1. `SpectateGame` 内存缺失时懒创建房间(回到 5 款游戏一致行为),不再 404。
2. 新增 `SetSeatHydrator(fn func(roomID string) ([]SeatRestoreInfo, error))`:
   新建房间且座位全空时,从 DB 恢复全部座位(人类 + Agent)。
3. 新增 `RestoreSeatsLocked(infos []SeatRestoreInfo)`:
   - 按座位号写 `r.Seats[seat] = userID`(人类 + Agent 都恢复,与 DB 一致);
   - Agent 座位写 `r.BotSeats[seat]=true` + `r.BotModels[seat]=modelKey`;
   - `r.State == nil` 时 `NewGame` + 逐个 `AddPlayer`;
   - 恢复后若 `IsReady()` 且 `Street == PhaseWaiting` 则 `StartHand()`
     (纯 Agent 房间重启后观战者进来即看到活局,对齐狼人杀 force-start 语义);
   - 人类玩家不恢复筹码快照(手牌状态不可恢复,新一轮开始即可)。
4. **注意**:德扑的 bot 决策驱动(thpDriver.RegisterAgents + watchdog)在 ws 层,
   manager 层无法触达 -- 见 2.2。

**`ServerGo/ws/game_service.go` handleSpectate texasholdem 分支**:
SpectateGame 返回的房间若为「本次懒创建」(通过返回值新增的 `created bool` 标记),
在锁外调 `registerTexasHoldemAgentSeats(roomID, agentSeatsFromDB)` 重建 bot 运行时
(driver 注册 + watchdog 启动)。数据源: `roomSvc.SeatsForRoom(roomID)` 过滤
`ModelKey != ""`。

**`ServerGo/main.go`**: `thpMgr.SetSeatHydrator(...)` 接线,读 `roomSvc.SeatsForRoom`。

### 2.2 P0-2 前端 -- game.error 全局上报 + 观战失败自动退场

**`ClientWeb/src/hooks/useTexasHoldem.ts`**:
`game.error` 分支对齐 useWerewolf: `reportGlobalError({message, severity:'error'})`。
同时在 payload 携带 room_id 时透传,便于多房间隔离。

**`ClientWeb/src/pages/TexasHoldemGamePage.tsx`**:
- 新增 `spectateError` state: 观战模式下收到 30001(ErrRoomNotFound)错误帧时,
  立即显示错误 banner(「房间已失效(服务重启或已解散)」+ 返回大厅按钮),
  不再等 15s。实现路径: hook 的 game.error 回调扩展 onWSError 可选参数,
  页面注入处理函数;或 store 增加 lastError 字段(后者改动面更小,选后者)。
- 15s joinTimeout banner 文案改为中性:「长时间未收到游戏状态」。

### 2.3 P1-3 观战等待态文案区分

**`TexasHoldemGamePage.tsx`**: 观战者 + `gameState && !gameState.ready` 时,
waiting-board 显示「👁 观战中 · 等待玩家入座(当前 N/6)」而非 spinner-only;
只有 `!gameState`(数据未到)才显示 spinner。i18n 三语言补
`texasholdem.spectatingWaiting` 键。

### 2.4 P1-4 boot/僵尸清理扩展到德扑 Agent 房间

**`room_orphan_cleanup.go`**: `scanOrphanedAgentRooms` 的 `WHERE r.game_kind='werewolf'`
放宽为 `r.game_kind IN ('werewolf','texasholdem')`。Path 1/Path 2 逻辑不变
(Path 2 的 ForceDisbandRoom 走 RemoveRoomState,对德扑 in-memory 缺失场景幂等安全)。

**`room_service_janitor.go`**: `zombieAbandonedCandidate` 的 `gameKind != "werewolf"`
放宽为 `gameKind != "werewolf" && gameKind != "texasholdem"`,注释同步更新
(纯 bot 德扑局不再假设自然收敛)。

### 2.5 回归测试

`ServerGo/game/texasholdem/room_spectate_test.go`(新增):
- T1: SpectateGame 内存缺失 -> 懒创建成功,返回房间,Seats 全空;
- T2: hydrator 恢复混合座位(1 人类 + 2 Agent)后 `BuildClientStateWithRoom`
  的 `ready=true`,BotSeats/BotModels 正确;
- T3: hydrator 恢复后纯 Agent 房间自动 StartHand(Street != PhaseWaiting);
- T4: 已有内存房间时 SpectateGame 不触发 hydrator(幂等,不重复 StartHand);
- T5: spectate 不会给观战者发底牌(viewer=-1 时 MyHole 恒空)。

`room_orphan_cleanup` 既有测试补德扑用例(扫到 texasholdem agent 房间)。

## 3. 不改的部分(明确决策)

1. **菜单归类(需求 1)**: 已完成,复核通过,零改动。AppHeader 无游戏分组逻辑,
   移动端走 AppSidebar 同一数据源,无遗漏。
2. **JoinGame 重启恢复人类座位**: 玩家侧 `game.join` 对已存在 DB 行的玩家仍坐新座位
   (seat 由 in-memory 空位决定)。本轮不修 -- 玩家 join 路径可用(懒创建 + 新开局),
   且 5 款游戏行为一致;座位漂移是独立的「重启恢复」大题,避免本次 diff 失焦。
   观战 hydrator 恢复座位后,玩家 join 会走「已入座直接返回」分支,实际影响被
   P0-1 修复大幅缓解。
3. **其他 3 款游戏 hook 的 game.error 违规**: 留待各自游戏的任务修(§13 单一职责)。
