### 1.3 三大根因

1. **狼人杀历史在德扑之前,旧产物已落盘,德扑上线时强制带游戏名但狼人杀侧没回头改** → 历史 `自动化测试报告_*.md` 仍合法存在,新增「狼人杀」前缀会破坏旧文件兼容性
2. **多脚本重复同一段样板**:`for candidate in PROJECT/./PWD` + `pick_agent` + `nohup setsid` + 日志头,5 个脚本里复制了 5 遍,任一脚本更新逻辑其他 4 个会立即漂移
3. **Glob 列表散落在 3 处**:`AutoDebugTestReport.sh` 的多游戏 union glob、`AutoTestAndSaveReport_Werewolf.sh`/`..._TexasPoker.sh` 的接力扫描,加新游戏需改 3 处

### 3.2 向后兼容策略(双轨 glob)

每个扫描 glob 同时接受「新前缀」与「兼容旧前缀」,例如狼人杀测试报告扫描:

```text
'狼人杀自动化测试报告_*.md'   # 新
'自动化测试报告_*.md'         # 旧(狼人杀历史)
```

> **不主动重命名历史文件**(避免污染 git 历史),只确保新文件用新前缀、旧文件继续可被检索与提交。

### 4.2 函数清单

| 函数 | 职责 | 替代 .sh 里的哪些行 |
|------|------|---------------------|
| `print_section_header "<TAG>" "<prompt>" "<log>" "<workdir>" "<agent>"` | 启动日志头 4 行 | 5 个 .sh 中 `{ echo "=====" ... } >> LOG` |
| `locate_prompt_file "<prompt_name>"` | 三层定位 prompt 文件 | `for candidate in PROJECT/./PWD` |

## 10. 关键设计决策与教训

1. **不重命名历史文件** — `自动化测试报告_*.md` 等旧文件名已在 git 历史,重命名会污染 diff;采用「新前缀 + 兼容旧」是零破坏升级
3. **公共库拆分而非单文件膨胀** — `auto_run_common.sh` 与既有 `agent_cli_common.sh` 职责清晰分离:前者管"游戏产物",后者管"Agent CLI 选择"
4. **多游戏 glob 用关联数组** — `declare -A GAME_GLOBS` 一处声明,新游戏一行新增;避免 .sh 与 .md 双份维护
5. **公共库不引入新依赖** — 全部用 bash 4+ 内建(关联数组需 bash 4+,本机已用),不引入 jq/yq
6. **CLAUDE.md §4 单文件 ≤ 1800 行硬约束** — 5 个 .sh 各减 25-30 行,新公共库 ~250 行,完全合规
7. **CLAUDE.md §22 自动化测试报告处理流程** — 本方案不修改 AutoDebugTestReport.md 的流程规约,只在 glob 列表与产物命名上做文章
