# 狼人杀13人局 — 弹出式窗口/面板遮挡主界面优化解决方案

> 编号：§20260823-02 · 日期：2026-08-23 · 范围：`ClientWeb/`(纯前端，零后端改动)
> 触发：用户反馈 —— 白天发言阶段道具/流程/投票等面板全部摊开，无显式关闭按钮，
> 把游戏主界面（座位表 `WerewolfTable`）完全挡住；操作提交后面板不收起，长时间占位。

---

## 1. 问题现状（现场取证）

### 1.1 中栏「面板瀑布」挤占主界面

`WerewolfGamePage.tsx` 中栏（`.game-area` 中列）在 `speak` 阶段**同时**渲染以下面板，
全部位于 `WerewolfTable` 下方/上方的正常文档流中，垂直堆叠后把座位表挤出可视区：

| 顺序 | 组件 | 现状折叠行为 | 问题 |
|---|---|---|---|
| 1 | `DayControlPanel`（🗣 白天发言/🗳 投票） | **无任何折叠机制**（570 行，多阶段分支） | 永久全高展开 |
| 2 | `CommitmentPanel`（📝 承诺） | 默认折叠 ✅ | 已合规 |
| 3 | `CommitmentButton` | 按钮 + 弹层 | 弹层提交后不自动关 |
| 4 | `PropPanel`（🎴 道具系统） | 有折叠，但**默认展开**；localStorage 持久化 | 首次进 speak 即全高展开 |
| 5 | `SecretLetterPanel`（✉ 私下信件） | 有折叠，但**窗口开启时自动展开** | 每轮 speak 都被强制摊开 |
| 6 | `FactionBetPanel`（🐺/✋ 阵营赌注） | 同上，自动展开 | 同上 |

用户截图即此场景：6 个面板纵向堆叠 >1200px，主界面不可见。

### 1.2 道具特效遮罩 12 秒挡屏

`PropUseOverlay.tsx:77` — `DISPLAY_MS = 12000`（进场 600 + 保持 10800 + 退场 600）。
虽然 `pointer-events:none` 不阻塞点击，但**视觉上完全覆盖屏幕中央 12 秒**，
无任何手动关闭途径 —— 这是「长时间卡住，影响主界面显示」的直接来源之一。

### 1.3 提交后不收起

所有操作面板（道具/信件/下注/投票/承诺）均为 fire-and-forget：
用户点「发送」→ WS/HTTP 已把结果送达服务端 → **面板保持原状摊开**，
用户必须自己找到折叠箭头（若有）才能收回，且箭头小、无 ✕ 关闭语义。

### 1.4 缺关闭/收起的其余面板

| 组件 | 现状 |
|---|---|
| `RecallChatPanel`（赛后复盘 dock） | 无任何关闭/折叠按钮 |
| `WerewolfRestartVotePanel` | 投票后仍全量展示 |
| `LastWordsPanel` / `NightActionPanel` / `HunterShootInline` | 提交后无「已提交」收生态 |
| `ChatQueueModal` / `SheriffStreamPanel` / `HistoryDrawer` / `FactionDrawer` | ✅ 已有 ESC + ✕（合规，不动） |

## 2. 设计目标

1. **主界面优先**：任何时刻座位表 `WerewolfTable` 不被面板瀑布挤出首屏；
   中栏操作区默认以「紧凑条」形态呈现。
2. **明确的关闭语义**：每个可展开面板头部都有**醒目的大号折叠/关闭控件**
   （≥44px 触控目标，`--ww-touch-target`），不再是小箭头。
3. **提交即收起**：操作成功送达服务端后，面板自动收起为**单行结果摘要条**
   （如「✅ 已使用道具·剧本迷宫 → #5」「🗳 已投票 #3」），点击摘要条可重新展开查看。
4. **失败不收起**：提交失败（formError / 全局 toast）时面板**保持展开**，就地展示错误（§7.1）。
5. **特效可关闭**：`PropUseOverlay` 缩短至 ≤4s 且支持点击立即关闭。
6. **零后端改动**：全部状态为前端本地 UI 态，localStorage 记住用户偏好。

## 3. 方案设计

### 3.1 统一「可折叠操作面板」骨架（新增共享组件）

新增 `ClientWeb/src/components/werewolf/CollapsibleActionPanel.tsx`（狼人杀私有，不进共享目录，§2.1 约束）：

```
┌──────────────────────────────────────────────┐
│ 🎴 道具系统(心理战)   [✅已发送]   [ ▼ 收起 ] │  ← header 整行可点 + 右侧 44px 折叠钮
├──────────────────────────────────────────────┤
│  (展开态：完整表单/列表)                      │
└──────────────────────────────────────────────┘

收起态(单行 32~36px):
┌──────────────────────────────────────────────┐
│ 🎴 道具系统 · ✅ 剧本迷宫→#5 · 余额 1,250 ▶  │  ← 点击整行重新展开
└──────────────────────────────────────────────┘
```

**Props 契约**：

```ts
interface CollapsibleActionPanelProps {
  icon: string;                 // 面板 emoji
  title: string;                // i18n 后的标题
  summary?: React.ReactNode;    // 收起态单行摘要(结果/状态)
  badge?: React.ReactNode;      // 展开态 header 状态徽章(如 ☠已死亡 / 窗口已关闭)
  storageKey: string;           // localStorage 持久化键(ww_panel_*)
  defaultCollapsed?: boolean;   // 首次渲染默认(无存储时)
  collapseSignal?: number;      // 递增计数器:变化即自动收起(提交成功后 +1)
  forceExpand?: boolean;        // true 时强制展开(如提交失败、轮到我必须操作)
  disabled?: boolean;           // 死亡/观战等禁用态(仅样式)
  children: React.ReactNode;    // 展开态内容
  testId?: string;
}
```

**行为规约**：
- `collapseSignal` 变化 → 立即收起并**写入 localStorage**（视为用户意图的延伸）。
- `forceExpand=true` → 忽略折叠态强制展开（用于：动作失败需就地改错、阶段要求我必须操作）。
- 用户手动展开/收起始终写 localStorage，跨阶段记住偏好。
- 收起态单行高度 ≤36px，摘要含最近一次操作结果，点击整行重新展开。
- 折叠按钮：`aria-expanded` + `aria-label`（i18n），44×44px 触控区。

### 3.2 逐面板改造清单

|---|---|---|

### 3.3 「提交即收起」的统一判定

发送路径分两类：
- **HTTP 面板**（SecretLetter / FactionBet / CommitmentButton）：`await` 响应，
  2xx → `collapseSignal+1`；非 2xx → `setErr` 保持展开（§7.1 内联错误条）。
- **WS fire-and-forget 面板**（Prop / Vote / NightAction）：发送动作**本身**即视为
  「已交付服务端」（WS 已连接是渲染前提），发送后立即收起；
  后端拒绝会以 `game.error` / prop 事件回流，此时通过 `forceExpand` 重新展开并内联展示错误。

### 3.4 PropUseOverlay 关闭交互细节

- 保持绝对定位中央卡片；卡片本身 `pointer-events:auto`（容器仍 `none`，不挡座位点击）。
- ✕ 按钮 44px + `aria-label`；点击卡片本体亦可关闭（`role="button"` + `onClick`）。
- 手动关闭写入 ref 去重：同一 `lastPropSeq` 关闭后不复活；新事件（seq 变化）正常弹出。
- 展示时长常量收敛为 `DISPLAY_MS = 4000`，注释更新为「不遮挡原则：≤4s + 可手动关」。

## 4. 验收标准

1. speak 阶段首次进入：中栏仅 `DayControlPanel`（当轮需操作时）展开，其余面板默认收起为单行条；座位表完整可见。
2. 道具/信件/下注/承诺提交成功 → 对应面板 1 秒内自动收起为结果摘要条；点击摘要条可重新展开查看。
3. 提交失败 → 面板保持展开 + 内联红条错误（§7.1），不被误收起。
4. `PropUseOverlay` 展示 ≤4s 自动消失；点击 ✕ 或卡片立即消失；不影响 GlobalToast。
5. 赛后 `RecallChatPanel` 可 ✕ 关闭。
6. 折叠偏好 localStorage 持久化，刷新页面保持。
7. `tsc --noEmit` 零错误；`npm run build` 成功；三语 i18n 键齐全（zh-CN/en/ja 同步 grep 验证）。
8. 单文件 ≤1800 行（§4）；每个改完的组件 grep 验证折叠按钮 class 在 CSS 中有对应规则（§26.3）。
