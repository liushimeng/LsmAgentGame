### 2.2 文件命名规约(CLAUDE.md §3 同源)

| 类型 | 命名 | 示例 |
|------|------|------|

| 游戏级专用 | `Auto<Action>_<Game>.md` / `.sh` | `AutoTestAndSaveReport_Werewolf.sh` / `AutoScreenshotTexasPoker.sh` |

| 报告文件 | `<游戏名><动作>报告_<TS>.md` 或 `<动作>报告_<TS>.md` | `德州扑克自动化测试报告_20260819_120000.md` / `自动化测试报告_20260819_120000.md`(向后兼容) |

| 进度文件 | `<游戏名>自动化测试进度_<TS>.md` | `德州扑克自动化测试进度_20260819.md` / `截图进度_20260819.md` |
| 日志 | `logs/auto_<action>[_<game>]_<TS>.log` | `logs/auto_test_werewolf_*.log` / `logs/auto_screenshot_texas_*.log` |

### 2.3 报告 glob 规约

各游戏脚本只 **`git add`** 自己前缀的报告路径,**不** add 整个 `TestReport/` 父目录(避免污染)。

```
AutoTestAndSaveReport_Werewolf.sh   →  git add 'TestReport/自动化测试报告_*.md' + 子模块 UseReport
AutoTestAndSaveReport_TexasPoker.sh →  git add 'TestReport/德州扑克*.md'    + 子模块 UseReport(德州扑克测试工具使用报告_*)
AutoDebugTestReport.sh              →  待处理预检扫全部游戏前缀(以"多游戏 union"形式)
```

## 4. 还需要做的改动(后续 PR)

### 4.1 `AutoDebugTestReport.sh` 必须升级为多游戏 union 扫描

**当前 bug**: `AutoDebugTestReport.sh` 内部扫的 glob 是 `TestReport/自动化测试报告_*.md`(狼人杀 glob),德扑报告 `德州扑克自动化测试报告_*.md` 永远不会被它发现并自动修复。脚本必须升级为多游戏 union。

**推荐方案**:
```bash
# 4 个游戏前缀的 union 扫描
GAME_PREFIXES=(
  "自动化测试报告_*.md"                  # 狼人杀(向后兼容)
  "德州扑克自动化测试报告_*.md"           # 德扑 v1
  "象棋自动化测试报告_*.md"               # 象棋(预留)
  "斗地主自动化测试报告_*.md"             # 斗地主(预留)
  "军棋自动化测试报告_*.md"               # 军棋(预留)
)

PENDING=""
for prefix in "${GAME_PREFIXES[@]}"; do
  found=$(find TestReport -maxdepth 1 -name "$prefix" ! -name '*_无问题.md' 2>/dev/null | head -1)
  [[ -n "$found" ]] && PENDING="$found" && break
done
```

### 4.2 子模块 UseReport 报告命名规约

子模块 go-web-debug-tool 内 `UseReport/` 当前只有 `测试工具使用报告_*.md` 一种前缀。如德扑/象棋也要写工具报告,**建议统一前缀为 `测试工具使用报告_<Game>_<TS>.md`**(一个空格占位,即可向后兼容狼人杀历史报告)。

### 4.3 加固 CI 自检

## 5. 关键设计决策归档

### 5.1 为什么 `AutoDebugTestReport` 不打 `_Werewolf` 后缀?

**决策**: 保留项目级通用名(不带后缀)。

**理由**:
- 它的提示词全文不含任何具体游戏名词(`狼人杀` `德州扑克` 均 0 次)
- 它处理的"报告"路径**前缀可枚举**(测试 glob 升级后实现多游戏 union)
- 它与具体游戏无强耦合,后续接入任意游戏都自动适用

**反模式(避免)**: 把 `AutoDebugTestReport` 拆成 `_Werewolf` / `_TexasPoker` / `_Xiangqi` 多份 ——
会产生 N 个几乎完全相同的脚本,只 glob 不同,后续改动要在 N 处同步。这是典型的 DRY 违反。

### 5.2 为什么不复用同一 `AutoTestAndSaveReport.sh` 而要拆 3 份?

**决策**: 每个游戏一份 `AutoTestAndSaveReport_<Game>.{md,sh}`。

**理由**:
- 提示词内容**完全不同**(游戏术语、规则覆盖点、报告文件名前缀)
- 报告前缀不同(狼人杀 vs 德扑 vs 象棋)
- 测试步骤差异大(德扑有 4 个下注轮 + side pot,狼人杀有 13 个角色,不能合并)
- 后续棋类/斗地主/军棋接入时**同款脚本再复制** 一份(规约统一),不需要重新设计

### 5.3 为什么不抽公共 bash 函数?

**反模式警告**:
- 把 `AutoTestAndSaveReport_Werewolf.sh` 与 `_TexasPoker.sh` 共有的"随机选 Agent + setsid 后台启动 + git 提交 + 接力"逻辑抽到 `auto_common.sh` —— 第一份抽的时候是 N+0 行,第二份抽的时候是 N+M1,第三份是 N+M2,**逃不开"每个游戏的差异点也都进公共库"** 趋势,最终 `auto_common.sh` 会变成 800 行的大泥球。
- 当前选择: **保持 50% 重复**,真正通用的部分(`pick_agent` / `run_agent_with_prompt` / `ensure_openclaw_agent` / `list_available_agents`)已经抽到 `agent_cli_common.sh`。剩下的"git add 路径" / "接力预检 glob" / "提交信息文案"是**游戏级**的,各自维护,每次游戏新增一份脚本即可。

### 5.4 截图脚本与提示词文件为何不复用?

**结论**: 截图脚本(`scripts/screenshot/<game>_highlight_capture.py`)沿用狼人杀实现模板,但**提示词**(`AutoScreenshot<Game>.md`)按游戏特化。

**理由**:
- Python 截图脚本共享 95% 的 CDP 调用逻辑(`scripts/screenshot/atx.py` 已是公共层),只在 URL `/texasholdem/<room>` vs `/werewolf/<room>` 等细节不同 → 真正复用
- 截图清单(§3) 完全是游戏级 → 必须特化

### 5.5 AutoDebugTestReport 提示词里"严禁修改 CLAUDE.md"硬约束

**保留**: 即使脚本拆分多版本,`AutoDebugTestReport.md`(项目级通用) 必须显式包含「绝对禁止修改 CLAUDE.md/AGENTS.md」守门条款。当前脚本里有硬校验:

```bash
if ! grep -qF "绝对禁止修改 \`CLAUDE.md\`、\`AGENTS.md\`" "${PROMPT_FILE}" 2>/dev/null; then
    echo "[ERROR] 缺少守门条款,拒绝启动" >&2
    exit 2
fi
```

**教训**: §92a 教训的镜像变种 —— 「声明了却从不接线」反模式的预防措施。任何 AI Agent 自动修复流程的提示词文件都必须含此条款,且校验必须是 fail-fast。

## 7. 教训归档

| # | 教训 | 适用场景 |
|---|------|---------|
| L-1 | **每个游戏的报告文件名前缀必须独立** — 狼人杀 `自动化测试报告_` / 德扑 `德州扑克自动化测试报告_`;防止 git add 路径污染 | 任何「多个并列子系统共享同一报告根目录」的设计 |

| L-4 | **脚本内部 log tag 与文件名同步** — `[AutoTestAndSaveReport_Werewolf]` 而不是笼统的 `[AutoTestAndSaveReport]`;grep 友好 | 任何 bash 自动化脚本 |
| L-5 | **git add 用 glob 前缀而非整个父目录** — 父目录 add 会让多游戏脚本互相"代提交" | 多子系统报告提交 |
| L-6 | **接力预检必须分游戏** — Each game 入口脚本只承认自己前缀的待处理报告,德扑接力 ≠ 触发狼人杀接力 | 接力自动化 |
| L-7 | **`agent_cli_common.sh` 已实现公共 Agent 选择逻辑,新脚本必须 source 它** — 不要重写一遍 pick_agent / run_agent_with_prompt | 新增自动化入口 |
| L-8 | **`logs/` 应有 .gitignore,失败/中断日志永久归档** — 避免仓库膨胀 | 日志管理 |
| L-9 | **禁止把 `AutoTestAndSaveReport_<Game>.sh` 抽公共函数库** — 真正通用的部分已在 `agent_cli_common.sh`,剩下的"git add 路径" / "预检 glob"是游戏级,各自维护 | 重构时机判断 |
