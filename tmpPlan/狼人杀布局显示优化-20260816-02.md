## 0. 第二版前言 —— 首版落地后的实测复审

首版方案(commit `66f288a`)声称落地 U1–U6 六项优化。**2026-08-17 用 `go-web-debug-tool`
在真实 13 人局(1 人类 seat 0 + 12 Agent)重新截图 + `getComputedStyle` 实测,发现
首版的核心优化 U6 完全没有生效,且 U1 的收益被一条硬编码 CSS 高度整条吃掉。**

这正是 §130 系列教训的第 N 次复现,且这次的伪装形态是新的:
**不是「声明了却从不接线」,而是「接线了但选择器写错了目标节点」。**
CSS 不报错、`tsc` 不报错、`npm run build` 不报错,只有 `getComputedStyle` 实测会暴露。

## 1. 现状问题清单（基于 2026-08-17 实测复审）

### 1.1 【P0】U6 座位卡紧凑化 CSS 选择器写错节点 —— 整段死代码

- **症状**:首版 `werewolf-v2.css:575-593` 写的 4 条规则全部以
  `.werewolf-game .board-container.cols-4 ...` 为选择器,实测
  `.board-container.classList.contains('cols-4') === false`。
- **根因**:`cols-${cols}` 类由 `WerewolfTable.tsx:786` 加在
  **`.werewolf-table__grid`** 上,而不是 `.board-container` 上。首版作者
  写方案时(§3.7)假设类在 container 上,实现时也照方案写,**双方一致地错**。
- **量化证据**:`getComputedStyle` 实测 `min-height:200px` / `padding:8px 10px` /
  `avatar:64px` —— 与首版 commit message 宣称的 `170px` / `6px 8px` / `48px`
  **三项全不符**。即首版 U6 的收益 = 0。
- **影响**:座位卡仍是 200px 高,4 行 = 800px + gap/padding ≈ 884px,
  而 grid 可视高度只有 415px → **5 张座位卡落在 fold 之下**。

### 1.2 【P0】`.werewolf-table` 硬编码 `height: 460px` 吃掉 U1 的全部收益

- **症状**:`werewolf.css:439-441` 的
  `@media (max-width:1599px) { .werewolf-table { height: 460px } }`
  在 1920 视口下不触发,但 `min-width:1600 and max-width:1999` 分支给了
  `height: 560px`。实测 `.werewolf-table` 计算高度 `451px`(被 flex 压缩),
  实际渲染 `h=234`。
- **根因**:`.werewolf-table` 同时被 3 套规则约束:
  1. `werewolf.css:434` `flex: 1 1 auto; min-height: 320px`
  2. `werewolf.css:463` `height: 560px`(1600–1999 分支)
  3. `werewolf.css:451-456` `display:flex; overflow-y:auto; min-height:0`

  `min-height:0` + `flex:1 1 auto` 让它被父容器 `.board-container` 压缩;
  而 `.board-container` 的可用高度已被 `.phase-clock`(37) +
  `.my-turn-indicator`(49) + `.werewolf-action-panel`(264) +
  两个 strip(72) + gap/padding(约 80) ≈ **502px** 吃掉,
  776 − 502 = **274px** 才是牌桌的真实配额。
- **影响**:**U1 把 5 行降到 4 行(节省 250px)的收益,被固定高度与
  面板堆叠完全抵消** —— 4 行仍装不进 274px。

### 1.3 【P1】左栏 336px 垂直留白(实测 712px 容器装 376px 内容)

- **症状**:`.room-info-panel__body` 高 712px,内部唯一子元素
  `.game-info-panel` 仅 376px,**下方 336px 纯空白**。
- **根因**:左栏是 `grid` 固定 317px 宽 + `height:100%` 拉伸,但内容
  不足时没有任何填充策略(既不上移紧贴,也无第二块内容)。
- **影响**:截图中左栏下半部分是大片空洞,与中栏「装不下要滚动」形成
  **同屏内一边溢出一边留空**的强烈违和感 —— 这是用户反馈「大量留空」的直接来源。

### 1.4 【P1】座位卡内容仍被裁切(实测 5 张卡 `scrollHeight > height`)

- **症状**:实测 seat #0/#1/#5/#7/#10 的 `scrollHeight` 为 246/266/266/225/266,
  而 `height` 恒为 200 → **最多裁掉 66px**,`overflow:hidden` 直接切断。
- **根因**:座位卡内部是 6 行结构(header 20 + role 14 + speech 49 +
  action 13 + metrics 62 + model-row 13 = 171px)+ padding 16 + gap ≈ 200px,
  **发言气泡 `.werewolf-seat__speech` 一旦出现 2 行就必然溢出**。
- **影响**:Agent 发言内容被切掉一半,模型名行(最下方)常被完全切掉。

### 1.5 【P2】阶段信息三重重复占用 123px 垂直空间

- **症状**:实测同屏出现 3 处相同阶段文案:
  - `.werewolf-top-bar` → `遗言阶段`
  - `.phase-clock`(h=37)→ `遗言阶段 / ⌛ 等待阶段推进…`
  - `.werewolf-table__phase` → `🪦遗言阶段 · 当前白天 1`
  - 外加 `.my-turn-indicator`(h=49)→ `轮到 #1 行动`
- **影响**:`phase-clock`(37) + `my-turn-indicator`(49) + 上下 gap(20)
  = **106px 中栏纵向预算**,用于显示顶栏已有的信息。

### 1.6 【P2】夜间操作面板 264px 固定占位(13 个投票按钮 2 行铺开)

- **症状**:`.werewolf-action-panel` h=264,内部 13 个座位按钮
  以 7+6 两行铺开,每个按钮 44px 高 + 标题 + 提交行。
- **根因**:按钮用 `min-height: var(--ww-touch-target)` = 44px(§23 触控规范),
  13 个 ≈ 2 行 = 88px + 标题 30 + 已投票行 22 + 提交行 44 + padding ≈ 264px。
- **影响**:这是中栏第二大的空间消费者,且**它与座位卡功能重复**
  —— 座位卡本身就可以点击投票。

## 3. 设计方案

### 3.1 【U1-fix】把 U6 选择器修正到真实节点(P0)

`werewolf-v2.css` 的 4 条 `.board-container.cols-4` 规则,选择器改为
**`.werewolf-table__grid.cols-4`** 的后代:

```css
/* 修正前(死代码):.werewolf-game .board-container.cols-4 .werewolf-seat */
/* 修正后(真实命中): */
.werewolf-game .werewolf-table__grid.cols-4 .werewolf-seat { ... }
```

同时保留 `.board-container` 变体作为**向后兼容的双选择器**(万一未来
JSX 把类挪回 container),用逗号并列即可,零风险。

**验收**:`getComputedStyle(seat).minHeight === '170px'`。

### 3.2 【U2】座位卡改为「内容驱动高度 + 上限钳位」(P0)

固定 `min-height: 200px` + `overflow: hidden` 是 §1.4 裁切的根因。改为:

```
min-height: 150px;          /* 下限:保证空座位不塌陷 */
height: auto;               /* 内容驱动 */
max-height: none;           /* 不再硬切 */
```

并对**唯一的可变高元素**(发言气泡)做钳位,把不确定性收敛到一处:

```
.werewolf-seat__speech { max-height: 44px; overflow: hidden; }
```

**原理**:6 行结构里 5 行是定高的(header/role/action/metrics/model),
只有 speech 可变。钳位 speech 后整卡高度可预测 = 定高 5 行 + 44 + padding。
这比「钳整卡 + hidden」优越:**裁切点从「随机切掉最下面的模型名」
变成「只截断发言文本」**,而发言全文本来就在右侧聊天栏可读。

### 3.3 【U3】中栏垂直预算重新分配 —— 阶段信息去重(P2→P0 收益)

中栏 776px 的预算实测分配:

| 区块 | 现状 | 改后 | 依据 |
|---|---|---|---|
| `.phase-clock` | 37 | **0(删)** | 顶栏 `.werewolf-top-bar` 已有阶段 + `RoomRunningClock` 已有计时 |
| `.my-turn-indicator` | 49 | **28** | 保留(行动提示是关键),压缩为单行 chip |
| `.werewolf-table`(座位) | 234 | **≈ 560** | 收回的空间全部给座位网格 |
| `.werewolf-action-panel` | 264 | **≈ 110** | 见 §3.4 |
| 两个 strip | 72 | 72 | 首版已优化到位 ✅ |
| gap + padding | 80 | 48 | gap 10→6,padding 10→6 |

**净效果**:座位网格从 234px → 约 560px。配合 §3.1 的 170px 卡高,
4 行 = 4×170 + 3×6(gap) + 44(phase badge 净空) ≈ **742px**……
仍不够。故必须同时执行 §3.5 的 5 列方案。

### 3.4 【U4】夜间操作面板折叠为单行「快捷投票条」(P2)

`.werewolf-action-panel` 的 13 个 44px 按钮与座位卡点击功能重复。改为:

```
┌──────────────────────────────────────────────────────────┐
│ 🐺 狼人夜间投票 0/4 · 点击座位卡投票  [下拉:#?] [投票] [弃权] │
└──────────────────────────────────────────────────────────┘
```

- 13 个按钮 → 1 个 `<select>`(§26.3 四管齐下深底浅字规约)
- 高度 264 → **约 110px**(标题 24 + 已投票行 20 + 操作行 44 + padding 12)
- **触控可达性不降级**:`<select>` 与两个按钮仍 ≥ 44px(§23 token)
- 保留「点击座位卡投票」作为主交互(空间效率最高的路径)

### 3.5 【U5】5 列网格 + 阈值重新分档(P0)

13 人局的关键约束:**行数 = ⌈13 / cols⌉**。

| cols | 行数 | 卡宽(951px 容器) | 4 行总高(170px 卡) |
|---|---|---|---|
| 3 | 5 | 310px | 894px ❌ |
| 4 | **4** | 231px | 742px ⚠️ |
| **5** | **3** | **180px** | **562px** ✅ |

5 列 3 行是唯一能装进 560px 预算的方案。但 180px 卡宽必须配套:

- 头像 48 → **40px**
- 6 行结构压到 5 行:**`action` 行与 `model-row` 合并**(都是单行 13px)
- `metrics` 从 62px(3 行)压到 **40px**(2 行,`×N` 计数与 token 同行)
- 卡高目标 **≤ 175px**

阈值改为:

```
≤360  → 1        (极窄手机竖屏)
≤560  → 2
≤760  → 3
≤980  → 4
>980  → 5        ← 1920 视口下 container 951px…
```

**⚠️ 边界风险**:实测 container = **951px < 980**,会落到 4 列。
故阈值定为 **`>940 → 5`**,给 951px 留 11px 余量。同时把
`.game-area` 的中栏配额从 `1.1fr` 略调,确保 container ≥ 960px 更稳。

### 3.6 【U6】左栏填充策略 —— 消除 336px 留白(P1)

三个可选方案,选 **方案 C**:

| 方案 | 做法 | 评价 |
|---|---|---|
| A | 内容上移 + 下方留空 | 留白仍在,只是位置变了 ❌ |
| B | 拉伸各 section 平分高度 | 信息密度下降,违反「紧凑」目标 ❌ |
| C | **左栏宽度收窄,把空间还给中栏** | ✅ 一举解决留白 + 中栏不足 |

`.game-area` 的 `grid-template-columns` 从
`317px | 951px | 528px` 改为 **`260px | 1fr | 470px`**:

- 左栏 317 → 260(内容 376px 高不受影响,它是纵向的)
- 右栏聊天 528 → 470(仍足够显示 Agent 发言)
- **中栏 951 → 约 1086px** → 5 列下每卡 208px(比 180px 宽松)

左栏纵向留白则用 `justify-content: flex-start` + 底部
`.room-info-panel__filler`(仅在 `min-height:0` 下自然收缩)承接,
不再拉伸空容器。

### 3.7 【U7】保留首版已生效的成果(勿回退)

实测确认**首版这两项真实生效,本次不动**:

- ✅ `.ww-secret-letter.is-strip` / `.ww-faction-bet.is-strip` → 各 36px
  (方案原定 28px,实测 36px,含 border 与 touch-target 兜底,可接受)
- ✅ `BotPhaseIndicator` 长徽章 `max-width: 110px` 截断
- ✅ `GameStatusHeader` 双 chip 分组(顶栏左右分列)

### 5.2 附带修复的既有 P0 缺陷

**`buildGridOrder` 座位重复(BUG-20260817-01)** —— 实测截图发现 seat #1「我」
**渲染两张卡**、`seatCount=14`(13 人局)。根因:`all.slice(i, i + N)` 的上界
没有钳到 `headCount = total - 1`,而 `all` 长度是 `total`(mySeat 在末位),
当最后一段不足 N 个时会把末位的 mySeat 一并切进倒数第二行。

穷举验证(`total ∈ {7,12,13}` × `mySeat` × `cols ∈ 1..6`):

```
修复前: cols=5 total=13 → [[1..5],[6..10],[11,12,0],[0]]  ← 14 项, seat 0 重复
修复后: cols=5 total=13 → [[1..5],[6..10],[11,12],[0]]     ← 13 项, 无重复
全组合: ALL PASS (no dup, no missing)
```

**该缺陷在 cols=2/3/4/6 下恰好不触发**(整除或刚好不越界),
是 §20260817-01 U5 引入 5 列档时才暴露的**既有潜伏缺陷**。

## 7. 教训沉淀

1. **CSS 选择器写错节点 = 新形态的「声明了却从不接线」** ——
   §130 系列此前记录的都是「字段/函数零调用点」,本次是
   **「CSS 规则语法正确、文件已导入、但选择器永不匹配」**。
   `tsc` / `npm run build` / 目视截图三者**全部无法发现**,
   只有 `getComputedStyle` 实测能暴露。
   **新增硬约束**:凡「按状态类名派发样式」的改动(`cols-N` / `econ-tier-X` /
   `is-xxx`),提交前必须 `eval_js` 断言
   `getComputedStyle(目标元素).目标属性 === 期望值`,
   §26.6 的 `grep 至少一处命中` 是必要但**不充分**条件
   —— grep 命中的是 CSS 文本,不是 DOM 匹配。

2. **方案文档与实现同源错误时,评审无法发现** ——
   首版 §3.7 写「`.board-container.cols-4`」,实现照抄,
   **方案与实现完全一致,所以 code review 通过了**。
   缺陷在于双方共享同一个错误假设(类挂在 container 上)。
   **对策**:方案里写选择器时必须附上「该类由哪一行 JSX 挂载」的
   文件:行号引用,让假设可被单点验证。

3. **「节省 N px」的收益必须核对同屏其它消费者** ——
   首版 U1 确实把 5 行降到 4 行(真实节省 ~250px),
   但同屏的 `.werewolf-action-panel`(264px)+ `.phase-clock`(37px)
   把收益吃光。**单点优化的收益不等于整屏收益**,
   必须先做一次「垂直预算全量盘点」(§1.2 的表格)再决定改哪里。

4. **「一边溢出一边留空」是布局失衡的最强信号** ——
   实测中栏溢出 469px 而左栏留白 336px,两者几乎相等。
   这说明问题不是「空间不够」而是「空间分配错了」,
   **优先调整栏宽配比(§3.6 方案 C),而不是继续压缩中栏内容**。

5. **固定 `height` 与 `flex: 1 1 auto` 同时存在必出意外** ——
   `.werewolf-table` 被 `height:560px`(媒体查询)、`flex:1 1 auto`、
   `min-height:0` 三条规则同时约束,实测计算值 451px、渲染值 234px,
   **三个数字互不相同**。凡 flex 子项,应只用 `min-height` / `max-height`
   表达约束,不用 `height`。

6. **触控 token(44px)在密集网格里是空间杀手** ——
   §23 的 `--ww-touch-target: 44px` 让 13 个投票按钮吃掉 264px。
   **对策不是降低 token(可达性不可退让),而是减少按钮数量**
   (13 按钮 → `auto-fill` 多列紧排),把可达性成本从「2 行 × 44px」压到 1~2 行紧排。

7. **CSS 选择器必须从实测 DOM 抄,不能按命名惯例猜** ——
   本次实施时我自己也踩了同一个坑:先按惯例写了
   `.ww-seat-btn-grid` / `.night-action__targets` / `.vote-panel__targets`
   三个投票网格类名、以及 `.chat-message` / `.chat-msg` 两个聊天类名,
   **实测 DOM 全部零命中**(真名分别是 `.seat-grid` 与 `.game-chat-msg__text`)。
   若不实测,这五条规则会成为第二批死代码,复刻首版的错误。
   **硬约束**:写 CSS 前先 `eval_js` 列出目标节点的真实 `className`。

8. **`align-self: start` 打不过显式 `height: 100%`** ——
   消除左栏留白时,先只加了 `align-self: start` + `max-height: 100%`,
   实测容器仍是 776px、留白仍是 336px。原因是
   `.werewolf-game .game-sidebar` 与 `.werewolf-game .room-info-panel`
   两条既有规则都显式写了 `height: 100%`,**显式高度优先于对齐属性**。
   必须显式 `height: auto` 才把高度交还给内容(实测留白 336 → 0)。
   这是本次的「改了却没生效」第二例,再次只有 `getComputedStyle` 能发现。

9. **`overflow` 检测必须排除 hover-only 浮层** ——
   `seat.scrollHeight` 恒比 `height` 大 60~70px,一度被判为裁切;
   实测发现是 `.ww-emotion-popover`(160px,`position:absolute`,
   `visibility:hidden; opacity:0`,仅 hover 显示)贡献的。
   把它从 DOM 临时移除后 `scrollHeight === clientHeight`。
   **判断「是否溢出」应测语义内容容器**(此处 `.werewolf-seat__info`),
   而不是测带浮层的外层节点,否则会追一个不存在的 bug。

10. **新增网格档位会唤醒既有的取整潜伏缺陷** ——
    `buildGridOrder` 的 `slice(i, i+N)` 缺上界钳位,在 cols=2/3/4/6
    下恰好整除或刚好不越界,**潜伏至今无人发现**;一加 5 列档立刻
    暴露为「我的座位渲染两张卡」。**凡改变分组基数(列数/页大小/批大小)
    的改动,必须对新基数做一次「元素总数守恒 + 无重复」的穷举断言**
    —— 本次用 `total ∈ {7,12,13} × mySeat × cols ∈ 1..6` 全组合验证。
