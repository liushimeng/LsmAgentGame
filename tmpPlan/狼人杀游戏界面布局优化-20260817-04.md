## 1. 问题陈述

### 1.1 用户反馈（2026-08-17 报告）

#### 缺陷 A — 座位卡 Agent 5 行结构未紧凑填充，图像下方留空

狼人杀 13 人局主界面，每张座位卡为横版布局（左侧 avatar 64×88 + 右侧 info 5 行结构）。
真人玩家座位（如截图中的 #10 我）下方有 60~80px 的留白空间；`werewolf-seat__speech` 发言气泡
「私聊占位」与第 5 行 `werewolf-seat__metrics`（🐇23.0s / µ23.0s / ×31 / 📊31 / 🔤in:606.2K / out:25.4K / ⚡）
与第 6 行 `werewolf-seat__model-row`（MiniMax M3）**作为 3 个独立横排**分散渲染，
且真人玩家 5 行结构 ≠ 真人实际有意义信息（真人无 LLM 调用延迟 / token / 模型名）。

用户希望的**简洁指标块**：

```
🐇23.0s  µ23.0s  ×31
📊31      🔤in:606.2K / out:25.4K  ⚡
MiniMax M3
```

要求：把这 3 行**合并为 1 个紧凑区块**（贴头像下方右侧，不留空），并去除真人玩家
那些 N/A 的指标行。

#### 缺陷 B — 「最后一次聊天信息」气泡显示不全

截图 #8 bot 座位卡 `werewolf-seat__speech`（13px 2 行钳位 + `title` 全文）显示：

> 💬 我是 8号，首夜 …
> 2s前 · 发言

但全文是「我是 8号，首夜没什么信息，先听听大家发言。希望预言家能跳出来带队，我会
认真盘每个人的逻辑。就这样。」约 50 字。气泡钳位后用户**只看到前 2 行**，要看到全部
要么等 3s `.is-fresh` 高亮消失、要么 hover 看 title，但都不直观。

要求：气泡**支持 hover 弹出**完整聊天文本，或点击展开。

#### 缺陷 C — 房间聊天 Bot 私聊显示错误

截图：右侧 `房间聊天` 显示一条消息

```
Bot 12号🔒 私聊→ Bot e386999a_0🤖 Qwen 3.8-Max22:38
[私聊]
```

三处问题：
1. **目标账号错位**：`Bot e386999a_0🤖 Qwen 3.8-Max` 应该是目标 bot 的玩家序号（如「Bot 6号」），
   而不是 `bot_e386999a_0` 这种原始 UUID 格式。
2. **缺失对几号的私聊**：私聊的双方都应是「Bot N号」或「玩家 N号」格式，但目标 bot 显示了
   原始 user_id。
3. **模型名拼接**：🤖 Qwen 3.8-Max 紧跟 `e386999a_0` 后面，没有分隔符，视觉混乱。

#### 缺陷 D — 主界面控件布局综合优化

- 13 人局 5 列 3 行的座位网格（第 1 行 #11-#2 / 第 2 行 #3-#8 / 第 3 行 #9 我 + #10 [我]）
  在 1920 视口下**底部第 3 行只有 1 个真人 + 12 个 bot 中间夹**，但**死掉的 #10 旁有大量
  留白**。
- 顶部 `狼人杀 13 人标准竞技局` 标题栏右侧的 chip `已运行 0:06` / `历史` / 折叠按钮
  之间的间距在不同视口下不均。

```go
    var u models.TLsmGameUser
    if err := s.db.Select("nickname, account").Where("id = ?", userID).Take(&u).Error; err != nil {
        return userID  // ← DB miss 时返回原始 user_id（如 "bot_e386999a_0"）
```

`ServerGo/game/werewolf/agent_runner.go:1590` 是**唯一的调用点**：

```go
_, err := r.chatSvc.WhisperFromBot(r.roomID, r.botUserID, r.botAccount, r.modelKey, toUserID, "", text)
```

服务端从 `gameState.Players[]` 查出（user_id → seat → "Bot N号"），保证格式一致。

## 3. 解决方案

### 3.1 U1 — 座位卡 Agent 5 行结构紧凑化（缺陷 A）

**核心思路**：把 5 行结构中的 `action` / `metrics` / `model-row` 三个横排**收拢为 1 个
紧凑块**，紧贴 avatar 下方；真人玩家仅显示 1 行 `action`（决策摘要，无则省略）；高度
由 CSS 控制不留空。

**前端 `WerewolfTable.tsx`**（替换 §506-560 的 3 段渲染）：

```tsx
{/* 2026-08-17 §04 U1 — Agent 紧凑指标块（贴头像下方，去留空）。
    原 action / metrics / model-row 三段分散,改为 1 个紧凑块:
    - 行 1: 决策摘要(真人/Agent 共用)
    - 行 2: 延迟/调用指标 (Agent only)
    - 行 3: Token + 模型名 + 最后调用时间 (Agent only)
    真人玩家整块退化为「行 1(可能空) + avatar 撑满卡片高度」。 */}
<div className="werewolf-seat__agent-block">
  {/* 行 1 — 决策摘要,人机共用 */}
  {decisionShort && (
    <div className="werewolf-seat__action" title={decision}>
      📤 {decisionShort}
    </div>
  )}
  {/* 行 2 — 延迟 + 调用数 (Agent only) */}
  {botCtx && (lastLatencySec || avgLatencySec || totalCalls !== undefined || botCtx.api_call_count !== undefined) && (
    <div className="werewolf-seat__metrics-row"
         title={[
           lastLatencySec ? `最后 ${lastLatencySec}s` : '',
           avgLatencySec ? `平均 ${avgLatencySec}s` : '',
           totalCalls !== undefined ? `总调用 ${totalCalls} 次` : '',
           botCtx.api_call_count !== undefined ? `API ${botCtx.api_call_count} 次` : '',
         ].filter(Boolean).join(' · ')}>
      {lastLatencySec && <span className="werewolf-seat__metric is-last">🐇{lastLatencySec}s</span>}
      {avgLatencySec && <span className="werewolf-seat__metric is-avg">µ{avgLatencySec}s</span>}
      {totalCalls !== undefined && <span className="werewolf-seat__metric is-total">×{totalCalls}</span>}
      {botCtx.api_call_count !== undefined && (
        <span className="werewolf-seat__metric is-api">📊{botCtx.api_call_count}</span>
      )}
    </div>
  )}
  {/* 行 3 — Token + 模型名 + 最后调用时间 (Agent only) */}
  {botCtx && (
    <div className="werewolf-seat__model-row"
         title={hasTokenStats ? `Token: 输入 ${totalInTokens ?? 0} · 输出 ${totalOutTokens ?? 0}` : undefined}>
      {hasTokenStats && (
        <>
          <span className="werewolf-seat__token">🔤in:{formatK(totalInTokens)}</span>
          <span className="werewolf-seat__token">out:{formatK(totalOutTokens)}</span>
          {isCacheHit && <span className="werewolf-seat__cachebadge">⚡</span>}
        </>
      )}
      {player.agent_name && (() => {
        const ms = modelStyleOf(player.agent_name);
        const school = t(`werewolf.modelstyle.${ms.schoolKey}` as any);
        return (
          <span className="werewolf-seat__model ww-model-style"
                style={{ ['--ww-model-glow' as any]: ms.glow }}
                title={`${player.agent_name} · ${school}`}>
            <span className="ww-model-style__emoji">{ms.emoji}</span>
            {player.agent_name}
          </span>
        );
      })()}
      {!compact && nowMs !== undefined && (
        <AgentCallTimeBadge ctx={botCtx} nowMs={nowMs} />
      )}
    </div>
  )}
</div>
```

**真人玩家路径**：botCtx 为 undefined → 整块 `werewolf-seat__agent-block` 仅含「行 1
决策摘要（无 LLM 决策时为空）」 + LLM 5 态指示器（hasPhaseIndicator）；avatar 撑满卡片
高度（`flex: 1` 配合 `align-self: stretch`）。

一行装不下时**自动折成两行**而不是被裁。

### 3.3 U3 — 私聊目标账号格式化为「Bot N号」（缺陷 C）

**后端 `ServerGo/ws/chat_service.go::WhisperFromBot`**：在 `toDisplay = toAccount` fallback
前，先**用房间 gameState 查 user_id → seat**，再拼 `Bot {seat+1}号`（与发送方 `botAccount`
同源）：

```go
func (s *ChatService) WhisperFromBot(roomID, botUserID, botAccount, modelKey, toUserID, toAccount, text string) (*wwplayer.BotChatSendResult, error) {
    if roomID == "" {
        return nil, errRoomIDRequired
    }
    display := botAccount
    if display == "" {
        display = s.lookupAccount(botUserID)
    }
    toDisplay := toAccount
    if toDisplay == "" {
        toDisplay = s.lookupSeatAccount(roomID, toUserID)  // ← 改这里
    }
    ...
}

// §20260817-04 U3 — 私聊目标座位格式化。
// 优先于 lookupAccount,保证 whisper 接收方昵称与发送方"Bot N号"同源。
// 查找路径:roomID → game → seats[seat] == toUserID → "Bot N号" / "玩家N号"。
// 仅在 werewolf 房间有意义(其他 game_kind seats 未必有 user_id 反查);
// 非 werewolf 房间 fallback 到 lookupAccount。
func (s *ChatService) lookupSeatAccount(roomID, userID string) string {
    if userID == "" {
        return ""
    }
    if s.roomSvc == nil {
        return s.lookupAccount(userID)
    }
    snap := s.roomSvc.RoomSnapshot(roomID)
    if snap == nil {
        return s.lookupAccount(userID)
    }
    // 仅处理 werewolf 房间
    if snap.GameKind != "werewolf" {
        return s.lookupAccount(userID)
    }
    // seats[seat] = userID
    seats, _ := snap.Seats.([]string)  // type assertion 取决于 RoomSnapshot 实现
    for seat, uid := range seats {
        if uid == userID {
            // 区分 bot / 真人:bot 在 seats 中与 Bot N号 一致
            return fmt.Sprintf("Bot %d号", seat+1)
        }
    }
    // 真人玩家(seat -1 也走 fallback)
    return s.lookupAccount(userID)
}
```

**前提**：必须有 `roomSvc.RoomSnapshot(roomID)` 暴露 `(GameKind, Seats)`。
若当前实现没有，新增一个简洁的 read-only 方法（5 行），不做 deep copy，仅返回
`(GameKind, SeatsCopy)` 用于昵称解析。

**前端**：保持不变（`ChatMessage.to_account` 由后端下发，前端只渲染 `<span className="game-chat-msg__whisper-to">→ {to_account}</span>`）。

**降级路径**：
- 非 werewolf 房间 → `lookupAccount` (原行为)
- werewolf 但 userID 不在 seats → `lookupAccount` (原行为)
- werewolf + 找到 seat → `Bot N号` (新行为,与发送方格式一致)

**测试**：
- `room_whisper_to_account_test.go`：构造 werewolf 房间（13 个 bot 座位），bot 12 → bot 6
  whisper → 验证 `ToAccount == "Bot 6号"`。

## 8. 教训（项目层）

1. **「未紧凑填充」的留白是高密度 13 人局桌面布局的常见缺陷**：横版 5 行结构在 13 人局
   4-5 列网格下，座位卡宽度有限，行数过多必然分散 + 留空。**U1 的「1 个紧凑块」模式**
   （决策 + 指标 + 模型三行打包 + `margin-top: auto` 贴底）应推广到所有"信息块末尾"。
2. **气泡 hover popover 与 seat popover 复用同一抬层**：§20260817-03 已经为
   `.werewolf-seat:hover` 设了 z-index 60，§20260817-04 U2 直接复用同一变量，避免
   引入第二套 z-index 体系。
3. **私聊目标格式应与发送方同源**：发送方 `botAccount = "Bot N号"`（room_agent.go:1917
   显式拼），接收方却走 `lookupAccount` 返回短 ID，**同一函数两条路径不对称是缺陷**。
   修复 = 接收方也用同源路径（user_id → seat → "Bot N号"）。
4. **`title` 原生 tooltip 是 hover 全文的最低成本兜底，但不是 UX**：500ms 延迟 +
   鼠标移开即消失 + 移动端不响应，**不能作为唯一完整查看机制**。U2 引入 CSS-only
   popover 是更可靠的方案（无需 JS、无 portal、不破坏响应式）。
