## 2. 实施清单

### 2.1 移植 Texas Hold'em 版 MemoryCompact(本方案新增)

**设计动机**: 现有 thpagent `prompt_compress.go` 的 Tier80 LLM 压缩只针对
"牌桌闲聊(增量)" 这一段;但一段长对局后期,`Memory.HandRecord`(5 手)+ 
`OpponentStats`(6 座位累计)+ 频繁的 `DecisionSummary` 三者合计字节量
可能突破 50KB,LLM 决策上下文被 `RecentHandHistory` / `Reputation` 段
挤压。**wwplayer 的 `memory_compact.go` 已经用 LLM 把 messages 数组
压缩为 8 段结构化摘要**,德扑侧需要等价实现。

**与狼人杀差异**:
- 狼人杀 messages 是 LLM 视角的对话历史(identity + tools + assistant)
- 德扑 messages 不存在 — 用 `Memory.HandRecord[]` + `OpponentStats` 序列化
  作为压缩输入
- 8 段 → **4 段(风格画像 + 对手笔记 + 关键决策 + 当前局势)**,与
  `memory_persist.go::texasMemorySectionTitles` 保持同一语义(后者两段
  是 MEMORY.md,MemoryCompact 是 memory_decision_summary — 不可混)

**AgentClassName**: `LsmAgentGame-TexasHoldem-MemoryCompact`,登记到
`class_names.go::AllAgentClassNames()`。

**触发点**: `driver.go::DecideAction` 在 prompt 字节预算超 Tier100
(prompt >= budget)时,先 `ApplyPromptCompression(Tier100)` 仍超预算
则触发 `Memory.CompactWithLLM` 把"最近 4 手"压缩为 4 段结构化摘要,
挂回 `Memory.LastCompactSummary` 字段,`buildRecentHandHistoryBlock`
下次渲染时优先读摘要,空则按现有 RecentHandHistory 渲染。
**失败回退**: `IsValidCompactSummary` 校验失败 → 保留旧 RecentHandHistory。

**新文件**: `ServerGo/agent/thpagent/memory_compact.go`

### 2.2 狼人杀 13 人局房间聊天 Agent 发言可见性复核

**复核路径**:

1. **服务端广播** — `ChatService.SendFromBot`
   - `chat.message` 走 `BroadcastRoomIncludingSpectators` → 玩家 + 观战者
     都收;只一条 envelope,玩家/观战者 payload **一致**(`playerMsg`
     单条 JSON Marshal 后发一次)。✅ 正常
2. **前端订阅** — `useChat('room', roomId)` 自动 `chat.subscribe`
   - `matches(m.scope, m.room_id, scope, roomId)` 用 `scope==='room'`
     且 `m.room_id===roomId` 匹配;`SendFromBot` 落库后 `m.RoomID=roomID`
     一致。
4. **前端渲染** — `GameChatPanel.tsx` 渲染分支 `from_role === 'bot'`
   - 任何 `chat.message` 帧 if `from_role='bot'` → 渲染青边条 +
     `🤖 ${from_agent_name}` 徽章 + 文本。✅ 正常

**潜在缺陷(可能让用户感知"看不到")**:

A. **`from_account` 为空字符串** — bot 用户的 `account` 在 DB 中可能
   未写(`SendFromBot` 内部 `lookupAccount` 兜底),`display=""` →
   渲染时 `from_account` 显示空,看上去像无内容。**修复**: 
   `SendFromBot` 兜底路径优先用 `fmt.Sprintf("Bot %d号", seat+1)`
   (与德扑 `RecordTexasBotChat` 对齐),缺 seat 时回退 lookupAccount。

B. **观战者模式早期进入** — `chat.subscribe` 在 WS 连接建立后才发;
   观战者若在 game.state 推送到达前就打开了 chat panel,但 bot 已经
   发过 N 条(`chat.history` 应拉回),`chat.history` 的 `messages`
   包含 bot 消息。**已实测历史没问题**,只需在 chat panel 顶部加
   一句"🤖 模型徽章 = AI 发言"提示,让用户知道有 bot 发言存在。

C. **chat.panel 历史分页 dedupe bug** — 同 ID 重复添加会丢,正常
   `chat.history` 返回的 `id` 来自 DB row,带数字 ID;`chat.message`
   实时帧也用同一 ID;重复可能发生在订阅刷新瞬间。已用
   `if (prev.some((x) => x.id === m.id))` 防御;无新 bug。

**本次修复 A**(高优先级 — 与德扑对齐,消除空昵称空白条)。
