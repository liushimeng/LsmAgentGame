# 狼人杀游戏界面布局优化方案（§20260817-03）

> 日期：2026-08-17
> 范围：`ServerGo/game/werewolf/view.go` + `ClientWeb/src`（狼人杀对局页）
> 触发：用户反馈三项布局缺陷（AI 解说空占位 / 座位卡提示框被裁剪 / 缺少每小时 Token 消耗预期）

---

## 1. 背景与需求

### 需求 1 — AI 解说未开启时隐藏解说工具栏

观战者底栏 `SpectatorCompactBar`（解说席 + 观众押注合并组件）在房间**未开启** AI 解说时，
仍然渲染整块工具栏：

```
🎙️ 🎙️ AI 解说
🎯 投票阶段开始后可押注
解说席虚位以待——房间未开启 AI 解说。
```

占用中栏底部一整行垂直空间（grid 第 2 行 `1fr auto` 中的 auto 行），挤压 13 人局座位网格
的可用高度。要求：**未开启解说时隐藏解说相关布局，把空间让给游戏界面**。

### 需求 2 — 座位卡提示框/弹出框显示不全（层级问题）

鼠标悬停座位卡头像时，情绪 popover（`.ww-emotion-popover`）**只在座位卡框内显示、被裁掉**；
身份猜测弹层（`.werewolf-guess-popover`，10+ 个角色按钮，高度 ~300px）同样被裁剪。
用户判断为"控件显示的层级问题"。

### 需求 3 — 标题栏添加「每小时 Token 消耗」实时参考值

`狼人杀 13 人标准竞技局` 标题栏已有 `已运行 14:22` 运行时长 chip，以及统计区
`Token: 输入 9.9M · 输出 177.9K · 总计 10.1M` 累计 Token chip。
要求在运行时长后面追加一个**每小时平均 Token 消耗**实时值，单位自动缩放（K/M），
让玩家对"继续玩下去每小时烧多少 Token"有心理预期。

### 需求 4 — 同类问题一并修复

审计发现的同模式缺陷一并处理（见 §3.4）。

## 2. 现状代码分析

### 2.1 AI 解说链路

| 层 | 位置 | 现状 |
|----|------|------|
| 房间配置 | `ServerGo/game/werewolf/commentary_room.go:25` `CommentaryConfig{Enabled,Style,ModelKey}` | 创建房间时一次性写入 `r.commentaryDesired` |
| 房间字段 | `room.go:142` `commentaryDesired bool`（锁内访问） | 解说开关唯一事实来源 |
| 视图下发 | `view.go` spectator 分支（`viewer < 0`）只下发 `CommentaryFeed`（非空时） | **没有** `commentary_enabled` 标志位 —— 前端无法区分「未开启」与「已开启但暂无输出」 |
| 前端渲染 | `WerewolfGamePage.tsx:818` spectator → `SpectatorCompactBar` | 恒渲染，feed 为空时显示空态文案 |
| 前端 store | `werewolf.store.ts::commentaryFeed` | `game.state.commentary_feed` 灌入 + `chat.commentary` 增量 |

**根因**：前端缺少「解说是否开启」的权威信号，只能恒渲染空态占位。

**死代码**：`components/werewolf/CommentaryPanel.tsx`（42 行）自 §20260812-02 被
`SpectatorCompactBar` 合并替代后**零 import**（§126「组件存在但未被 import 等于不存在」），
是同一块"解说席"UI 的陈旧副本，一并删除。

### 2.2 座位卡提示框裁剪链路

三层叠加缺陷：

1. **`.werewolf-seat { overflow: hidden }`**（`werewolf-v2.css:978`）——
   座位卡本身是裁剪容器。`.ww-emotion-popover`（相对 `.ww-emotion-avatar` 绝对定位）
   与 `.werewolf-guess-popover`（相对座位卡右上角 wrap 绝对定位）一旦超出卡片矩形即被裁剪。
   这是「只在游戏角色框内显示」的直接根因。
2. **兄弟座位压层**：所有座位卡 `z-index: var(--ww-z-seat, 7)`（`werewolf.css:1092`），
   同为定位元素、同层级 → DOM 顺序在后的座位卡盖住悬停座位弹出的 popover。
   缺少「悬停座位抬层」规则。
3. **滚动容器边界裁剪**：`.werewolf-table { overflow-y: auto }` 与
   `.werewolf-table__grid { overflow-y: auto }`（`werewolf.css:451/457`，2026-07-26 聊天滚动
   修复引入）使网格成为滚动容器——overflow-y:auto 会连带把 overflow-x 的 visible 计算为 auto，
   超出网格 padding box 的 popover 被裁剪。而 `EmotionAvatar` 的翻转判定
   （`EmotionAvatar.tsx:115-133`，§20260811-06 U2）用的是 **viewport 坐标**
   （`aRect.top - pRect.height >= 8`），不是滚动容器边界：
   第 1 行座位头像在 viewport 中上方空间充足 → 判定向上展开 → 被网格上边界裁掉。
   身份猜测弹层恒向下展开，最后一行座位会被网格下边界裁掉。

发言气泡（`.werewolf-seat__speech`）本身是卡内 2 行钳位 + `title` 原生 tooltip，
原生 tooltip 由浏览器渲染不受层级影响；其「显示不全」的体感来源是上述 popover
裁剪的同源问题（用户把头像 popover 与气泡归为一类），本方案修复 popover 后一并消除。

### 2.3 运行时长 + Token 统计链路

| 位置 | 现状 |
|------|------|
| `GameStatusHeader.tsx:156-166` | `game_started_at` → `elapsedSec` → 标题行 `⏱ 已运行 {h}:{m}:{s}` chip |
| `GameStatusHeader.tsx:323-331` | 统计组 token chip：`werewolf.statusBar.tokenStats`，数据源 `gameState.agent_stats.total_{input,output,api}_tokens` |
| `shared/utils/format.ts::formatK` | 单位自动缩放：≥1e6 → `x.xM`，≥1e3 → `x.xK`（正好满足"单位自动增加"） |
| `nowMs` 驱动 | 父级 `WerewolfGamePage` 每次渲染传 `Date.now()`；`game.state` 帧驱动重渲染，秒级实时性足够 |

**根因**：两个数据都已存在（累计 Token、已运行秒数），只差一个派生展示
`rate = total_api_tokens / (elapsedSec / 3600)`。

### 2.4 顺带发现的小缺陷

- `SpectatorCompactBar.tsx:60` 硬编码 `🎙️` + i18n 值 `werewolf.commentary.title` 自带
  `🎙️` → 用户截图中的「🎙️ 🎙️ AI 解说」双 emoji。

## 3. 解决方案

### 3.1 U1 — AI 解说未开启时隐藏解说工具栏（后端补信号 + 前端按需渲染）

**后端**（`ServerGo/game/werewolf/view.go`）：

1. `ClientGameState` 新增字段（不带 omitempty，保证 false 也显式下发）：

   ```go
   // §20260817-03 U1 — AI 解说是否开启(房间级开关)。
   // spectator 据此决定解说席渲染;玩家侧恒 false(解说仅观众可见,§119 隔离)。
   CommentaryEnabled bool `json:"commentary_enabled"`
   ```

2. spectator 分支（`viewer < 0`，填充 `CommentaryFeed` 处）赋值：
   `cs.CommentaryEnabled = r.commentaryDesired`（调用方已持 r.mu，§92a 锁内直读）。

**前端**：

1. `types/werewolf.ts::WerewolfGameState` 加 `commentary_enabled?: boolean`。
2. `SpectatorCompactBar` 加 prop `commentaryEnabled: boolean`：
   - `showCommentary = commentaryEnabled`；`showBet = isVotePhase || !!myBet`；
   - `!showCommentary && !showBet` → **整体返回 null**（grid auto 行塌缩为 0，
     中栏 1fr 行自动吸收释放的垂直空间）；
   - 仅隐藏解说区时押注区占满整行；header 左右标题按需渲染；
   - 顺手删除硬编码 `🎙️`（i18n 值已含）。
3. `WerewolfGamePage` 透传 `commentaryEnabled={gameState?.commentary_enabled === true}`。
4. 删除死代码 `components/werewolf/CommentaryPanel.tsx`（零 import，§126）。

**行为矩阵**：

| commentary_enabled | 阶段/押注状态 | 渲染结果 |
|---|---|---|
| true | 任意 | 与现状一致（解说区 + 空态文案/内容） |
| false | 投票阶段 或 已押注 | 仅押注区（整行） |
| false | 其余 | 整个底栏不渲染，空间归还座位网格 |

### 3.2 U2 — 座位卡 popover 层级与裁剪修复

**CSS**（新文件 `styles/werewolf-20260817-03.css`，globals.css 中追加 @import，
位于 `werewolf-20260817-01.css` 之后 —— 同特异性靠级联顺序取胜；**不调整既有
import 相对顺序**，§2.1 硬约束 4）：

1. `.werewolf-seat { overflow: visible }` —— 解除卡片裁剪
   （`.werewolf-seat__avatar` 的 `overflow: hidden` 保留，头像图片圆角裁剪不受影响）。
2. 悬停/键盘焦点/弹层打开态座位抬层：

   ```css
   .werewolf-game .werewolf-seat:hover,
   .werewolf-game .werewolf-seat:focus-within,
   .werewolf-game .werewolf-seat:has(.werewolf-guess-popover) {
     z-index: var(--ww-z-popover, 60);
   }
   ```

   60 高于兄弟座位(7)/徽章(12)/桌面阶段标签(10)/操作面板(50)，
   popover 打开期间稳定压过相邻座位与桌面元素；`:has()` 覆盖
   「鼠标移开但猜测弹层仍开着」的残留窗口（不支持 :has 的浏览器降级为 hover/focus 规则）。

**JS（网格边界感知定位）**：

3. `EmotionAvatar.tsx` placement useEffect：翻转判定改为以
   `avatarEl.closest('.werewolf-table')` 的 bounding rect 为边界
   （取不到时降级 viewport）：
   - 默认向下；下方剩余空间 < popover 高 且上方空间更大 → 向上；
   - 水平居中越界时贴左/贴右（沿用现逻辑，边界换为容器 rect 与 viewport 的交集）。
4. `IdentityGuessBadge.tsx`：弹层打开后测 wrap 与网格边界，下方放不下时加
   `werewolf-guess-popover--above` 修饰类向上展开（CSS 新规则：
   `top:auto; bottom:100%; margin:0 0 6px`）。

### 3.3 U3 — 标题栏「每小时 Token 消耗」chip

`GameStatusHeader.tsx` 标题行 clock chip 之后追加：

- 计算：`ratePerHour = agentStats.total_api_tokens / (elapsedSec / 3600)`；
- 守卫：`hasClock && elapsedSec >= 60 && total_api_tokens > 0`
  （开局 1 分钟内外推误差过大，不显示；token 为 0 不显示）；
- 文案：`⚡ ≈{rate}/h`，`formatK` 自动 K/M 缩放；title 挂完整说明
  （"按当前运行时长折算的平均每小时 Token 消耗 = 总计 ÷ 已运行小时"）；
- 数据源与现有 token chip 完全同源（`agent_stats.total_api_tokens`，
  不含法官统计 —— 与用户参考的 `Token: 输入/输出/总计` chip 口径一致）；
- 实时性：随 `game.state` 帧 + 父级 nowMs 重渲染自动刷新；对局结束 status=over 后
  elapsed 与 token 都不再增长，数值自然冻结为整局均值；
- 新 chip 类 `.ww-game-status-header__chip--tokenrate`（新 CSS 文件内，绿色系与
  tokens chip 同族但区分：青绿底）。

**i18n 三语新增**（types.ts + zh-CN/en/ja）：

| key | zh-CN |
|-----|-------|
| `werewolf.statusBar.tokensPerHour` | `⚡ ≈{rate}/小时` |
| `werewolf.statusBar.tokensPerHourTip` | `平均每小时 Token 消耗(总计 {total} ÷ 已运行 {hours} 小时),随对局实时更新` |

## 6. 风险与回滚

- `commentary_enabled` 为新增 JSON 字段，老前端忽略、新前端 `=== true` 守卫，双向兼容。
- `overflow: visible` 若引发卡内元素意外溢出，回滚仅需删新 CSS 文件的对应规则
  （新文件级联在最后，删除即恢复原行为）。
- 单文件行数均远低于 §4 上限 1800。
