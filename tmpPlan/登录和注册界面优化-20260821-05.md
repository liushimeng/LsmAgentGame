# 登录和注册界面优化方案

> **编号**: 20260821-05
> **日期**: 2026-08-21
> **状态**: 待执行

## 1. 问题诊断

### 1.1 问题一：登录/注册切换时状态管理不当

**现象**：登录和注册界面切换时，表单数据未完全隔离。

**根因分析**：
- `AuthModal` 使用 `useState<'login' | 'register'>` 管理切换
- `LoginForm` 和 `RegisterForm` 作为条件渲染的子组件，切换时会完全卸载/重新挂载
- 这导致用户在登录表单输入内容后切换到注册，再切回登录时，之前输入的内容全部丢失

**预期行为**：
- 登录和注册应该是独立的子页面
- 切换时保留各自的状态，用户返回时能看到之前输入的内容

### 1.2 问题二：账号/手机号登录模式数据未独立

**现象**：账号登录和手机号登录两个Tab页的数据未完全隔离。

**根因分析**：
- `LoginForm` 内部使用 `useState<'account' | 'phone'>` 管理Tab切换
- `account` 和 `phone` 字段共享同一个组件状态
- `uiStorage.save()` 同时保存 account 和 phone，无论当前使用哪种模式

**预期行为**：
- 账号登录和手机号登录应该保存各自独立的凭证
- 切换到账号登录时，显示之前保存的账号凭证
- 切换到手机号登录时，显示之前保存的手机号凭证

### 1.3 问题三：注册表单保存密码到本地存储

**现象**：注册成功后，密码被保存到加密localStorage。

**根因分析**：
- `RegisterForm.tsx` 第54-59行的 `uiStorage.save()` 包含了 `password` 字段
- 注释明确说明 "We do NOT persist the password on the register path"
- 但实际代码与注释矛盾

**预期行为**：
- 注册成功后不应保存密码到本地存储
- 只保存 account 和 phone 用于下次登录时回填

### 1.4 问题四：验证码状态管理

**现象**：切换登录模式时，验证码状态可能残留。

**根因分析**：
- `captchaId` 和 `captchaAnswer` 在 `LoginForm` 级别管理
- 切换 account/phone 模式时不会自动刷新验证码

## 2. 优化方案

### 2.1 架构设计

```
AuthModal (容器)
├── mode: 'login' | 'register'
├── 使用 CSS display 控制显示/隐藏（不卸载组件）
├── LoginForm (始终保持挂载)
│   ├── mode: 'account' | 'phone'
│   ├── 独立的 account 凭证状态
│   ├── 独立的 phone 凭证状态
│   └── 验证码状态按模式隔离
└── RegisterForm (始终保持挂载)
    └── 独立的状态管理
```

### 2.2 核心改动

#### 改动1：AuthModal 改用 CSS 显示/隐藏

**文件**: `ClientWeb/src/components/auth/AuthModal.tsx`

```tsx
// 改动前：条件渲染（组件会卸载）
{mode === 'login'
  ? <LoginForm onSwitch={() => setMode('register')} />
  : <RegisterForm onSwitch={() => setMode('login')} />}

// 改动后：CSS 控制显示（组件保持挂载）
<div style={{ display: mode === 'login' ? 'block' : 'none' }}>
  <LoginForm onSwitch={() => setMode('register')} />
</div>
<div style={{ display: mode === 'register' ? 'block' : 'none' }}>
  <RegisterForm onSwitch={() => setMode('login')} />
</div>
```

#### 改动2：LoginForm 按模式隔离凭证

**文件**: `ClientWeb/src/components/auth/LoginForm.tsx`

```tsx
// 改动前：共享状态
const [account, setAccount] = useState('');
const [phone, setPhone] = useState('');
const [password, setPassword] = useState('');

// 改动后：按模式隔离
const [accountCreds, setAccountCreds] = useState({ account: '', password: '' });
const [phoneCreds, setPhoneCreds] = useState({ phone: '', password: '' });
const [accountCaptcha, setAccountCaptcha] = useState({ id: '', svg: '', answer: '' });
const [phoneCaptcha, setPhoneCaptcha] = useState({ id: '', svg: '', answer: '' });
```

#### 改动3：RegisterForm 移除密码保存

**文件**: `ClientWeb/src/components/auth/RegisterForm.tsx`

```tsx
// 改动前
await uiStorage.save({
  account: account.trim(),
  phone: phone.trim(),
  password,  // ← 移除
  mode: 'account',
});

// 改动后
await uiStorage.save({
  account: account.trim(),
  phone: phone.trim(),
  password: '',  // 不保存密码
  mode: 'account',
});
```

#### 改动4：uiStorage 支持按模式分别保存

**文件**: `ClientWeb/src/shared/utils/ui-storage.ts`

```typescript
// 扩展 SavedCredentials 接口
export interface SavedCredentials {
  account: string;
  password: string;
  phone: string;
  mode: 'account' | 'phone';
  savedAt: number;
  // 新增：按模式分别保存的凭证
  accountPassword?: string;  // 账号登录的密码
  phonePassword?: string;    // 手机号登录的密码
}
```

### 2.3 数据持久化策略

| 数据 | 保存时机 | 清除时机 | 存储位置 |
|------|----------|----------|----------|
| 账号登录凭证 | 账号登录成功时 | 手动清除 | lsm.auth.ui (加密) |
| 手机号登录凭证 | 手机号登录成功时 | 手动清除 | lsm.auth.ui (加密) |
| 注册信息 | 注册成功时（不含密码） | 手动清除 | lsm.auth.ui (加密) |
| Session Token | 登录/注册成功时 | 登出时 | lsm.token |
| Auth State | 状态变更时 | 登出时 | lsm.auth (zustand) |

### 2.4 安全加固

1. **密码隔离**：账号登录和手机号登录的密码分别存储
2. **注册不存密码**：注册成功后不保存密码到本地
3. **验证码隔离**：不同登录模式使用独立的验证码状态
4. **加密升级**：保持现有 AES-GCM-256 + PBKDF2 加密方案
