# 狼人杀 规则

> 狼人杀是一类以"信息博弈 + 公开推理"为核心的多人身份扮演游戏。平台支持 **13 人标准竞技局**(4 狼 + 4 神 + 5 民,默认)和 **7 人经典局**(2 狼 + 3 神 + 2 民)两种配置。平台实现以服务端权威为准,所有身份判定、技能结算、胜负裁决均在服务端进行。引擎代码位于 `ServerGo/game/werewolf/`,前端 UI 位于 `ClientWeb/src/components/werewolf/` 与 `ClientWeb/src/pages/WerewolfGamePage.tsx`。

## 1. 游戏概述

狼人杀是经典的身份推理桌游。平台默认 **13 人标准竞技局**,特点:

- **总人数**:13 名玩家(或 7 名玩家,视房间配置)。
- **阵营**:狼人阵营 4 人 / 好人阵营 9 人(神职 4 + 平民 5)。
- **核心机制**:每夜狼人暗杀,每白天通过发言、投票推理放逐狼人。
- **特色机制**:屠边胜负、神职用药、警长票权、白天自爆、遗言规则、白痴翻牌、晚上单线信息揭示。
- **信息博弈**:手牌(身份)始终隐藏,夜晚的唤醒动作按固定顺序,每个玩家只能看到属于自己的部分信息。

胜负判定概要(详见 [§8 胜负判定](#8-胜负判定)):

- **狼人阵营胜**:屠边规则——杀光所有神职(预言家 + 女巫 + 猎人 + 白痴),或杀光所有平民(5 名普通村民)。
- **好人阵营胜**:放逐全部 4 名狼人(7 人局为 2 名)。

> **平台定位**:在线对局不允许场外语言/手势交流,且强制禁用同一晚"解药 + 毒药"同用规则(与线下局惯例一致)。

| 狼人阵营   |  4   | 4 名普通狼人                                              |

> **屠边胜负**:任意一个被 `FactionOf() == good` 的角色死亡都可能影响胜负。基础神职(预言家 / 女巫 / 猎人 / 白痴)与当前扩展神职(守卫 / 骑士 / 魔术师 / 奇迹商人 / 射梦人 / 乌鸦 / 猎魔人 / 纯白之女)在 `IsGodRole()` 中均被识别为神职,屠神 = 杀光**全部**上述神职(不含平民)。

### 2.3 标准角色牌组

角色牌组合由后端 `StandardDeck13()` (13 人)或 `StandardDeck()` (7 人)给定——发牌前随机洗牌后分配至座位:

**13 人标准竞技局**(默认):
```
狼人 × 4 + 预言家 × 1 + 女巫 × 1 + 猎人 × 1 + 白痴 × 1 + 平民 × 5  =  13 张
```

**13 人随机牌组**(后端 `RandomDeck13()` / `AssignRoles13Random()`,房间配置启用时):
```
4 狼 + 1 预言家(必出) + 2~3 个随机神职(从 godRolePool 中抽取)
+ 剩余补齐平民(保证 ≥ 5 平民),第 13 人强制为平民
```

`godRolePool` 当前共 11 个候选神职:`女巫 / 猎人 / 白痴 / 守卫 / 骑士 / 魔术师 / 奇迹商人 / 射梦人 / 乌鸦 / 猎魔人 / 纯白之女`(不含预言家,预言家每局必出)。稻草人和定序王子仅保留旧 payload 展示兼容,不参与当前发牌。

**7 人经典局**:
```
狼人 × 2 + 预言家 × 1 + 女巫 × 1 + 猎人 × 1 + 平民 × 2  =  7 张
```

随机性来源:每个房间首次创建时由 `seed := time.Now().UnixNano()` 生成种子,经 `math/rand` 洗牌后写入 `GameState.Roles[seat]`。

### 2.4 7 人经典局配置

7 人局为历史兼容配置,共 7 名玩家:

| 阵营       | 人数 | 角色组成                                                  |
| ---------- | :--: | --------------------------------------------------------- |
| 狼人阵营   |  2   | 2 名普通狼人                                              |
| 好人阵营   |  5   | 1 预言家 + 1 女巫 + 1 猎人 + 2 名普通平民(无白痴)       |

## 3. 角色技能

### 3.1 狼人(Werewolf)

| 项目     | 规则                                                                                          |
| -------- | --------------------------------------------------------------------------------------------- |
| 阵营     | 狼人阵营                                                                                      |
| 数量     | 4 (13人局) / 2 (7人局)                                                                         |
| 夜间能力 | 每晚可**共同睁眼**,协商选择击杀任意一名**非狼人**玩家(空刀也合法)                          |
| 白天能力 | 隐藏身份,参与发言与投票;特殊地,**可在白天发言阶段"自爆"**                                  |
| 自爆规则 | 自爆后立即终止当轮发言,直接进入黑夜,自爆狼**死亡 + 无遗言**(详见 [§7.1 自爆规则](#71-自爆规则)) |
| 共同视野 | 同一阵营的所有狼人在**夜晚 wolves 阶段**可互相看到对方座位                                   |

> **代码约束**:`NightWolfKill(actor, target)` 校验 `actor` 必为存活狼人,`target != NoSeat` 时必须为另一阵营存活玩家,空刀 `target = NoSeat` 合法。

### 3.2 预言家(Seer)

| 项目     | 规则                                                                                          |
| -------- | --------------------------------------------------------------------------------------------- |
| 阵营     | 好人阵营                                                                                      |
| 数量     | 1                                                                                              |
| 夜间能力 | 每晚可查验任意一名玩家,服务端返回**该玩家的阵营**(好人/狼人,**不告知具体身份牌**)           |
| 信息保留 | 查验结果**仅自己知道**,需白天发言公开                                                          |
| 限制     | 每晚只能查验一名玩家;不支持对已查验玩家重复查验(规则上允许,无额外收益)                       |

> **代码约束**:`NightSeerCheck(actor, target)` 校验 `actor` 必为存活预言家、`target != actor`。查验后服务端把 `Roles[target]` 的阵营写入 `GameState.Players[actor].LastSeerCheck`,下一晚预言家再次睁眼时可通过服务端发回的视图读取历史。

### 3.3 女巫(Witch)

| 项目     | 规则                                                                                          |
| -------- | --------------------------------------------------------------------------------------------- |
| 阵营     | 好人阵营                                                                                      |
| 数量     | 1                                                                                              |
| 持有物   | **解药 1 瓶 + 毒药 1 瓶**,整局游戏各只能使用一次                                              |
| 解药     | 救活当晚**被狼人击杀**的玩家(无效情形:狼人空刀)                                             |
| 毒药     | 毒杀场上任意一名玩家(同刀同毒依然生效,目标仍然死亡)                                        |
| 核心限制 | **解药与毒药不能在同一个晚上同时使用**                                                        |
| 失效约束 | 解药仅对狼杀有效,对白天投票放逐、女巫毒药、猎人开枪等其他死亡方式**无效**                  |
| 特殊死亡 | 女巫当晚被毒杀时,不能再使用当晚的毒药                                                        |

> **代码约束**:`NightWitchAct(actor, action, target)` 校验 `actor == WitchSeat` 且存活;`action ∈ {"none", "antidote", "poison"}`;`witch_poison` 触发的 `killPlayer` 标记 `LastWords = false`(无遗言)。

### 3.4 猎人(Hunter)

| 项目     | 规则                                                                                          |
| -------- | --------------------------------------------------------------------------------------------- |
| 阵营     | 好人阵营                                                                                      |
| 数量     | 1                                                                                              |
| 持有能力 | 死亡时可**开枪带走**场上任意一名玩家                                                          |
| 触发条件 | 被狼刀 / 被白天投票放逐 → 可开枪                                                              |
| 触发限制 | **被女巫毒药毒死时不能开枪**(判定逻辑必须区分死亡来源)                                       |
| 选择权   | 猎人可选择"不开枪";若开枪,被带走的人如仍在遗言轮次内则**有遗言**                           |
| 身份公开 | **开枪 = 主动亮身份**,全场立刻知道他是猎人;被毒死不能开枪 → 身份保密;选择不开枪 → 同样不亮身份 |
| 副作用   | 猎人开枪带走女巫,若当晚女巫尚未用药,则该女巫的**剩余药剂直接失效**(同局规则锁定)            |

> **代码约束**:`HunterPendingFrom` 字段记录 `"vote" | "wolf"`;女巫毒杀路径不置 `HunterPendingShoot`。
> 实际开枪(`target != NoSeat`)时置 `Player.HunterFired = true`,该字段是 §7.0 身份公开白名单的判定依据之一。

### 3.5 白痴(Idiot)

| 项目     | 规则                                                                                          |
| -------- | --------------------------------------------------------------------------------------------- |
| 阵营     | 好人阵营                                                                                      |
| 数量     | 1 (13 人局) / 0 (7 人局)                                                                     |
| 特殊能力 | 被投票放逐时,**翻牌公开身份**后免于出局,继续留在场上                                         |
| 限制     | 翻牌后**失去投票权**(但仍可发言);被狼刀/毒药击杀时正常死亡                                  |
| 触发条件 | 仅白天投票放逐触发;猎人开枪、狼人自爆等不触发翻牌                                            |
| 身份公开 | **仅白天翻牌时公开**;夜晚被刀 / 被毒死亡 → **不翻牌,身份保密**                              |

> **代码约束**:`PhaseIdiotReveal` 阶段在 `FinishVote` 检测到 target 为白痴时触发;翻牌后 `Player.IdiotRevealed = true`,投票权重设为 0。

### 3.6 平民(Villager)

| 项目     | 规则                                                                                          |
| -------- | --------------------------------------------------------------------------------------------- |
| 阵营     | 好人阵营                                                                                      |
| 数量     | 5 (13人局) / 2 (7人局)                                                                        |
| 特殊技能 | **无**                                                                                        |
| 行动     | 夜间全程闭眼;白天靠发言和逻辑推理找出狼人                                                    |

### 3.7 技能消耗与全局约束

| 限制项                | 适用范围                       | 后端字段                                |
| --------------------- | ------------------------------ | --------------------------------------- |
| 解药全局一次性        | 女巫                           | `Player.WitchAntidoteUsed`              |
| 毒药全局一次性        | 女巫                           | `Player.WitchPoisonUsed`                |
| 同晚双药禁用          | 女巫                           | `NightWitchAct` 入口校验                |
| 毒杀不能开枪          | 猎人                           | `HunterPendingFrom != "poison"` 校验    |
| 警长 1.5 票           | 白天放逐投票(不含狼人自爆)     | `TallyVotes(false)` 用 `weight = 3` 简化 |

### 3.8 守卫(Guard)

| 项目     | 规则                                                                                          |
| -------- | --------------------------------------------------------------------------------------------- |
| 阵营     | 好人阵营                                                                                      |
| 数量     | 0~1(仅 13 人随机牌组池,标准 13 人局不出现)                                                  |
| 夜间能力 | 每晚可守护一名玩家免被狼人袭击;**不可连续两晚守护同一名玩家**                              |
| 信息保留 | 守护结果仅自己知道                                                                            |
| 限制     | 守卫可守护自己;女巫解药救人时,若守卫与狼人同时指向同一目标,该目标仍死亡                     |

> **代码约束**:`NightGuardProtect(actor, target)` 校验 `actor != target`(可守他人) + 同目标不可连续两晚;服务端把 `Player.GuardedSeats` 写入视图,守卫次日睁眼可看到是否成功。

### 3.9 骑士(Knight)

| 项目     | 规则                                                                                          |
| -------- | --------------------------------------------------------------------------------------------- |
| 阵营     | 好人阵营                                                                                      |
| 数量     | 0~1(仅 13 人随机牌组池)                                                                      |
| 白天能力 | 白天发言阶段任何时刻可发起**决斗**:与一名存活玩家单挑;若该玩家是狼人 → 该狼人立即出局        |
| 触发限制 | 决斗对象必须存活;若对象是好人或已死 → 骑士**自身出局**(惩罚机制)                            |
| 次数限制 | 整局 1 次                                                                                    |

> **代码约束**:`KnightDuel(actor, target)` 校验 `Phase ∈ {speak, sheriff_speech}` 且 `actor` 存活;若 `FactionOf(target) == wolf` 则 `killPlayer(target, "duel")`,否则 `killPlayer(actor, "duel")`。

### 3.12 射梦人(Dreamer)

### 3.13 乌鸦(Crow)

### 3.14 历史兼容角色(当前不可玩)

旧对局或旧服务端 payload 可能仍包含稻草人(`"scarecrow"`)与定序王子(`"prince"`)。客户端会继续识别并显示对应名称,避免历史记录、死亡揭示或复盘界面失真;但这两个角色不在当前标准或随机牌组池中,也不会出现在身份猜测等当前可玩角色列表里。

### 3.15 猎魔人(Demon Hunter)

| 项目     | 规则                                                                                          |
| -------- | --------------------------------------------------------------------------------------------- |
| 阵营     | 好人阵营                                                                                      |
| 数量     | 0~1(仅 13 人随机牌组池)                                                                      |
| 夜间能力 | **第 2 晚起**每晚可狩猎一名玩家;若该玩家是狼人 → 该狼人立即死亡;若该玩家是好人 → 猎魔人自身出局 |
| 限制     | 第 1 晚(首夜)不可用                                                                          |

> **代码约束**:`DemonHunterHunt(actor, target)` 校验 `DayNumber >= 2` 且 `actor` / `target` 均存活;若 `FactionOf(target) == wolf` → `killPlayer(target, "hunt")`,否则 `killPlayer(actor, "hunt")`。

### 3.16 纯白之女(Pure White)

| 项目     | 规则                                                                                          |
| -------- | --------------------------------------------------------------------------------------------- |
| 阵营     | 好人阵营                                                                                      |
| 数量     | 0~1(仅 13 人随机牌组池)                                                                      |
| 夜间能力 | 每晚可查验一名玩家;**若查验结果是狼人**,该狼人**立即出局**(无需等到次日)                  |
| 限制     | 仅作用于狼人;查验结果为好人时不附带任何副作用(与预言家相同)                                |

> **代码约束**:`PureWhiteCheck(actor, target)` 校验 `actor != target`;若 `FactionOf(target) == wolf` → `killPlayer(target, "pure_white_check")`(立即生效,无须经过 dawn)。

### 3.17 13 人随机牌组的牌组锁定(2026-07-11 起)

13 人随机牌组(`AssignRoles13Random`)在开局时即确定本局所有 13 个座位身份,不再中途替换;`RandomDeck13()` 返回的牌组顺序由房间创建种子(seed = time.Now().UnixNano())决定,同一房间的所有玩家收到一致的身份分配,后端 `GameState.Roles[seat]` 是唯一真相源。

> **UI 渲染一致性**:所有前端角色名(`SeatCell` 死亡揭示 / `GameInfoPanel` 身份区 / `IdentityGuessBadge` 下拉 / `FactionDrawer` 任务列表 / `HistoryDrawer` 时间轴 / `GameChatPanel` @mention 候选项)统一走 `t(\`werewolf.role.${role}\`)` 三语 i18n,与本节角色清单一一对应,任何新角色上线前必须**同步**更新:`cards.go` Role 枚举 / `RoleDisplayName()` / `werewolf.md` / i18n `types.ts` 类型字典 / 三语文件 5 处。

## 4. 游戏阶段机

平台后端用 12 个阶段枚举完整覆盖所有状态切换。`Phase.String()` 字符串是前后端通信的稳定契约。

| Phase 枚举              | 字符串          | 触发时机与内容                                                                  |
| ----------------------- | --------------- | ------------------------------------------------------------------------------- |
| `PhaseFilling`          | `"filling"`     | 等待玩家入座,人数不足房间处于此阶段                                          |
| `PhasePreWolves`        | `"pre_wolves"`  | 首夜强制发言阶段——每名玩家确认身份后必须至少发言 1 轮                         |
| `PhaseNightWolves`      | `"night_wolves"`| 夜晚·狼人睁眼:此阶段狼人协商刀人(`NightWolfKill`)                            |
| `PhaseNightSeer`        | `"night_seer"`  | 夜晚·预言家睁眼:此阶段预言家查验一名玩家(`NightSeerCheck`)                  |
| `PhaseNightWitch`       | `"night_witch"` | 夜晚·女巫睁眼:女巫在此阶段决定用药(`NightWitchAct`)                          |
| `PhaseDawn`             | `"dawn"`        | 黎明·公布上一晚死亡名单 + 遗言公布(`LastNightDeaths`)                         |
| `PhaseSheriff`          | `"sheriff"`     | 警长竞选(**仅 Day 1 白天才有**),候选人报名 + 投票 + 二次发言                  |
| `PhaseSpeak`            | `"speak"`       | 白天·轮流发言:每个存活玩家按座位号顺序发言                                     |
| `PhaseVote`             | `"vote"`        | 白天·投票放逐:每名存活玩家投出一票(警长 1.5 票)                              |
| `PhaseIdiotReveal`      | `"idiot_reveal"`| 白痴被投票放逐时翻牌免死阶段(13 人局)                                          |
| `PhaseHunterShoot`      | `"hunter_shoot"`| 猎人死亡后等待其选择开枪或不开枪(`HunterShoot`)                                |
| `PhaseDeathLyric`       | `"death_lyric"` | 遗言阶段                                                                        |
| `PhaseGameOver`         | `"over"`        | 对局结束:阵营胜负已分(`Status = "over"` + `Winner` 已填)                       |

### 4.1 阶段合法性约束

`GameState.IsNight()` 报告当前是否属于夜晚:

```go
func (p Phase) IsNight() bool {
    return p == PhaseNightWolves || p == PhaseNightSeer || p == PhaseNightWitch
}
```

夜间动作校验以阶段名为强约束——任何不在正确阶段发起的 `werewolf_action` 都会被服务端拒绝并返回 `ErrNotYourTurn (30008)`。

### 4.2 角色唤醒顺序

每个夜晚严格按以下顺序依次唤醒对应角色:

1. **狼人睁眼** → 协商并选择当晚击杀目标(或空刀)
2. **预言家睁眼** → 服务端用手势(向上为好人、向下为狼人)告知查验结果
3. **女巫睁眼** → 服务端告知当晚狼刀目标;女巫决定是否用药

> 如任一角色已死亡,自动跳过该角色的睁眼环节,夜晚流程直接进入下一阶段。

## 5. 夜间流程

### 5.1 状态推进顺序

```
night_wolves
    ↓ wolf_kill  (target = NoSeat 表示空刀)
night_seer
    ↓ seer_check  (验证一名玩家)
night_witch
    ↓ witch_act   (none / antidote / poison)
dawn
    ↓ 检查胜负(若分出胜负则直接进入 over)
    ↓ 否则等待 GM / 计时器调 StartDay()
sheriff? / speak? / vote?  (白天)
```

> **平台差异**:线下局由真人法官手动切换阶段;平台实现在每名角色的动作被服务端接收后由服务端状态机自动推进。GM / 自动化测试可通过 `game.werewolf_finish { action: "start_day" }` 推进天亮。

### 5.2 狼刀规则

| 规则             | 含义                                                                              |
| ---------------- | --------------------------------------------------------------------------------- |
| 合法目标         | 任意**非狼人**存活玩家                                                            |
| 空刀             | `target = NoSeat`,当晚无人死亡(平安夜)                                          |
| 拒绝操作         | `target == actor` 或 `target == 另一狼人` 或 `target` 已死                         |

### 5.3 预言家查验规则

| 规则       | 含义                                                                        |
| ---------- | --------------------------------------------------------------------------- |
| 合法目标   | 任意**非自己**的存活玩家                                                    |
| 结果保留   | 服务端把**阵营字符串**写入 `Roles[target]`,预言家白天仅知道"好人/狼人"   |
| 公开方式   | 发言 / 警长竞选 / 自爆时自己公布,**不强制公开**                            |

### 5.4 女巫用药规则

| 时机       | action       | target             | 备注                          |
| ---------- | ------------ | ------------------ | ----------------------------- |
| 不用药     | `"none"`     | `-1`               | 默认行为                      |
| 用解药     | `"antidote"` | `-1` (使用狼刀目标) | 仅在当晚狼刀有效时可用        |
| 用毒药     | `"poison"`   | 合法玩家座位       | 目标可以与狼刀目标相同(同刀同毒) |

> **失效边界**:解药不响应猎人开枪、白天投票、女巫毒药等其他死亡方式。

### 5.5 同刀同毒规则

若狼人刀与女巫毒药指向**同一名玩家**,该玩家依然正常死亡,女巫的解药**不产生浪费**;服务端在 `endWitchPhase` 中把 WolfKillTarget 写入 `NightDeaths` 时已经做了 `appendUniqueSeat` 去重处理。

### 5.6 平安夜判定

当狼人选择空刀且女巫未用毒药,当晚无人死亡;服务端把 `LastNightDeaths = []` 发给客户端,前端显示"今晚平安夜"提示。

## 6. 白天流程

### 6.1 黎明阶段(dawn)

- 服务端公布上一晚死亡的玩家(`LastNightDeaths`),**不公布死亡原因和身份**(见 [§7.0](#70-身份公开规则死者身份牌不翻开))。
- 死亡的玩家根据遗言规则有 / 无遗言(`LastWordsRounds = 2` 内)。
- 死亡玩家发表遗言后,**全程不得发言**或以任何方式传递信息。
- 若夜间死亡的是**猎人**,遗言结束后进入 `hunter_shoot` 阶段(猎人可开枪亮身份或选择不开枪),
  结算完毕再回到黎明继续本白天流程。

### 6.2 警长竞选(仅 Day 1)

| 阶段     | 规则                                                                                              |
| -------- | ------------------------------------------------------------------------------------------------- |
| 参选     | 想要竞选警长的玩家通过 `game.werewolf_sheriff { action: "candidate" }` 举手示意                 |
| 发言     | 候选玩家按座位号顺序依次发言阐明竞选理由(预言家常在此环节起跳公布查验信息)                      |
| 投票     | **未参选**的玩家进行投票,得票最多的玩家当选警长                                                   |
| 平票     | 平票者进行二次发言 + 二次投票;再次平票则**本局无警长**                                          |
| 警长特权 | 拥有 **1.5 票投票权**;决定白天发言起点(死左 / 死右 / 警长左 / 警长右);白天投票有归票发言机会  |
| 服务端   | `SheriffCandidate` + `DayVote(sheriffMode=true)` + `SheriffElect` 三个动作                   |

> **简化**:`TallyVotes(sheriffMode=true)` 应用**单票权重**,警长 1.5 票仅在常规白天投票生效,警长竞选本身按一票一投。

### 6.3 轮流发言(speak)

- 按既定顺序(默认座位号升序,警长左右可由发起者调整),每位存活玩家依次发言。
- 发言期间其他玩家**不得插嘴**或打断。
- 玩家可自由表达观点、盘逻辑、跳身份、踩人或保人。
- 当前发言者通过 `game.werewolf_finish { action: "speak" }` 表明发言结束。

### 6.4 投票放逐(vote)

- 服务端检查所有**存活**玩家的 `DayVote` 调用。
- 警长 `1.5 票` 用 `TallyVotes(false)` 中 `weight = 3` 简化实现(整数比值不影响胜负判定)。
- 单一最高票者被放逐出局,发表遗言。
- **平票** → 平票者进行辩护发言 + 二次投票;再次平票 → 当天**无人出局**,直接进入黑夜。
- 平票结束后所有 `voted=false`,重新走完发言 + 投票流程。

### 6.5 狼人自爆(suicide)

狼人在白天**发言阶段**可以发起自爆:

| 时机     | 仅 `PhaseSpeak`                                                            |
| -------- | -------------------------------------------------------------------------- |
| 出局     | 自爆狼立即死亡 + 无遗言                                                    |
| 后续     | 立即终止当轮发言,直接进入下一夜(`startNight`),当晚狼人**照常刀人**        |
| 警长阶段 | 若警长竞选阶段自爆,**中断竞选**,本局无警长                                |
| 投票阶段 | 投票阶段**不可**自爆(规则)                                                |

> **代码约束**:`WolfSuicide()` 校验 `Phase == PhaseSpeak` 且 `actor` 为存活狼人;`killPlayer(actor, "suicide")` 标记 `LastWords = false`。

## 7. 特殊规则

### 7.0 身份公开规则(死者身份牌不翻开)⚠️ 核心

> 这是本局公平性的基石。**普通死亡出局,所有人不会自动知道死者身份**,死者身份牌**全程不翻开**。
> 法官(主持人)只公布「几号玩家昨晚死亡」,**不报角色** —— 只能靠死者遗言、技能发动来推断身份。

#### 全场仅 4 类事件会公开身份

| # | 事件 | 公开谁的身份 | 服务端判定 |
| :-: | --- | --- | --- |
| ① | **终局复盘** | 全部 13 人 | `Status == "over"` |
| ② | **白痴翻牌** | 白痴本人 | `Player.IdiotRevealed` |
| ③ | **狼人自爆** | 自爆狼 | `DeathCause == "suicide"` |
| ④ | **猎人开枪** | 开枪的猎人 | `Player.HunterFired` |

其余一切死亡 —— 狼刀、女巫毒杀、白天投票放逐、被猎人枪杀 —— **身份一律保密**。

#### 三个容易搞混的边界

| 情形 | 是否亮身份 | 说明 |
| --- | :-: | --- |
| 猎人**被狼刀 / 被投票**出局 → 开枪带人 | ✅ | 开枪即主动亮身份,全场立刻知道他是猎人 |
| 猎人**被女巫毒药毒死** | ❌ | **不能开枪**,身份依旧隐藏 |
| 猎人被刀/被放逐但**主动选择不开枪** | ❌ | 未亮身份,身份保持隐藏(藏身份 vs 带人的战术选择) |
| 白痴**白天被投票放逐** → 翻牌免死 | ✅ | 法官翻开白痴身份,免于出局,全场得知 |
| 白痴**夜晚被刀 / 被毒**死亡 | ❌ | **不翻牌**,身份保密 |
| 狼人**白天自爆** | ✅ | 全场立刻知道他是狼人 |
| 被猎人枪杀的那名玩家 | ❌ | 只有开枪的猎人亮身份,被带走者身份保密 |

#### 仍然公开的信息

身份保密**不等于**死亡保密。以下始终对全场公开:

- **死亡事实**:几号玩家死亡(`alive = false`);
- **处决 / 死亡 决断**:`verdict = execution`(白天投票、狼自爆)/ `death`(夜间狼刀、毒杀、猎人反杀);
- **屠边计数**:存活狼人数 / 神职数 / 平民数(不含具体是谁)。

> **为什么这条重要**:若死亡即翻牌,女巫的毒药会从"信息代价"退化成"免费验人",
> 狼刀预言家后的悍跳博弈价值归零,误票平民后好人也能立刻确认票错。
> 本平台在服务端统一由 `GameState.RolePubliclyRevealed(seat)` 单点判定,
> WS 视图、REST 房间详情、死亡列表三条通道全部走同一白名单。

#### 关于狼王 / 白狼王

> **本平台 13 人局不含狼王 / 白狼王**。标准牌组为 4 狼 + 预言家 + 女巫 + 猎人 + 白痴 + 5 民;
> 随机牌组从 `godRolePool`(女巫 / 猎人 / 白痴 / 守卫)中抽取神职。**猎人是本局唯一带枪的角色**。
> 部分线下板子里"狼王自爆或被投票出局可亮身份开枪、夜间被毒无法发动"的规则,在本平台不适用。

### 7.1 自爆规则

- **位置约束**:仅白天发言阶段;投票阶段不允许自爆。
- **死亡因果**:`cause = "suicide"` → 无遗言(`LastWordsRounds` 失效)。
- **阶段跳跃**:自爆后立即进入 `PhaseNightWolves`,当晚狼人照常运作(可在自爆狼名下的座位由该阵营另一狼人操纵当晚刀人)。

### 7.2 猎人开枪规则

#### 合法触发条件

| 死亡来源             | 可否开枪 | 服务端字段                            |
| -------------------- | :------: | ------------------------------------- |
| 被狼刀               |    ✅    | `HunterPendingFrom = "wolf"`(黎明遗言结束后进入开枪阶段) |
| 被白天投票放逐       |    ✅    | `HunterPendingFrom = "vote"`          |
| 被女巫毒药毒死       |    ❌    | 不置 `HunterPendingShoot`,且**身份保密** |
| 自爆 / 同守同救被判死 |    ❌    | 非猎人可达路径                        |

#### 选择权与身份代价

- 猎人不必强制开枪——可选择 `target = NoSeat` 直接关闭开枪阶段。
- **开枪 = 主动亮身份**(见 [§7.0](#70-身份公开规则死者身份牌不翻开));**选择不开枪则不亮身份**。
  这是一个真实的战术权衡:带走一人 vs 让好人阵营多保留一份信息迷雾。
- 猎人开枪带走的人**仍要判定遗言**:若当前 `DayNumber <= LastWordsRounds(=2)` 则被带走者有遗言。
- 被带走者的**身份不公开** —— 只有开枪的猎人自己亮身份。

#### 副作用

- 猎人开枪带走女巫,**当晚女巫尚未用的药剂直接失效**(服务端实现:已在 `wolf_target` 的同晚毒药 + 解药都不会再被女巫发出)。

### 7.3 遗言规则

7 人局标准遗言规则(`LastWordsRounds = 2`):

| 轮次                  | 是否有遗言                                  |
| --------------------- | ------------------------------------------- |
| 第 1 夜(开局)死亡     | ✅ 有                                        |
| 第 1 天白天出局       | ✅ 有                                        |
| 第 2 夜及之后夜间死亡 | ❌ 无                                        |
| 第 2 天及之后白天出局 | ❌ 无                                        |
| 狼人自爆              | ❌ 无(`cause = "suicide"`)                 |
| 猎人开枪带走别人      | 若仍在遗言轮次内 → ✅ 有,否则 ❌ 无         |

### 7.4 空刀与平安夜

狼人协商后选择不击杀任何人(`WolfKillTarget = NoSeat`),第二天白天为"**平安夜**",无人死亡。客户端显示由服务端 `LastNightDeaths = []` 触发。

## 8. 胜负判定

### 8.1 触发点

服务端在以下时机调 `checkWinner()`:

1. `endWitchPhase` —— 夜晚流转到天亮后
2. `FinishVote` —— 投票放逐某人 / 二次投票平票 → 无人出局
3. `WolfSuicide` —— 狼人自爆后
4. `HunterShoot` —— 猎人开枪带走某人后

### 8.2 判定规则(屠边规则)

```
if DivineCnt == 0 OR PlainCnt == 0:
    Winner = "wolf"
elif WolfAliveCnt == 0:
    Winner = "good"
else:
    no winner (继续)
```

| 阵营       | 胜利条件                                                            | 后端字段                              |
| ---------- | ------------------------------------------------------------------- | ------------------------------------- |
| 狼人阵营   | **屠神**:杀光预言家 + 女巫 + 猎人 + 白痴(全部神职)                    | `DivineCnt == 0`                       |
| 狼人阵营   | **屠民**:杀光全部平民(13 人局 5 名 / 7 人局 2 名)                   | `PlainCnt == 0`                        |
| 好人阵营   | **放逐所有狼人**(`WolfAliveCnt == 0`)                              | `WolfAliveCnt == 0`                    |

### 8.3 归类为胜负

胜负已分后:

- `Status = "over"`
- `Phase = PhaseGameOver`(`"over"`)
- 服务端对全员广播 `game.over { winner, status }`
- 客户端在 `useWerewolf` hook 的 `case 'game.over'` 中调用 `setGameOver({ winner })`

## 11. 礼仪与禁区

### 11.1 平台强禁区

- **禁止场外信息**:游戏过程中禁止通过声音 / 动作 / 表情等传递任何夜间信息。
- **禁止贴脸发言**:如以人格发誓、赌咒、场外担保等。
- **禁止讨论夜间细节**:如夜间操作时长、夜间声音、唤醒顺序等。
- **出局玩家沉默**:出局后不得用任何方式与在场玩家交流,不得在聊天中传递策略。

### 11.2 工程约束(子类)

- **隐藏信息由服务端权威**:客户端**绝不**信任本地计算的身份判定。
- **断线重连保护**:GamePage 进入对局前必须 `reset()` store(防 §22 教训)。
- **旁观者不可输入**:服务端在 5 个游戏输入 handler 入口调用 `rejectIfSpectator()` 返回 `ErrSpectatorInputForbidden (30011)`(§16.5 规范)。
- **退出房间走 ConfirmModal**:禁止使用 `window.confirm` 等阻塞型浏览器 API(§27 教训,阻塞 CDP 自动化)。
