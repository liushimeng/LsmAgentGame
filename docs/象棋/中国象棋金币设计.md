# 中国象棋（Xiangqi）游戏币策划方案

> 版本：v1.0  |
> 作者：game-designer  |
> 状态：实施就绪  |
> 适用范围：中国象棋（2 人对局，无随机性，平均 10–30 分钟/局）

---

## 1. 概述

### 1.1 产品定位

中国象棋是本平台**历史最悠久、玩家基数最大**的棋类游戏。引入游戏币后，定位为 **"休闲竞技 + 带注对局"**：

| 模式 | 是否需要金币 | 是否结算金币 | 适用场景 |
| --- | --- | --- | --- |
| **休闲房** | ❌ | ❌ | 练手、老友约战、新手教学 |
| **带注房** | ✅（底注 ante） | ✅（赢家通吃 + 和局退还） | 竞技排位、技术变现 |

### 1.2 设计目标

1. **零和博弈**：系统不为单局增发金币，仅在胜负/和局时转移 / 以系统奖励方式少量注入。
2. **低门槛高上限**：休闲玩家永不被踢出牌桌；高段位玩家有充足的"盲注分层"空间。
3. **防刷、防通胀**：所有金币变动走双簿记流水，任何外部可触达入口均计入审计。
4. **合规**：关闭充值/提现/玩家间转账，纯粹封闭资金池。

### 1.3 与用户旅程的关系

```
注册(≤28d) → 1000 启动金
                ↓
每日登录 → +2000/d (UTC+8 自然日, 不补领)
                ↓
创建休闲房(0 ante) ——— 不结算
创建带注房(50/100/500/1000 ante) ——— 赢家通吃 / 和局退还
                ↓
入不敷出(余额<50) → 赠送保护 500/每日一次
                ↓
邀请好友 → +500/位 (对方完成 1 局带注决胜局后触发, 单人上限 5 位)
                ↓
商城装饰消费(一次性买断, 不影响公平性)
```

## 2. 金币获取途径

### 2.1 注册奖励

| 项目 | 值 |
| --- | --- |
| 发放时机 | `Register` 落库后立即发放（auth_service.go） |
| 发放金额 | **1000 金币** |
| 一次性 | ✅ 每个 user_id 仅 1 次（由 `t_lsm_game_wallet.user_id` 唯一键保证） |
| 合规注意 | 新账号需完成邮箱/手机号至少一种验证，避免批量注册刷金 |

### 2.2 每日登录奖励

| 项目 | 值 |
| --- | --- |
| 发放时机 | 每次 `Login` 成功后检查当日是否已发 |
| 发放金额 | **2000 金币 / 自然日** |
| 时区 | UTC+8 自然日（00:00:00 – 23:59:59） |
| 补领 | ❌ 不补领，过期作废 |
| 持久化表 | `t_lsm_game_daily_reward(user_id, reward_date)` UNIQUE |
| 复投风控 | 同一 user_id 同一天最多 1 条；服务端原子 INSERT 防并发 |

### 2.3 胜场奖励（零和转移 + 系统零头补贴）

中国象棋本身 **玩家间流水 = 2 × ante**（双方各出 ante，赢家通吃）。**系统额外按赢家等级与底注比例给予小额补贴**，作为"技术变现"感知：

#### 2.3.1 基础补贴公式

```
系统补贴 = floor( ante × 补贴系数 × 对手等级系数 )

补贴系数表（按 ante 分档）：
  ante ≤ 100   → 1.0%   (上限 1)
  ante ≤ 500   → 0.8%   (上限 4)
  ante >  500  → 0.5%   (上限 5)

对手等级系数 = 对手当前等级 / 自身当前等级
  范围裁切到 [0.5, 2.0]
  即：打新手最多 ×0.5，打高手段最多 ×2
```

#### 2.3.2 段位等级（XP-based，不直接消耗金币）

| 段位名称 | XP 区间 | 等级数值(用于公式) |
| --- | --- | --- |
| 新手 | 0 – 999 | 1 |
| 入门 | 1000 – 2999 | 2 |
| 进阶 | 3000 – 6999 | 3 |
| 棋手 | 7000 – 14999 | 4 |
| 棋协 | 15000 – 29999 | 5 |
| 棋圣 | 30000 – 59999 | 6 |
| 宗师 | 60000+ | 7 |

XP 获取：
```
XP(胜) = 100 + ante                 (最高 200)   例：ante=50 → 150 XP
XP(负) = 20                         固定
XP(和) = 50                         固定
```

#### 2.3.3 数值范例

| 场景 | ante | 对手等级/自身等级 | 系统补贴 |
| --- | --- | --- | --- |
| 新手(1) vs 新手(1) | 50 | 1.0 | floor(50 × 0.01 × 1.0) = 1（最低 1） |
| 棋手(4) vs 新手(1) | 500 | min(4/1, 2.0) → 2.0 → 优势方减成 → 0.5 | floor(500 × 0.008 × 0.5) = 2 |
| 新手(1) vs 棋手(4) | 500 | min(1/4, 0.5) = 0.5 → 劣势方加成 → 1.5 | floor(500 × 0.008 × 1.5) = 6 |
| 棋手(4) vs 棋手(4) | 1000 | 1.0 | floor(1000 × 0.005 × 1.0) = 5 |

> 保证：**补贴只占玩家间流水的小头，不破坏零和本质**。

### 2.4 连胜奖励（Streak Bonus）

| 项目 | 值 |
| --- | --- |
| 触发条件 | 玩家**连续赢得 3 局及以上带注房** |
| 奖励公式 | 从第 3 局起，每多 1 连胜额外 **+ floor(ante × 5%)** |
| 上限 | 封顶 7 连胜（超过仍按 25% 计）；每日连胜奖励总额 ≤ 5000 金币 |
| 中断条件 | 负局立即中断；和局不中断也不递增（保持当前 streak） |
| 豁免权 | 段位 ≤ "入门"(XP < 3000) 的玩家，连胜奖励 **×1.5**（新手保护） |

### 2.5 邀请好友奖励（referral 系统复用）

| 项目 | 值 |
| --- | --- |
| 触发条件 | 被邀请人完成 **1 局带注房决胜局**（胜/负皆可）, 仅触发一次 |
| 奖励金额 | **+500 金币 / 位** |
| 单人上限 | 邀请人累计最多获得 **5 位 × 500 = 2500** |
| 持久化 | 在 `t_lsm_game_referral_log` 表中标记已结算(entry_id) |
| 风控 | 被邀请人与邀请人不允许在 7 天内对战带注房 |

### 2.6 其他获取途径（次要入口，合计占比 ≤15% 总发放量）

| 类型 | 触发 | 奖励 | 周/月上限 |
| --- | --- | --- | --- |
| **每日任务** | 完成 3 局（任意模式） | +300 | 每天 1 次 |
| **成就奖励** | 首次达到某段位 / 累计 100 胜 / 累计 500 局 | 500/1000/2000（一次性） | 1 次/账号 |
| **活动/节日** | 运营配置 | 由运营脚本注入 | 按活动规则 |

## 3. 金币消耗途径

### 3.1 带注房 ante（创建房间时锁定）

| ante 档位 | 适合段位 | 备注 |
| --- | --- | --- |
| 50 | 入门以下 | 低风险，新手练兵 |
| 100 | 入门 – 进阶 | 主力档位 |
| 500 | 进阶 – 棋手 | 高段位入场券 |
| 1000 | 棋手以上 | 竞技核心 |

创建 ante 房时，**系统立即从创建者钱包锁定 ante**（不可被重复消费）；对局结束后统一结算（见 §4）。

### 3.2 投降 / 输局扣减

输家输 ante（由赢家通吃）；**无额外惩罚**——纯零和。
投降 = 主动判负，扣减与正常输局相同，无 streak 保留。

### 3.3 商城（一次性买断）

| 品类 | 建议定价范围 |
| --- | --- |
| 头像框 | 500 – 3000 |
| 棋盘皮肤 | 1000 – 5000 |
| 棋子皮肤（红/黑套装） | 1500 – 6000 |
| 入场特效 | 800 – 3000 |

> 商城为**非必需装饰性消费**，不影响任何对局平衡。定价一次性买断，无租赁/续费。

## 4. 房间带注规则

### 4.1 创建带注房流程

```
POST /api/rooms
  { "game_kind":"xiangqi", "ante": 50|100|500|1000 }

服务端逻辑（room_service.go CreateRoom 后追加）：
  1. 冻结创建者 ante 金额（钱包表加字段 locked_balance）
  2. 广播房间信息（含 ante 字段）到大厅
  3. 第二位玩家加入时同样冻结 ante
  4. 双方 ante 进入 escrow，房主无法取回
```

### 4.2 结算规则（对局结束后服务端原子操作）

| 结果 | 赢家 | 输家 | 系统 |
| --- | --- | --- | --- |
| **胜负** | 拿回 ante + 拿走对方 ante + 系统补贴 | 失去 ante | 支出系统补贴 |
| **和局** | 退还各自 ante | 退还各自 ante | 0 |
| **对手掉线超过 15s 被判负** | 按胜负结算 | 按输局结算 | 与胜负相同 |

**胜负公式简化**：

```
赢家最终获得 = 2 × ante - 系统抽成(0) + 系统补贴
输家最终获得 = 0
系统净利润 = -系统补贴        (系统支出)
```

> MVP 阶段系统抽成 = 0，全部让利于玩家以培养生态。

### 4.3 和局处理

- 双方在 **60 步内未吃子** 或 **同等局面重复 3 次** 由系统主张和局 → 退还各自 ante
- 和局时双方 XP +50（见 §2.3.2）
- 无额外手续费（维持零摩擦）

### 4.4 破产保护（Bankruptcy Safety Net）

| 触发条件 | 操作 |
| --- | --- |
| 玩家余额 < 最低 ante（50） 且 玩家主动任意入口触碰游戏大厅 | 弹出"赠送保护"提示，可选领取 **500 金币** |
| 领取频率 | 每账号每自然日最多 1 次；每月上限 3 次 |
| 生命周期 | 累计 3 次保护金 = 1500 金币，足够玩家回到 ante=50 档位 ≥ 3 局 |

逻辑：**不自动发放**，玩家可见按钮，避免"无限印钞"。

### 4.5 异常掉线 / 平局 / 争议

- 掉线 15s 由 ws heartbeat 判负（现有 `ws-heartbeat-kick` feature，不改逻辑）
- 对局争议无申诉通道（中国象棋步数可重现，服务端权威）
- 对局状态回放数据保留 7 天供审计

## 5. 风控与防作弊

### 5.1 刷分检测

| 规则 | 阈值 | 动作 |
| --- | --- | --- |
| 同一 IP 5 分钟内创建/加入 ≥ 3 局带注房 | IP + 设备指纹 | 标记可疑，人工复核 |
| 同一设备 24 小时内累计 ≥ 10 局带注房 | 设备指纹 + 账号 | 临时限制 at 50 ante |
| 账户 A 与账户 B 始终匹配对局 ≥ 5 次 | 玩家对局矩阵 | 临时冻结双方 ante 结算 |

### 5.2 异常胜率监控

- 段位 ≥ 棋手 的玩家 **50 局滑动窗口** 胜率 > 85% → 触发人工审核
- 同一 IP 下多个账号胜率联合分析，若集体 > 75% → 标记 IP
- 审计报表每日 00:30 UTC 生成

### 5.3 流水审计要求

所有金币变动写入 `t_lsm_game_ledger_entry` 表：

| 字段 | 说明 |
| --- | --- |
| id | 主键 |
| user_id | 谁 |
| amount | +/- 数值 |
| balance_after | 变动后余额 |
| reason | REGISTER_REWARD / LOGIN_REWARD / MATCH_WIN / MATCH_LOSE / MATCH_DRAW / STREAK_BONUS / REFERRAL / DAILY_TASK / ACHIEVEMENT / SHOP_PURCHASE / BANKRUPTCY_PROTECTION |
| ref_id | 关联的业务 ID（房间号、对局号、订单号等） |
| created_at | 时间戳 |

- **每日抽检**：总系统支出 - 总系统收入 = 当日新增金币，需在 ±2% 容差内与表总和对平
- **不可篡改**：流水表 append-only，不做物理删除

### 5.4 跨账号转账

- 禁止玩家间任何形式转账
- 不开放赠送 / 借用 / 保险箱
- 无 P2P 市场

## 6. 数值平衡建议

### 6.1 通胀 / 通缩控制

| 类别 | 每日平均发放量（万玩家规模估算） | 每日平均消耗量 |
| --- | --- | --- |
| 注册奖励 | 随新增衰减 | — |
| 每日登录 | 2000 × DAU | — |
| 胜场补贴 | 约 每日总 ante × 0.5% | — |
| 连胜/活动/任务 | ~1500/任务触发 | — |
| **商城装饰** | — | 商城销售 100% 消耗 |
| **破产保护** | 500 × 30% 濒贫玩家 | — |

**控制阀**：
- 当系统总金币池 **月增长率 > 25%** → 调低商城价格 / 增加新装饰品类
- 当系统总金币池 **月减少率 > 15%** → 上调每日登录至 2500 / 加大 stalk 奖励
- **黄金法则**：非输赢类发放 ≤ 输赢类转移的 30%

### 6.2 段位分层（类似扑克盲注）

| 段位 | 最低 ante 推荐 | 平均局时 | 局数/天 | 日理论最大收益 (ante=50 档) |
| --- | --- | --- | --- | --- |
| 新手 | 50 | 15 min | 5 | 50×10/天 = 500 |
| 入门 | 100 | 20 min | 4 | 100×8/天 = 800 |
| 进阶 | 500 | 25 min | 3 | 500×6/天 = 3000 |
| 棋手+ | 1000 | 30 min | 2 | 1000×4/天 = 4000 |

> 入门玩家靠每日登录(2000)+ 对局收益可**3 天内攒到进阶门槛**。

### 6.3 通胀吸收器（长期方案）

- 商城装饰（一次性买断）
- 季度"赛季重置 XP"（金币不重置）
- "金币抽奖"（1000 次一次，获得限定装饰，不返现金币）

## 7. UI/UX 建议

### 7.1 大厅余额展示

- 顶部导航栏右侧显示 **金币图标 + 数字**（如 `🪙 4,500`）
- 余额旁加 "+" 按钮 → 弹窗说明获取途径（不跳转充值）
- 数字使用动画（+/- 飘字）

### 7.2 创建房间底注选择器

- 4 档按钮：**50 / 100 / 500 / 1000**
- 点击后实时预览：
  - 奖池 = ante × 2
  - 系统补贴预估（低 / 中 / 高，取决于对手段位未知时显示区间）
- 余额不足时按钮灰显 + 提示"参与破产保护"

### 7.3 对局内金币变化

- 倒计时结束 / 胜 / 负 / 和 时，在棋盘顶部中央动画：
  - 胜：`+98（对方）+2（补贴）= +100` 绿色飘 2s
  - 负：`-50` 红色飘 1.5s
  - 和：`0` 灰色显示"和局 - 底注退还"

### 7.4 结算面板（对局结束弹窗）

- 本局结果（胜 / 负 / 和）
- 奖金明细：基础 ante 转移 + 系统补贴 + 连胜奖励（若有）
- 当前余额 / streak 状态 / XP 进度条

### 7.5 钱包明细页

- `/wallet` 路由（个人中心子页）
- 时间线流水：发放入口 / 入口 + 金额
- 日/周/月筛选

## 8. 与其他游戏的差异化

| 维度 | 中国象棋 | 斗地主 | 德州扑克 |
| --- | --- | --- | --- |
| **对局人数** | 2 | 3 | 2-6 |
| **平均分局长度** | 10 - 30 min | 3 - 10 min | 5 - 15 min |
| **随机性** | 无（纯技术） | 有（发牌随机） | 有（发牌随机） |
| **底注档位** | 50/100/500/1000 | 20/50/200/500 | 100/500/1000/5000 |
| **补贴系数** | 0.5% - 1.0%（低） | 2% - 5%（高） | 1% - 3%（中） |
| **连胜奖励** | 最高 25% ante/局 | 无 | 无 |
| **玩家间结算** | 赢家通吃 | 赢家通吃 + 农民分摊 | 赢家通吃 + 边池 |
| **系统抽成（MVP）** | 0 | 5% (输家抽水) | 5% (赢家抽水) |

**差异化原因**：
1. **无随机性** = 高手刷新手更容易，必须通过**补贴系数下限保护 + 段位匹配**降低"虐菜刷金"
2. **双人零和** = 无第三方的复杂抽成逻辑，直接通吃
3. **局时长** = 单位时间金币流转低，底注档位相对低以鼓励玩家量
