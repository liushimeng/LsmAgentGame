本文档定义狼人杀游戏中**两类根本不同的死亡方式** ——「处决」与「死亡」,从 Web 端 UI、ServerGo 引擎、Agent 设计、Anthropic 协议四个层次全面规范化。

> **背景问题**:历史上"死"在客户端、服务端、Agent 中都使用混用术语("杀"/"放逐"/"出局"/"出局者")。LLM 在 prompt 中看到这些混用术语会产生策略混乱(把"被放逐"理解为"被杀")。本设计把术语统一为两个根本对立面 —— **白天投票 = 处决**(玩家集体决策)、**夜间 / 特殊死亡 = 死亡**(程序 / 技能驱动)。

---

## §1 概念定义

### 1.1 两类死亡

| 维度 | **处决**(Execution) | **死亡**(Death) |
|---|---|---|
| **驱动者** | 玩家集体(投票) | 系统 / 神职技能(狼刀、女巫毒、猎人枪) |
| **触发场景** | 白天 `PhaseVote` 投票放逐 | 夜晚 `PhaseNightWolves`/`PhaseNightWitch`、白天 `PhaseHunterShoot`、狼人自爆 |
| **决策权** | 玩家公开讨论 + 投票 → 多数决 | 程序化结算或神职玩家技能释放 |
| **玩家感知** | 全场可见、公开辩论 | 信息不对称(夜晚行动只对部分玩家可见) |
| **法官宣告术语** | "N 号被处决" | "N 号被 X 死亡"(X = 狼刀/毒杀/猎人枪) |
| **死因代码** | `cause = "vote"` | `cause = "wolf" / "witch_poison" / "hunter" / "suicide"` |
| **Verdict 字段** | `verdict = "execution"` | `verdict = "death"` |
| **遗言权** | 有(白天,且 Day ≤ LastWordsRounds) | 有/无按 cause 决定(详见 §[遗言设计]) |
| **狼自爆** | 视为处决(`cause = "suicide"`, `verdict = "execution"`) | — |
| **白痴翻牌失败** | 视为处决(`cause = "vote"`, `verdict = "execution"`) | — |

> **为什么狼自爆 = 处决?** 狼自爆是**白天玩家自主决策**(避免夜间暴露队友),程序只是执行玩家指令;法官宣告用「N 号被处决 · 自爆」即可,术语上与其他处决一致。

### 1.2 术语映射表(全栈统一)

| 中文 | English `cause` | English `verdict` | UI 显示 | LLM prompt 用词 |
|---|---|---|---|---|
| 被投票放逐 | `vote` | `execution` | ⚖️ N 号 · 处决 · K 票 | 处决(白天投票) |
| 白痴放弃翻牌 | `vote` | `execution` | ⚖️ N 号 · 处决 · 翻牌失败 | 处决(白痴放弃翻牌) |
| 狼人自爆 | `suicide` | `execution` | 💥 N 号 · 处决 · 自爆 | 处决(自爆) |
| 狼刀 | `wolf` | `death` | 💀 N 号 · 死亡 · 狼刀 | 死亡(狼刀) |
| 同刀同毒 | `wolf` + `witch_poison` | `death` | 💀 N 号 · 死亡 · 同刀同毒 | 死亡(狼刀+毒杀) |
| 女巫毒杀(无狼刀) | `witch_poison` | `death` | ☠️ N 号 · 死亡 · 毒杀 | 死亡(毒杀) |
| 猎人开枪带走 | `hunter` | `death` | 🔫 N 号 · 死亡 · 反杀 | 死亡(猎人反杀) |

> **混用禁忌**:
> - **禁止**用"杀"代指"处决"(处决 ≠ 杀);
> - **禁止**用"放逐"代指"死亡"(死亡 ≠ 放逐);
> - **禁止**LLM prompt 用"出局"等模糊词,必须二选一:"处决" / "死亡"。

## §2 后端设计(`ServerGo/`)

### 2.1 `engine.go::killPlayer` 升级

```go
// killPlayer 标记座位为死亡;按 cause 决定遗言权,并自动算出 verdict。
//
// cause ∈ {"wolf", "vote", "witch_poison", "hunter", "suicide"}
//   "wolf"/"witch_poison"/"hunter" → verdict = "death"
//   "vote"/"suicide"               → verdict = "execution"
//
// verdict 用于前端 UI / 法官宣告 / LLM prompt,不能直接传(避免逻辑散落)。
func (gs *GameState) killPlayer(seat Seat, cause string) *errcode.Error {
    if seat < 0 || seat >= MaxPlayers {
        return errcode.Code(errcode.ErrValidationFailed)
    }
    if !gs.Players[seat].Alive {
        return errcode.CodeMsg(errcode.ErrValidationFailed, "already dead")
    }
    gs.Players[seat].Alive = false
    // 计算遗言权(LastWordsRounds 内)
    allowLW := false
    switch cause {
    case "wolf", "vote", "hunter":
        allowLW = gs.DayNumber <= LastWordsRounds
    case "witch_poison", "suicide":
        allowLW = false
    }
    gs.Players[seat].LastWords = allowLW
    // 写入死因 + 决断(新增)
    gs.Players[seat].DeathCause = cause
    gs.Players[seat].DeathVerdict = verdictFor(cause)
    if gs.SheriffSeat == seat {
        gs.SheriffSeat = NoSeat
        switch cause {
        case "wolf", "witch_poison":
            gs.sheriffSlain = seat
        }
    }
    return nil
}

// verdictFor cause → verdict 查表函数(单一事实来源)。
func verdictFor(cause string) string {
    switch cause {
    case "wolf", "witch_poison", "hunter":
        return "death"
    case "vote", "suicide":
        return "execution"
    default:
        return "death" // 兜底:未知死因默认按"死亡"(更安全)
    }
}
```

## §3 Agent 设计(`ServerGo/agent/`)

### 3.1 玩家 Agent prompt 中显式区分

`BuildSystemPrompt` 末尾追加【死亡语义】块:

```
【死亡语义 — 关键】
- 「处决」(verdict=execution):白天被投票放逐、白痴放弃翻牌、狼自爆 → 都是玩家集体决策或自主决策的结果
- 「死亡」(verdict=death):夜间被狼刀、被女巫毒杀、被猎人开枪 → 都是系统/技能驱动的结果
- 在讨论时,被「处决」的人≠被「死亡」的人 — 两种死亡方式背后的信息完全不同
- 举例:白天「处决」1 号(投票放逐)与夜间「死亡」5 号(狼刀)是两件不同的事,
       需要分别推理 1 号和 5 号的真实身份,不要混为一谈
- 不要用"杀/放逐/出局"等模糊词 — 一律说"处决"或"死亡"
```

### 3.2 BotTranscript 加 4 字段

```go
type BotTranscript struct {
    // ... 既有

    // LastDeathVerdict 最近一次被该 bot 观测到的死亡事件决断(execution/death);
    // 用于前端 AgentInteractionPanel 渲染最近事件标签。
    LastDeathVerdict string `json:"last_death_verdict,omitempty"`
    // LastDeathCause 配合 LastDeathVerdict;空字符串=无最近死亡事件。
    LastDeathCause string `json:"last_death_cause,omitempty"`
    // LastDeathSeat 最近一次死亡的座位号;供前端提示"X 号被处决"。
    LastDeathSeat int `json:"last_death_seat,omitempty"`
    // LastDeathRound 第几轮(白天)发生的;0 = 夜间 / 不分。
    LastDeathRound int `json:"last_death_round,omitempty"`
}
```

填充时机:`room.go::appendRoomMessageLocked` 在写入 `chat_message` 时,若 message 是法官的 `declare_cause` 或玩家公开宣告死亡,把 verdict/cause/seat 同步到所有 bot 的 `BotTranscript.LastDeath*`。

### 3.3 Agent prompt 引用块

`BuildUserPrompt` 新增【最近死亡事件】块(在【玩家档案】之后):

```
【最近死亡事件(最近 3 条)】
- 第 2 天·白天:3 号被处决(投票 5 票) — 处决
- 第 1 天·夜间:5 号被死亡(狼刀) — 死亡
- 第 1 天·白天:7 号被处决(白痴放弃翻牌) — 处决
```

`DayVerdictCount[seat]`(Room 视图)统计该 bot 经历过的处决/死亡次数,玩家可据此推理。

### 3.4 speak_dedup 适配

`speak_dedup.go` 在清洗 LLM 输出时,确保不破坏处决/死亡术语(原本的"杀"应替换为"死亡","放逐"应替换为"处决"):

```go
// normalizeDeathTerms 在 dedup 之后做一次术语规范化。
func normalizeDeathTerms(text string) string {
    // 把"被 X 杀"统一为"被 X 死亡"(除了"自爆"特殊处理)
    text = strings.ReplaceAll(text, "被投票杀", "被处决")
    text = strings.ReplaceAll(text, "被放逐杀", "被处决")
    // ... 其他映射
    return text
}
```

## §4 Anthropic 协议设计(`ServerGo/llm/`)

### 4.1 出站请求体新增字段

**`system[]` 数组末尾新增一块**(`BuildSystemPrompt`):

```json
{
    "type": "text",
    "text": "【死亡语义 — 关键】\n- 处决(verdict=execution):白天被投票放逐...\n- 死亡(verdict=death):夜间被狼刀..."
}
```

**`metadata` 新增 `death_semantic_version`**(协议版本号,便于未来调整):

```json
{
    "metadata": {
        "user_id": "...",
        "death_semantic_version": "2026-07-10-v1"
    }
}
```

### 4.2 工具调用约定

所有 player-facing 工具的 `text` 参数(包括 `speak` / `whisper` / `sheriff_stream` 等)必须在 LLM 输出后由 `dedupSpeakText` + `normalizeDeathTerms` 两层清洗,确保 LLM 不会把"处决"和"死亡"混用。

### 4.3 服务端响应字段扩展

`LLMProvider.Chat` 返回的 `LLMResponse` 加可选 `DeathSemanticCompliant bool`(由 dispatcher 根据输出文本是否混用术语判定),若 false,在 `recordTranscript` 时打 WARN 日志 + 在前端 UI 显示"⚠️ 术语混用"提示。

## §6 实施要点

### 6.1 兼容性

- `cause` 字段名保持不变(已有 wolf/vote/hunter/witch_poison/suicide);
- 新增 `verdict` 字段,**所有 killPlayer 调用方自动升级**(verdictFor 函数);
- 旧前端无 `verdict` 字段时按 `cause` 兜底(`wolf`/`hunter`/`witch_poison` → 死亡,`vote`/`suicide` → 处决),前端的 `clientweb/src/types/werewolf.ts` 加 `verdict?: 'execution'|'death'` 可选字段。

### 6.2 单测覆盖

新建 `ServerGo/game/werewolf/engine_death_semantic_test.go`:

- `TestKillPlayer_WolfCause_DeathVerdict`
- `TestKillPlayer_VoteCause_ExecutionVerdict`
- `TestKillPlayer_SuicideCause_ExecutionVerdict`
- `TestKillPlayer_HunterCause_DeathVerdict`
- `TestKillPlayer_WitchPoisonCause_DeathVerdict`
- `TestVerdictFor_UnknownCause_DefaultsDeath`
- `TestDeadListVerbose_FillsVerdictCause`
- `TestNormalizeDeathTerms_DoesNotCorruptProperText`

### 6.3 锁不变式(§92a)

`killPlayer` 在 `r.mu` 持锁状态下调用,新加的字段赋值必须**不调任何会持锁的方法**(verdictFor 是纯函数,没问题)。

## §7 边界(不做的事)

- ❌ 不新增"死亡原因"以外的字段(如死亡时间戳由 GameState.DayNumber 推断);
- ❌ 不修改狼人/女巫/猎人的技能语义(只改 UI 标签和术语);
- ❌ 不动 LLM provider 接口(LlmProvider / Registry / OpenAI 预留字段保留);
- ❌ 不修改 LastWordsRounds=2 既有数值;
- ❌ 不让玩家 Agent 主动设置 DeathCause / DeathVerdict(只能由 killPlayer 内部赋值)。
