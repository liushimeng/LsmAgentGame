## §0 背景与目标

### 0.1 用户需求

1. 人类玩家和 Agent 玩家死亡后,由主持人(法官 Agent)宣布身份信息。
2. Agent 代码设计与人类玩家 Web 界面都要显示死亡玩家身份。
3. **公平性**:所有人同时通过公共通道获得,不得有信息差。

### 0.2 为什么是「房间级开关」而不是全局规则替换

现行 §135 规则(死者身份牌不翻开)是 13 人标准竞技局的根基之一 —— 它保证
女巫毒药不是免费验人、狼刀预言家有悍跳博弈价值。直接全局替换会摧毁竞技局的
核心信息博弈。因此本设计以**建房时可配置的房间级开关**落地:

| 开关 | 语义 | 目标人群 |
|---|---|---|
| `reveal_role_on_death = true`(默认) | 死亡即公开身份(娱乐局 / 教学局 / 快节奏局) | 普通玩家 |
| `reveal_role_on_death = false` | 现行 §135 竞技规则,零改动 | 竞技局 |

## §1 需求定义

### 1.1 术语

| 术语 | 定义 |
|---|---|
| **死亡结算 tick** | 引擎 `killPlayer(seat, cause)` 被调用、`Alive=false` + `DeathCause` 写入完成的那个临界区 |
| **身份公开** | 某座位的角色名对**全场所有玩家 + 观战者**可见(经 `RolePubliclyRevealed` 判定为 true) |
| **公共通道** | 全员同时可见的信息出口:① 法官公屏宣告(`announce` / `declare_cause` → `onAnnounce` → 房间聊天)② `BuildClientState` 按座位广播的脱敏视图 |
| **私有通道** | 仅部分玩家可见的信息出口:狼人互知、预言家查验、女巫用药、私聊 whisper、死者自身视角 |

### 1.2 公平性四不变式(本设计的硬约束)

1. **单一判定**:某座位身份是否公开,**只**由 `GameState.RolePubliclyRevealed(seat)`
   决定(§135 单点判定)。任何视图 / Agent / REST 通道不得复制第二份判定逻辑。
2. **同一 tick**:身份公开发生在死亡结算的同一临界区内生效(状态派生,无异步延迟),
   下一次 `BuildClientState` 广播 + 法官宣告同时携带 —— 人类与 Agent 同源同时获得。
3. **无抢先通道**:任何 Agent 不得早于公共通道得知死者身份。例外仅限两类**对称信息**:
   死者自身已知的自身信息;既有私有阵营通道(狼互知 / 预言家查验)—— 它们在死亡前后
   语义不变,不属于本设计引入的信息差。
4. **开关对称**:开关作用于**全体**(含观战者 REST 视图),不存在「人类可见、Agent
   不可见」或反向的拆分。

### 1.3 与 §20260810-12 D2「终局延时揭晓」的正交性

`RoomConfig.DeathRevealDelayMin`(0/5/15)只控制 **Status=="over" 终局后**前端
SettlementModal 的 UI 延迟显示,不改变服务端身份公开判定。本设计控制的是**局中
死亡即公开**。二者共存规则见 §7.7。

## §3 总体设计

### 3.1 数据流(开启时)

```
killPlayer(seat, cause)                    ← 10 个调用点,引擎内单一死亡结算
    │  写 Alive=false / DeathCause / DeathVerdict
    ▼
RolePubliclyRevealed(seat) == true          ← 第 ⑦ 分支:开关 && 死亡(状态派生,同 tick)
    │
    ├─► BuildClientState 按座位广播          ← 人类 Web 界面(座位徽章/历史抽屉/黎明公告)
    │     dead_list[].role / players[].role / all_dead_list_verbose[].role / ...
    ├─► REST 房间详情 PublicPlayerState      ← 大厅刷新 / 观战者(同判定)
    ├─► wakeJudgeLocked → GameSnapshot      ← 法官 Agent(全知,但出口仅公屏宣告)
    │     └─► announce / declare_cause → onAnnounce → 公屏:「…身份是〔角色名〕」
    └─► syncDeathRevealPriorsLocked         ← 全部存活 Agent 的 RolePriorStore
          ApplyDeathRevealPriorLocked(seat, role, now)(§130 接线,幂等 drain)
```

### 3.2 与现行 6 类白名单的关系

第 ⑦ 分支在语义上是 ②~⑥ 的**超集**(开启时任何死亡都公开),但 ②~⑥ 分支必须
保留原样 —— 关闭开关时它们仍需独立生效(白痴翻牌存活者也靠 ②)。函数注释从
「禁止 `!Alive` 分支」更新为「禁止**未经 `RevealRoleOnDeath` 门控**的裸 `!Alive` 分支」。

### 3.3 公平性保障机制(对应 §1.2 四不变式的实现手段)

| 不变式 | 实现手段 |
|---|---|
| 单一判定 | 只改 `RolePubliclyRevealed` 一处;§2.2 全部通道自动一致;前端渲染以**服务端脱敏字段**(`role` 非空)为准,不得用开关布尔自行推导身份 |
| 同一 tick | 身份公开是**状态派生**(`!Alive && DeathCause != ""`),不引入任何异步事件 / 定时器;法官宣告与 BuildClientState 广播都发生在死亡结算后的同一次唤醒内 |
| 无抢先通道 | Agent GameContext 的 `RevealedRoles` 也走 `RolePubliclyRevealed`(见 §6.1),不读 `gs.Roles` 原始数组;法官 GameSnapshot 虽全知,但唯一出口 `onAnnounce` 是公屏 |
| 开关对称 | `BuildClientStateWithRoom(viewer==-1)`(观战者)与 REST 详情走同一判定 |

### 4.4 `emitDeathReveal` 接线(修复 §130)+ 幂等 drain 模式

`role_prior.go:143 ApplyDeathRevealPriorLocked` 已存在但零调用。**不在 10 个
`killPlayer` 调用点逐点接线**(必然漏点,§130 复发模式),改为**幂等 drain**:

新文件 `ServerGo/game/werewolf/death_reveal.go` 核心函数:

```go
// syncDeathRevealPriorsLocked 幂等 drain:扫描全部座位,把「身份已对全场公开
// 且已死亡、但尚未写入先验表」的座位 hard-set 进全部 bot 的 RolePriorTable。
//
// 修复 §130:ApplyDeathRevealPriorLocked 此前全库零调用。
//
// 调用前置:必须已持 r.mu(§92a)。
// 幂等性:deathRevealEmitted 簿记保证重复调用零副作用,因此可在多个汇聚点
// 冗余调用(漏一个还有另一个兜底)。
func (r *WerewolfRoom) syncDeathRevealPriorsLocked() {
	gs := r.State
	if gs == nil {
		return
	}
	store := r.rolePriorStoreLocked()
	now := time.Now()
	for seat := 0; seat < MaxPlayers; seat++ {
		if r.deathRevealEmitted[seat] {
			continue
		}
		if gs.Players[seat].Alive || gs.Players[seat].DeathCause == "" {
			continue // 未死亡(含白痴翻牌免死)不进先验改写
		}
		if !gs.RolePubliclyRevealed(Seat(seat)) {
			continue // 开关关闭:仅 6 类白名单命中者进入
		}
		store.ApplyDeathRevealPriorLocked(seat, gs.Roles[seat].String(), now)
		r.deathRevealEmitted[seat] = true
	}
}
```

**两个汇聚调用点**(都持 r.mu、都先于任何消费者看到新状态;冗余即兜底):

| # | 位置 | 时机 |
|---|---|---|
| 1 | `judge_summary_bridge.go:473 wakeJudgeLocked` 入口首行 | 死亡宣告同一 tick,先于 `buildJudgeSnapshotLocked` |
| 2 | `room_agent.go:526 wakeAllAgentsLocked` 入口首行 | 任何玩家 Agent 唤醒前 |

§130 验证:`git grep -n "syncDeathRevealPriorsLocked" ServerGo -- ':!*_test.go'`
非测试调用点 ≥ 2;`ApplyDeathRevealPriorLocked` 非测试调用点 ≥ 1。

**重开一局**:restartGameLocked 重建 GameState 时清零
`r.deathRevealEmitted = [MaxPlayers]bool{}`(随 newGameStateLocked 替换点一并处理)。

## §12 边界(不做的事)

- ❌ 不为不同死因做差异化公开策略(公开与否不区分 cause;逐 cause 差异留给后续需求)
- ❌ 不做「死亡后延迟 N 秒再公开」(与 §20260810-12 D2 正交,不叠加定时器 —— 定时器会破坏「同一 tick」公平性不变式)
- ❌ 不支持局中改开关(建房一次性写入;改了会制造时序信息差)
- ❌ 不做存活白痴(IdiotRevealed)的 RolePrior hard-set(白痴翻牌公开的是「他是白痴」这一存活事实,死亡公开 drain 明确排除 `Alive=true`;如需支持另立设计)
- ❌ 不改动 6 类白名单 ②~⑥ 的既有语义与判定
- ❌ 不给 `deathRevealDelayMin` 补 API 接线(现状仅测试可设,是独立遗留问题,不混入本 PR)
- ❌ 不改 `killPlayer` 签名 / 遗言权规则 / LastWordsRounds
- ❌ 不为 12 / 7 人历史兼容局做开关豁免(同一开关同样生效)
- ❌ 不动 LLM Provider / Anthropic 协议层(纯业务字段,不涉 wire 形状)
