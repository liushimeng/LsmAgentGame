## §2 游戏规则(产品定义)

### 2.1 技能

> **猎魔人**:从第 2 晚起,每晚可狩猎一名存活玩家。
> 若对方是**狼人** → 对方立即死亡;
> 若对方是**好人**(神职 / 平民 / 白痴) → 猎魔人**自己出局**(误杀好人的代价)。
> 首夜不可用(保护猎魔人不被「信息盲猜」式操作害死)。

### 2.2 硬约束(按优先级)

| # | 约束 | 理由 | 引擎校验点 |
|---|------|------|-----------|
| DH1 | **首夜不可用** | 信息盲区+无验证机制,首夜误判 = 自己出局 = 好人阵营崩盘 | `DayNumber >= 2` |
| DH2 | **只能狩猎存活**玩家 | 与预言家 / 女巫 / 守卫一致 | `AliveSeat(target)` |
| DH3 | **不能狩猎自己** | 与守卫一致 | `target != actor` |
| DH4 | **可以空过**(`target = -1`) | 战术选择(没把握就不射);quarantine skip 的合法出口 | `NoSeat` 哨兵 |
| DH5 | **每晚限一次**,每晚**必须**狩猎或空过(不可跨夜累积) | 与守卫每晚必守同构 | `DemonHunterHuntTarget` 每日重置 |
| DH6 | 狩猎结果**立即结算**(夜间内死亡,不计入天亮公布死亡) | 与猎人开枪即时结算同源 | `killPlayer` 在 `endDemonHunterPhase` 内执行 |
| DH7 | 误杀(命中好人)**全公开**身份(全场知道谁是猎魔人) | 与骑士自决公开同源 | `RolePubliclyRevealed` 白名单新增「猎魔人发动」 |

### 2.3 夜间阶段顺序(插入点)

猎魔人狩猎阶段插在**女巫用药之后、公布死亡之前**,与守卫(在狼刀之前)对称:

```
pre_wolves        (首夜强制发言缓冲)
    ↓
night_guard       (§134 守卫守护)
    ↓
night_wolves      (狼人投票刀人)
    ↓
night_seer        (预言家查验)
    ↓
night_witch       (女巫用药)
    ↓
night_demon_hunter ← §猎魔人 新增(女巫用药后,守卫护盾与同守同救裁决仍由 endWitchPhase 完成)
    ↓
dawn              (公布死亡 + 警徽流结算)
```

> **顺序设计动机**:
> 1. 守卫护盾与同守同救必须在女巫用药后裁决(守卫挡狼刀 / 解药挡狼刀 / 双重抵消),
>    女巫阶段结束后 `WolfKillTarget` 已是「最终被杀的人」。
> 2. 猎魔人必须看到「女巫是否已救 / 是否已毒」之后才能决定狩猎谁 ——
>    女巫的毒药目标是与狼刀目标**独立**的额外死亡信息,猎魔人必须看见。
> 3. 女巫毒杀若与猎魔人狩猎同一人,**双重死亡 = 该人已死**(无副作用)。
> 4. 猎魔人狩猎阶段**不修改** `WolfKillTarget`(守卫护盾裁决仍在女巫后已完成),
>    只独立结算 `DemonHunterHuntTarget`。

### 2.4 死亡语义(遵循 §123 / 狼人杀死亡语义设计)

| 触发 | cause | verdict | 备注 |
|------|-------|---------|------|
| 猎魔人狩猎 → 命中狼 | `wolf` | `death` | 复用 `killPlayer(target, "wolf")`,语义与狼刀命中狼对齐(语义上「被识破后处决」) |
| 猎魔人狩猎 → 命中好人 | `demon_hunter_misjudge` | `execution` | 新增 `DeathCauseDemonHunterMisjudge`,verdict=`execution`(自主决策自决) |
| 猎魔人夜晚被狼刀 | `wolf` | `death` | 普通狼刀流程 |

> **为什么不复用 `"wolf"`?** —— 若复用 `wolf` cause,会让「被狼刀」与「被猎魔人识破」共用同一死因,前端死亡列表的「狼刀 vs 猎魔人识破」无法区分。本次新增
> `DeathCauseDemonHunterMisjudge = "demon_hunter_misjudge"` 单一死因,verdict=`execution`
> 表达「自主决策自决」(与狼自爆 / 骑士自决 / 白天被投对齐)。

### 2.5 公开身份(与 §135 衔接)

`RolePubliclyRevealed` 白名单新增第 **⑥ 类**:

```
① 终局复盘   —— Status == "over",全员亮牌
② 白痴翻牌   —— 仅白天被投票放逐时触发;夜间被刀/被毒不翻牌
③ 狼人自爆   —— 白天自爆出局,全场立刻知道他是狼人
④ 猎人开枪   —— 被狼刀/被投票出局时主动亮身份带人;被女巫毒死不能开枪,身份依旧隐藏;主动选择"不开枪"同样不亮身份
⑤ 骑士决斗   —— §198 发动即亮身份;无论结果(命中狼 / 自决)都立即公开
⑥ 猎魔人发动 —— §猎魔人 发动(demonHunterHuntUsed == true)即亮身份;无论结果(命中狼 / 误杀好人)都立即公开
```

**新增字段**:`Player.DemonHunterHuntUsed bool` —— 首次发动即锁定,后续即使跨多夜,
场上所有人都已知道该玩家是猎魔人(每晚可继续狩猎,无单局锁定)。

> 与骑士(`KnightDuelUsed`)区别:骑士是「本局一次性」技能(用错就锁死),猎魔人是「**每晚可发动**」技能。
> 因此 `DemonHunterHuntUsed` 仅作「是否曾发动」标记,**不锁定**技能。

## §3 引擎层

### 3.1 阶段枚举

`engine.go:PhaseNight*` 紧接 `PhaseNightWitch` 之后新增:

```go
PhaseNightWitch               // 夜晚:女巫用药
PhaseNightDemonHunter         // §猎魔人:夜晚狩猎(DH1 首夜不可用)
```

> ⚠️ **不要在 PhaseNightWitch 之前插入**:守卫 / 狼 / 预言家 / 女巫的行动顺序是 §134 已固化的「守卫在最前」链,
> 新阶段插入必须验证 `grep "Phase >=" 零命中`,且 DB phase 字段均为 varchar 存储,
> 新常量不影响历史 DB 行的 sort 比较(详见 §134 第 8 条教训)。

### 3.2 GameState 新增字段

| 字段 | 类型 | 含义 | 重置时机 |
|------|------|------|---------|
| `DemonHunterSeat` | `Seat` | 猎魔人座位缓存;`NoSeat` = 本局无猎魔人 | `StartGame` 时填充 |
| `DemonHunterHuntTarget` | `Seat` | 当晚狩猎目标;`NoSeat` = 空过 | `startNight` 时重置 |
| `DemonHunterHuntUsed` | (per Player) | 该玩家本局**曾发动过**狩猎;用作 `RolePubliclyRevealed` 单一信号 | 一次性,跨夜保留 |

### 3.3 Player 新增字段

```go
// §猎魔人 是否**本局曾发动过**狩猎(DH7 公开身份)。
// 不同于 KnightDuelUsed(K1 每局限一次),猎魔人每晚可发动;
// 仅作"是否曾发动"标记,不影响后续发动。
DemonHunterHuntUsed bool
```

### 3.4 关键校验链(`NightDemonHunterHunt`)

```
DH-A  Phase == PhaseNightDemonHunter      → 否则 ErrNotYourTurn
DH-B  DayNumber >= 2                       → 否则 ErrDemonHunterFirstNightUnavailable (首夜不可用)
DH-C  actor == gs.DemonHunterSeat && Alive → 否则 ErrPermissionDenied
DH-D  target == NoSeat (空过合法) OR:
        - target ∈ [0, MaxPlayers)
        - AliveSeat(target)
        - target != actor
DH-E  gs.DemonHunterHuntTarget = target
DH-F  gs.Players[actor].DemonHunterHuntUsed = true (DH7 公开身份)
DH-G  endDemonHunterPhase() → 结算
```

### 3.5 结算优先级(`endDemonHunterPhase`)

```
if target == NoSeat (空过) → 直接进 dawn,无死亡
elif Roles[target] == RoleWerewolf:
     killPlayer(target, "wolf")         // 复用狼 cause,verdict=death
     NightDeaths = append(NightDeaths, target)
elif Roles[target] 是好人阵营 (FactionOf == FactionGood):
     killPlayer(actor, "demon_hunter_misjudge")  // verdict=execution
     NightDeaths = append(NightDeaths, actor)
     // 注:此处 actor == gs.DemonHunterSeat(已死),NightDeaths 进 dawn 公布
     // 公开身份(§135 衔接:DemonHunterHuntUsed=true → RolePubliclyRevealed)
else (角色未识别 — FactionUnknown,理论上不应出现):
     // 防御性兜底:按"误杀好人"处理(保守)
     killPlayer(actor, "demon_hunter_misjudge")
```

### 3.6 嵌套状态处理

| 嵌套场景 | 处理 |
|---------|------|
| 猎魔人已被狼刀死 + DH1 首夜禁用 | 不可能出现:猎魔人首夜不可发动,被刀即出局 |
| 猎魔人已被女巫毒杀 | 与狼刀同理,当晚不再行动;若已死则 `AliveSeat(actor)==false` → DH-C 失败 |
| 女巫毒杀目标 == 猎魔人狩猎目标 | 双方结算后,该玩家**仅死一次**;若猎魔人狩猎对象是「女巫毒杀目标 + 狼人」会出现已死提示,服务端保守视为「目标已死」 → DH-D 失败 |
| 猎魔人空过(每晚可选) | `target = NoSeat` 合法,DH-G 走空过分支,无死亡,直接进 dawn |
| **女巫毒杀猎魔人本人 + 猎魔人发动** | 时序上不可能(`endWitchPhase` 先结算毒杀,猎魔人已死 → DH-C 失败) |

### 3.7 阶段跳过 / 终止条件

- `DemonHunterSeat == NoSeat` (本局无猎魔人) → `startNight` 直接跳过 PhaseNightDemonHunter,进入 dawn
- `DemonHunterSeat` 已死 → 同上,跳过
- `DayNumber == 1` (首夜) → `endWitchPhase` 完成后 `endDemonHunterPhase` 直接 `setPhaseAndDeadline(PhaseDawn)`,
  `DemonHunterHuntTarget = NoSeat` (无实际操作),但**仍走完阶段**,前端可见「猎魔人尚未可行动」UI 占位

### 3.8 与守卫 / 狼 / 预言家 / 女巫阶段的关系

- **DH 在女巫之后**:女巫用药后,猎魔人看到全部「今晚已死亡 / 今晚被毒」信息才能决断。
- **DH 在 dawn 之前**:猎魔人狩猎结果与狼刀 / 毒杀一同进 `LastNightDeaths`,天亮统一公布。
- **DH 不修改 `WolfKillTarget`**:守卫护盾与同守同救裁决已在女巫后由 `endWitchPhase` 完成,猎魔人狩猎不影响该裁决。

### 4.5 SkipPhaseAction

`ServerGo/agent/run.go::SkipPhaseAction` 新增 case(quarantine / 沉默兜底):

```go
case "night_demon_hunter", "PhaseNightDemonHunter":
    // §猎魔人 空过 = target=-1 = 合法(DH4);watchdog 兜底用空过,绝不盲射。
    return "demon_hunter_hunt_skip", 0
```

> **关键决策**:watchdog 兜底**永远空过**(target=-1)而非随机狩猎某个存活玩家 —
> 随机狩猎的失败率约 80%(场上 12 个玩家,4 狼+8 好,盲射命中狼 = 4/12 = 33%),
> 误杀好人会让猎魔人+1 个好人出局,直接屠边。
> 空过只是「本晚不动」,第二天白天仍可基于讨论再次狩猎,代价最低。

func (m *WerewolfManager) Action_DemonHunterHunt(roomID, userID string, target Seat) (*WerewolfRoom, *errcode.Error) {
    r := m.getRoom(roomID)
    if r == nil { return nil, errcode.Code(errcode.ErrRoomNotFound) }
    r.mu.Lock()
    defer r.mu.Unlock()
    if r.State == nil { return nil, errcode.Code(errcode.ErrGameNotStarted) }
    seat, ok := r.SeatOf(userID)
    if !ok { return nil, errcode.Code(errcode.ErrRoomNotIn) }
    if e := r.State.NightDemonHunterHunt(seat, target); e != nil { return nil, e }
    m.EmitDemonHunterHunt(r, int(seat), int(target))
    m.wakeActingAgentsLocked(r, "state_change")
    return r, nil
}

## §9 教训总结(为什么必须全链路同步)

参考 §134 教训 1-7 + §130/§198 全链路补全经验:

1. **角色卡池是契约** —— 任何进入 `godRolePool` 的角色必须有完整引擎+工具实现,否则就该移出卡池,二者必居其一。
2. **enum 剔除优于事后报错** —— 猎魔人狩猎 target 在服务端就剔除自己 / 已死,LLM 无法选出违规值。
3. **每晚必发动 vs 每局必发动**:守卫每晚必守 / 猎魔人每晚可选(空过合法),与骑士每局限一次形成「三态模式」。
4. **公开身份 vs 保密身份**:守卫「盲守」= 隐私保护;猎魔人「发动即公开」= 公开博弈,与骑士对齐。
5. **空过的合法性**:DH4 target=-1 空过是 watchdog / quarantine 兜底的合法出口。
6. **watchdog 兜底策略**:守卫 fallback 兜底守护 / 预言家 fallback 兜底查验 / 女巫 fallback 兜底 skip /
   **猎魔人 fallback 必须空过** — 命中狼的概率太低,误杀好人代价太大。
7. **嵌套状态**:女巫毒 + 猎魔人狩猎同一人 → 仅死一次(已死玩家狩猎目标被剔除)。
8. **新增夜间阶段必须同步**:`SkipPhaseAction` / `watchdogActingSeat` / `dispatchQuarantinedSkipLocked` /
   `isActingPhase` / `defaultPhaseDeadlineSec` 五处(§97 三处 + 两处易漏)。
9. **死因复用与新增**:命中狼复用 `cause=wolf`(语义对齐);命中好人新增 `cause=demon_hunter_misjudge` 单一死因。
10. **§130/§134/§198「声明了却从不接线」第四次复现** —— 这次伪装为「半实现 6 神职」批量出现,
    修复 1 个不能让另外 5 个也跟着活过来。本次补全猎魔人后,**剩余 5 个半实现角色**
    (魔术师/奇迹商人/射梦人/乌鸦/纯白之女) 仍需后续 §2xx 修复,**不在本次范围内**。
