## §2 游戏规则(产品定义)

### 2.1 技能

> **骑士(Knight)**:白天发言阶段,可在任意时刻翻牌点名一名玩家公开决斗。
> **若目标是狼人(狼阵营) → 该目标出局**;
> **若目标不是狼人 → 骑士自己出局**(技能反噬);
> **每局限一次**(用尽后即使存活也不能再发动)。

> **「翻牌」语义**:骑士公开亮明身份;亮牌后身份保密失效,场上所有玩家立刻知道骑士是谁。
> 这与 `RolePubliclyRevealed` 的「身份公开」规则衔接 — 骑士发动决斗立即触发身份公开。

### 2.2 硬约束(按优先级)

| # | 约束 | 理由 | 引擎校验点 |
|---|------|------|-----------|
| K1 | **每局限一次** | 防止骑士每轮翻牌赌博「猜对就赚、猜错认赔」无限利用 | `Player.KnightDuelUsed` |
| K2 | **只能发动一次,使用后本局不可再用** | 与 K1 同义;K2 强调即使未揭晓结果也不可撤销 | `Player.KnightDuelUsed` |
| K3 | **只能在白天发言阶段发动** | 守卫 / 女巫解药都是夜间;决斗是公开技能 | `PhaseSpeak` |
| K4 | **只能在骑士存活时发动** | 死亡不能发动 | `AliveSeat(actor)` |
| K5 | **必须且只能由骑士本人发动** | 与守卫 / 女巫同构 | `Roles[actor] == RoleKnight` |
| K6 | **目标必须存活** | 不能决斗死者 | `AliveSeat(target)` |
| K7 | **不能决斗自己** | 防止自杀破规则 | `target != actor` |
| K8 | **发动即公开身份**(亮牌) | 公开是发动代价,场上立刻知道骑士是谁 | `RolePubliclyRevealed` |
| K9 | **死法 = `execution`** | 骑士自决(猜错买单),与女巫毒 / 狼刀的「death」决断不同 | `verdictFor("duel")` |

### 2.3 决斗判定矩阵

| 目标阵营 | 结果 |
|---------|------|
| 狼(Werewolf) | **目标出局**(verdict=`death`,cause=`wolf` 由狼阵营技能驱动)。骑士存活,身份已公开 |
| 好人(其他) | **骑士出局**(verdict=`execution`,cause=`duel` 自决)。目标存活,游戏继续 |

> §135 衔接:骑士「自杀」按 verdict=`execution` 走,**骑士身份牌翻开**给全场看。
> 死者身份牌不翻牌的规则(§135)不适用于自决技能 — 自决等同于「主动认领」。

### 2.4 触发位置 — 白天发言阶段

骑士决斗**穿插在白天发言阶段**,规则细节:

1. 白天从 `PhaseSpeak` 开始,按座位号升序轮流发言;
2. 当轮到骑士发言时 / **任意非骑士玩家发言中**,骑士可发动决斗;
3. 发动决斗后,目标立刻公开裁决结果;
4. 骑士已用完(K1)→ 不能再发动,但白天流程不变;
5. 骑士已死亡 → skip 阶段。

**实现简化**(对齐 §134 守卫的「单点接入」原则):

```
骑士决斗只在 PhaseSpeak + 当前发言座位 == 骑士 时插入动作工具;

非骑士玩家发言中穿插决斗:
  → 暂时不支持(对齐女巫夜间工具的位置约束)。
  → 若要支持,后续可独立提交一项"任意座位发言中骑士可打断"
    重构,但本次 §198 不引入新阶段。
```

> 这个简化与官方规则一致:骑士只能在「轮到自己发言时」发动决斗,
> 因为非骑士发言中翻牌打断会破坏轮流发言秩序。13 人局 4 狼的快节奏下,
> 简化版仍保留博弈价值(骑士挑「像狼」的人决斗,狼人也可能通过发言试探)。

### 2.5 白天的整体顺序(无变化)

```
PhaseDawn (公布死亡 + 警徽流结算)
    ↓
PhaseSheriff  (仅 Day1)
    ↓
PhaseSpeak    ← §198 骑士决斗插在这里(发言过程中)
    ↓
PhaseVote     (无变化)
    ↓
PhaseIdiotReveal (无变化)
    ↓
...
```

骑士决斗**不**新增独立 Phase,而是在 `PhaseSpeak` 阶段就调用 `KnightDuel` action。
这样不需要扩展 phase 枚举,降低与 §134/§135 的耦合风险。

```go
// DeathCause 死因代码(扩展 §198)
const (
    DeathCauseWolf        = "wolf"
    DeathCauseVote        = "vote"
    DeathCauseHunter      = "hunter"
    DeathCauseWitchPoison = "witch_poison"
    DeathCauseSuicide     = "suicide"
    DeathCauseDuel        = "duel" // §198 骑士自决(决斗猜错的反噬)
)

// verdictFor: duel → execution(自决)
func verdictFor(cause string) string {
    switch cause {
    case DeathCauseWolf, DeathCauseHunter, DeathCauseWitchPoison:
        return DeathVerdictDeath
    case DeathCauseVote, DeathCauseSuicide, DeathCauseDuel: // §198
        return DeathVerdictExecution
    default:
        return DeathVerdictDeath
    }
}
```

### 3.5 核心方法(放 `engine_day.go` 与其他白天方法并列)

```go

//
// 前置条件(按顺序校验):
//   K3 Phase == PhaseSpeak
//   K4 AliveSeat(actor)
//   K5 Roles[actor] == RoleKnight
//   K2 !Players[actor].KnightDuelUsed
//   K6 AliveSeat(target)
//   K7 target != actor

//
// 结算:
//   if Roles[target] == RoleWerewolf:

//       + HunterPendingShoot 检查 + 同因果清单。
//       使用 killPlayer(target, "wolf") 是合理的(死因语义等价"狼阵营致死"),
```

### 3.6 KnightFired(身份公开白名单扩展)

修改 `engine.go` 的 `RolePubliclyRevealed`:

```go
func (gs *GameState) RolePubliclyRevealed(seat Seat) bool {
    ...
    // §198 骑士发动决斗 → 主动亮身份(K8 + §135 公开白名单)
```

> 骑士翻牌后才看到结果,场上所有人都看到决斗过程。

## §4 Agent 层设计(`ServerGo/agent/`)

### 4.1 工具 `knight_duel`

`BuildTools` 新增分支(`phase == speak || phase == day_speak` + `role == "knight"` + `!KnightDuelUsed`):

```go
// 在 BuildTools 的 phase switch 中加:
case "PhaseSpeak", "speak", "day_speak":
    if role == "knight" && !knightDuelUsed {
        enum := make([]int, 0)
        enum = append(enum, -1) // -1 = 本轮不决斗(放弃机会)
        for i := 0; i < MaxPlayers; i++ {
            if i != seat && alive[i] {
                enum = append(enum, i)
            }
        }
        add("knight_duel", "骑士白天决斗。<策略段>",
            schema(map[string]any{
                "target": map[string]any{
                    "type": "integer",
                    "description": "决斗目标座位号(-1=放弃本轮不决斗,本局机会仅一次)",
                    "enum": enum,
                },
            }, "target"))
    }
```

**关键决策**:`target=-1` 表示本轮放弃决斗。LLM 选择不决斗时**不会失去机会** —
会通过另一个指示器(下一轮仍可再发动)。但当 LLM 已成功调用 `knight_duel(target=狼)`
或 `knight_duel(target=好人)` 后,服务端置 `KnightDuelUsed=true`,
LLM 下次再调用 tool 时,BuildTools 不再提供 `knight_duel`(消失了),LLM 不会误用。

**enum 已剔除自己 + 已死的玩家** —— LLM 根本无法选错。

策略段 description 文案:

```
⚔️ 你是骑士 — 白天发言阶段可发动一次决斗。
❶ 你翻牌名X,服务器核对:若是狼 → X 出局;若不是狼 → 你自己出局。
❷ 选择哪些玩家决斗?通常是发言中表现可疑、像预言家/女巫/守卫的好人,或**真狼**。
❸ 不要盲目:Day1 信息不足时,选择放弃(-1)保留技能更好。
❹ 公开亮身份:发动即全房知道你是骑士,失去神职神秘性。
❺ ⚠️ 严守:技能仅一次,用错就立刻死。判定错误时**优先放弃**而非盲猜。
```

> 故意强调「判定错误优先放弃」,因为 Knights 的「自决」语义不像守卫失败可重试。

### 5.3 「决斗成功 / 失败」活动流(必读)

参考守卫的「不暴露目标」反例 — 骑士决斗**可以**公开目标与结果,因为这正是技能点。
服务端 `EmitKnightDuel(actor, target, isWolf bool)` 写两条文案:

```
⚔️ 3号 骑士对 7号 发动决斗!
     → 7号 是狼人,7号 出局!
或:
⚔️ 5号 骑士对 9号 发动决斗!
     → 9号 不是狼人,5号 骑士自决出!
```

> 注意:骑士名字会出现在文案中,**等同于亮身份**,符合 K8。
> 狼阵营的人立刻知道场上哪个位置是骑士(对狼人是优势信息),
> 但这正是「公开技能」的代价。设计上接受此博弈价值。

## §7 活动流(`activity_emitter.go`)

```go
const ActivityEventKindKnightDuel = "knight_duel" // §198

// EmitKnightDuel 广播骑士决斗结果(isWolf=true 时 target 出局;false 时 actor 出局)。
// 文案会公开 actor 与 target —— 这是「公开技能」的必要信息泄露。
func (m *WerewolfManager) EmitKnightDuel(r *WerewolfRoom, actor, target int, isWolf bool) {
    // 拼文案
    text := "⚔️ " + seatCN(actor) + "号 骑士对 " + seatCN(target) + "号 发动决斗"
    suffix := ""
    if isWolf {
        suffix = seatCN(target) + "号 是狼人," + seatCN(target) + "号 出局!"
    } else {
        suffix = seatCN(target) + "号 不是狼人," + seatCN(actor) + "号 骑士自决出!"
    }
    text += "\n → " + suffix
    // 调 emitActivity(refSeat=actor, refSeat2=target)
}
```

`knight_dude` 以便前端 switch。
