## §1 背景与需求

用户反馈两条(2026-08-30),本设计一并解决:

1. **自爆链路残缺**:狼人(人类或 Agent)白天自爆后,既没有遗言,也没有
   「带走一名玩家」的爽点机制;人类玩家更没有任何自爆后的操作界面。
2. **死亡后链路残缺**:玩家(人类或 Agent)死亡后,遗言与「死亡触发的技能
   环节」(猎枪/带走)缺少明确的操作界面;Agent 侧甚至存在**死者被系统性
   屏蔽**的缺陷(见 §2.3),死亡 Agent 永远只能被 watchdog 代打 skip。

需求要求**人类与 Agent 完全同源**:同一 Action 入口、同一 WS 帧协议、同一
工具集、同一 deadline/watchdog 兜底,不允许出现人类有 UI 而 Agent 无能力
(或反之)的不对称。

**缺失**:自爆遗言权、自爆带走机制、自爆确认弹窗、自爆后阶段 UI。

### 2.2 遗言(`PhaseDeathLyric`)

引擎 / 工具 / WS 帧(`game.werewolf_last_words`)/ 人类面板(`LastWordsPanel`)
/ 全员进度条(`LastWordsStage`)均已实现。**死者身份徽章**已按 §20260830-01 接线。

### 2.3 死亡 Agent 被系统性屏蔽(核心缺陷)

`wwplayer/run.go:172` 的死者守卫:

```go
if !containsSeat(aliveList, mySeat) {
    logger.L().Debug("agent: dead seat; ignoring wake ...")
    return   // ← 死者一律不调 LLM、不派发工具
}
```

后果(全部是「死亡触发的合法行动」被吞):

| 阶段 | 应行动者 | 实际表现 |
|---|---|---|
| `death_lyric` | 当前遗言死者 | Agent 死者**永远发不出遗言**,watchdog 到期代打 `last_words_skip` |
| `hunter_shoot` | 死亡猎人 | Agent 猎人**永远开不出枪**,watchdog 到期代打 `hunter_shoot(-1)` 放弃 |
| (新)`suicide_take` | 自爆狼(已死) | 同上,必须避免复现 |

`room_agent_context.go` 的 `PhaseHunterShoot` 分支早已修过 `MyTurn`(注释
BUG-WEREWOLF-P0-2 明确写了 "hunter dies THEN shoots"),但 `run.go` 的死者
守卫把 wake 在更上游拦掉了 —— **MyTurn 修了,守卫没修**,又一个
§130「声明了却从不接线」的变体。

### 2.4 视图层 `my_turn_now` 同源缺陷

`view.go:932` `PhaseHunterShoot` 分支带 `myAlive &&` 守卫 —— 死亡猎人的
`my_turn_now` 永远为 false,`MyTurnIndicator` 不亮。同批修复。

### 2.5 文档/代码既有偏差(记录不修)

`13人标准局规则.md` §8.1 写「`PhaseSpeak` / `PhaseSheriff` 均可自爆」,代码
仅 `PhaseSpeak`。本设计维持**仅 PhaseSpeak**(警长竞选自爆属扩展,超出本次
范围),规则文档随本设计同步改写。

## §3 规则设计

### 3.1 自爆强化(遗言 + 带走)

```
PhaseSpeak(狼发言轮)
   │ wolf_suicide
   ▼
自爆狼死亡(cause=suicide,verdict=execution,身份③白名单公开 — 不变)
   ▼
PhaseDeathLyric — 自爆狼遗言(新增:自爆必有遗言,不受 LastWordsRounds 限制)
   │ 遗言队列清空(或 DeathLyric 关闭时 onDone 直通)
   ▼
PhaseSuicideTake — 自爆带走选择(新阶段)
   │ wolf_suicide_take {target}  target=-1 = 放弃带走
   ├── 放弃 ──────────────────────────────┐
   ▼ 带走存活玩家                          │
被带走者死亡(cause=suicide_take,verdict=death,身份不公开)
   ├── DayNumber ≤ 2 → PhaseDeathLyric(被带走者遗言)
   │        └─ 清空后 ─┐
   ├── 被带走者是猎人 → PhaseHunterShoot(反枪,from="suicide_take")
   │        └─ 结算后 ─┤
   ▼                   ▼
checkWinner ─→ advanceDay(DayNumber++)→ startNight(当夜照常刀人)
```

要点:

- **遗言必给**:自爆是「亮身份 + 出局 + 终止白天」的三重代价,遗言与带走
  是新规则的补偿,不再沿用「自爆无遗言」旧条款。两者由同一开关联动(§3.4)。
- **带走可选**:`target=-1` = 放弃(与猎人不开枪同语义)。watchdog 兜底
  永远派发**放弃**而非随机带走 —— 随机带走期望收益为负(误带队友),与
  猎魔人兜底空过同一决策原则。
- **白天语义**:带走不受守卫夜间守护 / 女巫解药影响(白天动作,夜间结算
  字段 `GuardProtectTarget` 已在黎明重置)。
- **猎反枪**:被带走者是猎人 → 可开枪(带走 ≠ 毒杀)。反枪目标可再触发
  遗言/胜负判定,复用既有 `HunterShoot` 链路,`HunterPendingFrom="suicide_take"`。
- **入夜路径**:与旧实现 `startNight()` 裸调不同,新链路统一走
  `advanceDay()`(DayNumber++ + startNight)。这同时修复旧实现自爆后
  **DayNumber 不递增**的天数编号缺陷(自爆吞掉整个白天却记同一天)。

### 3.2 死者行动白名单(dead-actor phases)

`GameContext` 新增 `DeadActorTurn bool`,`buildAgentContextLocked` 在三个
阶段为死者置 true;`run.go` 死者守卫改为:

```go
if !containsSeat(aliveList, mySeat) && !evt.Context.DeadActorTurn {
    return
}
```

| 阶段 | DeadActorTurn 条件 | 行动 |
|---|---|---|
| `death_lyric` | `seat == DeathLyricCurrent` | `last_words` / `last_words_skip` |
| `hunter_shoot` | `seat == HunterSeat && HunterPendingShoot` | `hunter_shoot` |
| `suicide_take` | `seat == SuicidedWolfSeat` | `wolf_suicide_take` |

白名单之外死者仍一律屏蔽(防止死者继续 speak/vote/whisper 的旧约束不变)。
`view.go fillMyTurnExtra` 同步: hunter 分支去掉 `myAlive` 守卫、新增
`suicide_take` 分支 —— 人类 `MyTurnIndicator` 与 Agent `MyTurn` 同源同亮。

### 3.3 死因与身份公开

- 新增 `DeathCauseSuicideTake = "suicide_take"`,`verdictFor → "death"`
  (被带走者非自主决策,死亡语义与猎枪一致)。
- **不入** `RolePubliclyRevealed` 白名单:被带走者身份不公开(终局 /
  `reveal_role_on_death` 房间开关除外) —— §135 单点判定不变。
- 自爆狼自身仍走 ③ 白名单(`DeathCause=="suicide"`),不变。
- 法官词表补 `suicide_take`:宣告格式「N 号死亡·被自爆带走」。

### 3.4 配置开关

`config.WerewolfConfig` 新增:

```go
SuicideTakeEnabled bool `json:"suicide_take_enabled"` // 默认 true
```

- `true`(默认):§3.1 全链路(遗言 + 带走)。
- `false`:完整回退旧行为(自爆无遗言、直接 `startNight()`)—— 竞技规则
  房间可关闭,行为与 2026-08-30 之前完全一致。
- 安全读取 helper `isSuicideTakeEnabled()`(config 未加载/测试环境默认 true,
  与 `isDeathLyricEnabled` 同模式)。

### 3.5 阶段属性

| 项 | 值 |
|---|---|
| Phase 常量 | `PhaseSuicideTake`(枚举追加在末尾,不重排既有值) |
| String() | `"suicide_take"` |
| isActingPhase | true |
| deadline 默认 | human 120s / 全 AI 300s(与 hunter_shoot 对齐) |
| TurnActingSeat | `SuicidedWolfSeat` |
| watchdog acting seat | `SuicidedWolfSeat`(异常时 -1) |
| watchdog 兜底 | deadline 到 → 派发 `wolf_suicide_take(-1)` 放弃 |

### 3.6 阵营金币池 / 战报 / 活动流

- 自爆本身仍触发狼阵营 -30(`wolf_pool.go` 不动);`suicide_take` 死亡不
  触发额外扣减(被带走者非自爆者本人)。
- 战报新增 trigger:`HighlightKindSuicideTake`(「自爆狼 X 带走 Y」)。
- 活动流新增 `EmitSuicideTake`(「🧨 自爆狼带走:N 号」/「🧨 自爆狼放弃带走」)。

## §4 公平性设计(不变式)

> 用户明确要求「注意游戏公平性」。以下不变式为本设计的硬约束,验收与
> 回归测试逐条对应。

1. **信息同源**:带走选择只基于白天公开信息(发言/投票/已公开身份);
   服务端不下发任何额外身份字段。Agent 的 `GameContext` 与人类视图
   `BuildClientState` 均不因 `suicide_take` 阶段新增身份泄露。
2. **身份公开单点**:被带走者身份只经 `RolePubliclyRevealed` 判定
   (§135),`suicide_take` 不新增白名单分支;终局/房间开关语义不变。
3. **人机同源**:人类 WS 帧 `game.werewolf_suicide_take` 与 Agent 工具
   `wolf_suicide_take` 进同一 `Action_SuicideTake` → `suicideTakeLocked`;
   deadline、watchdog、quarantine skip 三条兜底路径行为一致。
4. **死者行动最小化**:死者仅在被 `DeadActorTurn` 白名单命中时可行动;
   工具暴露按阶段收敛(遗言阶段只给遗言工具,带走阶段只给带走工具),
   防死者干扰存活玩家的发言/投票。
5. **先手信息一致性**:自爆狼遗言在带走选择**之前**完成 —— 与猎人
   「先遗言后开枪」同一时序,被带走者遗言在带走**之后**,先手方无法
   通过遗言探测后手方的选择。
6. **守卫/解药不干预白天**:带走为白天结算,不读夜间守护字段。
7. **胜负裁决完备**:`checkWinner` 触发点覆盖 自爆死亡后 / 带走死亡后 /
   猎反枪后 —— 带走导致屠边/屠神即时终局,不再进入遗言/反枪。
8. **可回退**:`suicide_take_enabled=false` 时引擎路径与旧版逐字节等价
   (含 DayNumber 旧缺陷行为不动 —— 回退优先于顺手修复)。
