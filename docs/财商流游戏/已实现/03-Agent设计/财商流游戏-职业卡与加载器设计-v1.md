## 1. ProfessionCard 结构

```go
// game/wealth/profession/card.go
type Card struct {
    ID             string   // "P01"…（文档池为 "N9012345"）
    Title          string   // 职业名
    Name           string   // 化名（文档池卡；精选手卡可空）
    Salary         int64    // 月薪（税前，元；P16 为均值基准）
    SalaryVolatile bool     // true = 收入波动带（P16）
    Expense        int64    // 月支出基数（元）
    Savings        int64    // 初始储蓄（元）
    StartAge       int      // 开局年龄（精选手卡恒 25；文档卡 clamp 20–55）
    Energy         int      // 初始精力 0–10
    Network        int      // 初始人脉 0–10
    Cognition      int      // 初始认知 0–10
    CreditScore    int      // 初始信用分（《规则》§8.6.1）
    HomeDistrict   string   // 工作区/初始所在区（8 区 id）
    RiskPreference string   // conservative | balanced | aggressive
    Personality    []string // 2–4 词（Schema v1.1 词库）
    BehaviorTraits []string // 2–4 词（可空）
    HealthGrade    string   // "A"|"B"|"C"（健康事件概率档）
    Marital        string   // single | married（文档池）
    ChildrenCount  int      // 初始子女数
    EldersDependent int     // 需赡养老人数（月支出 +1000/位，P0 新定）
    OpeningHook    string   // 30–50 字开场白（开局 SendFromBot）
    Goals          []string // 含 1 条 5 年目标
    Source         string   // "curated" | "docs"
}
```

校验（`card.go::Validate`）：Salary/Expense/Savings ≥0；Energy/Network/Cognition ∈[0,10]；
CreditScore ∈[400,850]；HomeDistrict ∈ 8 区 id；OpeningHook 长度 ∈[20,60]（rune 计）。

## 3. 文档池加载器

`loader.go`——从 `cfg.Wealth.ProfessionDocsPath`（json 键 `profession_docs_path`，默认
`./docs/财商流游戏/玩家职业设计`）加载 75,115 张人物卡（Schema v1.1，frontmatter 65 字段）。

### 3.1 懒加载三段式

```
阶段 0（NewLoader）：不读盘。仅记录根路径 + sync.Once。
阶段 1（buildIndex，首次抽卡触发或 HTTP professions 触发）：
   walk 根目录收集 *.md 相对路径清单（五层树 <L1>/<L2>/<L3>/<L4>/<L5>/<编号>-<姓名>.md），
   构建 []string 索引 + 总数；**不解析 frontmatter**。75k 次 stat ≈ 秒级，结果缓存进程内。
阶段 2（Draw(n, rng)）：从索引均匀抽 n 张不重复相对路径 → 逐张读取文件 → 只解析
   frontmatter（首个 --- 块，yaml 子集解析：逐行 key: value，够用且零依赖）→
   映射为 Card（§4）→ LRU 缓存（上限 256 张，命中免读盘）。
```

- **seed**：`Draw` 使用注入的 `*rand.Rand`；同 seed 同索引快照 → 同卡集合（确定性测试）。
- **并发**：`sync.RWMutex`；索引构建一次写、后续读。
- **失败语义**：任一卡解析失败 → 跳过并 `logger.Warn`；可用卡 < n → 回退精选手卡补足；
  根目录不可用（`available=false`）→ **全量回退精选手卡** + `game.event` 提示（错误码 35012
  仅在回退也失败时抛出，实际不可能——curated 内嵌常量恒可用）。
- **路径安全**：拒绝 `..` 与符号链接逃逸（`filepath.Clean` + `strings.HasPrefix` 根前缀校验）。

## 4. 字段映射表

文档池 frontmatter（Schema v1.1）→ `Card`：

| frontmatter 字段 | Card 字段 | 映射规则 |
|-----------------|-----------|---------|
| `id` / 文件名编号 | `ID` | 原样（N 卡） |
| `_raw.legacy_name` 或文件名 `-<姓名>` 段 | `Name` | 化名 |
| `occupation` / `industry_l3` | `Title` | 取occupation，缺省取 l3 |
| `income_monthly` | `Salary` | int64（元/月） |
| `income_stability` | `SalaryVolatile` | 含「波动/不稳定」→ true |
| `monthly_expense` | `Expense` | int64 |
| `savings_stock` | `Savings` | 可空 → **兜底 = income_monthly × 6**（P0 新定） |
| `age` | `StartAge` | clamp [20,55] |
| （无直接字段） | `Energy` | 由 `work_intensity` 映射：高→4、中→6、低→8；clamp[0,10]（P0 新定） |
| `health_grade` | `HealthGrade` | A/B/C 原样；缺失 → B |
| `personality` | `Personality` | 词库过滤（Schema §3.1 十三词），保留 2–4 个 |
| `behavior_traits` | `BehaviorTraits` | 同上（十词库），可空 |
| `risk_preference` | `RiskPreference` | conservative/balanced/aggressive 原样 |
| `marital` | `Marital` | 已婚→married，其他→single |
| `children_count` | `ChildrenCount` | int |
| `elders_dependent` | `EldersDependent` | int |
| `opening_hook` | `OpeningHook` | 骨架 30–50 字直接使用；>60 rune 截断 + 「…」 |
| `goals_short` | `Goals` | 取前 3 条 |
| `housing_city` / 就业城市启发 | `HomeDistrict` | 城市名→8 区映射（一线核心→finance、高新区→tech、县城→oldtown…；无命中 → `residential`，P0 新定启发表） |
| （无） | `CreditScore` | 按收入档：≥20000→700、8000–20000→650、<8000→550；个体/自由就业 -50 下限 500（P0 新定，对齐 §8.6.1 分组精神） |
| （常量） | `Source` | "docs" |

> ⚠️ 精选手卡 `Name` 为空、`StartAge=25`；文档卡 `StartAge` 取卡面。混合池（curated+docs 同房）
> P0 不支持——`pool` 为房间级单选，避免同龄轴混乱。

## 5. 扩展到数十万卡的路径

P0 的懒加载三段式在 75k 卡下已够用（索引 ≈ 75k × 60B ≈ 4.5MB 字符串）。P3 十万级+多房间高并发下的路线：

| 阶段 | 措施 | 内存预算 |
|------|------|---------|
| P3.1 | **索引持久化**：walk 结果序列化为 `index.json`（路径+编号+行数），启动加载代替 walk；mtime 校验失效 | <16MB |
| P3.2 | **分片索引**：按 L1（26 域）分片 `index/<L1>.json`；抽卡限定分片集合（如「只从 Q 金融域抽」） | 按需加载 |
| P3.3 | **解析缓存升级**：LRU 256 → 带 TTL 的两级缓存（进程内 1024 张 + mmap 直读 frontmatter 首 4KB，避免整文件 IO） | <64MB 硬上限 |
| P3.4 | **D2–D7 切片索引**：接入六维切片索引（`_框架/10-维度索引`），支持「收入阶层 × 人生阶段」组合抽卡，用于平衡对局 | 索引另计 |
| P3.5 | **卡池服务化**：loader 抽成独立内嵌服务（仍 in-process），`Draw(filter, n, seed)` 接口稳定，未来可拆进程 | — |

硬约束：任何阶段 `Draw` 的 P99 < 100ms（12 座一房仅 12 次解析）；内存超预算时优先降缓存不降索引。

## 6. HTTP 暴露

`GET /api/games/wealth/professions`（协议文档 §6）→ `{curated:[10 张公开字段], pool:{available, total, indexed}}`：

- `curated[]`：`{id,title,salary,expense,savings,start_age,energy,network,cognition,credit_score,home_district,risk_preference,personality,opening_hook,goals}`（不含内部字段）。
- `pool.total`：索引条目数（阶段 1 后精确；未触发时为 -1 + `available` 按目录存在性判断）。
- `pool.indexed`：已解析进 LRU 的张数（观测用）。
