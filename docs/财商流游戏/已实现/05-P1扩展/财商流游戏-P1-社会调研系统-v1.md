# 财商流游戏 · P1 扩展：社会调研系统（对全体 Agent 的预测模拟）

> **版本**：v1 ｜ **日期**：2026-09-16 ｜ **game_kind**: `wealth`
> 本文件是 P1 第二期的**实现契约**——面向全体 Agent（模型玩家）的社会调研
> （预测）系统：人类发起问题 → 12 个 bot 各自作答 → 自动聚合 → 全房广播。
> 上游设计来源：用户需求「对全体 Agent 的社会调研/预测」；
> 依赖同目录《财商流游戏-P1-真实经济循环引擎-v1.md》（下称《循环引擎》）。
> 实现以本文件为唯一事实来源。

## 1. 设计目标

财商流房间里有 10–12 个由**不同 LLM 驱动**的模型玩家（§12 座扩容），每个都有
独立职业卡人设、性格标签与财务处境——这本身就是一座现成的「AI 焦点小组」。
本系统把这座小组开放给人类：

| 用途 | 示例问题 | 预测价值 |
|------|---------|---------|
| **产品定价接受度调研** | 「奶茶涨 20% 你还买吗？」「月薪多少你愿意为知识付费年卡买单？」| 不同模型/人设的价格敏感度分布 |
| **政策民意** | 「央行降息你会加杠杆买房还是存钱？」「延迟退休你支持吗？」| 政策传导的微观预期 |
| **选举/倾向模拟** | 「高福利高税收 vs 低福利低税收，你投哪边？」| 价值观光谱分布 |

三个设计硬点：

1. **零额外 LLM 成本**：bot 回答调研**不发起任何额外 LLM 调用**——问题注入
   每月决策上下文（GameContext），`answer_survey` 是决策循环内的一个普通工具
   （§4.2），聚合是纯 Go 代码。一次调研的全链路成本 = 12 个 bot 本来就要做的
   月度决策，边际成本为零。
2. **答案有理由**：每个 bot 必须附 ≤50 字理由，聚合时摘录 Top 3——分布数字
   之外保留「人味」，供前端与研究者阅读。
3. **引擎纯状态**：调研生命周期全部在 `World.Surveys`（纯引擎无锁状态），
   广播/持久化由房间层钩子完成（§92a 锁纪律）。

与《循环引擎》的关系：调研问题的「经济环境」背景由循环引擎注入（CPI/失业率/
待答调研同段渲染，见《循环引擎》§7.2/§7.3）；`answer_survey` 工具与
`set_consumption`/`query_economy` 同批接入 ToolRunner。

## 2. 数据结构（新文件 `survey.go`，契约）

```go
// Survey 单次调研(引擎纯状态,挂 World.Surveys;JSON 由 view 层 SurveyJSON 映射)。
type Survey struct {
    ID           string                   // "SV1"…(World.SurveySeq 自增)
    Question     string                   // 问题文本(≤100 rune,发起时截断)
    Options      []string                 // 2-6 个选项(每个 ≤40 rune)
    LaunchMonth  int                      // 发起月(w.Month)
    DeadlineMonth int                     // LaunchMonth + 2
    Status       string                   // "open" | "closed"
    Answers      map[int]*SurveyAnswer    // seat → 回答(1 seat 1 答)
    Result       *SurveyResult            // closed 时聚合填充
}

// SurveyAnswer 单座位回答。
type SurveyAnswer struct {
    Seat      int    // 回答者座位
    OptionIdx int    // 选项下标 0-based
    Reason    string // ≤50 rune(写入时截断)
    ModelKey  string // 回答者模型 key(按模型切片分析用)
}

// SurveyResult 聚合结果。
type SurveyResult struct {
    Counts     []int     // len == len(Options)
    Percents   []float64 // Counts/Total(和≈1)
    Total      int       // 回答总数
    TopReasons []string  // 去重后前 3 条理由摘录(每条 ≤30 rune)
}

// World 新增字段(engine.go World 结构体追加):
//   Surveys    []*Survey // 全房调研(≤20,按发起序)
//   SurveySeq  int       // id 自增序列
```

状态常量：`SurveyOpen = "open"` / `SurveyClosed = "closed"`。

## 3. 发起（HTTP API + 限流）

### 3.1 端点（`router/router.go:238-243` wealth 组追加）

| 端点 | 方法 | 说明 |
|------|------|------|
| `/api/games/wealth/rooms/:id/survey` | POST（需登录）| 发起调研。body `{question: string, options: []string}`；返回 `{survey: SurveyJSON}` |
| `/api/games/wealth/rooms/:id/surveys` | GET（需登录）| 返回 `{surveys: [SurveyJSON]}`（全部历史，≤20）|

实现落在 `api/wealth_api.go`（或新建 `api/wealth_survey_api.go`）：构造注入
房间源接口 `interface{ Get(roomID string) *wealth.WealthRoom }`（ws 层把
`*wealth.Manager` 适配传入，同 `professionAPI` 装配模式）。房间不存在 → 35001。

### 3.2 发起规则（任意登录用户；观战者优先场景）

- **权限**：任意登录用户（在座玩家/观战者/房外用户均可）——调研是「向 AI 提问」，
  与座位无关。
- **校验**：`question` 非空（≤100 rune，超出截断）；`options` 2–6 个且非空
  （每个 ≤40 rune 截断）→ 违反 35016。
- **限流**（三层，房间级）：
  1. 每房同时仅 1 个 `open` → 违反 35017；
  2. 每月（`w.Month`）仅可发起 1 个新调研（扫描 `Surveys[].LaunchMonth`）→ 违反 35018；
  3. 每房累计 ≤20 个（`len(Surveys) >= 20`）→ 违反 35018（复用上限码，message 区分）。
- **开关**：`cfg.Wealth.SurveyEnabled == false` → 发起返回 35010（ErrWealthGateFailed，
  message「调研系统未启用」）；已 open 的调研照常走完关闭流程。
- **时机**：仅 `Status == StatusPlaying` 可发起（35002）。

func (r *WealthRoom) LaunchSurvey(question string, options []string) (*Survey, *errcode.Error)

// ListSurveys 返回全部调研快照(持 r.mu 拷贝)。

## 4. 回答与聚合

### 4.1 注入（`agent_runner.go` BuildContextForAgent，`agent_runner.go:412-547`）

在现有 GameContext 填充尾部追加：遍历 `w.Surveys` 找唯一 `open`（限流保证至多 1 个），
填 `OpenSurveyID/OpenSurveyQuestion/OpenSurveyOptions`（无则空串/nil）。bot 的月度
决策 prompt 因此「顺带看见」调研（《循环引擎》§7.3「■ 经济环境」段渲染）。

### 4.2 Agent 工具 `answer_survey`（不耗动作预算）

```go
// wealthplayer/tools.go 常量:
ToolAnswerSurvey = "answer_survey"

// BuildTools 定义(python 无关,JSON schema):
//   survey_id:    string  required  "调研 id,如 SV1(见经济环境段)"
//   option_index: integer required  minimum 0 "选项下标(0 起,对应经济环境段列表)"
//   reason:       string  optional  maxLength 50 "≤50 字理由"

// ToolRunner 接口追加(tools.go:18-45):
AnswerSurvey(seat int, surveyID string, optionIdx int, reason string) error

// agent_runner.go 实现(锁纪律照 QueryMinsky):
func (a *AgentRunner) AnswerSurvey(seat int, surveyID string, optionIdx int, reason string) error {
    // 持 r.mu:① 校验 survey 存在且 open 且本人未答且 OptionIdx ∈ [0, len(Options))
    //   → 违反任一:errcode.Code(ErrWealthSurveyNotFound 35019)/35016
    // ② 写入 Answers[seat] = &SurveyAnswer{...}(reason 截 50 rune)
    // ③ 若全部存活 bot 已答 → 立即 closeAndAggregate(§4.3),取出 closed survey
    // 解锁后:若 ③ 触发,锁外调 a.room.hooks.OnSurvey(roomID, sv)
}
```

- 仅 **alive 且 IsBot** 座位可答（人类座位的作答入口为 P2 扩展，见 §11）。
- 回答写入后当月即固定，不可修改（再次调用 → 35019「已回答」）。

### 4.3 关闭与聚合（引擎方法）

```go
// CloseAndAggregate 关闭调研并聚合结果(survey.go;调用方持房间锁)。
// 顶层入口 2 个:
//   ① World.CloseSurveyIfDue()(SettleMonth ⑤ w.Month++ 后逐个检查:
//      w.Month > sv.DeadlineMonth 的 open → 关闭)
//   ② AgentRunner.AnswerSurvey 全员已答提前关闭(§4.2)
// 关闭动作:Status="closed" → 填 Result → emitEvent("survey", -1,
//   "调研『<question>』结果:选项A xx%/选项B yy%(共 n 人)")。
func (w *World) CloseAndAggregate(sv *Survey)
```

聚合规则（纯 Go，无随机）：

```
Total   = len(Answers)
Counts  = 按选项下标计数
Percents= Counts[i] ÷ max(1, Total)
TopReasons = 全部 Reason 按提交顺序去重(精确匹配) → 取前 3 条,
             每条截 30 rune 前缀 + "…"(不足则原样)
```

### 4.4 广播（`room.go` BroadcastHooks 追加 + ws 层）

```go
// BroadcastHooks(room.go:38-45)追加(锁外调用,§92a 纪律):
OnSurvey func(roomID string, sv *Survey) // game.survey_result

// ws 层装配(game_service_wealth.go):OnSurvey → 构造 SurveyJSON →
s.hub.BroadcastRoomIncludingSpectators(roomID,
    wsEnvelope("game.survey_result", 0, map[string]any{
        "room_id": roomID,
        "survey":  surveyJSON(sv),   // §5.1 结构
    }))
```

时序来源两处，均由房间层在**锁外**触发钩子：
- `SettleResult` 追加 `ClosedSurveys []*Survey`（`SettleMonth` ⑤ 填充），
  房间结算路径锁外逐个调 `hooks.OnSurvey`；
- `AgentRunner.AnswerSurvey` 提前关闭路径（§4.2 ③）。

`emitEvent("survey", …)` 产生的事件照常走既有 `OnEvent` 增量下发
（`room.go:89` eventsSent 机制），前端事件流自动可见。

## 5. 视图与协议

### 5.1 `ClientGameState.Surveys`（`view.go`）

《循环引擎》§6.1 已声明 `Surveys []SurveyJSON` 字段，本节定义其结构：

```go
// SurveyJSON game.state.surveys 单项(view 层映射)。
// 下发范围:所有 open(≤1) + 最近 4 个 closed(含 Result),按时间倒序。
type SurveyJSON struct {
    ID            string            `json:"id"`
    Question      string            `json:"question"`
    Options       []string          `json:"options"`
    LaunchMonth   int               `json:"launch_month"`
    DeadlineMonth int               `json:"deadline_month"`
    Status        string            `json:"status"` // open|closed
    AnswersCount  int               `json:"answers_count"`
    Result        *SurveyResultJSON `json:"result,omitempty"` // closed 时非空
}

// SurveyResultJSON 聚合结果(选项文本一并下发,前端免查表)。
type SurveyResultJSON struct {
    Options     []string  `json:"options"`
    Counts      []int     `json:"counts"`
    Percents    []float64 `json:"percents"`
    Total       int       `json:"total"`
    TopReasons  []string  `json:"top_reasons"`
}
```

> 下发不包含 `Answers` 明细（座位/模型归属不进公开快照；`ModelKey` 留在引擎内
> 供 P2「按模型切片」分析）。空态初始化为 `[]`（P0-bugfix 纪律）。

### 5.2 S→C 帧总表追加（协议契约文档 §2 同步）

| 帧 | 触发 | 载荷 |
|----|------|------|
| `game.survey_result` | 调研关闭（deadline / 全员已答）| `{room_id, survey: SurveyJSON}` |

`game.state` 全量快照每次重连/刷新自动携带 `surveys`（无需额外帧）。

### 5.3 错误码（与《循环引擎》§6.4 共用声明）

| 码 | 常量 | 语义 |
|----|------|------|
| 35016 | `ErrWealthSurveyOptionsInvalid` | 选项数非 2–6 / 选项文本空 / 作答 option_index 越界 |
| 35017 | `ErrWealthSurveyOpenExists` | 已有进行中调研 |
| 35018 | `ErrWealthSurveyMonthlyLimit` | 本月已达发起上限 / 累计 20 个上限 |
| 35019 | `ErrWealthSurveyNotFound` | 调研不存在 / 已关闭 / 本人已回答 |
| 35020 | `ErrWealthConsumptionLevelInvalid` | （循环引擎消费档位）|

### 5.4 配置

`cfg.Wealth.SurveyEnabled`（json `survey_enabled`，默认 true）——接线与回退语义见
《循环引擎》§6.5；本系统无独立的引擎级开关回退（关闭仅影响发起入口）。

## 9. 测试验收

### 9.1 `survey_test.go`

- 发起校验：options 1 个/7 个 → 35016；question 空 → 35016。
- 限流：第 2 个并发 open → 35017；同月第 2 次（第 1 个已关）→ 35018；
  第 21 个 → 35018。
- 回答聚合：3 答（A/B/A）→ Counts=[2,1]、Percents≈[0.667,0.333]、Total=3；
  重复回答 → 35019；option_index 越界 → 35016；关闭后回答 → 35019。
- deadline 关闭：LaunchMonth=5 → DeadlineMonth=7；月结推进到 8 时 `CloseSurveyIfDue`
  关闭并填 Result；`SettleResult.ClosedSurveys` 携带该调研。
- 全员已答提前关闭：存活 bot 全答 → 立即 closed（不等 deadline）。
- TopReasons：重复理由去重；超 3 条取前 3；单条截 30 rune。
- `survey_enabled=false`：LaunchSurvey → 35010；既有 open 照常关闭。

### 9.2 集成与门禁

- `BuildContextForAgent`：open 时注入 id/question/options；closed 后为空。
- 端到端：HTTP 发起 → bot 决策循环产出 `answer_survey` tool_use → 聚合 →
  `game.survey_result` 帧到达（integration-tester，10 bot 房间实测 1 次）。
- 门禁：`go build -o LsmAgentGame main.go` + `go test ./...` +
  前端 `tsc --noEmit` + `npm run build` 全过。

## 11. 设计取舍

1. **零额外 LLM 成本**：不单独触发「调研专用对话」——问题随月度决策上下文下发，
   回答是决策循环内的 tool_use。12 bot × 额外一轮 = 每调研多 12 次 LLM 调用的
   方案被否：月窗口（默认 8s）与并发信号量（8）都装不下，且成本随调研数线性涨。
   代价：bot 至多在下一个月结窗口内作答（deadline=launch+2 覆盖 3 个窗口，
   冗余 2 个防个别 bot 被 watchdog 强制 submit 跳过）。
2. **deadline = launch+2**：发起月当月 + 2 个完整月。太短（+0）会撞上「本月已
   submit 的 bot 无机会作答」；太长（+5）让人类等得无聊。3 个窗口是「全员必答」
   与「即时反馈」的折中，且提前关闭机制（全员已答）让快房间不空等。
3. **每月 1 个新发起**：调研要「新鲜」——同月连环问 5 个会把 bot 的决策上下文
   挤成问卷填写现场，破坏游戏主循环的财商决策质量。
4. **人类在座玩家不能作答（P1）**：调研对象是 AI（预测模拟场景），混入人类答案
   会污染「模型观点分布」的口径；P2 可加 `game.wealth_action {type:"answer_survey"}`
   与座位标记（answer 带 `is_bot`）再放开。
5. **Answers 明细不下发**：公开快照只给聚合——防「谁投什么」成为房内社交压力
   （匿名投票原理）；`ModelKey` 留在引擎侧，P2 做按模型切片时不破坏协议。
6. **限流用扫描不用计数器**：`len(Surveys) ≤ 20`、逐月扫 `LaunchMonth`——
   O(20) 的扫描换来零新增状态字段，重启恢复零成本（§130 接线纪律：少一个字段
   少一处「声明了却从不接线」）。
