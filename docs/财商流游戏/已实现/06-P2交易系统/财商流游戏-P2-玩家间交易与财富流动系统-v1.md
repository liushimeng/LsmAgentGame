## 1. 设计目标：打通真实财富循环流

### 1.1 现状缺口

P0/P1 已完成的引擎：
- ✅ 央行货币政策（M0/M1/M2、LPR 重定价）
- ✅ 明斯基三阶段（对冲→投机→庞氏）
- ✅ 真实经济循环（消费品八大类 → 内生 CPI → 劳动力市场 → 工资 Phillips 曲线）
- ✅ 社会调研系统（Agent 作答 → 聚合预测）

**仍缺失的真实经济核心**——**玩家间直接财富流动**：

| 缺口 | 真实世界对应 | 教育价值 |
|------|-------------|---------|
| ❌ 玩家间不能直接交易资产 | 二手房/二手车/二手商品市场 | 价格发现、议价能力 |
| ❌ 玩家间不能借贷 | 亲友借贷、民间金融 | 信用风险、担保责任 |
| ❌ 信息完全对称 | 信息不对称是利润来源 | 信息价值、尽调能力 |
| ❌ 无拍卖机制 | 艺术品/法拍/股权拍卖 | 赢家诅咒、估值能力 |
| ❌ 无企业股权交易 | 一级/二级市场 | 股权稀释、退出机制 |

### 1.2 循环链路（每月闭合一次）

```
玩家 A 发起出售挂牌 ──▶ 挂单簿(ListingBook)
                            │
玩家 B 发起购买/还价 ──▶ 议价协商(Negotiate)
                            │
达成一致 ──▶ 资金+资产过户 ──▶ Ledger 双式记录
                            │
                    ┌───────┴───────┐
                    ▼               ▼
              玩家间借贷       拍卖市场
              (利息流动)      (价格发现)
                    │               │
                    └───────┬───────┘
                            ▼
                    社会结构演化
               (基尼系数/财富集中度)
```

### 3.1 挂牌与订单

```go
// ListingType 挂牌类型。
type ListingType string
const (
    ListingAsset   ListingType = "asset"   // 资产出售

    ListingInfo    ListingType = "info"    // 信息出售

    ListingLoanReq ListingType = "loan_req" // 借款请求

// Listing 单笔挂单(挂单簿条目)。
type Listing struct {
    ID         string      // "LF1"(挂出)/"LB1"(收购)
    Type       ListingType
    Seat       int         // 发起座位
    Payload    ListingPayload // 挂单内容(资产/借贷/信息)
    AskCNY     int64       // 要价(资产/信息);借贷=0
    Status     string      // open|negotiating|deal|expired|cancelled

    ExpireMonth int        // 过期月份(创建月+3)

// ListingPayload 挂单内容联合。

    Loan        *LoanPayload        // 借贷类
    InfoOffer   *InfoOfferPayload   // 信息类

    Asset       Asset  // 资产快照

}

// LoanPayload 借贷挂单详情。
type LoanPayload struct {
    Direction   string // lend|borrow
    PrincipalCNY int64 // 金额
    MaxRate     float64 // 最高可接受利率(借入)/最低(贷出)
    TermN       int     // 期数(月)

}

## 4. 四种拍卖机制规格

### 4.1 英式公开叫价（English Auction）—— 房产交易

**触发**：季度交易窗口 T2，玩家挂牌房产且 ≥ 2 名玩家表示购买意向。

**流程**：
1. Agent 公布评估基准价 = 房产原价 × 当期周期价格系数 × 折旧系数
2. 起拍价 = 评估基准价 × 80%
3. 从挂牌者左手边玩家开始，顺时针轮流加价
4. 连续一轮无人加价时，最高价者得
5. 挂牌者保留权：若最高价 < 评估基准价 × 90%，挂牌者可拒绝出售（流拍）

**数值约束**：

| 参数 | 取值 |
|------|------|
| 起拍价折扣 | 评估价 × 80% |
| 流拍保护线 | 评估价 × 90% |
| 最小加价 | 住宅 10,000 / 商业 50,000 |
| 最大轮次 | 8 轮 |
| 时间盒 | 90 秒 |

### 4.2 密封暗标（Sealed Bid Auction）—— 信息/企业股权

**触发**：自由圈中，某玩家的企业/信息被 ≥ 2 名玩家提出购买意向。

**流程**：
1. Agent 公布标的信息（公开信息，不公布底价）
2. 所有意向买家在 60 秒内同时提交密封报价
3. Agent 开标：最高价者得
4. 平局处理：出价相同则「人脉值高者得」
5. 卖方保留权：最高价 < 估值下限时可拒绝

**数值约束**：

| 参数 | 取值 |
|------|------|
| 报价精度 | 10,000 元整数倍 |
| 估值下限 | 净资产 × 1.0 |
| 时间盒 | 60 秒 |

### 4.3 一口价 + 单次还价（Take-It-or-Leave-It）—— 副业转让

**触发**：副业项目转让。

**流程**：
1. 卖方设固定价 + 底价（保密）
2. 买方选择「接受」或「还价一次」
3. 卖方选择「接受还价」或「拒绝」
4. 一轮定成败

### 4.4 一轮竞价（Single-Round Bid）—— 大宗股票

**触发**：季度交易窗口，大宗股票（≥ 100 手）。

**流程**：
1. 公布基准价（当期股价轨道）
2. 所有买家同时出价 + 数量
3. 按价格优先、数量优先分配

```

### 6.2 利率约束

| 约束 | 规则 |
|------|------|
| 利率下限 | 0.3%/月（年化 3.6%，相当于存款利率） |
| 利率上限 | 3.6%/月（年化 43.2%，法定民间借贷上限） |
| 信用分影响 | 每 50 分差异 ±0.2%/月 |
| 担保影响 | 有担保 −0.3%/月 |

### 6.3 月结处理

借贷合约在月结时处理：
- 借款人月供 = Principal × rate × (1+rate)^TermN / ((1+rate)^TermN - 1)
- 逾期判定：现金不足支付月供 → Overdue=true
- 逾期后果：罚息 5%、信用分 −50、连续 3 月逾期 → 担保人代偿

### 6.4 担保机制

```go
// AddGuarantor 为借贷添加担保人。
func (w *World) AddGuarantor(loanID string, guarantorSeat int) *errcode.Error
```

担保人责任：借款人连续 3 月逾期 → 担保人代偿（Balance 从担保人现金扣除）
担保人权利：代偿后取得对借款人的追偿权（系统记录为担保人对借款人的债权）

## 12. 社会结构联动

### 12.1 财富集中度指标

交易系统上线后，社会结构统计新增：

| 指标 | 计算 | 展示 |
|------|------|------|
| 财富基尼系数 | 净资产分布 | Society.WealthGini |
| 交易活跃度 | 月均成交笔数 | Society.TradeVolumeTop1Pct |

| 信息不对称指数 | 信息交易均价 | Society.InfoAsymmetryIdx |

### 12.2 宏观反馈

- 交易活跃 → 市场流动性溢价 → 资产价格上升
- 借贷扩张 → 信用风险累积 → 明斯基时刻触发概率上升
- 信息交易活跃 → 市场效率提升 → 价格发现加速
