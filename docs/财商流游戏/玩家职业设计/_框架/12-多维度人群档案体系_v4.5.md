## 1. 为什么需要多维度

财商流游戏是 **全 Agent 真实世界模拟**（CLAUDE.md §14），需要的人群样本**远超**「26 个行业域 × 职业族」能覆盖的范围：

| 真实世界人群 | 行业维度能否覆盖 | v4.5 归属维度 |
|---|---|---|
| 普通本科生（兼职家教） | ❌ 无「学生」职业族 | **维度②身份与就业状态** |
| 退休中学教师 | ⚠️ 行业有但身份已变 | **维度②**（行业仍记为 T） |
| 全职太太（照料孩子） | ❌ 不算就业 | **维度②** |
| 失业/待业/零工青年 | ❌ 无职业族 | **维度②** |
| 灵活就业 / 平台零工 | ⚠️ 局部有 | **维度②** |
| 连续创业者 | ⚠️ 多行业混杂 | **维度②** |
| 高净值人群 / FIRE / 收租者 | ❌ 不在职 | **维度③财富阶层** |
| 高负债 / 失信被执行 | ❌ 无行业身份 | **维度③** |
| 拆迁暴富户 / 遗产继承者 | ❌ | **维度③** |
| 啃老族 / 三和大神 | ❌ | **维度② + ③** |
| 残障人士就业 / 重病回归社会 | ⚠️ | **维度④家庭生活** |
| 留守儿童家庭（隔代抚养） | ❌ | **维度④** |
| 单亲妈妈 / 丧偶独抚 | ❌ | **维度④** |
| 赌徒 / 投机暴富暴跌 | ❌ | **维度⑤财商观念** |
| 数字游民 / 跨境投资人 | ⚠️ | **维度⑥调研驱动真实样本** |

## 3. 路径形态

五段式 + 叶段，与 v4.4 行业树**完全一致**：

```
<维度根>/<维度L2>-<细分名>/<维度L3>-<人群族名>/<L4地区档>/<L5年龄段>/<编号>-<姓名>.md
```

**L4 地区档**——v4.5 维度卡的新约定：原 v4.4 行业卡 L4 = 籍贯档；
维度卡 L4 = **现居地区档**（`l4_basis: residence`），使「跨省流动人口」这一真实财富
现象在路径上可见。字段 `migration_status` ∈ `{本地人, 省内流动, 跨省流动, 海外流动}`。

**L5 年龄段**——严格使用 `16-24 / 25-34 / 35-44 / 45-54 / 55-64 / 65+ / XX-未知`，
**禁止** `65` 这种截断（`_seg('65+')` 会丢 `+`）。

**示例**：

```
维度2-身份与就业状态/DIM2-01-在校学生与应届毕业生/DIM2-0101-在校本专科生/CN-E-华东/16-24/N9020000-邓礼恭.md
维度3-财富阶层与资产负债/DIM3-04-高净值与FIRE/DIM3-0401-企业主阶层/CN-S-华南/45-54/N9025000-陈砚青.md
```

## 4. frontmatter Schema v1.1（增量）

维度卡继承 v4.4 全部 65 字段 + 5 个新增维度字段族：

```yaml
# ── 维度归属（v4.5 新增）──
dimension: DIM2                # 维度代码
dimension_name: 身份与就业状态  # 维度中文名
dim_l2: DIM2-01                # 维度 L2 码
dim_l2_name: 在校学生与应届毕业生
dim_l3: DIM2-0101              # 维度 L3 码
dim_l3_name: 在校本专科生
dim_tag: 在校本专科生           # 人群标签

# ── 收入语义（v4.5 新增；统一解决父类把无业学生填成零的问题）──
income_semantics: 月度可支配现金流入（含工资/经营/财产/转移性收入）
income_composition:            # 必须>0；组成=各项 share 之和=1
- {source: 家庭转移支付, share: 0.50}
- {source: 兼职零工,     share: 0.35}
- {source: 奖助学金,     share: 0.15}

# ── 地理一致性（v4.5 新增）──
housing_province: 湖北
migration_status: 跨省流动     # 本地人 / 省内流动 / 跨省流动 / 海外流动
l4_basis: residence

# ── 维度溯源章（不与 v4.4 _enrich_v44 重名）──
source_kind: dimension_pool_v4.5
_gen_v45:
  ts: '2026-09-16T10:43:30+08:00'
  script: lib_dim_v45.py
  schema_version: '1.1'
  fields_holistic: [personality, behavior_traits, risk_preference, birth_family, life_story, opening_hook]
  method: pool_driven_derivation
```

**`industry_l1` 占位**：无行业归属人群置 `NA / NA00 / NA0000`，`occ_industry_num: '20'`
（v2.0 数字编号「20 = 学生/待业/退休/无业」）；有行业归属人群仍用原字母码 + 维度归属并列。

## 5. 加载器可玩性硬约束

`ServerGo/game/wealth/profession/loader.go` 在 backend P0 修复后必须满足：
- `id` / `name` / `occupation` 非空；
- `income_monthly > 0`（语义 = 月度可支配现金流入，零者视为无效卡回退精选）；
- `opening_hook` ∈ [20, 60] rune（过长会被 loader 截断 + 「…」）；
- `health_grade ∈ {A, B, C}`；
- `risk_preference ∈ {conservative, balanced, aggressive}`;
- `personality` / `behavior_traits` 命中词库才保留，否则被过滤为空（属正常行为）；
- `debts` 中每条必含 `type / balance / monthly / source` 四键；
- `assets` 中每条含 `type / value_cny`。

维度卡**出生即满足**上述全部约束（`lib_dim_v45._coherence_fix` + `_self_check` 双重保证）。

## 7. 命名与去重

- **化名**：取自 `work/v45/names_<dim>.txt`（由 `alloc_names_v45.py` 预生成），
  格式 `<化名>\t<性别>`，**禁止**在生成器内自行随机取名（会破坏全局唯一性）。
- **卡号**：各维度独占区间，`_new_id()` 在约束通过前不递增，重试**不浪费号段**。
- **唯一性三重校验**：生成批次写盘后 `_self_check` 内 `yaml.safe_load` 必须无错，
  且每张卡的 `id` / `name` 在维度内 + 与既有 75k 库**全局唯一**。

## 9. 与现有 75k 库的兼容

1. **零冲突**：所有维度卡的 `id` 在 `N9020000–N9049999` 区间内递增，与既有 `N0000001–N9019999` 零重叠；化名取自预分配块，与既有 75k 零碰撞（`alloc_names_v45.py` 校验）。
2. **loader 即插即用**：维度目录**无 `_` 前缀**，文档池索引阶段全量 walk 收录，`Draw(MaxSeats=12, rng)` 抽卡可均匀抽到任意维度的卡。
3. **schema_version**: 维度卡 `schema_version: '1.1'`（与既有 75k 卡的 `1.0` 并存，后端 loader 容错）。
4. **字段双轨**：v4.4 旧卡保留 `legacy_name` 在 `_raw.legacy_name`；维度卡的维度归属单独成一族，避免与旧字段重名。
