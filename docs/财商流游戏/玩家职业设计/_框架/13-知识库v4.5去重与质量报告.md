## 2. 修复过程

### 2.1 A. 化名去重（`repair_dup_names_v45.py`）

**原理**：
1. 扫描全库人物卡，按文件名化名段分组。
2. 每组按 `card_id` 升序，保留最小 ID 卡不变。
3. 其余卡片从 `work/v45/names_repair.txt` 按性别取名（repair 块 1200 个化名，与既有 75k 零碰撞）。
4. 执行：文件重命名 + frontmatter `name:` 更新 + `_raw.legacy_name` 追加（追溯旧名）。

**运行命令**：

```bash
# dry run（只扫描报告）
python3 scripts/财商流游戏知识库/repair_dup_names_v45.py --dry

# 执行修复
python3 scripts/财商流游戏知识库/repair_dup_names_v45.py
```

**关键日志**：

```
[scan] 总人物卡: 75115
[scan] 重名组: 355, 涉及卡: 725, 需改名: 370
[load] repair 化名池: 男 614, 女 586
[fix] N9012662-丁国.md → N9012662-熊浩建.md (name: 丁国→熊浩建, legacy_name: 丁国)
[fix] N9012397-丁帆.md → N9012397-XXX (...)
...
[done] 改名 370 张，错误 0 个
[verify] 修复后重名组扫描...
[verify] 剩余重名组: 0
```

**耗时**：~3 秒（扫描 + 370 次重命名写盘）。

**化名分配**：
- 需要改名 370 张（男 181 / 女 189）
- repair 块提供 1200 化名（男 614 / 女 586），剩余 830 未使用

### 2.2 B. YAML 重复键修复（`repair_dup_yaml_keys_v45.py`）

**原理**：
1. 用 `grep -rc` 快速定位含 2+ 行 `  legacy_name:` 的文件（避免扫描全库 75k）。
2. 逐文件在字符串层面精确修复：保留最后一个 `legacy_name` 行，删除前面的。
3. 修复后用 `yaml.safe_load` 校验 + `legacy_name` 数量验证。
4. **禁止** yaml.safe_load → dump 重排（保护既有格式与字段顺序）。

**运行命令**：

```bash
# dry run
python3 scripts/财商流游戏知识库/repair_dup_yaml_keys_v45.py --dry

# 执行修复
python3 scripts/财商流游戏知识库/repair_dup_yaml_keys_v45.py
```

**关键日志**：

```
[phase1] grep 定位含重复 legacy_name 的文件...
[phase1] 目标文件: 8895
[fix] N19220-刘萍彤.md 删除 1 个重复键 {'legacy_name': 1}
...
[done] 修复文件: 1169, 删除重复键行: 1169, 错误: 0
[summary] 按 key: {'legacy_name': 1169}
```

**注意**：实测仅 1,169 个文件需要删除多余行（与任务预估的 13,323 差异见 §4）。

**耗时**：~11 秒（grep 0.3s + 逐文件解析写盘）。

## 4. 遗留风险与说明

### 4.1 任务预估 vs 实际修复数量差异

| 指标 | 任务预估 | 实际修复 | 差异说明 |
|------|---------|---------|---------|
| 含重复 YAML 键文件 | 13,323 | **1,169** | 任务预估可能基于 `_enrich_v44` 块内所有子键的重复检测（含 `ts`、`script`、`schema_version` 等不缩进子键被误识别为块内键）。实测真正需要删除的多余 `legacy_name` 行为 1,169 行（每文件恰好 1 行重复）。 |
| 同名重名卡 | 755 张（v4.3+） | **725 张**（全部重名） | 任务描述的 755 可能仅计 v4.3+ 新增卡；实测全部重名涉及 725 张卡（355 组），已全部修复。 |

### 4.2 已确认无风险

- `_enrich_v44` 块内 **仅有 `legacy_name` 一种重复键**（`grep` 全库验证）。
- `legacy_name` 值保留策略（保留最后一个）正确：v4.4 enrich 阶段最新写入的即为最终值。
- 字符串级修复 **未破坏** 字段顺序、缩进、注释。
- 修复后全部文件 `yaml.safe_load` 校验通过。

### 4.3 下一批 v4.5+ 任务建议

1. **`_legacy_ids` / `legacy_name` 历史残留**：verify_dim_v45.py 可能仍报告这些为 issues。需确认是否纳入后续清理。
2. **维度卡化名块剩余 830 个**：未使用的 repair 块化名可回收或保留供后续富化补卡。
3. **v4.3+ 新增卡（~2,800 张）的 `src_line` 一致性**：可在后续批次中统一校验。
