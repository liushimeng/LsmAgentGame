# 财商流游戏 · 玩家职业设计目录结构与分片规约

## 2. 路径五段定义

| 层 | 名称 | 取值来源 | 基数 |
|---|------|----------|------|
| **L1** | 行业域 | `03-行业分类体系-ICG.md` §2，单字母 `A`–`Z` | 26 |
| **L2** | 行业细分 | 同文档，`<L1><2位>` | 239（已用） |
| **L3** | 职业族 | 同文档，`<L2><2位>` | 2,224 |
| **L4** | 地区档 | `CN-N-华北` / `CN-NE-东北` / `CN-E-华东` / `CN-C-华中` / `CN-S-华南` / `CN-SW-西南` / `CN-NW-西北` / `OV-海外` / `XX-未知` | 9 |
| **L5** | 年龄段 | `16-24` / `25-34` / `35-44` / `45-54` / `55-64` / `65+` / `XX-未知` | 7 |
| **叶** | 人物卡 | `<编号>-<姓名>.md` | 1 人 |

**完整示例**

```
O-住宿与餐饮/O01-餐饮门店经营/O0101-餐厅店长/CN-S-华南/35-44/N1034000-陈砚青.md
```

### 2.1 路径段净化规则

目录段与文件名中的以下字符**必须**替换为 `_`，避免产生意外层级：

`/` `\` `:` `*` `?` `"` `<` `>` `|` 以及空白字符

> 例：L3 族名 `UI/UX设计` → 目录段 `P0701-UI_UX设计`。

## 5. 扩容路径（**核心不变式：路径前 5 段永不改变**）

规模增长时，**只切换叶子形态**，不动路径前缀。

| 规模 | 叶子形态 | 单目录文件数 | 切换动作 | 需改动 |
|------|----------|--------------|----------|--------|
| **十万级（当前）** | 一人一档 `N1034000-陈砚青.md` | 1–6 | — | — |
| **百万级** | 在 L5 下插入 **L6 分片目录** `S000`…`S999`，每片 ≤ 500 人 | 20–60 | 新增 L6 一层 | 分片号 = `floor(序号/500)` |
| **千万级** | L6 分片扩为 `S0000`…；或叶子改为**聚合档案** `S000-0001-0100.md`（每文件 ≤ 100 人） | 100–500 | 叶子由「人」改「人群」 | 聚合卡 `card_type: shard` |
| **数十亿级** | 目录树降级为**索引层**；全量数据入 GORM 表 `t_lsm_game_person_card`，目录树由生成器按需导出切片 | 索引层不承载全量 | 数据入库 + 按需导出 | 新增导出台账 |

### 5.1 每级扩容的具体做法

**百万级**
```
…/CN-E-华东/45-54/S000/N1026362-栗景虞.md
                    ↑ 新增分片层
```

**千万级（聚合档案）**
```
…/CN-E-华东/45-54/S000-0001-0100.md     ← 单文件含 100 人（10 张 8 列总览表 + 或折叠正文）
```
聚合档案的 YAML `card_type: shard`，`id` 形如 `SHARD-CN-E-华东-45-54-0000`，
每人在文件内的 `## 人物 <编号>` 小节中保留完整 59 字段。

**数十亿级**
引入数据库为唯一事实来源：

```
t_lsm_game_person_card(
  card_id, name, l1, l2, l3, region, age_band, ... 59 列,
  source_file, legacy_ids, completeness, grounded
)
```

目录树退化为**浏览/导出视图**：需要落盘时按 L1→L5 逐级导出，
每次只导出被请求的分片，磁盘上不存在「全量 65 亿个文件」这一形态。

> **为什么不能纯目录承载十亿级**：任何文件系统都撑不住十亿个 inode，
> 且 git 仓库会因 blob 数量爆炸而不可用。因此方案在千万级即切换到
> 「数据库为源 + 目录为视图」，这是唯一可扩展的形态。

## 6. 硬约束

1. **路径深度**：早期落地固定 5 段目录 + 1 个文件；进入百万级后为 6 段 + 1 文件。
2. **段名合法**：所有段必须通过 §2.1 净化规则，且命中 §2 的码表。
3. **编码**：全部 UTF-8 **无 BOM**。
4. **单文件行数**：人物卡 ≤ 1,800 行（CLAUDE.md §4）。
5. **框架文档**：`_框架/**` 除本规约外均为生成物，**不得手工编辑**；
   修改分类或字段请改 `scripts/财商流游戏知识库/` 下源码后重跑。
6. **追加而非改写**：新批次只能**新增** L1/L2/L3（在码表末尾续号），
   不得复用已废弃的码。
