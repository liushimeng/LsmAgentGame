## 3. 与行业维度（L1–L5）的关系

行业维度是**主索引**（每张人物卡有唯一 L1/L2/L3 路径），D2–D7 是**切片视图**。
设计上**不重复存储**：D2–D7 由现有 59 字段派生，无需为人物卡新增字段。

派生规则：

| 维度 | 派生字段 | 派生规则 |
|---|---|---|
| D2 收入阶层 | `income_monthly` / `household_monthly` / `net_worth` | 见 `D2-收入阶层与资产画像.md` §2 |
| D3 家庭结构 | `household_type` / `children_count` / `marital` | 见 `D3-家庭结构与抚养压力.md` §2 |
| D4 人生阶段 | `age` / `career_stage` | 见 `D4-人生阶段与生命周期目标.md` §2 |
| D5 职业风险类型 | `work_intensity.risk` / `health_risks` / `occupation` | 见 `D5-职业风险类型与健康压力.md` §2 |
| D6 资产形态 | `housing_tenure` / `assets[]` / `net_worth` | 见 `D6-资产形态与财商工具适配.md` §2 |
| D7 地理流动 | `birth_province` / `housing_city` / `housing_tenure` | 见 `D7-地理流动与社保连续性.md` §2 |

## 4. 维护规约

1. **本目录下的索引文件是生成物**：由 `scripts/财商流游戏知识库/gen_dimensions.py`（v4.3 新增）读取人物卡 frontmatter 派生。
2. **不在人物卡新增维度字段**：D2–D7 必须从现有 59 字段派生；如需新字段则升 `schema_version`。
3. **索引与卡池同步**：每次卡池更新后，必须重跑 `gen_dimensions.py`，否则索引数字会与实际偏离。
4. **CLAUDE.md §4 单文件 ≤ 1800 行**：每个维度索引文件 ≤ 1800 行，超出按"细分阶层"拆分为多个分册。

## 6. 使用场景

| 单人模式开局 | D4（生命周期）× D2（收入阶层） |
