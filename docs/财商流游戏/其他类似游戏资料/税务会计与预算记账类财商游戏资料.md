## A. 税务/会计主题桌游与教具

### A1. Tax Master（税务大师）

- **发行方**：IEEE Xplore 学术论文配套项目（2024）
- **年份**：2024
- **目标人群**：青少年及教师，提升"tax literacy"（税收素养）
- **① 完整流程**：玩家扮演纳税人，在多轮回合中完成收入申报、扣除选择、税款计算；每轮模拟一个纳税年度，最终比较税后净资产。
- **② 详细规则含数值**：采用真实数学运算与财务决策，将税法条文转化为卡牌效果；具体税率表参照当地现行税制。
- **③ 道具卡牌机制**：收入卡、扣除卡、稽查事件卡、优惠政策卡。
- **④ 棋盘设计**：传统棋盘 + 卡牌驱动，非固定路线。
- **⑤ 经济系统**：税后净资产为胜负标准，鼓励合法节税而非逃税。
- **⑥ 财商理念**：税收是公民义务，理解税制比逃避税更重要。
- **⑦ 对财商流游戏的可借鉴点**：将真实税法条文转化为可玩卡牌的设计方法论；"稽查事件"可作为游戏中的随机惩罚机制。

> 📌 **来源**：IEEE Xplore, "Tax Master: A Board Game to Enhance Tax Literacy", 2024. https://ieeexplore.ieee.org/document/10663196

### A3. 《税务风云：风险与红利》（民间设计师作品）

- **发行方**：个人设计师（微信公众号"进击的税务人生"）
- **年份**：2025（圣诞节发布完整版规则）
- **目标人群**：16 岁以上，有基础税务概念者
- **① 完整流程**：2-4 人卡牌策略游戏，6 回合制。每回合抽取事件牌（稽查/优惠），打出手牌应对，目标是 6 回合后企业健康度最高（初始 50 分）。
- **② 详细规则含数值**：资源牌 80 张（三类）、事件牌 30 张（两类）；稽查事件扣分，优惠事件加分；组合出牌可获得额外分数。
- **③ 道具卡牌机制**：资源牌分三类（⚠️ 公开资料未给出确切分类名称）；事件牌分稽查事件与优惠事件。
- **④ 棋盘设计**：纯卡牌，无棋盘。
- **⑤ 经济系统**：企业健康度积分制，非货币。
- **⑥ 财商理念**：税务合规是风险管理的一部分，优惠政策是合法红利。
- **⑦ 对财商流游戏的可借鉴点**：事件牌 + 手牌组合的机制可直接映射到财商流的"税务事件格"；6 回合制与财商流的"市场周期四阶段"节奏相近。

> 📌 **来源**：微信公众号"进击的税务人生", 《进击的税务人生（叁拾捌）——税务风云：风险与红利完整版规则》, 2025-12-26.

### A19. ERP 沙盘模拟中的财税模块视角

> **注**：现有知识库已覆盖 ERP 沙盘的经营视角，此处仅补充**财务/税务模块**的独特设计。

- **用友新道 / 金蝶 / SAP 教育沙盘**：
  - **财务报表编制**：每年经营结束必须编制损益表和资产负债表；报表不平或账实不符按 **20 分/次**罚分；晚交报表亦罚 20 分。
  - **企业所得税**：税率 25%；当上年所有者权益 < 初始值（如 66M）时，税金 =（上年权益 + 本年税前利润 - 初始权益）× 25%；当上年权益 > 初始值时，税金 = 本年税前利润 × 25%。
  - **业财税一体化**：金蝶 AI 星辰支持业务单据自动生成凭证，科目多维核算（最多 12 个辅助核算维度），覆盖采购、销售、库存、财务、税务全流程。
  - **智能财税实践教学平台**：新道科技的智能沙盘实训台 + 智慧税厅 VR 沉浸式平台，已在陕西能源职业技术学院等院校部署（中标金额 71.6 万元 + 53.45 万元）。

> 📌 **来源**：政府采购网中标公告; 沙盘模拟结算规则; 金蝶模拟软件产品文档.

### A20. 品类小结：税务/会计主题桌游的资料稀缺性评估

经多源检索（中英文关键词覆盖 "tax board game"、"accounting board game"、"bookkeeping game"、"Audit board game"、"CPA exam game"、"税商桌游"、"会计沙盘"、"记账桌游"），结论如下：

| 品类 | 产品数量 | 评估 |
|------|---------|------|
| 纯税务主题桌游 | 3 款（Tax Master / Mobility Era / 税务风云） | **稀少**，均为教育项目或小规模作品 |
| 会计教学桌游/教具 | 7+ 款（Liike / Ledger Mania / Putra Salamanis / Bank On It / Accounting Arcade / Lemons / 会计模拟器） | **较丰富**，但以数字化工具为主，实体桌游少 |
| 中国本土税商游戏 | 3 款（前海税商 / 郑州模拟创业路 / 河北税小店 / 宁波税收宝藏地图） | **均为税务机关普法活动**，非商业化产品 |
| ERP 沙盘财税模块 | 成熟（用友/金蝶/SAP） | **商业成熟**，但面向高校而非大众 |
| 税务/会计主题商业桌游 | **未检索到** | ⚠️ **该品类在商业桌游市场几乎空白** |

**关键发现**：税务/会计主题的**商业化桌游产品几乎不存在**。现有产品要么是教育机构的教具，要么是税务机关的普法活动，要么是数字化 App/网页游戏。这恰恰说明财商流游戏在"税务会计桌游化"方向具有显著的市场空白与创新机会。

## C. 真实世界的税务与会计知识底座

> ⚠️ 以下内容仅作游戏设计参考，不构成税务建议。政策文号与生效年份已标注，请以最新官方文件为准。

### C1. 复式记账法完整规则

#### 会计恒等式
$$资产 = 负债 + 所有者权益$$

扩展形式：
$$资产 = 负债 + 所有者权益 + (收入 - 费用)$$

#### 六大要素
| 要素 | 定义 | 举例 |
|------|------|------|
| 资产 | 过去交易形成的、由企业控制的、预期带来经济利益的资源 | 现金、应收账款、存货、固定资产 |
| 负债 | 过去交易形成的、预期导致经济利益流出的现时义务 | 应付账款、短期借款、应交税费 |
| 所有者权益 | 资产扣除负债后由所有者享有的剩余权益 | 实收资本、资本公积、盈余公积、未分配利润 |
| 收入 | 日常活动中形成的、导致所有者权益增加的经济利益总流入 | 主营业务收入、其他业务收入 |
| 费用 | 日常活动中发生的、导致所有者权益减少的经济利益总流出 | 营业成本、管理费用、销售费用、财务费用 |
| 利润 | 一定会计期间的经营成果 | 营业利润、利润总额、净利润 |

#### 借贷记账方向口诀
> **"有借必有贷，借贷必相等"**

| 账户类型 | 借方（Debit） | 贷方（Credit） |
|----------|-------------|---------------|
| 资产类 | 增加 ↑ | 减少 ↓ |
| 负债类 | 减少 ↓ | 增加 ↑ |
| 所有者权益类 | 减少 ↓ | 增加 ↑ |
| 收入类 | 减少 ↓ | 增加 ↑ |
| 费用类 | 增加 ↑ | 减少 ↓ |

速记口诀：**"资费借增贷减，负所收借减贷增"**

#### 会计科目分类
- **资产类**：库存现金、银行存款、应收账款、应收票据、预付账款、存货、固定资产、累计折旧、无形资产
- **负债类**：短期借款、应付账款、应付票据、预收账款、应付职工薪酬、应交税费、长期借款
- **所有者权益类**：实收资本、资本公积、盈余公积、利润分配
- **损益类-收入**：主营业务收入、其他业务收入、投资收益、营业外收入
- **损益类-费用**：主营业务成本、其他业务成本、税金及附加、销售费用、管理费用、财务费用、营业外支出、所得税费用

### C2. 三张报表的完整编制流程

```
原始凭证 → 记账凭证 → 日记账（现金/银行存款日记账）
                    → 明细分类账
                    → 总分类账
                    → 试算平衡表
                    → 调整分录（应计/递延/估计）
                    → 调整后试算平衡表
                    → 财务报表（损益表 → 所有者权益变动表 → 资产负债表 → 现金流量表）
                    → 结账分录
```

**三表联动关系**：
- 损益表的**净利润** → 流入资产负债表的**未分配利润**
- 资产负债表的**现金变动** → 等于现金流量表的**期末现金余额变动**
- 现金流量表的**经营活动现金流** → 与损益表净利润的差异通过调整项解释

### C3. 常见会计错弊与试算平衡

借贷不平的六种情形：
1. **漏记**：一笔分录的借方或贷方完全遗漏
2. **重记**：同一笔分录重复过账
3. **方向记反**：应借记贷、应贷记借
4. **金额错误**：借方或贷方金额写错
5. **科目用错**：记入错误的账户（试算平衡可能仍然平衡，但报表错误）
6. **过账错误**：从日记账过入分类账时抄错数字

> **注意**：试算平衡只能验证借贷总额相等，不能发现第 5 类错误（科目用错）和第 6 类中的对称错误。

### C4. 中国个人所得税年度汇算清缴

#### 基本规则
- **汇算时间**：次年 3 月 1 日至 6 月 30 日（《个人所得税法》第十一条）

#### 年终奖单独计税 vs 并入综合所得

**政策依据**：财政部 税务总局公告2023年第30号，延续至 **2027年12月31日**。

### C5. 增值税

| 纳税人类型 | 税率/征收率 | 备注 |
|-----------|-----------|------|
| 小规模纳税人 | 3%（征收率） | 现行优惠政策：月销售额 ≤ 10 万元免征（财政部 税务总局公告2023年第1号） |
| 一般纳税人-销售货物/加工修理修配 | 13% | 标准税率 |
| 一般纳税人-交通运输/邮政/基础电信/建筑/不动产租赁/农产品 | 9% | 低税率 |
| 一般纳税人-现代服务/生活服务/增值电信/金融/文化体育 | 6% | 低税率 |
| 出口货物 | 0%（退税） | 出口退税 |

**进项销项抵扣机制**：
- 应纳税额 = 销项税额 - 进项税额
- 进项税额必须有合法的增值税专用发票才能抵扣
- 不得抵扣的项目：用于简易计税/免税/集体福利/个人消费的购进

> 政策依据：《中华人民共和国增值税暂行条例》及其实施细则；财政部 税务总局公告2023年第1号

### 1. 会计分录自动生成规则

| 企业销售收入 | 银行存款/应收账款 | 主营业务收入 + 应交税费-增值税(销项) | |

| 支付员工工资 | 管理费用/销售费用 | 应付职工薪酬 | |

| 公益捐赠 | 营业外支出 | 银行存款 | 触发扣除限额校验 |
| 参加标会（出资） | 其他应收款-标会 | 银行存款 | 高风险借贷标记 |

### 2. 试算平衡校验时机

| 校验节点 | 触发条件 | 校验内容 | 失败处理 |
|----------|---------|---------|---------|
| 每笔交易后 | 实时 | 单笔分录借贷相等 | 阻止交易提交 + 提示错误 |
| 每阶段结束 | 市场周期切换时 | 全部账户借贷总额平衡 | 弹出"账务异常"面板，要求玩家检查 |
| 年度汇算 | 游戏内年度结束时 | 三表勾稽关系验证 | 触发"审计事件"，错误越多罚款越高 |
| 终局结算 | 游戏结束时 | 完整三表 + 税务合规评分 | 计入终局"人生赢家"评分 |

### 3. 记账难度分级

| 难度 | 目标用户 | 记账方式 | 税务处理 | 教学深度 |
|------|---------|---------|---------|---------|
| **新手** | 无会计基础 | 全自动记账，玩家只看三表结果 | 自动计算税款，不展示过程 | 认识三表、理解现金流 |
| **进阶** | 有基础财商知识 | 半自动：系统生成分录草稿，玩家确认/修改 | 展示税款计算过程，玩家选择计税方式 | 理解分录、体验税率跳档 |
| **专家** | 会计/税务从业者 | 全手工记账，玩家自行编制分录 | 完整税务申报流程（增值税/个税/企业所得税） | 三表编制、税务筹划、审计应对 |

### 4. 错误账务的游戏化惩罚与教学

| 错误类型 | 游戏惩罚 | 教学内容 |
|----------|---------|---------|
| 借贷不平 | 本阶段行动力 -1 | 弹出"试算不平衡"提示，展示差额 |
| 科目用错 | 不影响平衡但报表失真 | 年度审计时发现，扣除"信誉分" |
| 漏记交易 | 现金流偏差累积 | 年底对账时发现，触发"补记"事件 |
| 税务计算错误 | 补缴税款 + 滞纳金（每日万分之五） | 展示正确的计算过程 |
| 故意逃税 | 稽查概率提升，罚款 0.5~5 倍 | 展示《税收征管法》第六十三条 |
| 年终奖落入盲区 | 到手收入反常减少 | 弹出"税率跳档陷阱"教学卡片 |

借鉴《会计模拟器》和 Lemons App 的实时 Dashboard：

-- 会计科目表
CREATE TABLE t_lsm_game_chart_of_accounts (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    code VARCHAR(20) NOT NULL,      -- 科目编码如 '1001'

    entry_date DATE NOT NULL,
    description VARCHAR(200),
    auto_generated BOOLEAN DEFAULT TRUE,
    player_confirmed BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 分录明细表
CREATE TABLE t_lsm_game_accounting_line (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,

    credit_amount DECIMAL(15,2) DEFAULT 0,
    FOREIGN KEY (entry_id) REFERENCES t_lsm_game_accounting_entry(id)
);

    id BIGINT PRIMARY KEY AUTO_INCREMENT,

    tax_year INT NOT NULL,

    tax_due DECIMAL(15,2),
    tax_paid DECIMAL(15,2),
    refund_or_pay DECIMAL(15,2),   -- 正数=退税，负数=补税
