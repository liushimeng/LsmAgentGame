# 斗地主 (Doudizhu) — 规则与协议

> 本文档记录斗地主游戏的服务端权威规则判断、WS 帧协议、客户端实现要点。
> 前端/后端修改前请先阅读本文档。

## 1. 基本规则（服务端权威）

### 牌面定义（`game/doudizhu/cards.go`）

- Rank：`3..10, J=11, Q=12, K=13, A=14, 2=15, 小王=16, 大王=17`
- Suit：`1=♠, 2=♥, 3=♣, 4=♦, 0=无花色（王）`
- 一副牌 54 张（13×4 + 2 王）

### 牌型识别（`game/doudizhu/combo.go`）

| ComboType | 说明 | 主体点数 | 长度 |
|-----------|------|---------|------|
| Single | 单张 | 该张 rank | 1 |
| Pair | 对子 | rank | 1 |
| Triple | 三张 | rank | 1 |
| TripleSingle | 三带一 | 三张 rank | 1 |
| TriplePair | 三带二 | 三张 rank | 1 |
| Straight | 顺子 ≥5 | 最大 rank | 张数 |
| PairStraight | 连对 ≥3 对 | 最大 rank | 对数 |
| Plane | 飞机 ≥2 组三张 | 最大 rank | 组数 |
| PlaneSingle | 飞机带单翅膀 | 最大 rank | 组数 |
| PlanePair | 飞机带对翅膀 | 最大 rank | 组数 |
| QuadTwoSingle | 四带二（单） | 四张 rank | 1 |
| QuadTwoPair | 四带二（对） | 四张 rank | 1 |
| Bomb | 炸弹 | rank | 1 |
| Rocket | 王炸 | RankBig(17) | 1 |

**约束**：2/小王/大王不进入顺子/连对/飞机的连续序列。

### 跟牌规则（`CanBeat`）

1. 自由出牌（`prev == nil`）：任何合法牌型均可。
2. 王炸压一切（除另一王炸不可能出现）。
3. 炸弹压非炸弹；炸弹间比 rank。
4. 普通牌型：同类型 + 等长 → 比主体 rank。

### 游戏流程（`game/doudizhu/engine.go`）

1. **发牌**：洗牌后每人 17 张 + 3 张底牌。
2. **叫地主**（PhaseBidding）：首叫座位轮流，每人叫一次，可叫 1/2/3/不叫(0)。叫 3 直接定地主；一轮结束最高分者为地主；全不叫→重新发牌（首叫顺延一位）。
3. **出牌**（PhasePlaying）：地主拿底牌后首出，逆时针轮流。首出可任意合法牌型；跟牌须同型更大或炸弹/王炸；可过（`Pass`）但自由出牌不可过。两家连续过→上家重获自由出牌权。
4. **结束**（PhaseOver）：某人手牌空→地主胜或农民胜。计分 = 基础分(叫分) × 倍数(炸弹×2/火箭×2)。

## 2. WS 帧协议

### 客户端→服务端

| 帧类型 | payload | 说明 |
|--------|---------|------|
| `game.join` | `{ room_id, game_kind:"doudizhu" }` | 入座（幂等），满3人自动发牌 |
| `game.bid` | `{ room_id, score:0\|1\|2\|3 }` | 叫分 |
| `game.play` | `{ room_id, cards:[{rank,suit},...] }` | 出牌 |
| `game.pass` | `{ room_id }` | 过（要不起） |
| `game.resign` | `{ room_id }` | 认输 |
| `game.leave` | `{ room_id }` | 退出房间（进行中按认输处理） |
| `game.state` | `{ room_id }` | 请求当前状态 |

### 服务端→客户端

| 帧类型 | 触发时机 | payload |
|--------|---------|---------|
| `game.joined` | 入座成功 | `{ my_seat, phase, ready }` |
| `game.peer_joined` | 有人加入 | `{ player_count, ready }` |
| `game.started` | 满员发牌 / 叫完地主 | `{ phase:"bidding"\|"playing", landlord? }` |
| `game.bidded` | 叫分确认 | 操作确认，等 game.state |
| `game.redealt` | 全员不叫重发 | `{ phase:"bidding" }` |
| `game.played` | 出牌确认 | 操作确认 |
| `game.passed` | 过牌确认 | 操作确认 |
| `game.state` | **按座位过滤的视图** | 见下方 ClientGameState |
| `game.over` | 对局结束 | `{ winner, score, multiplier }` |
| `game.error` | 操作错误 | `{ code, message }` |

### ClientGameState 结构

```json
{
  "room_id": "uuid",
  "game_kind": "doudizhu",
  "seats": ["uid0", "uid1", "uid2"],
  "my_seat": 0,
  "ready": true,
  "phase": "bidding|playing|over",
  "turn": 1,
  "status": "playing|landlord_win|farmer_win",
  "my_hand": [{"rank":14,"suit":1}, ...],   // 仅自己完整手牌
  "hand_counts": [17, 17, 20],              // 三家剩余张数
  "first_bidder": 0,
  "bids": [2, 0, -1],                      // -1=未叫
  "current_bid": 2,
  "landlord_seat": 0,                       // -1=未定
  "bottom": [{"rank":5,"suit":2}, ...],     // 叫完后亮出
  "last_play": { "seat": 0, "cards": [...] },
  "multiplier": 2,
  "bomb_count": 0,
  "winner": "",
  "score": 0
}
```

**关键**：`game.state` 通过 `hub.BroadcastTo(userID, ...)` 按座位单独推送（不能用 `BroadcastRoom`），因为手牌按人过滤。

## 3. 容量

- `service/room_service.go` 中 `CreateRoom` 根据 `game_kind` 设置容量：`doudizhu=3`，其余=2。
- DB 模型 `TLsmGameRoom.Capacity` 已支持任意值，无需改表。

## 4. 断线恢复

`useSessionRestore.ts` 的 `parseGameRoute` 已支持 `/doudizhu/:roomId` 路由。
断线/刷新后自动发送 `room.join` → `game.join`（带 `game_kind:"doudizhu"`）→ `game.state`。

## 5. 美术

- 两种风格：`traditional_landlord`（传统地主）/ `urban_worker`（都市打工仔）
- 由 `python-generate-image-tool/generate_doudizhu_assets.py` 生成 PNG
- 前端 `CardView`：PNG 优先加载，`onError` 时回退 CSS 文字卡面
- `assets/images/doudizhu/index.ts` 用 `new URL('./<style>/<name>.png', import.meta.url)` 打包
