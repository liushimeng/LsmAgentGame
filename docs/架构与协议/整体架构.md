## 进程布局

- 单进程。`ServerGo/main.go` 按以下顺序启动：
  1. `config.Load()` —— 读取 `LsmWebGame.conf`（缺失时回退到 `.example`）。
  2. `logger.Init()` —— 包装 zap，同时输出到 stdout 和日志文件。
  3. `db.Init()` —— 打开 GORM，配置连接池，执行 `AutoMigrate`。
  4. 服务层构造函数（`AuthService`、`GameService`）。
  5. Gin 引擎（HTTP）、`ws.Handler`（WSS 升级）。
  6. 启动两个 `http.Server`（HTTPS 39001、WSS 39002），分别在 goroutine 中运行。
  7. Hub 心跳 goroutine（15 秒一周期）。
  8. `signal.Notify(SIGINT, SIGTERM)` → 两个 Server 优雅退出。

## 命名规范

- `ServerGo/models/` 下的 Go 模型文件使用 `t_lsm_game_*.go` 命名。
- 其他所有 Go 文件使用 `snake_case.go` 命名。
- 完整规则请参考 [CLAUDE.md](../CLAUDE.md)，AI 代理应严格遵守。

## TLS

- **开发环境**：自签名的 `server.crt` / `server.key` 放在项目根目录，通过 `LsmWebGame.conf` 中的相对路径加载。
- **生产环境**：**禁止**提交新的生产证书。应通过密钥管理服务挂载真实证书材料，并在部署的 `LsmWebGame.conf` 中覆盖 `server.tls_cert` / `server.tls_key`。建议每 90 天轮换一次。
- HTTPS 和 WSS 共用同一份证书。

## CORS

白名单位于 `LsmWebGame.conf → cors.allowed_origins`。默认值为：`https://localhost:39001`、`https://127.0.0.1:39001`。新增来源请在此配置，**禁止**在中间件中硬编码。

## 数据库

使用 GORM 的 `mysql` 驱动（同时兼容 MySQL 和 MariaDB）。DSN 格式由 `config.DBConfig.DSN()` 构造。

开发阶段使用 `AutoMigrate` 自动建表。生产环境应切换到 `golang-migrate`，配合 `ServerGo/db/migrations/` 下版本化的 SQL 文件使用。

## WebSocket 协议（阶段一）

JSON 信封，使用 UTF-8 文本帧：

```json
{ "type": "heartbeat", "seq": 0, "payload": { "server_ts": 1700000000000 } }
{ "type": "ack",       "seq": 7, "payload": { ...回显内容... } }
{ "type": "error",     "payload": { "code": 20001, "message": "bad envelope" } }
```

阶段三（proto 代码生成）将把上述格式替换为带长度前缀的 protobuf 线缆格式。Go 端的 `Hub` 和 `Client` 接口在切换过程中保持稳定。

## 前端打包器

使用 Vite 作为打包器。生产构建底层使用 Rollup。Vite 开发服务器监听 `:39003`，将 `/api` 和 `/ws` 反向代理到后端，从而保证 Cookie、请求头以及 WSS 升级都能正确转发。自签名开发证书通过代理配置中的 `secure: false` 放行。

## 范围外（当前脚手架阶段）

- 真实游戏状态、tick、预测、状态调和。
- 生产级加固（限流、验证码、密钥轮换、TLS 钉扎）。
- CI/CD 流水线。本地 `rebuild_restart_app.sh` 是当前的发布命令。
