# Spectator / Observer Architecture

> 适用于所有 5 款游戏：象棋、国际象棋、军棋、斗地主、德州扑克。

## 1. 目标

允许任何登录用户以观察者身份实时观看任意一局对局，满足以下硬性约束：

1. **可观察** —— 任何登录用户都能进入任意活跃房间观看；不消耗座位，不受 `t_lsm_game_room.Capacity` 限制。
2. **公开进度可见** —— 棋盘 / 公共牌 / 已亮牌面 / 当前回合 / 比分倍数 / 聊天 等公开信息对观察者开放。
3. **隐私隔离** —— 任何玩家的私有信息（手牌、底牌、未提交布阵、其他玩家的隐藏棋子），观察者一律看不到。
4. **不可干预** —— 观察者无法发出 `game.move / game.bid / game.play / game.pass / game.action / game.layout / game.promote / game.resign` 等游戏输入帧；后端硬性拒绝 (`ErrSpectatorInputForbidden = 30011`)。
5. **玩家无感知** —— 玩家的对局界面（棋盘 / 牌桌 / 操作按钮 / 座位高亮）不显示观察者存在；唯一的"被观察"信号是聊天面板中带 👁 标识的观察者消息。

## 2. 架构核心：两组互不相交的广播集合

`ws/hub.go` 维护两组互不相交的 room 集合，保证协议级隔离：

| 集合 | 内容 | 协议 |
|------|------|------|
| `Hub.rooms[roomID]` | 玩家 + 仅订阅聊天的用户 | `game.*` 帧（玩家私有视图），`chat.*` 帧 |
| `Hub.spectators[roomID]` | 仅观察者 | `game.state`（脱敏视图），`chat.*` 帧 |

二者**永不相交**。`Hub.BroadcastRoom` 不会触达观察者；`Hub.BroadcastRoomSpectators` 不会触达玩家；`Hub.BroadcastRoomIncludingSpectators` 同时给两组发（仅聊天使用）。

任何玩家输入帧（`game.move` 等）的处理函数顶部都有一道 `rejectIfSpectator` 守卫：

```go
func (s *GameService) rejectIfSpectator(c *Client, env Envelope, roomID string) bool {
    if s.isSpectatorOf(roomID, c) {
        s.sendError(c, env.Seq, errcode.ErrSpectatorInputForbidden, "")
        return true
    }
    return false
}
```

`handleLeave` 拒绝观察者（强制使用 `game.unspectate`），避免把 "leave" 误处理为认输。

## 3. 视图脱敏 —— 各游戏的处理方式

每种游戏都有一种天然的"无座位"路径：`BuildClientState(roomID, seats, viewer, gs)` 中的 `viewer == -1`。

| 游戏 | 脱敏关键点 |
|------|----------|
| **象棋 / 象棋 / 国际象棋** | 棋盘完全公开，仅移除 `my_color`、玩家徽章；二者本就是公开事件。 |
| **军棋 (暗棋)** | `JunqiRoom.buildSpectatorBoardView()` —— 重新构建 12x5 视图，仅保留双方战斗过的公开揭开的格子 + 司令阵亡亮旗 后公开的军旗位；其它格子统统为 `{hidden:true}`。明棋模式下走原有 `BoardView()` 的全公开路径。 |
| **斗地主** | `viewer == -1` 时 `MyHand` 不填充；`HandCounts`、底牌（叫地主结束后）、`LastPlay` 等公开信息照常填充。 |
| **德州扑克** | `viewer == -1` 时任何玩家的 `Hole` 数组都不填充；公共牌、`Stack`、行动状态、胜负照常。 |

多个观察者共享同一份脱敏视图：`DoudizhuManager.SpectatorView(roomID)` / `TexasHoldemManager.SpectatorView(roomID)` 只构建一次，分别推给所有连接中的观察者。

## 4. WS 协议

### 客户端 → 服务端

| 帧 | 说明 |
|----|------|
| `game.spectate` `{room_id, game_kind?, mode?}` | 注册为观察者；`mode` 仅军棋有效（`hidden` / `open`），缺省 `hidden`。 |
| `game.unspectate` `{room_id, game_kind?}` | 反注册。 |
| `game.spectators` `{room_id, game_kind?}` | 查询当前连接的观察者数。 |
| `game.state` `{room_id, game_kind?}` | 观察者收到的是脱敏视图；`my_color`/`my_seat` 不填或为 -1。 |

任何 `game.move / game.bid / game.play / game.pass / game.action / game.layout / game.promote / game.resign / game.leave` 帧若来源是观察者 → 服务端返回 `game.error {code: 30011}`。

### 服务端 → 客户端

| 帧 | 说明 |
|----|------|
| `game.spectated` | 订阅确认。`{room_id, game_kind, role:"spectator", ready?, phase?, mode?}`。 |
| `game.unspectated` | 取消确认。 |
| `game.spectators_resp` | 当前房间连接的观察者数。 |
| `game.state` | 推送给观察者的脱敏视图。**不会**推送 `game.moved` / `game.bid` / `game.play` / `game.action_accepted` —— 观察者不需要这些事件，他们只接收按需重建的 `game.state`。 |
| `game.over` | 仍然广播到两组（对局结束后胜负是公开信息）。 |
| `chat.message` | 增加 `from_role` 字段（`"player" | "spectator" | ""`）。客户端 `GameChatPanel` 为 `from_role === "spectator"` 的消息渲染 👁 徽章。 |

观察者离开房间（路由切换 / 关闭 tab）时，`Hub.Unregister` 会同时把该连接从玩家集合和观察者集合里移除，并调用 `cleanupSpectator` 清理 `t_lsm_game_player(role='spectator')` 行 + 广播 `room.state { action: 'spectator_left' }` 给 lobby 订阅者（**无需**前端显式调 `game.unspectate`；即便前端漏了，服务器的清理路径也不会留下孤儿记录）。修复细节见 `CLAUDE.md §22`。

## 5. 数据库

`t_lsm_game_player` 新增列：

| 列 | 类型 | 默认值 | 说明 |
|----|------|--------|------|
| `role` | `varchar(16)` | `'player'` | 角色：`"player"` 或 `"spectator"` |

新增复合唯一索引：`(room_id, user_id)`。约定一名用户在同一房间只能扮演一种角色 —— RoomService 在 `SpectateRoom` / `JoinRoom` 里都先 SELECT 校验冲突，返回 `ErrAlreadyInOtherRole`（code 30012）。

新增 HTTP 路由（`AuthRequired`）：

| 方法 + 路径 | 服务 |
|------------|------|
| `POST /api/rooms/:id/spectate` | `RoomService.SpectateRoom` |
| `POST /api/rooms/:id/leave_spectate` | `RoomService.LeaveSpectate` |

`RoomService.GetRoomDetail` 多返回一个 `spectators []RoomSpectatorInfo` 字段；大厅列表暂不返回 `spectator_count`（避免每次刷新都做 GROUP BY）。需要展示的页面再单独 GET 一遍。

## 6. 前端

- `/<game>/spectate/:roomId` 五个新路由，渲染同一个 GamePage 组件，由 `useSpectatorMode()` hook 切换模式。
- 每个 `use<Game>()` hook 多返回 `spectate()` / `unspectate()` 两个回调。
- `GameInfoPanel` 多接一个 `spectator?: boolean` 属性，true 时隐藏认输按钮和"你"徽章，改显示一个 👁 观战徽章。
- 所有大厅房卡新增一个 "👁 观战" 按钮（独立于"入座"按钮，避免误触）。
- 退出房间时调用 `roomService.leaveSpectate()` 而不是 `roomService.leave()`，避免触发后端的认输逻辑。

## 7. 测试建议

1. 玩家 A、B 创建象棋房间；玩家 C（观察者）以 `test_03` 身份访问 `/xiangqi/spectate/<id>`。验证：
   - 观察者拿到 `game.state` 但 `my_color` 为 `""`。
   - 玩家 A 走出一步 → A、B、观察者均收到 `game.moved`；但观察者**不会**额外收到任何玩家私有数据。
   - 观察者尝试 `game.move` → 收到 `game.error {code: 30011}`。
2. 斗地主观察者：让 3 名玩家凑齐开局 → 观察者能看到所有 `hand_counts`，但任何玩家的 `my_hand` 数组永远是空。
3. 德州扑克：观察者看到对手的 `hole_count = 2` 但 `hole = []`。
4. 军棋暗棋：观察者打开 `BoardView`，己方玩家未揭开的营地格子全部为 `{hidden:true}`。
5. 大厅里有 N 个观察者时，房卡显示 `N/Capacity · 👁 N`。
6. WS 重连：观察者刷新页面后，`game.spectate` 重新发送一次，服务端重新构建并推送 `game.state` —— 不需要任何玩家侧逻辑配合。

## 8. 已知边界与未来工作

- 大厅`/api/games/:kind/rooms`列表接口 **不**返回 `spectator_count`（避免每个 lobby poll 引发 GROUP BY）。如果将来需要展示在大厅房卡上，可在 `RoomService.ListRooms` 改成 `LEFT JOIN (room_id, count) sub WHERE role='spectator'` 一次性聚合。
- 服务端没有为观察者发送"心跳 / 已断开"的回执，因为观察者本身不需要在线感知；他们的状态由 `useSessionRestore` 自动重连 + 重新 `game.spectate` 重建。
- 日后若引入 `GameState.Snapshot()` 让客户端可以快速 diff（增量更新），观察者分支需要单独写一个 `SpectatorDiff`，目前直接全量 `game.state` 已能跑通 P99 的局面同步。
