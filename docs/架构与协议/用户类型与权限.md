# 用户类型与权限说明

> 本文档定义了 LsmWebGame 平台的用户类型体系和权限规则。
> 供 Agent 自动加载使用，确保前后端权限逻辑一致。

---

## 1. 用户类型定义

| 类型值 | 名称 | 说明 |
|--------|------|------|
| 1 | 普通用户 (Normal) | 默认注册用户类型，拥有基础功能权限 |
| 2 | 管理员用户 (Admin) | 可查看所有用户信息，但不可编辑/删除 |
| 3 | 超级管理员用户 (Super Admin) | 拥有完整管理权限，可查看、编辑、删除用户 |

---

## 2. 权限矩阵

### 2.1 用户列表权限

> 自 2026-07：用户列表对**所有登录用户**开放，字段按权限分级可见，数据交互走
> WebSocket `user.*` 帧（详见 [`WebSocket重连与恢复.md`](WebSocket重连与恢复.md) §6）。

| 操作 | 普通用户 | 管理员 | 超级管理员 |
|------|----------|--------|------------|
| 查看用户列表（昵称 + 在线状态） | ✅ | ✅ | ✅ |
| 查看用户详情（账号/手机/邮箱/邀请码等，**无密码**） | ❌ | ✅ | ✅ |
| 编辑用户信息 | ❌ | ❌ | ✅ |
| 删除用户（级联删除关联数据） | ❌ | ❌ | ✅ |
| 修改用户类型 | ❌ | ❌ | ❌ (仅数据库) |

### 2.2 游戏功能权限

|------|----------|--------|------------|

| 加入房间 | ✅ | ✅ | ✅ |
| 游戏对战 | ✅ | ✅ | ✅ |
| 聊天 | ✅ | ✅ | ✅ |

### 2.3 系统功能权限

| 操作 | 普通用户 | 管理员 | 超级管理员 |
|------|----------|--------|------------|
| 修改个人信息 | ✅ | ✅ | ✅ |
| 修改语言设置 | ✅ | ✅ | ✅ |
| 查看提交记录 | ✅ | ✅ | ✅ |
| 访问用户列表 | ✅ | ✅ | ✅ |

## 3. 前端实现规则

### 3.1 路由守卫

- `/admin/users`（用户列表）对**所有登录用户**开放；未登录访问自动重定向到首页。
- 渲染粒度由服务端 `user.list_resp.my_user_type` 决定：普通用户仅见昵称+在线，
  管理员见详细列，超管额外见删除按钮（`can_delete` 行）。

### 3.2 侧边栏菜单

- `用户列表` 菜单项 `minUserType: 1`，对所有登录用户可见
- 使用 `minUserType` 字段控制菜单可见性

### 3.3 操作按钮

- 删除按钮仅对 `userType === 3` (超级管理员) 可见
- 管理员只能查看，不能执行删除操作

---

## 4. 后端实现规则

### 4.1 API 端点

| 端点 | 方法 | 权限要求 |
|------|------|----------|
| `/api/admin/users` | GET | userType >= 2 |
| `/api/admin/users/:id` | DELETE | userType === 3 |

### 4.2 中间件校验

- 所有 `/api/admin/*` 端点需要 JWT 认证
- 在 handler 内部校验 `userType` 字段
- 权限不足返回 `403 Forbidden` + 错误码 `10403`

### 4.3 删除用户流程

删除用户时需要同时删除以下关联数据（事务内执行）：

1. 聊天消息 (`t_lsm_game_chat_message`)
2. 玩家记录 (`t_lsm_game_player`)
3. 会话记录 (`t_lsm_game_session`)
4. 清空被邀请人的 `referrer_user_id` 字段
5. 最后删除用户记录 (`t_lsm_game_user`)

## 5. 数据库字段

### 5.1 `t_lsm_game_user.user_type`

- 类型: `tinyint`
- 默认值: `1` (普通用户)
- 约束: `NOT NULL`
- 取值范围: `1`, `2`, `3`

### 5.2 用户类型常量定义

**后端 (Go):**
```go
type UserType int

const (
    UserTypeNormal UserType = 1 // 普通用户
    UserTypeAdmin  UserType = 2 // 管理员用户
    UserTypeSuper  UserType = 3 // 超级管理员用户
)
```

**前端 (TypeScript):**
```typescript
// 通过 API 返回的 user_type 字段判断
// 1 = 普通用户, 2 = 管理员, 3 = 超级管理员
```

---

## 6. 安全注意事项

1. **禁止前端修改 userType**: 用户类型只能通过数据库直接修改，不提供 API 修改接口
2. **防止权限提升**: 普通用户无法通过任何方式获取管理员权限
3. **删除保护**: 超级管理员不能删除自己
4. **审计日志**: 所有用户删除操作记录管理员 ID 和目标用户 ID

---

## 7. 初始管理员设置

系统初始化时创建的 root 用户默认为普通用户。如需设置管理员，需要直接修改数据库：

```sql
-- 设置为管理员
UPDATE t_lsm_game_user SET user_type = 2 WHERE account = 'admin_account';

-- 设置为超级管理员
UPDATE t_lsm_game_user SET user_type = 3 WHERE account = 'super_admin_account';
```
