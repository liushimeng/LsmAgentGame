# LsmAgentGame 产品设计规范

> 本文件是 LsmAgentGame 的**产品设计唯一事实来源**。Agent 在做任何前端改动之前必须先
> 阅读本文件，并按其中的规范实施。所有 UI 行为、布局规则、可访问性约束、断点策略
> 都在此定义。
>
> 与 `中国军棋规则.md` / `中国象棋规则.md` / `国际象棋规则.md`（业务规则）不同，本文件
> 关注**展示层与交互层**的规则。

## 1. 设计哲学

1. **空间优先**：界面是棋盘与聊天的容器，不是主角。无论在什么终端，棋盘/游戏区都必须
   占据最大可用面积，其它面板（标题栏、菜单栏、聊天框）默认不抢占空间，且必须提供
   折叠/展开的能力。
2. **端无关体验**：PC、平板、手机都要能跑通核心流程（登录、加入房间、对局、聊天）。
   同一份代码、同一份状态、不同布局。
3. **状态可恢复**：用户对布局的偏好（哪些面板折叠了）必须持久化到 `localStorage`，
   刷新或重新登录后能复原。
4. **零回归**：任意终端改动都必须保证 `tsc --noEmit` 与 `npm run build` 通过；
   后端 Go 代码改动必须 `go build` + `go test ./...` 通过。

## 2. 响应式断点

| 断点      | 触发条件            | 主要目标        |
| --------- | ------------------- | --------------- |
| `mobile`  | `max-width: 640px`  | 手机竖屏        |
| `pad`     | `641px ~ 1024px`    | 平板 / 小屏笔电 |
| `desktop` | `min-width: 1025px` | PC / 大屏显示器 |

> CSS 写法：用 `@media (max-width: 1024px)` 命中 pad 与 mobile 时的"中屏 + 折叠"
> 模式；用 `@media (max-width: 640px)` 命中手机时的"抽屉"模式。**禁止**写死像素
> 阈值到组件内，统一在 `globals.css` 中维护。

## 3. 统一布局

```
┌────────────────────────────────────────────────────┐
│   Header  (标题栏 + 工具栏) — 可整行折叠          │ height: 56
├──────┬───────────────────────────────┬─────────────┤
│      │                               │             │
│ Side │      Main Content             │  Chat       │
│ bar  │      (game / page)            │  Panel      │
│      │                               │             │
│ ↕ 折 │  ↕ 折：进入全屏模式时连        │ ↕ 折：转     │
│ 叠   │   header/sidebar/chat 一起     │   抽屉      │
│      │   收掉，只留游戏区            │             │
└──────┴───────────────────────────────┴─────────────┘
```

四个区块定义：

- **标题栏（AppHeader）** —— 品牌、版本号、编译时间、用户信息、登出。
- **工具栏** —— 实际上是 Header 的右侧区域；列出用户操作（退出、全屏等）。
- **菜单栏（AppSidebar）** —— 路由导航：游戏大厅 / 全部游戏 / 个人中心 / 关于。
- **聊天框（ChatPanel）** —— 实时聊天（lobby / room 两类 scope）。

## 4. 可折叠规则（强约束）

> 标题栏、工具栏、菜单栏、聊天框——**四个面板都必须支持折叠**。不允许任何面板写死为
> 不可隐藏。

### 4.1 折叠状态

每个面板维护一个布尔状态（`collapsed: boolean`），由 zustand store `ui.store.ts`
统一管理，键名固定：

| 键名               | 适用面板      | 默认值                             |
| ------------------ | ------------- | ---------------------------------- |
| `headerCollapsed`  | 标题栏+工具栏 | `false` (PC) / `true` (mobile)     |
| `sidebarCollapsed` | 菜单栏        | `false` (PC/pad) / `true` (mobile) |
| `chatCollapsed`    | 聊天框        | `false` (PC) / `true` (mobile/pad) |

UI 组件**禁止**自己用 `useState` 维护折叠状态（除非要"局部、临时"的状态），
**必须**调用 `useUiStore` 的 setter，确保状态可被全站协调（例如"全屏模式"会同时
把 4 个面板全部收起）。

### 4.2 持久化

通过 zustand `persist` 中间件把折叠状态写入 `localStorage`，键名 `lsm.ui`。
在 `App.tsx` 启动时调用 `useUiStore.getState().hydrateFromMedia()` 根据当前视口
宽度覆盖默认值。

### 4.3 全屏模式

游戏页（`/game/:id`）提供"全屏"按钮。点击后：

1. 标题栏收起（只剩极薄一条返回条）。
2. 菜单栏收起。
3. 聊天框变成右侧抽屉（仅留 36px 的"夹子"）。
4. 游戏区占满剩余空间。

实现：在 `ui.store` 中暴露 `setFullscreen(boolean)`，对应设置
`headerCollapsed = true && sidebarCollapsed = true && chatCollapsed = true`，
退出全屏时恢复上一次的折叠状态。

## 5. 移动端规则

- **断点 ≤ 640px**：默认收起 sidebar 与 chat；header 显示 hamburger 按钮，点击弹出
  sidebar 作为 drawer 覆盖在内容之上。
- **聊天框**：变成底部抽屉，从屏幕底部上滑；用户可关闭。
- **菜单栏**：用 `<dialog>` 风格的浮层或滑出式 drawer，**禁止**使用嵌套侧栏。
- **触摸目标**：所有可点击元素 `min-height: 40px`，`min-width: 40px`，避免误触。
- **横屏**：游戏页在横屏下应保持 PC 布局（断点 >= 1025px），因为棋盘需要横向空间。

## 6. 平板端规则

- **断点 641~1024px**：默认收起 chat（保留 36px 夹子），sidebar 仍显示但只显示
  图标（隐藏 label）。
- 棋盘自动等比缩放，使用 `<canvas>` 的 `resize` 事件。

## 7. 主题与无障碍

- 颜色全部走 CSS 变量（`--bg` / `--panel` / `--text` / `--accent` 等），
  改主题只需要改 `:root`。
- 所有折叠按钮必须带 `aria-label` + `title`，并用 emoji 或文字标识方向
  （◀ / ▶ / ☰）。
- 键盘快捷键：
  - `Ctrl/Cmd + B` 切换 sidebar
  - `Ctrl/Cmd + J` 切换 chat
  - `Ctrl/Cmd + .` 进入/退出全屏（仅 game 页）
- 高对比度：所有可点击元素 hover 时颜色变化 ≥ 20%。

## 8. 不要做的事

- ❌ 不要在某个具体页面里写死响应式断点 —— 全部在 `globals.css` 集中维护。
- ❌ 不要新增与现有 4 个面板并列的"第 5 个"折叠面板 —— 想要新区域先扩展本文件。
- ❌ 不要把后端 API 地址、密钥、token 写进前端代码。
- ❌ 不要禁用浏览器的水平滚动条（在小于 320px 的设备上我们仍要保持最小可玩性）。
- ❌ 不要使用 Webpack；继续 Vite。

## 9. 改动工作流

1. 修改本文件：先在本文件登记新的 UI 规则（断点、面板、约束），提交后再写代码。
2. 改前端：先 `tsc --noEmit` 再 `npm run build`，都通过再 commit。
3. 改后端：先 `go build -o LsmAgentGame main.go` 再 `go test ./...`。
4. 任何与本文件冲突的实现都是 bug，先改文件再改代码。
