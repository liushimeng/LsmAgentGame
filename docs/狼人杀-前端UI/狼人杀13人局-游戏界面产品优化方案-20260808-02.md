### 1.2 缺陷清单

**缺陷 A（P0）—— 遗言阶段「无舞台」**

`phase === 'death_lyric'` 时，除**当前遗言者本人**（看到 LastWordsPanel）外，
其余 12 个座位的玩家与观战者在主界面**没有任何阶段专属 UI**：

- 看不到「现在是遗言阶段、轮到几号、还剩几人」的进度条；
- 已死亡座位的座位格只有静态 ✝ 死面罩，**当前正在发表遗言的座位没有任何高亮**；
- 法官虽会宣告「遗言阶段」，但混入聊天流后即刻被后续消息顶走。

对照其他阶段：警长有 `DayControlPanel`、投票有投票面板、白痴有 `IdiotRevealPanel`、
重开局有 `WerewolfRestartVotePanel` —— **遗言是唯一没有阶段专属可见组件的主阶段**。

**缺陷 B（P0）—— 遗言队列数据已下发但零消费**

`phase_extra.death_lyric{current_seat,total,done}` 与 `phase_extra.dead_list[]`
（含 `last_words_status: spoken/skipped/pending/ineligible`）自 2026-07-09 起
就由 `view.go` 下发，前端类型也已对齐（`types/werewolf.ts:359-375`），
但**全仓 grep 无任何组件消费**（LastWordsPanel 只用了 `current_seat` 一个字段，
`total/done/dead_list/last_words_status` 全部未渲染）。典型「下发了却从不消费」。

**缺陷 C（P1）—— 遗言活动事件三个分支视觉不一致**

- `death_lyric_spoken` → 已按「发言体」渲染（💀 徽章 + 正文字号，§20260805-02 F4）✅
- `death_lyric_start`（💀 X号 开始遗言）→ 普通系统小灰条
- `death_lyric_skipped`（💀 X号 放弃遗言）→ 普通系统小灰条

「开始/放弃」两个节点事件与正文事件视觉权重差距过大，在 13 人高频聊天流里
一刷即没，给人「遗言没有发生」的体感。

**缺陷 D（P2）—— 历史抽屉时间轴无遗言事件**

`HistoryDrawer` 时间轴只拼 phase 切换 / 投票 / 警徽流 / 白痴翻牌 / 死亡，
遗言的「已发表/已放弃」状态不在时间轴上，复盘时缺失。

### 1.3 边界说明：Agent 侧「是否真的会发遗言」

后端工具链已通（§1.1），Agent 不发遗言只有两种真实情形，均**不是 UI 缺陷**，
但 UI 必须让这两种情形**可区分、可感知**：

1. **LLM 主动选择 `last_words_skip`**（沉默出局）→ 应看到「💀 X号 放弃遗言」；
2. **超时/隔离被 watchdog 强推 skip** → 同样落 `death_lyric_skipped` 事件。

当前这两个事件都是小灰条（缺陷 C），修复后玩家即可区分
「没发」与「发了但我没看到」。

## 2. 设计目标与硬约束

### 2.1 目标

| # | 目标 | 对应用户诉求 |
|---|------|-------------|
| G1 | 遗言阶段全员可见：进度条 + 当前遗言座位高亮 | 「Agent 之间和人类玩家之间都没有看到遗言流程」|
| G2 | 遗言三节点（开始/正文/放弃）视觉成体系 | 「没有看到关于遗言完成的流程」|
| G3 | 人类玩家（含观战者）看到完整队列：谁已说、谁跳过、谁待说 | 「人类玩家在 Web 界面也需要看到完整流程」|
| G4 | 复盘可见：时间轴补遗言事件 | 同 G3 |

### 2.2 硬约束

1. **后端零改动** —— `DeathLyricExtra / DeadList / death_lyric_*` 活动事件全部复用，
   不新增字段、不新增帧、不改引擎与 Agent 行为。
2. **不改 `globals.css` @import 顺序**（§2.1 硬约束 4）；新增样式写入
   `werewolf-panels.css`（阶段面板既有归属文件）。
3. **i18n 三语同步** —— 新增键必须同时进 `i18n/types.ts` + zh-CN/en/ja，
   否则运行期 t() 返回 key 字符串（§23 教训）。
4. **§26 对比度规范** —— 遗言面板为暗底面板，正文 ≥ 4.5:1、徽章 ≥ 5.0:1；
   状态色相沿用既有库（死亡=灰、处决=橙），**禁新创色相**。
5. **§7.1** 本方案无失败路径（纯展示），不涉及错误展示降级。
6. 新 className 必须 grep 至少一处命中（§26.5 防「声明了却从不接线」）。

## 3. 目标设计

### 3.1 新组件 `LastWordsStage`（全员可见的遗言进度条）

挂在 `WerewolfGamePage` 中栏顶部（`LastWordsPanel` 之上），
**任何身份（存活/死亡/观战）在 `phase === 'death_lyric'` 时都渲染**：

```
┌ 💀 遗言 · 第 2 天 ──────────────────────────── ⏱ 24s ┐
│ ●●◐○○   正在发言: #7 DeepSeek V4-Pro                  │
│ #3 ✅已发表   #7 🕯 发言中   #9 ⏭已放弃   #11 …待发表   │
└───────────────────────────────────────────────────────┘
```

数据来源（全部既有字段）：

| 元素 | 字段 |
|------|------|
| 当前座位 / 总数 / 已完成 | `phase_extra.death_lyric.current_seat / total / done` |
| 逐座位状态 | `phase_extra.dead_list[].last_words_status`（spoken/skipped/pending/ineligible） |
| 座位昵称 | `players[seat].account`（bot 显示 agent_name） |
| 倒计时 | `phase_extra.remaining_sec`（1s 本地 tick，与 LastWordsPanel 同一机制） |

**不做的事**：不显示死者角色（§135 身份公开公平性，`dead_list.role` 由服务端
按 `RolePubliclyRevealed` 白名单脱敏，前端直接透传、不做二次推断）。

### 3.2 座位格高亮：当前遗言者

`WerewolfTable.tsx` 座位格：当 `phase==='death_lyric'` 且
`seat === phase_extra.death_lyric.current_seat` 时给座位格加
`werewolf-seat--last-words-speaking` 修饰类（紫灰色光晕 + 🕯 角标），
覆盖死亡面罩 ✝ 之上（CSS `box-shadow`，不受 night brightness 滤镜衰减 —— §26.2 反模式 4）。

同时已发表遗言的死座在座位格 `last_speech_kind === 'last_words'` 处已有 💀 图标
（`WerewolfTable.tsx:90/102` 已有映射），本次补 CSS 使其在死座上也渲染
（当前死座整体 `grayscale` 滤镜会冲淡该图标，给 `.is-dead .werewolf-seat__action`
单独提升对比度）。

### 3.3 聊天区三节点视觉成体系

`GameChatPanel.tsx` 活动行：`eventKind` 三分支统一为「遗言家族」样式
（共享 `game-chat-activity--speech` 基底的字号/字重，差异仅在徽章色）：

| event_kind | 徽章 | 语义色（§26.4 色相库） |
|-----------|------|----------------------|
| `death_lyric_start` | 🕯 开始遗言 | 紫（沿用白痴翻牌紫，表「仪式性节点」） |
| `death_lyric_spoken` | 💀 遗言（既有） | 灰白正文（既有，不动） |
| `death_lyric_skipped` | ⏭ 放弃遗言 | 灰（死亡灰） |

三节点共用左侧 3px 竖条（`border-left`）形成「同一事件链」的视觉分组。

### 3.4 历史抽屉时间轴补遗言条目

`HistoryDrawer.buildTimeline` 追加：遍历 `phase_extra.dead_list`（进行中的当前轮）
与 `all_dead_list_verbose`（历史轮）中 `last_words_status` 为 spoken/skipped 的项，
各推一条时间轴条目：`💀 #N 遗言已发表` / `⏭ #N 放弃遗言`（day 取 `d.day`）。

> 说明：进行中一轮的 spoken/skipped 也可从 dead_list 取；历史轮的 spoken 文本
> 本身在聊天流与 500K 队列里，时间轴只放「事件发生了」这一事实，不放全文
> （避免与 🤖 独白/聊天记录重复）。

### 3.5 线框：玩家主界面（遗言阶段，人类幸存者视角）

```
┌ Header: Day 2 · 💀 遗言阶段 · ⏱ 24s ──────────────── 📜 历史 ┐
│ ┌ LastWordsStage（全员可见）─────────────────────────────┐   │
│ │ ●●◐○○  正在发言: #7 …                                  │   │
│ └───────────────────────────────────────────────┘   │
│  座位格区（#7 紫灰光晕 + 🕯）                            │
│  ┌ 聊天区 ─────────────────────────┐                   │
│  │ 🕯 #7 DeepSeek V4-Pro 开始遗言   │ ← 紫徽章竖条       │
│  │ 💀 [遗言] 我昨晚查了 3 号是金水…  │ ← 发言体（既有）    │
│  │ ⏭ #9 放弃遗言                   │ ← 灰徽章竖条       │
│  └─────────────────────────────────┘                   │
└──────────────────────────────────────────────────────┘
```

### 4.7 i18n（types.ts + zh-CN/en/ja）

新增 8 键：

| key | zh-CN | en | ja |
|-----|-------|----|----|
| `werewolf.lastWords.title` | 遗言 | Last Words | 遺言 |
| `werewolf.lastWords.progress` | {done}/{total} 已完成 | {done}/{total} done | {done}/{total} 完了 |
| `werewolf.lastWords.nowSpeaking` | 正在发言 | Now speaking | 発言中 |
| `werewolf.lastWords.statusSpoken` | 已发表 | Spoken | 発言済み |
| `werewolf.lastWords.statusSkipped` | 已放弃 | Skipped | 放弃 |
| `werewolf.lastWords.statusPending` | 待发表 | Pending | 待機中 |

> 进度/座位名等用插值而非拼接，保证三语语序可调。

### 4.8 不做的事（划界）

- ❌ 不改后端（引擎 / manager / Agent 工具 / 活动事件 / view 字段全部复用）。
- ❌ 不做遗言「弹幕式」全屏特效 —— 与 §124 Day/Night 覆盖层不同，遗言是
  高频事件（每局最多 7 人次），全屏特效会打断游戏节奏。
- ❌ 不在座位格显示遗言全文 —— 全文在聊天区（发言体）与 500K 队列，座位格只做状态。
- ❌ 不消费 `dead_list[].role` 做额外推断（§135 脱敏白名单由服务端裁决）。

## 6. 风险与缓解

| 风险 | 等级 | 缓解 |
|------|------|------|
| `dead_list` 仅在 `phase==='death_lyric'` 下发，阶段结束后 Stage 立即卸载，无残留状态 | 低 | 组件以 phase 为唯一渲染条件，无本地持久 state（倒计时 tick 随卸载清理） |
| 座位格高亮类与既有 `is-selected` 光晕叠加混乱 | 低 | 遗言阶段无投票/狩猎操作，两类光晕不会同时出现；CSS 用独立 box-shadow 层叠而非替换 |
| 时间轴条目变多撑长列表 | 低 | 每轮遗言最多 +7 条，与死亡条目同量级 |
| 三语插值语序 | 中 | 全部用 `t(key, {done,total})` 插值，禁字符串拼接 |
