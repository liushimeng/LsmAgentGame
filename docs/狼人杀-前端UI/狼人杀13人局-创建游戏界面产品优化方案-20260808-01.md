# 狼人杀 13 人局 —— 创建游戏界面产品优化方案（20260808-01）

> 范围：`ClientWeb/src/components/werewolf/RoomCreateModal.tsx` +
> `ClientWeb/src/styles/werewolf-modal.css`。
> 目标：**用横向空间换纵向高度**，让「创建狼人杀房间」弹窗在 768px 高（乃至 600px 高）
> 的浏览器窗口里，AI 座位列表**完整可见、可操作、不重叠、不截断**。
> 不改动：后端契约、`CreateRoomOptions` 类型、座位分配算法、提交逻辑、i18n 既有键的语义。

---

## 1. 现状审计

### 1.1 结构现状（纵向 6 块，全部单列堆叠）

弹窗 `body` 是 `flex-direction: column; gap: 12px`，自上而下 6 个独立块：

| # | 区块 | 组成 | 实测占高（1440×768） |
|---|------|------|---------------------|
| 1 | 房间名 | label + text input | ~55px |
| 2 | AI 玩家数量 | label + range + hint | ~75px |
| 3 | 🎭 我的角色 | label + select | ~55px |
| 4 | AI 座位列表 | 13 行 × 4 控件 | `max-height:280px` 内部滚动 |
| 5 | ⚖️ 法官卡 | 标题 + 2 radio + 模型 select + hint | ~130px |
| 6 | 角色规则说明 | 长 hint（约 40 汉字，常折 2 行） | ~36px |

加上 header(53) + footer(61) + body padding(32) + 5 个 gap(60)，
固定开销约 **347px**；`.ww-create-modal__card` 的 `max-height: calc(100vh - 48px)`
在 768px 窗口下为 720px，留给内容仅 373px —— 而块 1/2/3/5/6 的固定高度合计
已达 **351px**，**AI 座位列表实际只剩 ~22px 的可视高度**，即用户反馈的
「选择 AI 列表具体的看不到」。

### 1.2 已发现的真实缺陷（不只是"挤"）

**缺陷 A（P0，控件错位）—— seatrow 列数与子元素数不匹配**

```css
/* werewolf-modal.css:142 */
.ww-create-modal__seatrow {
  grid-template-columns: 60px 110px 1fr;   /* 3 列 */
}
```

而 JSX 渲染 **4 个**子元素：`AI n` 标签 / 座位 select / 模型 select / **角色 select**
（角色 select 于 2026-08-06 §20260806-03 新增，CSS 未同步）。
CSS Grid 对超出显式列数的子元素会创建**隐式行**，因此每个座位行实际渲染成 **2 行**：

```
┌──────┬──────────┬────────────────────┐
│ AI 1 │ 0号位  ▾ │ DeepSeek V4-Pro  ▾ │   ← 显式行
├──────┼──────────┴────────────────────┤
│ 随机▾│                               │   ← 隐式行：角色 select 被塞进第 1 列
└──────┴───────────────────────────────┘     宽度只有 60px，文字截断
```

后果三连：① 座位列表高度翻倍（13 行 → 26 行）；② 角色 select 被压到 60px 宽，
选项文字（"猎魔人"/"随机"）显示不全；③ 与用户诉求 #4「不要出现控件重叠、显示不全」
直接对应。**这是本次优化中优先级最高的一项，且与"挤高度"是同一根因的两个表现。**

**缺陷 B（P1）—— 座位列表用固定 `max-height:280px`，不随视口伸缩**

`max-height:280px` 是死值：窗口再高也只显示 280px（浪费空间），窗口再矮也占 280px
（挤掉法官卡，触发 body 外层滚动 → **嵌套双滚动条**，用户滚 body 以为在滚列表）。

**缺陷 C（P2）—— 三条 hint 各占一行**

`ai-count-hint` / `judge.hint` / `rolePick.hint` 三条说明文字纵向排列，
其中 `rolePick.hint` 长 40 字常折行，合计吃掉约 90px，但信息密度极低。

**缺陷 D（P2）—— 法官卡横向大量留白**

`⚖️ 法官` 标题独占一行，2 个 radio 仅用掉约 200px，右侧 ~480px 全空；
模型 select 又另起一行。即用户诉求 #3 直接点名的浪费。

## 2. 设计目标与约束

### 2.1 目标（对应用户 6 条诉求）

| 诉求 | 设计响应 |
|------|---------|
| ① AI 列表看不到 | 座位列表改为 **flex 弹性主体**（`flex:1; min-height:0`），吃掉所有剩余高度 |
| ② 字体/标题栏减高 | header 53→40px；h2 18→15px；正文 14→13px；控件 padding 8→5px |
| ③ 合并行、横向换纵向 | 4 组合并（见 §3.2），固定块由 6 行压到 **2 行 + 1 弹性区 + 1 hint 行** |
| ④ 不重叠/不截断 | 修缺陷 A（4 列 grid）；所有 select 加 `min-width:0` 防 grid 溢出；窄屏断点降级 |
| ⑤ 先出方案 | 本文档 |
| ⑥ 按方案实现 | §5 实施清单 |

### 2.2 硬约束（不可违反）

1. **不改后端契约**：`agent_seats[] / judge{mode,model_key} / creator_role / name`
   四个提交字段的形状与语义完全不变。
2. **保留全部自动化钩子**：`data-testid` 五个键
   （`ww-create-modal__ai-count-label` / `...-slider` / `...-hint` /
   `ww-create-modal__creator-role` / `ww-create-modal__seat-role-{i}` /
   `ww-create-modal__form-error`）与 `window.__wwTestBridge.setAiCount` 一律保持。
3. **不动座位分配算法**：`fillCursor` / Fisher-Yates / `usedSeatNumbers` 三处
   历史 bug 修复（见组件内注释）原样保留，本次只改渲染层。
4. **CSS 只改 `werewolf-modal.css`**：该文件是弹窗样式的唯一归属，
   不触碰 `globals.css` 的 `@import` 顺序（CLAUDE.md §2.1 硬约束 4）。
5. **§7.1 错误展示不降级**：`formError` 红条仍在 footer 上方就地渲染，弹窗不关。
6. **可访问性**：所有 select 保留 `aria-label`；radio 保持 `<label>` 包裹可点；
   交互控件最小高度 ≥ 30px（弹窗为鼠标场景，不套用 §23 的 44px 触控 token —
   该 token 作用域是 `.werewolf-game`，弹窗在大厅页不受影响）。

### 3.2 四组合并明细

| 合并 | 合并前 | 合并后 | 省高 |
|------|--------|--------|------|
| **M1** | 房间名（行1）+ AI 数量（行2） | ROW 1 双列：`1fr / 1.25fr` | ~55px |
| **M2** | 我的角色（行3）+ 法官标题/radio（行5上）+ 法官模型（行5下） | ROW 2 三列：`180px / auto / 1fr` —— 即用户诉求 #3 点名的"法官那行后面大量剩余空间放模型选择" | ~130px |
| **M3** | 3 条 hint 各一行 | AI 数量 hint 内联到 ROW 1 右上；`judge.hint` + `rolePick.hint` 合成一条单行省略 hint（`title` 属性给全文） | ~72px |
| **M4** | 座位列表标题缺失 + 固定 280px | 加一行 24px 紧凑标题（含计数 + 重新分配按钮，占用横向空白），列表本体改弹性 | 净赚（见 §3.3） |

固定块合计由 **~351px** 降至 **~150px**，节省 **约 200px** 全部让给座位列表。

### 3.3 高度预算验算（表内为设计期估算，实测见 §9）

| 视口高 | 卡片高<br>`min(100vh-32, 860)` | 减 header40+footer52+padding20 | 固定块 ~150 | **座位列表可视高** | 可见座位行<br>(30px/行) |
|--------|------|------|------|------|------|
| 1080px | 860 | 748 | 598 | **598px** | 13 / 13 ✅ 无滚动 |
| 900px  | 868 | 756 | 606 | **606px** | 13 / 13 ✅ 无滚动 |
| 768px  | 736 | 624 | 474 | **474px** | 13 / 13 ✅ 无滚动 |
| 700px  | 668 | 556 | 406 | **406px** | 13 / 13 ✅ 无滚动 |
| 600px  | 568 | 456 | 306 | **306px** | 10 / 13（内部滚动，滚动条明确可见）|
| 500px  | 468 | 356 | 206 | **206px** | 6 / 13（内部滚动）|

对比现状：768px 下由「**约 0.7 行可见**」提升到「**13 行全见**」。

### 3.4 响应式断点（两级，阈值由实测反推）

| 断点 | 行为 | 阈值依据 |
|------|------|---------|
| `> 700px` | 双列 / 三列如上；卡片 `width: min(760px, 100%)`（由 720 微增 40px）| 默认态 |
| `≤ 700px` | ROW 1 / ROW 2 的 `grid-template-columns` 降为 `1fr` 单列 | ROW2 三列固定开销 = 180(我的角色) + ~200(法官 radio) + 24(gap) = 404px；700px 视口 → card 652px → 模型列仅剩 ~230px，再窄不可用 |
| `≤ 520px` | 座位行由 4 列降为 `48px 1fr 1fr`，角色 select **显式** `grid-column: 2 / -1`（而非隐式行，避免重蹈缺陷 A）| 座位行固定开销 = 52+88+18(3 gap) = 158px；520px → card 472 → 列表内宽 426 → 每个 select (426−158)/2 = 134px |

> **实测教训（第一版把两级并成一个 800px 断点，是错的）**：
> 800px 断点在 760px 视口下过早触发，而实测该视口的 4 列布局每个 select
> 仍有 **253px** 余量完全够用；过早降级反而让座位行高度从 **24px 翻到 54px**，
> 与本次「省高度」的目标完全相反（实测 13 行由 312px 涨到 702px）。
> **断点阈值必须由"该布局在多窄时真正不可用"反推，而不是取 768/800 这类直觉整数。**

## 5. 实施清单

### 5.1 `werewolf-modal.css`

1. 压缩 header / body / footer 的 padding 与字号（§4 表）。
2. `.ww-create-modal__card` → `width: min(760px,100%)`；
   `max-height: min(calc(100vh - 32px), 860px)`。
3. `.ww-create-modal__body` 增 `flex: 1; min-height: 0;`（弹性容器前提）。
4. **新增** `.ww-create-modal__row`（双列）与 `.ww-create-modal__row--3`（三列）。
5. **新增** `.ww-create-modal__seatblock`（弹性外框）+ `__seatblock-head`（24px 标题条）
   + `__reshuffle`（右侧小按钮）。
6. `.ww-create-modal__seats` 由 `max-height:280px` 改 `flex:1 1 auto; min-height:96px;`
   并保留 `overflow-y:auto`。
7. **修缺陷 A**：`.ww-create-modal__seatrow` → `grid-template-columns:
   52px 88px minmax(0,1fr) minmax(0,1fr)`（4 列显式），
   所有 `select` 加 `min-width: 0`（grid item 默认 `min-width:auto` 会撑破容器）。
8. `.ww-create-modal__judge` 由「卡片」降级为「行内组」：去掉 border/padding/背景，
   改 `__judge-inline`，使其能平铺进 ROW 2。
9. **新增** `.ww-create-modal__foot-hint`：单行 `overflow:hidden; text-overflow:ellipsis;
   white-space:nowrap;` + `title` 全文。
10. **新增** `@media (max-width: 800px)` 降级块（§3.4）。

### 5.2 `RoomCreateModal.tsx`

1. ROW 1：房间名 + AI 数量滑块并排（`__row`），AI 数量的 label 与 hint 同排
   （`__field-head` 左标签右 hint），**保留三个 `data-testid` 不变**。
2. ROW 2：我的角色 + 法官模式 radio + 法官模型（`__row--3`）。
   - `agentCount === MAX_AI_SEATS`（全 AI 房）时无人类座位 → 我的角色列不渲染，
     此时 ROW 2 降为两列（用 `--3` 的 `grid-template-columns` 变体或直接 2 列类名）。
   - `agentCount === 0` 时无法官 → ROW 2 只剩我的角色列。
   - `judgeMode !== 'agent'` 时模型列渲染为**禁用占位**而非移除，避免行内控件数量
     跳变导致的布局抖动（真人法官无需选模型）。
3. 座位区：包一层 `__seatblock`，标题条显示 `AI 座位 · {n}` + 「🎲 重新分配」按钮。
   - 重新分配 = `setSeats([])` + `setShuffleNonce(n+1)`，`useEffect` 依赖数组
     追加 `shuffleNonce`。因首遍循环遍历的 `prev` 为空，13 个座位与模型会整体重摇。
     **不新增任何分配逻辑分支**，复用既有 useEffect 全路径。
4. 底部 hint：`judge.hint` 与 `rolePick.hint` 用 ` · ` 拼成一行，加 `title` 全文。
5. 弹窗标题：`创建狼人杀房间` → `创建狼人杀房间 · 13 人`（同宽度内提升信息量，不加高）。

### 5.3 不做的事（明确划界）

- ❌ 不引入折叠面板 / 分步向导（Stepper）—— 创建流程只有 4 个决策点，
  分步会把 1 次点击变成 3 次，是反向优化。
- ❌ 不引入虚拟滚动 —— 13 行 DOM 成本可忽略。
- ❌ 不改 i18n 既有键的文案；新增的 3 处 UI 文案（座位块标题 / 重新分配 / 弹窗副标题）
  沿用本文件既有的**硬编码中文**风格（该组件已有 8 处硬编码中文，
  混入 i18n 键反而破坏一致性；全量 i18n 化列为独立后续项）。
- ❌ 不动 `WerewolfLobbyPage.tsx` 的 `handleCreateWithAgents`。

## 7. 风险与缓解

| 风险 | 等级 | 缓解 |
|------|------|------|
| `flex:1` 主体在 Safari 旧版不收缩 | 低 | 同时给 `min-height: 0`（Flexbox 收缩的标准解药）|
| grid item 被长模型名撑破 | 中 | 所有 grid 内 select 显式 `min-width: 0` |
| 窄屏角色 select 再次落入隐式行 | 中 | 断点内**显式** `grid-column: 2 / -1`，不依赖自动放置 |
| 重新分配按钮引入 useEffect 死循环 | 中 | nonce 为纯 number 且仅由点击递增，effect 内不写 nonce |
| 字号下调影响可读性 | 低 | 最小 12px（座位行 12.5px），高于 WCAG 正文下限；主标题仍 15px |
