# Web 前端代码结构优化（ClientWeb/src 重构方案）

> 日期：2026-08-07 · 编号：20260807-03 · 状态：**已实现**（S1–S7 全部完成）
> 关联：CLAUDE.md §2/§4/§16、`docs/架构与协议/整体架构.md`
> 适用范围：**仅 `ClientWeb/src`**（§13.1 职责线 1 `frontend-dev`）

## 1. 目标

按「**共享基础设施 / 各游戏私有**」两条轴，重构 `ClientWeb/src` 的文件夹结构，使：

1. 共享的基础界面、工具、类型集中在**一处**，任何游戏都从同一路径引用；
2. 每个游戏的子窗口 / 控件 / 元素，**以游戏名称命名文件夹**，互不越界；
3. 消除跨游戏 import（A 游戏引用 B 游戏的组件）；
4. 消除同名组件的重复实现（3 份 `GameChatPanel`、6 份 `GameInfoPanel`、2 份 `CardView`）；
5. 满足 CLAUDE.md §4「单文件 ≤ 1800 行」硬上限。

## 2. 现状盘点

`ClientWeb/src`：193 个 `.ts/.tsx/.css` 文件，42,857 行；17 个 `components/` 子目录、
21 个 `pages/`、17 个 `hooks/`、13 个 `store/`、17 个 `styles/`。

### 2.1 六项结构缺陷

### 2.2 重复组件量化

| 组件组 | 副本 | 结论 |
|--------|------|------|
| `GameChatPanel` | xiangqi 574 / chess 303 / werewolf 87 | **并非 3 份重复**：xiangqi 版是事实上的共享实现（其文件头自述 "Shared by xiangqi, junqi, doudizhu, texasholdem, and werewolf"）；werewolf 版是 87 行薄适配器（已是正确的「基座 + 游戏 props」范式）；**仅 chess 版是真 fork**，且为纯子集（`diff` 397 行差异全部是 chess 缺少的特性） |
| `GameInfoPanel` | 6 份，122–263 行 | 分 3 簇：**A** 棋类(xiangqi/chess/junqi，~75% 同构)、**B** 卡牌类(doudizhu/texasholdem，~50%)、**C** werewolf(263 行，仅尾部共享)。**不应强行合并为单一基座**——werewolf 会污染 API |
| `CardView` | doudizhu 86 / texasholdem 73 | ~90% 相同，差异仅 4 处（`selected` 属性、`isRedSuit` 签名、根类名、`small` 传递方式），全部可参数化 |

### 2.3 CSS 级联现状（不可轻改）

`styles/globals.css` 是唯一入口，17 个 `@import` **顺序即优先级**。关键链：

```
werewolf.css (v1 椭圆布局)
    ↓ 被覆盖
werewolf-v2.css (§126 13人局表格布局)   ← 1940 行，超限
    ↓ 必须在其后
werewolf-speech.css (座位气泡，重写 .werewolf-seat min-height)
```

`werewolf.css` 与 `werewolf-v2.css` 在 `.werewolf-seat` / `.werewolf-table__grid`
等**同优先级**选择器上碰撞，靠 import 顺序决胜；`werewolf-v2.css:493-508` 有一条
已修复的级联 bug 注释为证。**因此本次重构禁止调整 `@import` 顺序。**

共享 CSS 基本干净：`base.css`/`common.css`/`chat.css`/`appmodal.css` 中
游戏前缀选择器 **0 处**，仅 `lobby.css:2` 有一个 `.xiangqi-lobby`。

chess 与 junqi **无专属 CSS**（`grep '\.chess-\|\.junqi-' styles/` 零命中）——
棋盘用内联 `style={{}}`（ChessBoard 11 处 / JunqiBoard 6 处），
其余复用 `xiangqi.css` 的无前缀类（`.game-area` / `.board-container` / `.btn` …）。
`xiangqi.css` 因此是**未声明的共享游戏页样式表**。

## 3. 设计原则

1. **共享优先于复制**：同一职责只允许一份实现。
2. **游戏私有代码必须落在 `<game>/` 目录内**——判据是「引用方是否全部属于该游戏」。
3. **薄适配器是好范式**：`werewolf/GameChatPanel.tsx` 87 行做 props 映射，
   保留游戏语义又零重复，应推广而非消除。
4. **不为合并而合并**：`GameInfoPanel` 的 werewolf 版与棋类版语义差异过大，
   强行统一会产出一个谁都不好用的联合 API。只抽真正共享的尾部。
5. **零行为变更**：本次为结构重构，不改任何 UI 行为、不改 CSS 级联顺序。

## 4. 目标结构

```
ClientWeb/src/
├── app/                       # 应用装配（App.tsx / main.tsx 保持在 src 根，不动）
├── shared/                    # ← 新增：共享基础设施（跨游戏）
│   ├── utils/                 #   balance.ts / ui-storage.ts / format.ts / time.ts
│   └── ...                    #   (后续可继续内聚)
├── components/
│   ├── chat/                  # ← GameChatPanel 迁入（原 xiangqi/）
│   │   ├── ChatPanel.tsx      #   大厅聊天（已有）
│   │   └── GameChatPanel.tsx  #   房间聊天（5 款游戏共用）
│   ├── common/                # DraggableModal / ErrorBoundary / GlobalToast / ...
│   ├── ui/                    # AppModal / ConfirmModal / SettlementModal / ...
│   ├── layout/  auth/  lobby/  rules/  wallet/  git/  wiki/  source-stats/
│   ├── xiangqi/  chess/  junqi/  doudizhu/  texasholdem/   # 各游戏私有
│   └── werewolf/              # 含 emotion.ts（原 utils/werewolfEmotion.ts）
├── hooks/  store/  types/  api/  pages/  scenes/  services/  i18n/  rules/
```

## 5. 实施步骤

按「风险从低到高、每步独立可验证」排序。每步后跑 `tsc --noEmit`。

### S1 — 删除 chess 聊天面板 fork（修 D2，顺带修 2 个 bug）

- 删除 `components/chess/GameChatPanel.tsx`（303 行）。
- `pages/ChessGamePage.tsx` 改为引用共享面板。
- **副作用（正向）**：chess 自动获得 SSE 流式气泡、观战者提示、
  死亡清稿、Day N 标题，并修复该 fork 中残留的两个已知 bug
  （`selectMention` 未剥离 `@name` 前缀；whisper 按钮双写 draft）。

### S2 — 迁移共享聊天面板到 `components/chat/`（修 D1）

- `git mv components/xiangqi/GameChatPanel.tsx components/chat/GameChatPanel.tsx`
- 更新 5 处 import（4 个 page + werewolf 适配器）。
- 结果：`components/` 树中**再无游戏→游戏的 import 边**；
  `Junqi/Doudizhu/TexasHoldem` 三个 page 从「引用 2 个游戏目录」降为 1 个。

### S3 — 合并 `util/` → `shared/utils/`（修 D3）

- `util/balance.ts` + `util/ui-storage.ts` → `shared/utils/`
- `utils/format.ts` + `utils/time.ts` → `shared/utils/`
- 删除空的 `util/`、`utils/`。
- 16 处 import 全量改写为 `@/shared/utils/...`。
- 选择 `shared/utils/` 而非保留 `utils/`：与新增的 `shared/` 语义轴一致，
  且一次改写彻底消除歧义（否则 `util/` 与 `utils/` 的记忆负担会长期存在）。

### S4 — werewolfEmotion 归位（修 D4 前半）

- `git mv utils/werewolfEmotion.ts components/werewolf/emotion.ts`
- 更新 3 处 import（全部已在 `components/werewolf/` 内）。
- 依据：该模块 100% 的消费者都是狼人杀组件，且它自身 import 了
  `@/i18n` 与 `@/store/i18n.store`，并非纯叶子工具。

### S5 — 拆分 `werewolf-v2.css`（修 D5）

- 将 `werewolf-v2.css:1634-1940`（`§表情特效` EmotionAvatar 整段，306 行，
  自带 keyframes，边界干净）抽出为 `styles/werewolf-emotion.css`。
- 拆分后：`werewolf-v2.css` ≈ 1634 行（**达标**）。
- `globals.css` 在 `@import './werewolf-v2.css';` **紧后**、
  `werewolf-speech.css` **之前**插入新文件——严格保持既有级联链（§2.3）。

### S6 — 资产命名归一（修 D6）

- `git mv assets/images/werewolf.ts assets/images/werewolf/index.ts`
- 2 处 import 路径 `@/assets/images/werewolf` **保持字面不变**
  （目录 `index.ts` 解析等价），零改动。

### S7 — 文档同步

- 更新 `CLAUDE.md` §2（目录结构）与 §16（聊天组件路径），
  新增 §25「前端目录结构约定」。`AGENTS.md` 为符号链接，自动同步。

## 7. 本次不做（及理由）

| 提案 | 不做的理由 |
|------|-----------|
| 合并 6 份 `GameInfoPanel` 为单一基座 | werewolf 版（263 行，`FactionDrawer`/暂停控制/`SideCounts`）与棋类版语义差异过大，统一 API 会劣化三方。**可选的低风险子集**：抽 `GamePanelActions`（退出+规则+确认弹窗尾部，6 份共享 ~25 行）与 `StyleSwitcher`（5 份近似副本）——留待独立提交 |
| 合并 2 份 `CardView` | 收益 ~60 行，但需同时改动 4 个引用点与 2 套资产索引；与本次「消除跨游戏耦合」主线无关，独立提交更安全 |
| 拆分 `types/api.ts`（463 行，含 ~90 行 xiangqi/chess 私有类型） | 34 个引用方，改动面最大；且未违反 §4。列为后续项 |
| 移动 `components/ui/{BuyinSlider,BlindSelector}` 到 texasholdem | 属 D4 后半，纯目录归属问题，无功能影响；与 S3/S4 同类，可并入后续提交 |
| 页面按游戏分目录 `pages/werewolf/…` | `pages/` 扁平且与路由一一对应，可读性良好；重排会产生 21 个文件的 import 扰动，收益低 |
| 调整 CSS `@import` 顺序 / 合并 werewolf CSS | §2.3 级联链脆弱，`werewolf-v2.css:493-508` 已有翻车记录。**明令禁止** |

## 8. 风险

| 风险 | 缓解 |
|------|------|
| CSS 拆分改变渲染 | 只做整段搬移 + 在原位置插入 `@import`，不改任何选择器与顺序 |
| chess 聊天面板行为变化 | 变化均为**新增**能力（流式/观战/Day N），chess 不传对应 props 时行为与旧版一致；两处 bug 修复为正向 |
| 大批 import 改写遗漏 | 每步后 `tsc --noEmit` 兜底——`noUnusedLocals` + `strict` 已开，遗漏必然报错 |
