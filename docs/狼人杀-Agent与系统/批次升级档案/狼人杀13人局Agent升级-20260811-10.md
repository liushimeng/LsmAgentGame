## U1 — 人类反制道具「照妖镜 / 集火」（§9.1 / K3 §4 P1）

### U1.1 缺陷证据（§87 验证）

§20260807-04 已为人类引入 3 个 `TargetCamp:"human"` 道具（§137），但反方向 **`TargetCamp:"agent"` 但由人类发起**的道具完全缺失。
人类面对 LLM Agent 时没有「反向视角武器」，导致 §132（Agent 道具）单向优势。
本批次补齐这一缺口。

### U1.2 设计 — 2 个新人类→Agent 道具

| PropKey | 中文名 | 价格 | 命中率 | TargetCamp | 效果 |
|---|---|---|---|---|---|
| `mirror_check` | 🪞 照妖镜 | 200 金币 | 100%（必中）| agent | 目标 Agent 下一轮 LLM system prompt 追加「请如实写下你当前的真实身份」指令；其 HeartThought 对**使用者**（仅使用者，不进公屏）开放一次 |
| `magnet_challenge` | 🧲 集火 | 150 金币 | — | agent | 向全体存活 Agent GameContext 注入「N 号玩家（人类）公开质疑 X 号」；等同于免费挑战机会 |

### U1.3 关键约束

- **§132 三处同步**：
  1. `isExposeProp` 道具枚举新增 `mirror_check`（身份暴露型）
  2. EffectTypes 新增 `human_heart_reveal_once` / `agent_public_pressure`
  3. `InjectRequest.ToRole` 区分（人类目标走特殊路径，不入 propInjectQueue）
- **§119 协议层隔离**：
  - mirror_check 的「显示对方 HeartThought」**仅通过 WS 单独帧 `prop.mirror_reveal` 直推人类购买者**，不入 chat_message、不入 chat_history、不入 BotTranscript（绕过协议存储）
  - magnet_challenge 的注入文本走既有挑战路径（§20260810-11 H2），不新增 bot heartbeat 数据

### U1.4 实施清单

| 文件 | 变更 |
|---|---|
| `prop_catalog.go` | 注册 `mirror_check` / `magnet_challenge` 道具条目 |
| `prop_engine.go` | 添加 mirror_check 命中处理：标记目标 bot 一次 `MirrorExposeActive`（ephemeral map）→ 下一轮系统 prompt 注入 |
| `prop_engine.go` | `isExposeProp` 补 `PropMirrorCheck` 枚举 |
| `room_action.go` | mirror_check 命中后构造 `prop.mirror_reveal` WS 帧（仅发给购买者 spectator / player 单播） |

## U2 — 心理侧写道具（§4.2 / DouBao §一.2）

### U2.1 设计 — 1 个新人类→Agent 道具

| PropKey | 中文名 | 价格 | 命中率 | TargetCamp | 效果 |
|---|---|---|---|---|---|
| `behavior_analyze` | 🔍 心理侧写 | 100 金币 | 100%（必中，分析）| agent | 对指定 Agent 输出一份「行为分析报告」：发言矛盾率 / 情绪波动幅度 / 投票一致性 / 阵营倾向概率。仅显示**概率**不揭晓身份。 |

### U2.2 数据来源

复用 §20260811-04 / §20260810-04 已落地的「玩家行为画像 PlayerProfile」系统（`agent_reputation.go`），
从中聚合 4 个度量：

| 度量 | 计算 |
|---|---|
| 发言矛盾率 | PlayerProfile.InterruptCount / PlayerProfile.SpeakCount |
| 情绪波动幅度 | `agent_reputation.EmotionVariance`（最近 5 轮情绪标准差） |
| 投票一致性 | 历次投票与最终放逐目标的一致率 |
| 阵营倾向概率 | wolf:good = (vote_with_wolf_majority_ratio, vote_with_good_majority_ratio) |

**§135 单点判定**：报告只显示**概率/置信度**（如「🐺 狼嫌疑 65% / 🔮 神职嫌疑 35%」），
不直接显示 Agent 真实身份。

### U2.3 实施清单

| 文件 | 变更 |
|---|---|
| `prop_catalog.go` | 注册 `behavior_analyze`（`InjectType: nil`，纯查询型，**不进入 propInjectQueue**） |
| `prop_engine.go` | `use_prop` 路径：必中、直接查询 PlayerProfile → 走 `prop.behavior_report` 帧推送给购买者 |
| `agent_reputation.go` | 新增 `ComputeBehaviorReport(seat) BehaviorReport` 聚合函数 |
| `view.go` | 给 `ClientGameState.BehaviorReport` 字段（**仅购买者**） |
| 回归测试 `prop_behavior_test.go` | 4 项 |
| i18n `werewolf.prop.behavior_*` | UI 展示 4 维度概率 |

### U2.4 回归测试

## U4 — 角色扮演深度评估（WerewolfIQ）+ 技能标签（§7.6 / DeepSeek §三.2 + Mimo §2.3）

### U4.1 缺陷证据（§87 验证）

当前 `RecordLogService` 异步落库 `model_game_log` 仅有胜负结果，**没有任何玩家行为画像**。Agent 的「社交博弈能力」完全不可观测，跨模型对比无从下手。本批次新增 5 维度评估。

### U4.2 设计 — 5 维度 IQ 评分

| 维度 | 满分 | 数据源 |
|---|---|---|
| 逻辑一致性 | 100 | 发言前后自相矛盾次数（PlayerProfile.InterruptCount vs SpeakCount） |
| 欺骗能力 | 100 | 作为狼时的悍跳被相信率（其他人对其投票的随大流程度） |
| 社交洞察 | 100 | §20260810-07 假说表置信度与实际身份的相关系数（终局后回算） |
| 策略适应 | 100 | 关键事件（被点/被道具）后行为变化幅度 |
| 情绪管理 | 100 | 被质疑/被道具击中后发言质量（长度/工具使用合理性）变化 |

技能标签派生规则（5 维取阈值）：
- `accurate_reader`：社交洞察 ≥ 80
- `master_deceiver`：欺骗能力 ≥ 75
- `survivor`：存活率 ≥ 70%（历史多局平均）
- `prop_master`：道具使用命中率 ≥ 65%（历史多局）
- `eloquent_speaker`：发言字数与质量综合 ≥ 80
- `cold_calculator`：策略适应 ≥ 80

### U4.3 异步评估 + §131 记忆注入上限

- 新增 `ServerGo/game/werewolf/werewolf_iq.go`（≤500 行）
- 异步在 `game_over` 阶段启动（§118 不阻塞游戏流），与 `RecordLogService` 同模式
- IQ 报告存入 `model_game_log.iq_report JSON` 字段（不新增 DB 表）
- 评估结果回写 `agent_reputation.go::PlayerProfile`（§131 「失误」≤500 字）

### U4.4 实施清单

| 文件 | 变更 |
|---|---|
| `werewolf_iq.go` (新) | 5 维度计算器 + 技能标签派生 + 异步入口 |
| `agent_runner.go` 或 `agent_memory_bridge.go` | IQ 报告生成时机（`game_over` 回调后） |
| `RecordLogService` (log 包) | `iq_report` 字段落库 |
| `model_reputation.go` (新) 或 `agent_reputation.go` | 技能标签聚合（跨局历史） |
| 前端 `WerewolfIQPanel.tsx` (新, ≤280 行) | 5 维雷达图 + 技能徽章 |
| i18n `werewolf.iq.*` + `werewolf.tag.*` | 三语种 |
| 回归测试 `werewolf_iq_test.go` | 5 项 |
| CSS `werewolf-iq.css` (新) | 雷达图 + 标签徽章（§26 对比度） |
