# 狼人杀 13 人局 Agent 升级 — §20260810-10

> **批次定位**：第 10 批 Agent 升级（承接 §20260810-01 ~ 09）。
> **采纳来源**（`Agent-Surpport-01.md` 优先级总表）：
> - **U1 狼队角色分工定位（`WolfRoleAssignment` + 轮值狼王）** — DeepSeek §二.3 + DouBao §二.4 二期（优先级 P3-C）
> - **U2 模型自我认知注入（`ModelSelfPortrait`）** — DeepSeek §五.1（优先级 P5-C）
>
> **选题理由**：两项都是"让 Agent 从『反应者』升级为『有策略身份的推演者』"这一主线上
> 剩余建议中最重要、最复杂的：
> - U1 是**狼队阵营博弈深度**的核心 —— 现有 `wolf_whisper`（§20260810-04 U1）只提供了
>   "能说话"的通道，但没有"说什么"的结构；4 只狼若没有人设分工，公屏行为趋同、悍跳/倒钩
>   全靠各模型自发，博弈层次明显弱于真人局。分工 + 轮值狼王把狼队从"平行发言"升级为
>   "有组织犯罪"。
> - U2 是**Agent 元认知**的地基 —— 跨局记忆（§131）、天梯聚合（§20260810-03 F3）、
>   耗时公平性统计（§120）三块数据此前**从未回流到 Agent 自己的决策 prompt**；
>   让模型知道自己"狼胜率高 / 发言偏长 / 响应偏慢"，是后续难度分级（P2-B）、
>   人设化（P2-C）、WerewolfIQ（P6-I）全部依赖的公共输入。
>
> 两项均为**纯增量**：不改博弈规则、不改 wire 协议、不动 §119/§135 隔离边界。

## 1. U1 狼队角色分工定位（WolfRoleAssignment）

### 1.1 现状审计

- `WolfPackRoom`（`ServerGo/game/werewolf/wolfpack_room.go`）已有：FIFO 留言通道
  （≤50 条 × ≤80 字）、`SetMembers` / `PurgeByDeath` 死亡清理、协议层隔离。
- `wolf_whisper` 工具（§20260810-04 U1）在 `speak` + `night_wolves` 双阶段挂载。
- **缺口**：狼队没有任何结构化分工概念 —— 4 只狼各自为战，谁来悍跳预言家、谁倒钩、
  谁深水全靠 LLM 即兴，经常出现"0 狼悍跳"或"2 狼同时悍跳"的塌房局面。

### 1.2 设计

#### 1.2.1 四种战术定位

| 角色（WolfPackRole） | 职责 | 公屏发言风格 |
|---|---|---|
| `悍跳位`（hype） | 假冒预言家，争夺警徽 | 高调、自信、主动报查验 |
| `冲锋位`（charger） | 为悍跳位造势、攻击真预言家 | 激进、煽动、带节奏 |
| `倒钩位`（hook） | 假装好人混入好人阵营，必要时卖队友 | 随大流、温和 |
| `深水位`（deep） | 极端低调，不被注意，留到最后 | 划水、装平民、少说话 |

数量映射（狼数 → 分工模板，按座位升序依次指派）：

| 存活狼数 | 模板 |
|---|---|
| 4 | 悍跳 / 冲锋 / 倒钩 / 深水 |
| 3 | 悍跳 / 冲锋 / 倒钩 |
| 2 | 悍跳 / 倒钩 |
| 1 | （不指派，独狼自由发挥） |

#### 1.2.2 自动分工 + 轮值狼王

- **自动分工**：`StartAgentsLocked` 在 `wolfPack.SetMembers(allWolfSeats)` 之后调用
  `wolfPack.AutoAssignRoles(allWolfSeats)`（纯函数、确定性：按座位升序套模板，
  **不引入随机**，保证同房间所有路径结论一致）。
- **轮值狼王**：`AssignRoles` 后 `KingSeat = 狼座位[0]`；每当夜晚进入
  `night_wolves` 阶段（`startNight` / 引擎入口）若当前 King 已死，则
  `RotateKingLocked` 顺延到下一个存活狼。
- **重协商工具**：新增 Agent 工具 `wolfpack_assign {role: enum}`：
  - **仅当前轮值狼王**可见（`MountIf: faction==wolf && gc.WolfKingSeat==gc.MySeat`）；
  - 调用后把**自己**的分工改为指定值，其余狼自动按模板重排空缺位；
  - 修改结果以一条系统留言（`FromSeat=-2`）写入 WolfPackRoom，全狼可见；
  - 失败（非狼王 / 阶段不符）返回 rejected 文案，**不**计入 consecutiveFailures。

#### 1.2.3 注入链路（§133 协议层隔离）

- `GameContext` 新增字段（`wwtypes/context.go`）：
  - `WolfPackRole string` — 本 bot 的分工（"" = 未指派/非狼）；
  - `WolfPackRoleTable map[int]string` — 全狼分工表（仅狼 bot 可见）；
  - `WolfKingSeat int` — 当前轮值狼王座位（-1 = 无）。
- `buildAgentContextLocked` 在既有 WolfPackSnapshot 分支旁填充上述三字段。
- `WolfPackPromptBlock`（`agent/wwplayer/prop_blocks.go`）末尾追加分工段：

  ```
  🐺 狼队战术分工（仅狼队可见）:
  - 你是【悍跳位】:假冒预言家争夺警徽,发言高调自信
  - 分工表: 3号=悍跳位 / 7号=冲锋位 / 9号=倒钩位 / 12号=深水位
  - 本轮狼王: 3号(狼王可用 wolfpack_assign 重排分工)
  ```

- **隔离红线**：分工信息**只**走 GameContext → user prompt；
  **不**写入 `chat_message` 表 / `chat_history` 队列 / `BotTranscript.HeartThought`；
  观战者 `view.go` 不下发（§119 同 wolf_whisper 留言）。

#### 1.2.4 死亡与重开局

- `PurgeByDeath` 扩展：除清理留言外，把死亡狼从 `Roles` 表中移除；
  若死的是 King，立即触发 `RotateKingLocked`（该函数已在 EmitPlayerDied 持锁路径
  调用，符合 §92a —— `RotateKingLocked` 为 `*Locked` 变体，公开入口包锁委托）。
- `restartGameLocked` 走既有 `resetPropStateLocked` 同位置调用
  `wolfPack.ResetAssignments()`，下一局 `StartAgentsLocked` 重新自动分工。

### 1.4 约束对照

- **§92a**：`AssignRoleLocked` / `RotateKingLocked` 为锁内变体；`agentRunner.WolfpackAssign`
  走 `TryLock` 短持锁（同 `WolfWhisper` 现有模式）。
- **§97**：不新增 phase、不新增引擎动作 → 五处同步**不需要**（`wolfpack_assign`

- **§119**：分工表 + 系统留言都不进 chat 表/队列，协议层隔离。
- **§130**：所有新字段在 `buildAgentContextLocked` 有真实填充点，单测 grep 级验证。

## 2. U2 模型自我认知注入（ModelSelfPortrait）

### 2.1 现状审计

- §20260810-03 F3 已落地 `ModelLogService.Leaderboard()`（games/wins/win_rate/
  avg_tokens/net_coins 聚合，基于 `t_lsm_game_model_game_log`）。
- §120 已有 per-bot `avgLLMLatencyMs`（本局运行时统计）。
- §131 已有跨局 `memory_md`（自由文本）。
- **缺口**：胜率/角色表现/速度档这些**量化特征**从未进入 Agent 的 prompt ——
  模型不知道"我狼人胜率 38% 高于平均"，就无法做差异化自我定位。

### 2.2 设计

#### 2.2.1 数据层：`ModelSelfPortrait`

`ServerGo/service/model_log_service.go` 新增：

```go
type ModelSelfPortrait struct {
    ProviderID   string
    ModelKey     string  // 展示名（Join provider 表取 agent_name）
    Games        int64
    WinRate      float64        // 总胜率 0..1
    WolfGames    int64
    WolfWinRate  float64        // role="werewolf" 的胜率
    GoodWinRate  float64        // 非狼角色的胜率
    AvgWinRateAll float64       // 全模型平均胜率(基准线)
    SampleOK     bool           // Games >= 最小样本阈值(默认 8 局)
}
```

- 单条 SQL 聚合：`GROUP BY provider_id` + `SUM(CASE WHEN role='werewolf' ...)`；
  命中既有 `idx_provider_created`；全模型平均胜率用一次 `AVG` 子查询。
- **小样本保护**（§120 公平性）：`Games < 8` 时 `SampleOK=false`，prompt 使用
  「通用自画像」（见 2.2.3），避免 2~3 局的偶然结果被当成"模型特点"。

#### 2.2.2 装配层：房间级快照 + 注入 system 末尾

- `WerewolfRoom` 新增 `modelPortraits map[string]*service.ModelSelfPortrait`
  （key = provider modelKey），`StartAgentsLocked` 中经可选接口
  `PortraitProvider`（`m.modelLogs` 已实现则注入，nil 时跳过）一次性拉取本房间
  涉及的全部 modelKey 快照。**一局拉一次**，挂在房间上，agent 创建时直接引用，
  避免每轮 LLM 调用都查 DB（§118 异步/缓存友好）。
- `wwplayer.Agent` 新增可选字段 `SelfPortraitText string`（纯文本，房间装配时生成）。
- `BuildSystemPrompt()` 改签名 → `BuildSystemPrompt(selfPortrait string)`：
  非空时在返回值末尾追加一段 `【🪞 模型自画像】` block；空串时行为与现状
  **逐字节一致**（向后兼容，全部现有测试不受影响）。
  - §20260810-01 D3 教训：这次签名变化是**真实消费**参数（直接拼进返回值），
    不是"声明了却从不接线"；单测断言文本确实出现在 system 末尾。
- 注入 **system 末尾**而非 user：system 块在 Anthropic prompt cache 中命中前缀，
  自画像一局不变，天然缓存友好。

#### 2.2.3 文案模板

样本充足（`SampleOK=true`）：

```
【🪞 模型自画像 — 你在本平台的历史表现】
- 总对局: 23 局, 综合胜率 43.5%(全模型平均 31.2%)
- 狼人胜率: 55.6%(9 局) — 你擅长欺骗与伪装,拿狼可更主动悍跳
- 好人胜率: 35.7%(14 局) — 你当好人时容易被骗,投票前多交叉验证
- 建议: 发挥狼人侧优势;好人侧对「一个人的孤证」保持怀疑
```

小样本（`SampleOK=false` 或无 DB 数据）：

```
【🪞 模型自画像 — 通用基线】
- 本平台对局数据不足(<8 局),使用通用策略基线:
- 狼人: 优先悍跳预言家争夺警徽,发言自信
- 好人: 少下结论,多交叉验证他人发言
```

速度档（复用 §120 avgLLMLatencyMs，**运行时 user prompt 已有**，不重复进 system）。

#### 2.2.4 隐私与公平性

- 自画像只含**聚合统计**，不含任何单局聊天原文、不含对手信息 → 不触碰 §135。
- 所有 bot 在**同一局**内都能拿到自己的自画像 → 对称信息，不产生新的不公平。
- 开关：`werewolf.model_self_portrait_enabled`（默认 `true`；`false` 时
  `SelfPortraitText=""`，`BuildSystemPrompt` 输出与现状一致）。

### 2.4 约束对照

- **§118**：DB 查询只在开局 `StartAgentsLocked` 发生一次；失败仅 `logger.Warn`
  降级为通用自画像，不阻塞游戏流。
- **§120**：`SampleOK` 阈值防小样本偏差。
- **§130**：`SelfPortraitText` 在 `run.go` 两处 `BuildSystemPrompt` 调用点
  真实消费；单测断言文本注入。
- **§121**：不改任何 HTTP API → 无前后端 wrapper 同步问题。
- **§14**：`ModelSelfPortrait` 只读 `t_lsm_game_model_game_log`，不污染 LLM
  Provider 模块。
