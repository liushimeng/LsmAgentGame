# 狼人杀 13 人标准竞技局 · 房间聊天增强设计

> 实施日期:2026-07-09
> 关联规则:[`docs/狼人杀13人标准局规则.md`](狼人杀13人标准局规则.md)
> 关联技术:[`docs/狼人杀-Agent与系统/狼人杀Agent设计.md`](狼人杀Agent设计.md) / [`docs/狼人杀观众唤醒设计.md`](狼人杀观众唤醒设计.md)
> 关联历史教训:CLAUDE.md §96(quarantine UI)/ §111(500K 队列)/ §112(发言下限)/ §114(观众全频唤醒)

本文档描述狼人杀 13 人标准竞技局**房间聊天**的三项增强:
1. **whisper 可见性矩阵**——人类玩家 / 观众 / 收信 bot / 其他 bot 各自能看到什么。
2. **模型名称公开**——`Bot N号` 后追加模型名徽章(覆盖 R34 的"模型名隐藏"策略)。
3. **活动事件流**——除了 chat/speak 之外,服务器在 phase 切换 / 投票 / 夜晚击杀 / 预言家查验 / 女巫用药 / 猎人开枪等节点主动向聊天流广播 `chat.activity` 事件,前端用带阶段色的事件条渲染。

## 1. whisper 可见性矩阵

### 1.1 旧行为(R55 之前)

```
Whisper 发送者          → 服务器 BroadcastRoomIncludingSpectators(redacted "[私聊]")
Whisper 发送者/收信者   → 额外收到完整明文 (sendWhisperDirect)
其他 bot(仅 server)    → 收信 bot 与发送 bot 的 500K 队列各存一条
```

前端 `GameChatPanel` 在 `visibleMessages` 内自己过滤:自己发/自己收/管理员 → 显示明文,其他人 → 显示 redacted `[私聊]`。

### 1.2 新行为(本次 §115 增强)

| 收信人 | 是否能看 whisper 明文 | 备注 |
|---|---|---|
| whisper 发送者(自己) | ✅ 总是看明文 | 由 `sender.send` 推送 |
| whisper 收信者(自己) | ✅ 总是看明文 | 由 `hub.SendToUser` 推送 |
| 收信 bot 的 500K 队列 | ✅ 收到明文(LLM 上下文) | `appendRoomMessage` → `appendToChatQueueLocked` |
| 发送 bot 的 500K 队列 | ✅ 收到明文(LLM 上下文) | 同上 |
| **其他 bot 的 500K 队列** | ❌ **不存** | whisper 不进入 other bots 队列 |
| 人类玩家(非收信) | ❌ redacted "[私聊]" | `BroadcastRoomIncludingSpectators` |
| 人类观众(非收信) | ❌ redacted "[私聊]" | 同上 |
| 管理员(非收信) | ✅ 总是看明文 | 客户端 `isAdmin` 过滤 |

**关键点**:`SendFromBot` / `WhisperFromBot` 的 `emitRoomMessage` 调用仍然进入 `appendRoomMessage`,
但 `appendToChatQueueLocked` 在 whisper 分支只写 sender+recipient 两个 bot 队列;
公开 chat 分支仍写所有 alive bot 队列(保持 §111 的 500K 注入语义)。

### 1.3 后端责任

`ServerGo/ws/chat_service.go::Whisper` 和 `WhisperFromBot` 保持双轨广播不变:
- 房间广播 = redacted
- sender.send + hub.SendToUser(recipient) = full payload
- `appendToChatQueueLocked` 内部已经做 sender+recipient 限定(`if toSeat >= 0` 分支),
  其他 bot 队列在 whisper 时不会触发。

**人类 ↔ 人类 / 人类 → 人类** 的 whisper 完全沿用上面规则(redacted 房间 + 明文定向),
不进入 bot 队列(appendRoomMessage 找不到 bot 座位)。

### 1.4 前端责任

`ClientWeb/src/components/xiangqi/GameChatPanel.tsx` `visibleMessages` filter 保留。
新增 helper `isWhisperVisibleToMe(m, myUserId, isAdmin)`:
- `!m.whisper` → true
- `isAdmin` → true
- `m.from_user_id === myUserId` || `m.to_user_id === myUserId` → true
- else → false

## 2. 模型名称公开(覆盖 R34 §115)

### 2.1 旧行为(R34 BUG-WEREWOLF-P1-NEW-32)

R34 报告后,出于"防止玩家 meta-strategy(基于模型名推测行为)"的考虑,
`SendFromBot` 把 `FromAgentName` 强制置空;`WhisperFromBot` 仍保留。
该决策的副作用:玩家无法在 UI 上区分 7 个 bot 各自用了什么模型,
调试 / 复盘时也缺少信息。

### 2.2 新行为(§115 翻转)

`FromAgentName` 恢复推送:
- `SendFromBot`:`FromAgentName: s.lookupAgentName(modelKey)`
- `SendInterjectFromBot`:同样
- `WhisperFromBot`:同样
- `History()` room scope bot 装饰:同样(从 `botModel` map 取)

**理由**:
- 玩家体验侧:7 个 bot 名字雷同(`Bot 1号` … `Bot 7号`)在 7-AI 房缺乏辨识度,
  模型名是低成本的差异化手段。
- 调试 / 复盘侧:测试报告(每轮 `AutoDebugTestReport.md`)需要按模型归类
  思考/行为,模型名是元信息。
- 隐私侧:模型名是 LLM 服务侧的标识,不是用户身份,泄露不构成隐私问题。

### 2.3 前端渲染

`GameChatPanel` 当前已渲染 `🤖 ${from_agent_name}` 徽章(`role-badge--bot`),
`from_agent_name` 恢复后立即可见,无需额外改动。

## 3. 活动事件流(`chat.activity`)

### 3.1 目标

在房间聊天流中,除了 `chat.message` (speak/interject/whisper) 之外,
服务器在关键游戏节点主动广播**结构化活动事件**,让玩家和观众
能在不离开聊天面板的情况下跟踪游戏进度。

### 3.2 事件类型

| EventKind | 触发位置 | 中文标签 | 默认色 |
|---|---|---|---|
| `phase_transition` | `room.advanceDayLocked` / `setPhaseLocked` | `→ 切换到 X 阶段` | 灰 |
| `round_start` | `State_Begin` 第 1 次 / `advanceDayLocked` 跨日 | `第 N 天 开始` | 蓝 |
| `night_start` | `setPhaseLocked(PhaseNight)` | `🌙 夜晚降临` | 紫 |
| `day_start` | `setPhaseLocked(PhaseDay)` | `☀️ 天亮了` | 黄 |
| `wolf_kill` | `wolfKillLocked` | `🐺 狼人击杀 X号` | 红 |
| `seer_check` | `seerCheckLocked` | `🔮 预言家查验 X号` | 紫 |
| `witch_act` | `witchActLocked` | `🧪 女巫使用 X 药` | 绿 |
| `vote_cast` | `Action_Vote` 成功后 | `🗳 X号 投票给 Y号` | 灰 |
| `vote_result` | `finishVoteLocked` | `📊 投票结果:X号 出局` | 红 |
| `hunter_shoot` | `hunterShootLocked` | `🏹 猎人开枪: X号` | 红 |
| `sheriff_elect` | `sheriffElectLocked` | `⭐ 警长:X号` | 金 |
| `game_over` | `checkWinner` 触发 | `🏆 游戏结束:X 阵营胜利` | 金 |
| `player_died` | `killPlayer(seat, cause)` | `💀 X号 死亡(原因)` | 灰 |
| `quarantine` | `setQuarantine` | `🚫 Bot N号 已被禁用` | 橙 |
| `auto_skip` | watchdog 派发 | `⏭ 系统自动跳过` | 灰 |

### 3.3 wire 协议

```
server → client: chat.activity {
  id:            number   // 与 ChatMessage 共用 id 列(可空)
  room_id:       string
  event_kind:    string   // 见上表
  text:          string   // 人类可读中文(前端可覆盖)
  phase:         string?  // 当前 phase(便于前端按阶段色)
  round_number:  number?  // 第几天
  ts:            number   // unix millis
  severity:      "info"|"success"|"warn"|"error"  // 默认 info
  icon:          string?  // emoji 前缀(可选)
  ref_seat:      number?  // 相关 bot 座位(0..6)
  ref_seat_2:    number?  // 第二相关座位(vote 等)
  silent_for_bots: bool   // true → 不写入 500K 队列(系统内部事件)
}
```

### 3.4 后端实现

**`ServerGo/ws/chat_service.go`** 新增方法:

```go
// EmitRoomActivity 把一条活动事件广播给所有 room 订阅者(玩家 + 观众)。
// silentForBots=true 时不进 500K 队列(仅前端展示)。
func (s *ChatService) EmitRoomActivity(roomID, eventKind, text, phase string,
    round int, severity string, icon string, refSeat, refSeat2 int, silentForBots bool) {
    env := Envelope{Type: "chat.activity", Payload: marshal(activity{...})}
    s.hub.BroadcastRoomIncludingSpectators(roomID, env)
    // 转发给 werewolf manager(若已注册 hook);hook 决定是否注入 500K 队列
    s.emitActivity(roomID, eventKind, text, phase, round, refSeat, refSeat2, silentForBots)
}
```

**`ServerGo/game/werewolf/room.go`** 在以下点调用:
- `advanceDayLocked` → `round_start` + `day_start`
- `setPhaseLocked` 内部统一插入 → `phase_transition`
- `wolfKillLocked` → `wolf_kill` (silentForBots=false,但仅在 phase=pre_wolves/post_wolves 时发)
- `seerCheckLocked` → `seer_check` (silentForBots=true,内部信息,系统活动)
- `witchActLocked` → `witch_act` (silentForBots=true)
- `Action_Vote` 内 → `vote_cast`
- `finishVoteLocked` → `vote_result`
- `hunterShootLocked` → `hunter_shoot`
- `sheriffElectLocked` → `sheriff_elect`
- `checkWinner` → `game_over`
- `killPlayer` → `player_died`(若非 wolf/sea/witch 已知事件)
- `setQuarantine` → `quarantine`
- `phaseWatchdogTick` 派发 skip → `auto_skip`

**`ServerGo/game/werewolf/manager.go`** 新增 `OnActivity` 回调,与 `OnGameOver` 类似;
`ChatService` 通过 `SetRoomActivityHook` 注入到 manager,
manager 决定是否把这条事件写入 bot 的 500K 队列(`appendToChatQueueLocked` 接收 `silentForBots` 参数)。

### 3.5 前端渲染

`ClientWeb/src/components/werewolf/GameChatPanel.tsx`(包装)无需改动,
所有 `chat.activity` 通过 `useChat` hook 注入 `messages` 流;
`GameChatPanel` 通过 `m.from_role === 'activity'`(新增枚举值)分支渲染:

```tsx
{m.from_role === 'activity' ? (
  <div className={'game-chat-activity game-chat-activity--' + (m.severity || 'info')}>
    <span className="game-chat-activity__icon">{m.icon || 'ℹ'}</span>
    <span className="game-chat-activity__text">{m.text}</span>
    <span className="game-chat-activity__time">{formatChatTime(m.ts)}</span>
  </div>
) : (
  /* 原 chat.message 渲染 */
)}
```

颜色方案:

| severity | 边框色 | 背景色 |
|---|---|---|
| info | `#cbd5e1` | `rgba(148,163,184,.10)` |
| success | `#10b981` | `rgba(16,185,129,.12)` |
| warn | `#f59e0b` | `rgba(245,158,11,.12)` |
| error | `#ef4444` | `rgba(239,68,68,.12)` |

`phase` 字段驱动左边细线颜色(夜晚=紫,白天=黄,投票=灰)。

### 3.6 持久化

`chat.activity` **不写 DB**(避免污染 `t_lsm_game_chat_message`),
前端通过 `game.state` 的 `phase` / `round_number` 字段已经能拿到大部分信息,
活动事件是**实时**信号(例如"刚投票出局"瞬间出现),不需要回放。

如果未来要支持"重连后回放最近 N 条活动",可在 Redis 加一个 room-scoped 环形 buffer,
目前不做(与 §111 的 500K 队列是不同语义:500K 是 LLM 上下文,这里是 UI 提示)。

                  │ ChatService  │

  WS subscribers    (sender+rcpt for
                    whisper, all for

## 5. 安全与隐私

- **whisper 明文**只在定向通道(`sender.send` / `hub.SendToUser`)传输,
  房间广播永远是 redacted 形式(防御 §R55 教训)。
- **活动事件**不含任何玩家身份信息,只含 `seat` (0..6),与 `game.state` 已有字段一致。
- **模型名**是 LLM 服务侧标识,非用户身份,可公开。
