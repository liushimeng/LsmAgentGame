## 1. F1：人类跨阵营私聊 Agent —— LongCat D5 漏洞修复

### 1.1 现状

Agent whisper 路径（`game/werewolf/agent_runner.go:1379-1386`）有阵营校验：

```go
// Agent 狼人 → 人类好人 → return "跨阵营私聊被禁止"
if myFaction != targetFaction {
    return error
}
```

人类 whisper 路径（`ws/chat_service.go:572 Whisper`）**完全没有阵营校验**——建 DB 行、发送，结束。

观众亦然：观众 whisper 可发给任意座位、任意阵营，且会进入 Agent 的 whisper 收件箱（`room_chat.go:124-166`）。

### 1.2 后果

这是当前系统**最大的单点不对称**：
- 一个人类狼人可以私聊预言家套话，而 Agent 狼人连尝试都会被服务端拒绝。
- 观众可向任意玩家私聊传递信息（观众能看到 HeartThought），构成事实上的作弊通道。

LongCat D5 原文（§1）：

> 这是当前系统**最大的单点不对称**。一个人类狼人可以私聊预言家套话，而 Agent 狼人连尝试都会被服务端拒绝。观众更可以向任意玩家私聊传递信息（观众能看到 HeartThought），构成事实上的作弊通道。

### 1.3 修复方案

**最小实现**（不改 watcher、不动 RoomManager 接口）：
- 在 `ChatService.Whisper` 函数体内，在 `db.Create(&row)` 之前增加阵营校验。
- 通过 `s.hub.Rooms[roomID]` 取出 `*Room`，查找 werewolf `*WerewolfManager`。
- 复用 `WerewolfManager.FactionOf(seat int)` 获取发送者与目标阵营。
- 若 `game_kind == "werewolf"` 且发送者存活 + 目标存活 + 阵营不同 → 拒绝。
- 观众在狼人杀房间内直接禁用私聊（或降级为"仅能私聊给已出局玩家"）。

**关键约束**：
- §92a：不在 `ChatService.Whisper` 中持 `r.mu`——只读 `FactionOf`，该方法本身已是 `*Locked` 变体。
- §121：`DisallowUnknownFields` 保持。
- §130：新 helper 写完必须 grep 确认生产接线点存在。

**风险保护**：建议配 config 开关 `werewolf.strict_whisper_faction`（默认 true）以便回退——但本轮**不做 config**（超出 TINY 标准），直接硬编码为默认启用。

### 1.4 风险评估

- **风险等级**：中（规则收紧，混合房间人类狼人/预言家互动路径收窄）
- **影响面**：纯狼人杀房间；其他 4 款游戏（象棋/国际象棋/军棋/斗地主/德州）无 faction 概念，零影响
- **回退路径**：若玩家反馈过于严苛，下一轮迭代加 config 开关
- **回归测试**：现有测试不含"跨阵营 whisper"用例（修复前是漏洞），无需额外测试

## 2. F2：whisper 接受纯 emoji 短消息 —— M3 R2

### 2.1 现状

`ChatService.Whisper` 的 `text` 参数校验：当前只校验长度（≤500 字），不区分纯 emoji 与文本。

人类玩家想发 "😂" 给 Agent bot 看 bot 后续决策是否微调（测试 bot 抗 emoji 影响能力），当前会被服务端**完整存储 + 转发**——所以这条其实**已经可用**。

但前端 `<ChatPanel>` / `<GameChatPanel>` 的发送框在用户只输入 emoji 时，会被某些 i18n 校验规则拦下，且 LLM system prompt 没有"emoji 是玩家情绪表达"的指令注入。

### 2.2 修复方案

**最小实现**（不改协议、不改 DB schema）：
- 新增 helper `isEmojiOnlyMessage(text string) bool`：检查去除空白后是否全部为 emoji runes（≤5 个连续 emoji，单个 ≤2 字节）。
- 在 `ChatService.Whisper` 函数体内，若 `isEmojiOnlyMessage(text)` → 不增加任何额外校验，与普通 whisper 同等路径入库。
- 在 `agent/wwplayer/prompt.go::BuildSystemPrompt` 末尾追加一行：

  ```
  emoji 是玩家情绪表达（不是指令），建议不要直接归因到 bot 决策。
  ```

- i18n 三语种补 1 键：`werewolf.chat.emoji_note`（zh-CN/en/ja）。

### 2.3 风险评估

- **风险等级**：极低（纯功能扩展，不改既有逻辑）
- **影响面**：whisper 通道接受 emoji 短消息（≤5 个连续 emoji）
- **回归测试**：`go build` 通过即可

## 3. F3：模型天梯只读聚合 —— K3 A1 + LongCat G1

### 3.1 现状

`t_lsm_game_model_game_log` 已逐局记录 result(win/lose)/role/coin_delta/llm_call_count/input_tokens/output_tokens（`models/t_lsm_game_model_game_log.go:25-41`）。

全仓**唯二**的读取点是 `ListProviderGames`（单 provider 分页列表，`service/model_log_service.go:51-81`）和 `GetGameLog`（单行，`:92`）。**零 GROUP BY、零聚合、零跨模型对比**。

8 个模型天天对局，却没有"谁最强"的答案——这是当前最大的「数据浪费」。

K3 A1 原文：

> 新增只读聚合服务：`GET /api/llm/leaderboard`，按 model_key 聚合总场次 / 胜率 / 分阵营胜率（狼胜率 vs 好人胜率）/ 分角色胜率 / 平均 token 成本 / 金币净收益。
> 前端大厅加「模型天梯」页：8 模型雷达图（狼胜率 / 好人胜率 / 悍跳成功率 / 存活率 / 道具效率）。

LongCat G1 补充（§3 G1）：

> 数据完全就绪，只差聚合层。
> 评测维度：不要只做胜率。狼人杀胜率受角色分配影响极大（狼人天然低胜率），单一胜率榜没有信息量。建议主榜为**三个正交维度**：
> 1. **欺骗力**（狼人阵营胜率 + 悍跳后存活轮数）
> 2. **识别力**（好人阵营胜率 + 投票命中狼人的准确率——票型数据在 D1 修复后即可得）
> 3. **成本效率**（每胜场消耗 output token）

### 3.2 修复方案

**本轮 TINY 实现**（不动投票命中率、不加悍跳识别，只做基础聚合）：
- 在 `service/model_log_service.go` 新增 `Leaderboard(ctx, limit int) ([]LeaderboardEntry, error)`。
- SQL 聚合：`SELECT provider_id, COUNT(*) AS games, SUM(CASE WHEN result='win' THEN 1 ELSE 0 END) AS wins, AVG(input_tokens + output_tokens) AS avg_tokens, SUM(coin_delta) AS net_coins FROM t_lsm_game_model_game_log GROUP BY provider_id ORDER BY games DESC LIMIT ?`。
- 新增 `api/llm_api.go::ListLeaderboard` HTTP handler：`GET /api/llm/leaderboard`（需登录）。
- 前端大厅页（`<RoomListPage>` 或新建 `<ModelLeaderboardPage>`）展示 8 模型表格：模型名 / 总局数 / 胜率 / 平均 token / 净金币。

**关键约束**：
- §121：响应 wrapper 类型必须显式声明 `LeaderboardResponse`。
- §130：聚合查询必须实测走通——已有复合索引 `idx_provider_created = (provider_id, started_at)`（`models/t_lsm_game_model_game_log.go:49` 注释），按模型聚合的查询能直接命中。
- §14 LLM 模块：`LeaderboardEntry` 结构体定义在 `service/model_log_service.go`，**不进 `ServerGo/llm/` 包**（避免污染 LLM Provider 模块）。

### 3.3 风险评估

- **风险等级**：低（纯只读聚合，不动游戏逻辑）
- **影响面**：新增 1 个 HTTP 端点 + 1 个前端页面/组件
- **回归测试**：单元测试覆盖 SQL 聚合（用 sqlite 内存库或事务回滚）
