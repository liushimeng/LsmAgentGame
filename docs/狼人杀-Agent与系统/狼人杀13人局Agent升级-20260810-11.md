## 1. H1 — 法官「高光时刻」第 6 段

### 1.1 设计目标

- 法官整局总结从 5 段扩到 6 段，**追加「【高光时刻】」** 段。
- LLM 输入额外提供：每 seat 的 `LastDecisionSummary`（§128）/ 道具命中事件（§137）/ 情绪切换历史（§213）。
- LLM 输出：3 个戏剧化瞬间 `{seat, moment, quote}`（K3 §2 V1 范式）。
- 前端 `SettlementModal` 渲染 3 张高光卡片（已有栏目，新加 1 列）。

### 1.2 实现要点

1. **SummarySections 扩字段**（`ServerGo/agent/wwjudge/judge_summary.go`）：
   ```go
   type SummarySections struct {
       Outcome       string
       TurningPoint  string
       RoleTimeline  string
       MVP           string
       WolfDeception string
       Highlight     string  // 【新】高光时刻(3 个戏剧化瞬间,JSON 数组字符串)
   }

   type SummarySectionsJSON struct {
       // ... existing 5 + Highlight + GeneratedAt + Model
       Highlight string `json:"highlight,omitempty"`
   }
   ```

2. **`BuildSummaryPrompt` 追加**：
   - 输入：`SummaryInput` 新增 `DecisionSummaries map[int]string` + `EmotionHistory map[int][]string` + `PropHits []PropHitEvent`（复用 `prop_blocks.go` 既有结构）
   - 提示语追加：
     ```
     6. 【高光时刻】输出 3 个 JSON 对象,按戏剧性排序:
        [{"seat":1,"moment":"被全场票出时,亮明女巫身份反咬 5 号",
          "quote":"我还有一瓶毒,5 号今晚必死"},
         ...]
        无高光则输出 []
     ```

3. **`ParseSummary` 兼容 6 段**：
   - `titles` 切片从 5 元素扩到 6 元素（追加 `【高光时刻】`）。
   - **向后兼容**：旧 LLM 输出（仅 5 段）`Highlight == ""`，`AllSectionsFilled()` 改为 `HasCoreSectionsFilled()`（不强制第 6 段；非空时校验 JSON 合法）。

4. **`FallbackSummary` 与 5 段同款**，第 6 段在 LLM 失败时填 `"[]"`。

5. **SettlementModal 渲染**（前端 `ClientWeb/src/components/werewolf/SettlementModal.tsx`）：
   - 新增 sub-tab 「🎬 高光」或追加在第 5 sub-tab 内。
   - `try { JSON.parse(sections.highlight) }` → 渲染 3 张卡片（座位标签 / moment 描述 / quote 引文）。
   - 解析失败 → 静默不渲染，不阻塞其他栏目。

### 1.3 §13 教训对齐

- **§92a 锁内变体**：`Highlight` 字段填入走 `recordSummaryInternal`（已锁内），不需新增加锁点。
- **§130 接线验证**：`BuildSummaryPrompt` 拼接 `DecisionSummaries` / `EmotionHistory` / `PropHits` **必须 grep `judge_summary_bridge.go` 确认输入组装接通**（关键易漏点）。
- **§125 5 段格式约束**：「3 个 JSON 对象」必须明确「不允许段标题外的额外字符」才不会污染 `ParseSummary`。

## 2. H2 — 质疑轻量交互 `challenge`

### 2.1 设计目标

- 白天发言阶段：任何存活玩家可对**当前发言者**发起一次公开质疑。
- 工具：Agent `challenge {target_seat, question}` + 人类 WS 帧 `game.werewolf_challenge`。
- 限制：每人每天 1 次（§13 限流模式，参考 `commitment_ledger.go`）。
- 行为：被质疑 Agent 下一轮 prompt 出现「⚠️ 你被 N 号公开质疑：{question}」块。
- 公开广播：走既有 §13 活动流（`Activity.kind="challenge"`），前端 `GameChatPanel` 天然可见。

### 2.2 实现要点

1. **新活动类型**（`ServerGo/game/werewolf/activity_emitter.go`）：
   ```go
   // activity_kind 常量新增
   ActivityKindChallenge = "challenge"

   // emitActivity payload
   type ChallengePayload struct {
       ChallengerSeat int    `json:"challenger_seat"`
       TargetSeat     int    `json:"target_seat"`
       Question       string `json:"question"`
       DayNumber      int    `json:"day_number"`
   }
   ```

2. **`GameState` 字段**（`ServerGo/game/werewolf/wwtypes/...`）：
   ```go
   type Player struct {
       // ... existing
       DailyChallengeUsed      map[int]bool  // 0-indexed day -> 已用(单次)
       LastChallengedBy        int           // -1 表示无
       LastChallengeQuestion   string
   }
   ```
   - 重置时机：`startDay()` 阶段开头重置 `LastChallengedBy = -1` 与 `LastChallengeQuestion = ""`。
   - `DailyChallengeUsed` 持久到 GameOver，避免重开局误读。

3. **Action 工具与 WS 帧**（`ServerGo/game/werewolf/room_action.go` + `ServerGo/ws/game_service.go`）：
   - `Action_Challenge(challengerSeat, targetSeat int, question string) error`
   - 服务端校验：① 白天 speak 阶段；② challenger 与 target 均存活；③ 同一日未用过；④ question 长度 ≤ 60 字。
   - 校验失败返回明确错误码（参考 §121 `ErrChallengeForbidden = 30020`）。

4. **Agent 工具**（`ServerGo/agent/wwplayer/challenge_tools.go`）：
   - `BuildTools` 注册 `challenge` 工具（仅白天 speak 阶段挂载）。
   - 实施：`DispatchTool` 路由 → `WerewolfManager.Action_Challenge`。
   - **限流**：复用 `speakLimiter` 同源 token（`RateLimit(speakLimiter, "challenge")`）。

5. **GameContext 注入块**（`ServerGo/agent/wwplayer/prop_blocks.go` 类比）：
   - `buildAgentContextLocked` 末尾追加：
     ```
     ⚠️ 你被 {challenger_seat+1} 号公开质疑：{question}
     ```
   - **红条样式**（前端 `WerewolfTable.tsx` 顶部 `InjectedBlock` 区）。

6. **前端**：
   - `GameChatPanel` 旁加「❓ 质疑当前发言者」按钮（仅自己存活 + 白天 speak + 当日未用时显示）。
   - 输入弹层 60 字 textarea + 「对 {target+1} 号发起质疑」提交。
   - `Activity.kind="challenge"` 在 `GameChatPanel` 渲染为「💬 N 号质疑 M 号：…」。

### 2.3 §13 教训对齐

- **§130 三处同步**：`Action_Challenge` + `MountTools` 阶段过滤 + `BuildTools` 文档注释 + i18n（§97 教训延伸到工具维度）。
- **§119 协议层隔离**：质疑问题公开，不入 `chat_message` / `chat_history` 队列外的内容。
- **§92a 锁内变体**：`Action_Challenge` → `challengeLocked` 双变体（参考 §134 守卫）。
- **§121 严格校验**：WS 帧用 `DisallowUnknownFields` + 字段长度限制。
- **§128 对话即思考**：质疑回应应走 `speak_with_thought` 而非 `speak`（被质疑可能涉及「心口不一」场景）。

### 2.4 预计规模

- `activity_emitter.go`：+40 行
- `room_action.go`：+80 行（含 `challengeLocked`）
- `wwtypes/...`：+30 行

- `agent/wwplayer/prop_blocks.go`：+20 行（注入块）

## 3. P1 — 胜方道具折扣券 + 败方安慰包

### 3.1 设计目标

- **胜方**：结算后限时 5 分钟「胜方道具折扣券」（下一局购买任意道具享 50% 折扣）。
- **败方**：结算后弹「败方安慰包」 —— 随机 1 个低价值道具（`char_confuse` / `char_confuse_human` / `markdown_bomb`）免费获得一次使用。
- 目的：让金币「花得更快」，反通胀（§133 EconTier 减压）+ 败方「再来一次」激励。

### 3.2 实现要点

1. **新表**（不新建，复用 `t_lsm_game_kv` 即可）：
   - key 前缀：`werewolf_settlement_reward:user:{user_id}:room:{room_id}`
   - value JSON：`{reward_type: "victory_discount_voucher" | "consolation_prop", prop_key: "...", expires_at: int64, used: bool}`
   - TTL：`expires_at - now` < 0 自动忽略。

2. **结算流程接入**（`ServerGo/game/werewolf/engine_day.go` 终局路径）：
   ```go
   func grantSettlementRewardsLocked(r *WerewolfRoom) {
       winnerSide := r.checkVictory()
       for seat, p := range r.State.Players {
           if p.IsBot { continue }  // 仅人类
           userID := p.UserID
           if winnerSide == factionOf(p) {
               // 胜方:50% 折扣券
               saveKV("werewolf_settlement_reward:user:%d:room:%s", userID, r.RoomID, VictoryDiscountVoucher{
                   DiscountRate: 0.5,
                   ExpiresAt:    time.Now().Add(5 * time.Minute).Unix(),
               })
           } else {
               // 败方:随机 1 个低价值道具
               propKey := pickRandomConsolationProp()
               saveKV("werewolf_settlement_reward:user:%d:room:%s", userID, r.RoomID, ConsolationProp{
                   PropKey:   propKey,
                   ExpiresAt: time.Now().Add(5 * time.Minute).Unix(),
               })
           }
       }
   }
   ```

3. **道具购买路径接入**（`ServerGo/game/werewolf/prop_engine.go`）：
   - `UseProp(seat, propKey)` 顶部查询 `t_lsm_game_kv` 有无 `victory_discount_voucher`：
     - 有：`cost = baseCost * 0.5`，扣款后写回 `used: true`。
     - 过期：静默忽略，按原价扣款。
   - `consolation_prop` 在 `UseProp` 顶部判断：若 `cost == 0`（用户标记免费），直接放行不扣款，写 `used: true`。

4. **SettlementModal 接入**（前端）：
   - 结算页追加「🎁 你的奖励」一栏：
     - 胜方：折扣券倒计时（5:00 → 0:00）+ 「下一局使用」按钮。
     - 败方：道具卡片 + 「立即使用」按钮（跳到下一局创建时自动装备）。
   - i18n 三语种补 4 键：`werewolf.reward.victory_discount` / `werewolf.reward.consolation_prop` / `werewolf.reward.expires_in` / `werewolf.reward.next_game_use`。

5. **防滥用**：
   - `consolation_prop` 仅在本局结算后 5 分钟内有效。
   - `victory_discount_voucher` 仅在下一局购买时有效，结算后 5 分钟未用即作废。
   - KV `used: true` 后不再匹配。

### 3.3 §13 教训对齐

- **§118 模型金币**：仅触及**真人钱包** + `t_lsm_game_kv` 表，不污染 LLM Provider 模块（CLAUDE.md §14）。
- **§133 EconTier**：独立常量 `werewolf.settlement_reward_discount = 0.5` 与 EconTier 解耦。
- **§130 接线验证**：`grantSettlementRewardsLocked` 必须在终局路径**实际调用**（grep `Status = "over"` 关联代码确认），否则又成「声明了却从不接线」。
- **§121 严格校验**：前端 `consolation_prop` 列表必须与后端 enum 对齐。

### 3.4 预计规模

- `ServerGo/game/werewolf/settlement_reward.go`（新文件）：+100 行
- `ServerGo/game/werewolf/prop_engine.go`：+30 行
- `ServerGo/game/werewolf/engine_day.go` 终局路径：+5 行
- 前端 `SettlementModal.tsx`：+60 行
- i18n：+4 键
- 测试 `settlement_reward_test.go`：+120 行

## 4. V1 — 全视角读心观战（GodMode 视角切换）

### 4.1 设计目标

- 观战者可自由切换任意玩家的「第一视角」，同步看到完整信息（身份 / 夜间行动 / `HeartThought` / 决策摘要 / 工具调用日志）。
- 复用 §20260810-09 已落地的 `GodModeSnapshot` 框架，仅在**前端**新增视角切换 UI。
- 严格 §119 协议层隔离：spectator 可见 `HeartThought` 但**不可**让 spectator 向玩家推送（防止"读心"反向作弊）。

### 4.2 实现要点

1. **`GodModeSnapshot` 扩展**（`ServerGo/game/werewolf/room_godmode.go`，已存在 §20260810-09）：
   - 现有结构已含 `BotContextsBySeat map[int]*BotContextFull` + `HeartThoughtBySeat map[int]string`。
   - 验证：spectator HTTP `GET /api/games/werewolf/rooms/:id/godmode` 返回结构完整。

2. **前端新组件**（`ClientWeb/src/components/werewolf/GodModeView.tsx`）：
   ```tsx
   // 新增 13 座位小卡片网格(可点击切换 activeSeat)
   // 切换时,主面板渲染该 activeSeat 的:
   //  - 真实身份(终局前隐藏 → "?",终局后公开)
   //  - 夜间行动时间线(狼刀目标/守卫守护/女巫用药/预言家查验)
   //  - HeartThought(§119 仅 spectator 可见)
   //  - LastDecisionSummary
   //  - 工具调用日志(从 BotTranscript 拉)
   ```

3. **§135 身份公开白名单**：
   - 终局前：身份栏显示「🔒 [已隐藏]」（与 §135 一致）。
   - 终局后：`RolePubliclyRevealed(seat)` 命中白名单（白痴翻牌/狼自爆/猎人开枪/终局）→ 显示真实角色 + 阵营。

4. **§13 跨职责边界**：
   - 后端 GodMode API 不变（§20260810-09 已完整）。
   - 前端 `GodModeView.tsx` 独立组件 + `HistoryDrawer` 第 5 sub-tab「👁️ 第一视角」入口。

5. **i18n 三语种补 5 键**：`werewolf.godmode.view_as` / `werewolf.godmode.hidden_identity` / `werewolf.godmode.night_actions` / `werewolf.godmode.heart_thought` / `werewolf.godmode.tool_log`。

### 4.3 §13 教训对齐

- **§119 协议层隔离**：`HeartThought` 仅 spectator 可见；玩家本人不可切换到「看其他玩家 HeartThought」（前端按 `user_id !== player.user_id && isSpectator` 双重判断）。
- **§135 身份公开**：`RolePubliclyRevealed` 单点判定（§135 教训核心：5 处通道都要走单点）。
- **§92a 锁内变体**：前端只读，零后端锁变化。
- **§121 数据形状**：若后端 `GodModeSnapshot` JSON 字段变更，必须同步前端类型。

### 4.4 预计规模

- 前端 `GodModeView.tsx`（新文件）：+200 行

- `i18n` 三语种：+5 键
