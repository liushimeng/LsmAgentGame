## U1: 阵营胜率热力图（§7.2 P6-D 余项）

### 动机

§20260812-01 U4 落地了"发言信任度轨迹"（TrustTraceChart），但 §7.2 完整的"胜率热力图"未做。观战者需要直观看到每个玩家是狼/好人的概率分布，并能在每轮决策后看到概率变化趋势。

### 设计

**纯启发式计算（不调 LLM，符合 §120 公平性 + §13 跨职责）**：

**后端** — `ServerGo/game/werewolf/win_predict.go`（~180 行）：

- 启发式公式（**纯客观信号**，无 LLM 决策污染）：
  ```
  wolf_prob[seat] = base_alive_rate * (1 + faction_suspicion_signal)
                   + public_vote_suspicion * 0.3
                   - last_round_correctness * 0.2
  ```
  - `base_alive_rate`：当前阵营存活占比（活人局狼比例 ~23%，末日局动态调整）
  - `faction_suspicion_signal`：基于 `InfluenceTracker.SuspicionScore` 复用
  - `public_vote_suspicion`：被投票集中的座位加分
  - `last_round_correctness`：上一轮发言被验人/被毒后的修正
- 数据源：完全复用 `r.State.Players[]` / `r.voteTally` / `r.recentSpeeches[]`，**零新字段**
- 触发时机：每个 `speak` 阶段结束 + `vote` 阶段结束两个时点重算
- 输出：13 长度的 `[]float64` 概率数组，normalize 到 0~1

**API** — `GET /api/games/werewolf/rooms/:id/win-probability`（需登录，spectator-only）：
- 返回 `{ probabilities: number[], round: number, computed_at: number }`（wrapper 类型，前端 `http<{ probabilities: number[] }>` 解包，§121）

**view 透传** — `ServerGo/game/werewolf/view.go`：
- `ClientGameState` 加 `WinRateProbability []float64 \`json:"win_rate_probability,omitempty"\``
- `BuildClientStateWithRoom` spectator 分支（`viewer < 0`）调用 `computeWinRateProbabilityLocked` 并塞入
- **非 spectator 一律为 nil**（omitempty，前端取不到即为 nil，§132 隐私隔离）

**前端** — `ClientWeb/src/components/werewolf/WinRateHeatmap.tsx`（~250 行）：
- 13 座位方格网格，色阶 6 阶（蓝 0~16% / 青 16~33% / 黄 33~50% / 橙 50~66% / 红 66~83% / 深红 83~100%）
- 单元格悬浮显示「座位 N · 狼人概率 X% · 当前存活/总存活 Y/Z」
- 每轮有"📈 概率变化"小箭头（绿=下降=好/红=上升=坏）
- 挂在 `HistoryDrawer` 第 5 sub-tab「🔥 胜率」（已有 4 个 sub-tab：⏱ 时间轴/🤖 独白/⚰ 死亡/🏆 总结）

**i18n** — 3 语种补 6 键：
- `werewolf.heatmap.title` / `werewolf.heatmap.subtitle` / `werewolf.heatmap.empty` / `werewolf.heatmap.prob_tooltip` / `werewolf.heatmap.trend_up` / `werewolf.heatmap.trend_down`

### 风险

- **低**：纯读操作 + 启发式（不调 LLM）
- **§120 公平性**：公式不含 LLM 判断信号，仅客观行为数据
- **§130 接线**：3 处（API 注册 + view 透传 + 前端 fetch）
- **§132 隐私隔离**：spectator-only 通过 omitempty + viewer<0 单点判定
- **§135**：概率值不含身份明文，仅数值
- **§13 跨职责**：胜率算在 `ServerGo/game/werewolf/`，不在 `agent/` 包

## U2: 暗线信件 / 私下通道（§3.1 + §4.3 合并，P4-B）

### 动机

§3.1「暗线信件」与 §4.3「私密结盟提议」本质同构（私下双向通道），合并实现为「Secret Letter Room」单一抽象。仿 `wolfpack_room.go` 协议层隔离模板，仅在白天 `speak` 之后 → `vote` 开始前的窗口可用。

### 设计

**数据模型** — `ServerGo/models/t_lsm_game_secret_letter.go`：

```go
type TLsmGameSecretLetter struct {
    ID        string    `gorm:"type:char(36);primaryKey"  json:"id"`
    RoomID    string    `gorm:"type:char(36);not null;index:idx_slr_room_round"  json:"room_id"`
    FromSeat  int       `gorm:"not null"                  json:"from_seat"`
    ToSeat    int       `gorm:"not null"                  json:"to_seat"`
    Body      string    `gorm:"type:varchar(200);not null" json:"body"`
    Round     int       `gorm:"not null"                  json:"round"`
    IsRead    bool      `gorm:"not null;default:false"    json:"is_read"`
    CreatedAt time.Time `gorm:"autoCreateTime"            json:"created_at"`
}
```

- 200 字符上限（30 字中文约等于 90 字符，宽松一些）
- 每日每人发送上限 5 条（`cfgWerewolf.SecretLetterDailyLimit = 5`）
- §119 三重隔离：绝不入 `chat_message` 表 / `chat_history` 队列 / `BotTranscript.HeartThought`

**后端房间态** — `ServerGo/game/werewolf/secret_letter_room.go`（~300 行）：

```go
type SecretLetterRoom struct {
    mu       sync.Mutex
    letters  map[string]*TLsmGameSecretLetter  // key = id
    inbox    map[int][]string                   // key = seat, value = letter ids
    sentToday map[int]int                       // key = seat, value = today sent count
}

func (r *SecretLetterRoom) Send(seat int, toSeat int, body string, round int) (*TLsmGameSecretLetter, error)

func (r *SecretLetterRoom) MarkRead(seat int, letterID string)
```

- 单房间态，**不写 DB**（U2 协议层隔离优先；DB 仅审计 trail，可选）
- 仿 `wolfpack_room.go::WolfPackRoom` 模板（§119 隔离典范）
- 校验：不可发给自己 / 不可发群 / 不可发给死亡玩家 / 不可超过每日上限 / 必须白天非夜间 phase

**WerewolfRoom 接入** — `ServerGo/game/werewolf/room.go`：
- 加字段 `SecretLetterRoom *SecretLetterRoom` + lazy init `secretLetterRoomLocked()`（§92a）
- `restartGameLocked` 调用 `r.SecretLetterRoom.Reset()`（§130 接线必须）

**Agent 工具** — `ServerGo/agent/wwplayer/tools_letter.go`（新文件，~120 行）：
- 仿 `tools_wolf.go::buildWolfWhisperSchema` 模板
- 注册两个工具：
  - `secret_letter_send` (target_seat, body) — 仅白天 `PhaseSpeak` 末尾可调（`MountIf: phase ∈ {speak}` + 队伍无限制 + 活人 + 真实玩家）
  - `secret_letter_inbox` (no args) — 仅自己可读
- `init()` 注册到 `RegisterTool`（§130 单点）
- 仿 `wolf_whisper` 共享 `speakLimiter`（§122 限流）

**`BuildTools` 接入** — `ServerGo/agent/wwplayer/tools.go`：
- `tools.go:198+` 1504 行 switch 接近上限，**新增 tool 在新文件**（§130 单点）
- `MountIf: phase ∈ {speak}` 已通过 `RegisterTool` 机制（§20260811-04 统一）

**API** — `ServerGo/api/werewolf_api.go`：
- `POST /api/games/werewolf/rooms/:id/secret-letter` body: `{target_seat, body}` → `{letter_id, sent_at}`
- `GET  /api/games/werewolf/rooms/:id/secret-letter/inbox` → `TLsmGameSecretLetter[]`（仅自己）

**前端** — `ClientWeb/src/components/werewolf/SecretLetterPanel.tsx`（~200 行）：
- 白天发言阶段右侧抽屉，标题"✉️ 私下通道"

**i18n** — 3 语种 8 键：

### 风险

## U3: 阵营赌注系统（§6.2 P7-B）

### 动机

Mimo §3.4 提案，1w 工作量，下注行为本身是信息泄露 + 经济策略深度 + LLM 概率推理能力展示。

### 设计

**数据模型** — `ServerGo/models/t_lsm_game_faction_bet.go`：

```go
type TLsmGameFactionBet struct {
    ID              string    `gorm:"type:char(36);primaryKey"  json:"id"`
    RoomID          string    `gorm:"type:char(36);not null;index:idx_fb_room_round"  json:"room_id"`
    UserID          string    `gorm:"type:char(36);not null"    json:"user_id"`
    Round           int       `gorm:"not null"                  json:"round"`
    TargetSeat      int       `gorm:"not null"                  json:"target_seat"`
    PredictedFaction string   `gorm:"type:varchar(8);not null"  json:"predicted_faction"`  // "wolf"/"good"
    Amount          int       `gorm:"not null"                  json:"amount"`
    Settled         bool      `gorm:"not null;default:false"    json:"settled"`
    Payout          int       `gorm:"not null;default:0"        json:"payout"`
    CreatedAt       time.Time `gorm:"autoCreateTime"            json:"created_at"`
}
```

- 每人每轮最多下注 1 次（同 seat 同 round 唯一索引）
- 金额范围 10~500 金币
- 赔率 1:1（押中翻倍，未押中 50% 销毁 + 50% 滚存）

**下注窗口**：
- 开启：白天 `speak` 阶段结束（最后一位玩家发言完毕）
- 关闭：`PhaseVote` 启动时
- 窗口长度：通常 0~30 秒（视配置，默认 `cfgWerewolf.BetWindowSec = 30`）

**结算 hook** — `ServerGo/game/werewolf/room_action.go::EmitVoteResult`：
- 末尾追加 `settleFactionBetsLocked(roomID, votedOutSeat, actualFaction)` 调用
- 流程：
  1. 取 `TLsmGameFactionBet WHERE room_id=? AND round=? AND settled=false`
  2. 真实身份通过 `r.State.Players[votedOutSeat].Role` 查 faction
  3. 押中：`Payout = Amount * 2`，调 wallet `+Payout`
  4. 未押中：销毁 50% + 滚存 50%（与 §133 EconTier 同款）
  5. 更新 `Settled=true, Result, Payout`

**后端** — `ServerGo/game/werewolf/faction_bet.go`（~250 行）：

```go
type FactionBetService struct {
    db       *gorm.DB
    walletSvc *wallet.Service
}

func (s *FactionBetService) PlaceBet(roomID string, userID string, seat int, round int, targetSeat int, faction string, amount int) error
func (s *FactionBetService) SettleBetsLocked(roomID string, round int, votedOutSeat int, actualFaction string) error
func (s *FactionBetService) GetBetStatus(roomID string, userID string) (*BetStatus, error)
```

**配置** — `ServerGo/config/config.go`：
- `werewolf.bet_window_sec = 30`
- `werewolf.bet_min_amount = 10`
- `werewolf.bet_max_amount = 500`
- `werewolf.bet_destroy_rate = 50`（独立常量，不与 §133 道具销毁耦合）

**API** — `ServerGo/api/werewolf_api.go`：
- `POST /api/games/werewolf/rooms/:id/faction-bet` body: `{target_seat, predicted_faction, amount}`
- `GET  /api/games/werewolf/rooms/:id/faction-bet-status` → `{bets: TLsmGameFactionBet[], pending_window_sec: number, settled_round: number}`

**前端** — `ClientWeb/src/components/werewolf/FactionBetPanel.tsx`（~200 行）：
- 30s 倒计时抽屉，标题"💰 阵营赌注"
- 选 target_seat（13 座位下拉）+ 选 faction（狼/好人）+ 金额（slider 10~500）
- 提交按钮：显示余额 + 押中收益预览
- **重要约束**：保持 `Activity.vote_summary` 字段不变（§6.2 风险项）

**i18n** — 3 语种 6 键：
- `werewolf.bet.title` / `werewolf.bet.faction_wolf` / `werewolf.bet.faction_good` / `werewolf.bet.amount_label` / `werewolf.bet.settled_win` / `werewolf.bet.settled_lose`

### 风险

- **中低**：新表 + WS 帧（用 HTTP 即可，不必 WS）+ 结算 hook
- **§133 EconTier**：独立常量 `werewolf.bet_destroy_rate = 50` 不与道具耦合
- **§130 接线**：4 处（API 注册 + 结算 hook + 前端 fetch + 跨局清理）
- **§122 限流**：新增 `betLimiter` 5s/次（防误触连点）
- **§121 数据形状**：`GetBetStatus` 返回 wrapper 类型，前端 `http<{bets: ...}>` 解包
- **§118 钱包**：仅人类钱包，不污染 LLM Provider 模块

## U4: 3 条核心理由强制输出（§2.1 DouBao §五.4 余项）

### 动机

§20260810-12 D1 落地了"决策可解释性"（DecisionTrail 运行时回放），但 DouBao §五.4「每次关键行动明确列出 3 条核心理由」的 prompt 增强部分未做。本 U 通过 prompt 硬约束 + 自动截取，让 LLM 决策更具可解释性且不增加 LLM 调用次数。

### 设计

**纯 prompt 增强，零 LLM 额外调用，零前端/数据库改动**。

**后端** — `ServerGo/agent/wwplayer/prompt.go`（仅末尾追加 1 个 block）：

```go
// 2026-08-12 §20260812-03 U4 — 3 条核心理由硬约束。
// 关键行动前必须先用 internal_thought(speak_with_thought) 列出 3 条核心理由,
// 供 BotTranscript.LastDecisionSummary 截取展示。
const ThreeReasonsBlock = `

【3 条核心理由约束 §20260812-03 U4】
当你执行以下关键行动前，必须先用 speak_with_thought 工具：
  - vote（投票）
  - seer_check（预言家查验）
  - witch_act（女巫用药）
  - guard_protect（守卫守护）
  - hunter_shoot（猎人开枪）
  - wolf_kill（狼人刀人）
在 internal_thought 字段中先列出 3 条核心理由（每条 ≤ 30 字，编号 1/2/3），
再在 text 字段中给出对外发言 / 决策描述。
internal_thought 字段不入公聊（§119 协议层隔离），仅作决策可解释性记录。
若你不是上述角色且该阶段不要求工具决策，可忽略此约束。
`
```

调用位置：`BuildUserPrompt` 末尾（`return s` 之前）追加 `s += ThreeReasonsBlock`。

**自动截取** — `ServerGo/agent/wwplayer/decision_summary.go`：

- `BuildDecisionSummary(toolName, toolInput, toolResult)` 已存在，复用
- 在 `speak_with_thought` 工具结果被处理时（`tools_speak_thought.go` 已有），从 `internal_thought` 字段前 3 行截取，写入 `BotTranscript.LastDecisionSummary`（已存在字段，§128）
- 截取规则：以 `1.` `2.` `3.` 开头的中文/数字行；取首条 hit 的 3 行；无则保留原 `LastDecisionSummary`

**风险**：
- **极低**：纯 prompt 增强，零 LLM 额外调用，零前端/数据库改动
- **§128 决策统一字段**：走 `LastDecisionSummary` 而非新字段
- **§197 流式续命**：复用现有 `parentCtx + extendedTimeout`，不变
- **§119 协议层隔离**：`internal_thought` 字段已在 `speak_with_thought` 中实现物理隔离（§213），不重复造轮子
- **§130 接线**：2 处（prompt.go 末尾追加 + decision_summary.go 截取逻辑）
- **性能影响**：prompt token 增加 ~150 token/次，对 13 人局总体 token 消耗 < 3%

### 验证

- 单测 `ServerGo/agent/wwplayer/prompt_three_reasons_test.go`（2 项）：
  - `TestThreeReasons_BlockPresent`：断言 `BuildUserPrompt` 输出包含"3 条核心理由约束"字样
  - `TestThreeReasons_Truncate3Lines`：mock `internal_thought` 含 5 行（1.~5.），断言 `BuildDecisionSummary` 仅取前 3 行
