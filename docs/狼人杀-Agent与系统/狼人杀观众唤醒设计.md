# 狼人杀 Agent 观战者 wake 代码设计

> 实施日期:2026-07-08
> 关联规则:[`docs/狼人杀13人标准局规则.md`](狼人杀13人标准局规则.md) §13
> 关联产品:[`docs/狼人杀观众交互设计.md`](狼人杀观众交互设计.md)
> 关联设计:[`docs/狼人杀-Agent与系统/狼人杀Agent设计.md`](狼人杀Agent设计.md) §5 工具表 / §15

本文档面向**后端 Go / 前端 React** 实现者,详述观战者发言触发 Agent wake 的代码改动点、复用机制、限流策略、数据结构。

---

## 1. 核心思路

**问题**:人类观众在 `chat.send` 发出的消息经过 `ChatService` 广播后,`WerewolfManager.appendRoomMessage` **只**写入 `r.recentSpeeches`,**不**触发 Agent 唤醒。Agent 只能在下次 phase wake 时通过 `BuildUserPrompt` 读取(延迟 60-180s)。

**解决**:
1. 在 `appendRoomMessage` 内识别"观战者公开消息",调用新的 `maybeSpectatorWake` 方法。
2. `maybeSpectatorWake` 带 15s per-room 滑动窗口节流,通过则对**所有存活 bot** 推 `AgentEvent{Kind:"spectator_speech"}`。
3. `run.go handleEvent` 看到该 Kind 时,记录"必须思考"语义 — 若 LLM `end_turn` 未调任何工具,自动追加 `[idle_thinking]` 审计行到 `BotTranscript.RecentMessages`。
4. 阶段黑名单 + 4 层限流,防止夜间信息泄露 + token 暴增。

## 2. 关键数据结构扩展

### 2.1 `AgentEvent.Kind` 扩展(零侵入)

```go
// ServerGo/agent/agent.go L179-184
// AgentEvent wakes an agent up. `Kind` is one of: "state_change", "your_turn",
// "sync", "game_over", "spectator_speech" (2026-07-08 new).
//
// "spectator_speech": fired by WerewolfManager.maybeSpectatorWake when a
//   human spectator's public chat arrives at the room. The agent loop
//   uses this Kind to:
//     (a) require the LLM to make a decision (interject / whisper /
//         idle_think / end_turn) — fully ignoring the message is logged
//         as an [idle_thinking] audit line.
//     (b) never block the event on the 8s LLMCallLimiter bypass; the
//         bot's own limiter decides whether to call LLM now or later.
//   Phase whitelist: pre_wolves / sheriff / speak / vote only.
type AgentEvent struct {
    Kind    string
    Context GameContext
}
```

> **为什么不引入新 type**:`AgentEvent` 已经是 `{Kind, Context}` 字符串事件总线,新增 Kind 字符串即可,无新类型 → 无破坏性改动。

### 3.3 `maybeSpectatorWake` 方法(新增,~30 行)

```go
// ServerGo/game/werewolf/room.go (新增方法,L428 之后)

// maybeSpectatorWake 由 appendRoomMessage 在收到观战者公开消息后调用。
// 节流 15s,白名单 phase 校验,然后对所有存活 bot 推 spectator_speech 事件。
// 设计要点:
//   - 持有 room lock(appendRoomMessage 调用方已加锁),所以走 wakeAllAgentsLocked;
//   - 跳过 quarantined bot(与现有 WakeAllAgents 一致);
//   - 跳过已死亡的 bot(读取 r.State.AliveSeats);
//   - 跳过非白名单 phase。
func (m *WerewolfManager) maybeSpectatorWake(r *WerewolfRoom) {
    if m.spectatorWakeLimiter == nil {
        return
    }
    if !spectatorWakeAllowedPhases[r.State.Phase.String()] {
        return
    }
    if !m.spectatorWakeLimiter.Allow() {
        logger.L().Debug("werewolf: spectator wake throttled",
            zap.String("room_id", r.RoomID),
            zap.String("phase", r.State.Phase.String()))
        return
    }
    // 构造 GameContext 一次复用(7 个 bot 共享)
    ctx := m.buildAgentContextLocked(r, 0)  // seat=0 占位,bot_seat 后续覆盖
    n := 0
    for seat, ag := range r.BotAgents {
        if ag == nil || ag.IsQuarantined() { continue }
        if !r.State.AliveSeats[seat] { continue }
        ctx.MySeat = seat
        ctx.Role = r.State.Roles[seat].String()
        ag.PushEvent(agent.AgentEvent{Kind: "spectator_speech", Context: ctx})
        n++
    }
    logger.L().Info("werewolf: spectator wake fired",
        zap.String("room_id", r.RoomID),
        zap.String("phase", r.State.Phase.String()),
        zap.Int("awakened_bots", n))
}
```

### 4.2 `BuildTools` 阶段白名单更新

```go
// ServerGo/agent/tools.go BuildTools,在每个 phase 分支内追加 idle_think
func BuildTools(phase, role string, seat int, alive bool, speakTurn int) []ToolDef {
    var tools []ToolDef
    idleThink := ToolDef{Name: "idle_think", /* ... */}

    switch phase {
    case "pre_wolves", "PhasePreWolves":
        tools = append(tools, /* speak */, /* interject */, /* whisper */, idleThink)
    case "night_wolves", "PhaseNightWolves":
        if role == "werewolf" { tools = append(tools, /* wolf_kill */, /* wolf_suicide */) }
        // idle_think 不在夜间暴露
    case "night_seer", "PhaseNightSeer":
        if role == "seer" { tools = append(tools, /* seer_check */) }
    case "night_witch", "PhaseNightWitch":
        if role == "witch" { tools = append(tools, /* witch_act */) }
    case "dawn", "PhaseDawn":
        tools = append(tools, /* start_day */, /* interject */, /* whisper */, idleThink)
    case "sheriff", "PhaseSheriff":
        tools = append(tools, /* sheriff_candidate */, /* sheriff_elect */,
                       /* interject */, /* whisper */, idleThink)
    case "speak", "PhaseSpeak":
        if speakTurn == seat {
            tools = append(tools, /* speak */, /* finish_speak */, /* wolf_suicide(狼) */,
                           /* interject */, /* whisper */, idleThink)
        } else {
            tools = append(tools, /* interject */, /* whisper */, idleThink)
        }
    case "vote", "PhaseVote":
        tools = append(tools, /* vote */, /* finish_vote */,
                       /* interject */, /* whisper */, idleThink)
    case "hunter_shoot", "PhaseHunterShoot":
        if role == "hunter" { tools = append(tools, /* hunter_shoot */) }
        tools = append(tools, idleThink)  // 其他角色可 idle_think
    case "gameover", "PhaseGameOver":
        // 不暴露任何工具
    }
    return tools
}
```

### 4.5 `agentRunner` 实现 `IdleThink`

```go
// ServerGo/game/werewolf/agent_runner.go (L22-46,新增方法)

// IdleThink 由 LLM 调用 idle_think 工具时触发。语义:
//   - 不广播任何消息
//   - 不调用 ChatService
//   - 仅在 BotTranscript.RecentMessages 追加一条 [idle] 审计行
//   - 触发 wakeAll() 以让下一位 bot 继续决策
//
// 实际写入由 run.go 在 dispatch 完成后统一处理(见 §4.7)。
func (r *agentRunner) IdleThink(reason string) (string, error) {
    r.wakeAll()  // 推进到下一位 bot
    logger.L().Debug("werewolf: bot idle_think",
        zap.String("bot_id", r.botID),
        zap.String("reason", reason))
    return "idle_think recorded", nil
}
```

### 4.7 `run.go handleEvent` 新分支

```go
// ServerGo/agent/run.go handleEvent (~L270-776,新增分支)

// handleEventSpectatorSpeech 处理 spectator_speech 事件的 LLM 决策。
// 与普通 state_change 不同的点:
//   1. 强制要求 LLM 做出决策(必须调 interject / whisper / idle_think 之一);
//   2. 若 LLM end_turn 且未调任何工具,自动追加 [idle_thinking] 审计行;
//   3. 30s 静默提示在 BuildUserPrompt 末尾注入。
func (a *Agent) handleEventSpectatorSpeech(ctx GameContext) {
    // 与普通决策循环相同的 LLM 调用流程
    resp := a.callLLM(ctx)
    if resp.HasToolUse("interject") || resp.HasToolUse("whisper") || resp.HasToolUse("idle_think") {
        // 正常分支,DispatchTool 已执行
        return
    }
    // LLM 未调任何工具:自动追加审计行
    a.appendIdleAuditLine(ctx, "LLM end_turn without tool_use after spectator_speech")
}
```

### 4.8 BotTranscript 追加审计行

```go
// ServerGo/agent/agent.go (新增方法)
func (a *Agent) appendIdleAuditLine(ctx GameContext, reason string) {
    a.Lock()
    if a.lastTranscript == nil {
        a.lastTranscript = &BotTranscript{Seat: a.Seat, Model: a.ModelKey}
    }
    a.lastTranscript.RecentMessages = append(a.lastTranscript.RecentMessages,
        fmt.Sprintf("[%s] 观众/玩家发言,本轮选择保持沉默: %s",
            time.Now().Format("15:04:05"), reason))
    a.lastTranscript.UpdatedAt = time.Now().UnixMilli()
    a.Unlock()
    logger.L().Debug("werewolf: agent idle_thinking audit",
        zap.String("bot_id", a.BotID()),
        zap.String("reason", reason))
}
```

## 5. 限流矩阵(精确数值)

| 层级 | 类型 | 间隔 | 触发点 | 复用 / 新增 |
|---|---|---|---|---|
| L1 per-room | `spectatorWakeLimiter` | 15s | `maybeSpectatorWake` 入口 | **新增** |
| L2 per-bot | `LLMCallLimiter` | 8s | Agent.run 调 LLM 前 | 复用 (R1 既有) |
| L3 per-bot | `Limiter` | 45s | Agent 调 `speak` / `interject` 后 | 复用 (R1 既有) |
| L4 per-bot | `WhisperLimiter` | 90s | Agent 调 `whisper` 后 | 复用 (R1 既有) |
| L5 per-bot | `MaxToolUse` | 4 calls | Agent 单轮 LLM 决策循环上限 | 复用 (R1 既有) |

**理论峰值**:1 观众 30s 内连发 10 条 → 触发 2 次 wake(15s 间隔)= 14 次 LLM 调用(7 bot × 2 wake)/ 30s ≈ **0.47 LLM/秒**。对比既有 `wakeAll()` 在 phase 切换时 7 bot 同时 wake 的 burst(7 LLM calls in < 1s,L232),新增 wake 的频率是**显著低于**既有事件源。

## 9. 部署与回退

### 9.1 部署顺序

1. **先部署后端**:commit 包含 `agent/*` + `werewolf/room.go` + `werewolf/agent_runner.go`。
2. **再部署前端**:`AgentThoughtPanel.tsx` 增量更新,可选(后端先上线不影响功能)。
3. **后端灰度**:可在 `cfg.Werewolf.SpectatorWakeEnabled` 配置项控制(默认 `true`)。生产环境可临时设为 `false` 回退。

### 9.2 回退方案

- **配置回退**:`cfg.Werewolf.SpectatorWakeEnabled = false` → `maybeSpectatorWake` 立即 return,功能关闭。
- **代码回退**:`git revert` 单 commit,5 行新分支可一行删。
- **数据库回退**:无 schema 变更,无需迁移。
