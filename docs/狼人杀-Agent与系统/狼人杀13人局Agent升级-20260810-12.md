## 1. D1 — 决策留痕运行时回放（DecisionTrail）

### 1.1 设计目标

- 每位存活 Bot 在每轮 LLM 决策时，把「轮次 / 阶段 / 工具名 / 入参 / 工具结果 / 决策时长」压缩成 1 条 `DecisionEntry`，追加进 `BotTranscript.DecisionTrail`。
- 前端 `HistoryDrawer` 增加 sub-tab **「🧠 决策回放」**（仅 spectator 可见），按时间倒序展示所有 Bot 的决策流（点击座位过滤）。
- **不**通过 `LastDecisionSummary` 单一字段承载 —— 那是「单次决策的一句话总结」，无法回放「这一夜 5 次 LLM 调用之间发生了什么」。
- **不**复制 LLM 输入/CoT 全文（§128 已删除 `LastThinking` / `FullThinking`）—— 只存结构化的「步骤」，每条 ≤ 80 字。
- **opt-in 开关**：`werewolf.bots_log_decisions = true`（默认 true），关闭时 `decisionTrail = nil`，零内存开销。

### 1.2 数据形状

```go
// ServerGo/agent/wwplayer/decision_trail.go（新文件）

// DecisionEntry 是单次 LLM 决策的结构化留痕（§20260810-12 D1）。
//
// 设计取舍：
//   - 不复制 LLM CoT / 输入全文（§128 已删除 LastThinking）；
//   - 只存「决策时发生了什么」，对前端的暴露仅限于 spectator + 玩家自己。
//   - 每条 ≤ 80 字（JSON 序列化后），保证 wire 包大小可控。
//
// 字段语义：
//   - Round        : 1-based 天数（0 = 夜间未明 / pre-day）
//   - Phase        : 阶段 key（speak/vote/night_wolves/...）
//   - ToolName     : 本次决策调的工具名（"" = LLM end_turn 无工具）
//   - ToolSummary  : 决策一句话（走 BuildDecisionSummary，含脱敏目标）
//   - TookMs       : 本次决策 LLM 调用耗时（毫秒）
//   - CreatedAt    : unix 毫秒（决策完成时刻）
type DecisionEntry struct {
    Round      int    `json:"round"`
    Phase      string `json:"phase,omitempty"`
    ToolName   string `json:"tool_name,omitempty"`
    ToolSummary string `json:"tool_summary,omitempty"`
    TookMs     int64  `json:"took_ms,omitempty"`
    CreatedAt  int64  `json:"created_at,omitempty"`
}
```

### 1.3 BotTranscript 字段扩展

```go
// ServerGo/agent/wwplayer/agent.go::BotTranscript 新增

// 2026-08-10 §20260810-12 D1 — 决策留痕运行时回放。
// 本局 Agent 每次决策追加一条 DecisionEntry,最多保留 30 条（≈30 个轮次）,
// 超过则 FIFO 丢弃最早一条。前端 HistoryDrawer 第 5 sub-tab「🧠 决策回放」渲染。
//
// **§135 spectator 隔离**：sanitizeBotTranscript 在人类玩家分支清空此字段。
// **§128 兼容**：不复制 LLM CoT,只存结构化步骤(轮/阶段/工具/耗时/一句话)。
// **opt-in**：`werewolf.bots_log_decisions=false` 时为 nil,零内存开销。
DecisionTrail []DecisionEntry `json:"decision_trail,omitempty"`
```

### 1.4 写入路径（3 个 hook 点）

`Agent.recordTranscript`（`run.go:1113` / `:1654`）在合并 transcript 之前由新增的
`AppendDecisionEntry` 写一次。三个调用点对应三个时机：

| 时机 | 来源 | 字段 |
|---|---|---|
| `handleEvent` STAGE 4（最后一次 tool dispatch 后） | `run.go:1308` 写入 `RecordDecisionState.LastToolName/Input/Result/Outcome` 同一位置 | `Round/Phase/ToolName/ToolSummary/TookMs/CreatedAt` |
| `MarkLLMCallEnd`（已在 §120 写入耗时） | `run.go:RecordLLMCallLatency` 旁 | `TookMs` 由 `LastLLMLatencyMs` 复用 |
| 法官总结阶段 | 不入 trail —— `Judge` 是另一类 Agent，不污染 BotTranscript trail |

实现要点：

```go
// ServerGo/agent/wwplayer/decision_trail.go

// AppendDecisionEntry 由 recordTranscript 调一次。已持 a.mu。
// 入参 reason 是 recordTranscript 拼出的 DecisionEntry 字段（轮/阶段/工具名/...）。
func (a *Agent) AppendDecisionEntry(entry DecisionEntry) {
    if !a.botsLogDecisions {  // 配置 opt-in 开关
        return
    }
    a.lastTranscript.DecisionTrail = append(a.lastTranscript.DecisionTrail, entry)
    // 上限 30 条,FIFO 淘汰
    if len(a.lastTranscript.DecisionTrail) > 30 {
        a.lastTranscript.DecisionTrail = a.lastTranscript.DecisionTrail[len(a.lastTranscript.DecisionTrail)-30:]
    }
}
```

### 1.5 配置开关

`ServerGo/config/config.go::cfgWerewolfBotsLogDecisions()`（默认 `true`）。
Agent 构造时由 `NewWithRoom` 末尾读取配置写入 `a.botsLogDecisions bool`。
**关闭时 trail 完全不分配** —— 即使 `decision_trail` JSON tag 设为 `omitempty`，
Go 的 `[]DecisionEntry` 字段若不分配则 wire 上看不到，且 `AppendDecisionEntry` 提前 return，
所以零开销承诺可兑现。

### 1.6 前端渲染

`ClientWeb/src/components/werewolf/HistoryDrawer.tsx`：

- 新增第 6 sub-tab「🧠 决策回放」（位置：紧跟现有「🔮 假说」之后）。
- 仅 `isSpectator===true` 时显示（§119 + §135 隔离）。
- 内容区：
  - 顶部「座位过滤」13 座 chip（默认全选）。
  - 下方按 `CreatedAt DESC` 渲染 `DecisionEntry[]` 列表，每条：
    ```
    Day 3 · speak · speak(5号): 我怀疑4号是狼人... · 4.2s
    ```
  - 空状态：`暂无决策记录`。

### 1.7 §13 教训对齐

- **§92a 锁内变体**：`AppendDecisionEntry` 在 `recordTranscript` 持 `a.mu` 的同一上下文内调用，无需新增加锁点。
- **§128 对话即思考**：trail 不含 LLM CoT / 输入原文，只存结构化步骤；与已删除的 `LastThinking` / `FullThinking` 字段互补但范围更广。

- **§121 数据形状**：新增 JSON 字段，前端 `BotContextJSON` 类型必须同步（参考 §20260810-07 `HypothesisEntryJSON` 同步模式）。

## 2. D2 — 死者身份「终局延时揭晓」

### 2.1 设计目标

- 当前 §135 单点判定 `RolePubliclyRevealed(seat)`：终局前「死亡即公开」已被替换为「4 类白名单」（终局 / 白痴翻牌 / 狼自爆 / 猎人开枪）。
- 本批次的「延时揭晓」是 **UI 层可调延迟**，**不**触碰 §135 服务端真相 —— 终局后 ServerGo 始终把全部 `DeadPlayerJSON.Role` 下发，前端按用户偏好延时显示。
- 用户体验：让玩家在 `SettlementModal` 启动后能「不立刻看身份」，先看发言 / 投票 / 推理自行猜测，N 秒后再揭晓。
- 默认 `delay_min=0`（立即揭晓，旧行为零回归）；可选 5 / 15 分钟。

### 2.2 数据形状

```go
// ServerGo/game/werewolf/view.go::ClientGameState 新增（与 game_started_at 同款 omitempty）

// 2026-08-10 §20260810-12 D2 — 死者身份「终局延时揭晓」配置(可选 0/5/15)。
// 由房间创建时按 RoomConfig.DeathRevealDelayMin 下发,前端 SettlementModal 据此倒计时。
// 仅影响前端 UI 显示时机;RolePubliclyRevealed 单点判定(§135)不受影响。
DeathRevealDelayMin int `json:"death_reveal_delay_min,omitempty"`
```

### 2.3 RoomConfig + 创建房间流程接入

- `ServerGo/service/room_service_crud.go::createWerewolfRoom`：接受 `death_reveal_delay_min` 字段（enum 0/5/15），写入 `WerewolfRoom.config.deathRevealDelayMin`。
- `ServerGo/config/config.go::cfgWerewolfDeathRevealDelayMinAllowed()` 返回允许值切片 `[]int{0, 5, 15}`，给前端校验。
- `ServerGo/game/werewolf/room.go::WerewolfRoom`：新增 `deathRevealDelayMin int`（房间级，不参与 hash）。

### 2.4 下发路径

- `view.go::BuildClientStateWithRoom` 的 `Status == "over"` 分支：
  - 已存在 `gameStartedAt int64` 旁，新增 `cs.DeathRevealDelayMin = r.deathRevealDelayMin`。
  - **§135 隔离**：dead player 的 `Role` 字段**仍按现状下发**（白名单命中后才下发，与 D2 无关）；D2 只控制前端**何时**展示。

### 2.5 前端 SettlementModal

- `ClientWeb/src/components/werewolf/SettlementModal.tsx`：
  - 启动时检查 `delay_min`：
    - `0` → 立即显示身份（与现状一致，零回归）。
    - `5 / 15` → 顶部加「🔒 身份将在 M 分 N 秒后揭晓」倒计时 + 「⚡ 立即揭晓」按钮（满足好奇心玩家）。
  - 倒计时归零后，触发 React state 更新，已隐藏的身份区域淡入显示（200ms 过渡）。
  - 「立即揭晓」按钮：仅 spectator 可见（避免人类玩家借此作弊）。
- `ClientWeb/src/components/werewolf/HistoryDrawer.tsx`：
  - 死亡的 Bot 页签：倒计时期间显示「🔒 身份已隐藏 — 将在 N 秒后揭晓」。
  - 倒计时归零后渲染 `role` 字段（与现状一致）。

### 2.6 RoomCreateModal 配置

- `ClientWeb/src/components/werewolf/RoomCreateModal.tsx`：
  - 法官配置卡 / 高级选项区加一项「🪦 身份揭晓时机」下拉：`立即` / `5 分钟` / `15 分钟`（默认 `立即`）。
  - 提交时把 `death_reveal_delay_min` 加进 `CreateRoomOptions.advanced`。
- 三语 i18n：`werewolf.create.death_reveal_delay` / `werewolf.death_reveal.delay_0` / `werewolf.death_reveal.delay_5` / `werewolf.death_reveal.delay_15`。

### 2.7 §13 教训对齐

- **§135 单点判定**：`RolePubliclyRevealed` 不动；dead player `Role` 字段下发规则不动；本批只是 UI 层延时。
- **§119 协议层隔离**：延时不触碰任何 chat / HeartThought / wolfpack 频道。
- **§121 数据形状**：后端 ClientGameState 加字段，前端类型同步；RoomCreateOptions 加字段。
- **§128 对话即思考**：与「决策即思考」主题一致 —— 终局复盘节奏由用户掌控。
- **§92a 锁内变体**：前端只读 + 后端字段赋值都在已有锁内路径（`BuildClientStateWithRoom` 已 `r.mu`），无需新增加锁点。
- **§130 接线验证**：`CreateRoomWithAgents` 入口必须 `grep r.deathRevealDelayMin` 确认赋值。
