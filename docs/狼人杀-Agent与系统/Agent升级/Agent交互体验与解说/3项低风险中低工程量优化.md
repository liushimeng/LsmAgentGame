## U1: 反事实推理链（Counterfactual Reasoning Chain）

### 设计理念

当前 Agent 是「事件→响应」的反应式系统。LLM 最强大的能力——反事实推演——在游戏中几乎未被利用。
通过 system prompt 注入反事实推理指令，让 LLM 在关键决策前自然产出「如果 X 则 Y」推演，
无需新增独立工具（避免 tool_use 消耗），写入 `HeartThought` 或 `LastDecisionSummary`。

### 核心价值

- LLM「想象不存在的世界线」能力展示
- 猜疑链深化（Agent 需要考虑多条可能性路径）
- 观赏性（观众可对比真实情况 vs Agent 推演）
- Token 成本极低（~150 tokens/轮/Agent，7 bot 合计 ~1000 tokens/轮）

### 实现方案

#### 1. System Prompt 注入（`ServerGo/agent/wwplayer/prompt.go`）

在 `BuildSystemPrompt` 的 `gameMindset` 段（§128 对话即思考理念之后）追加反事实推理指令：

```go
// §20260811-01 U1: 反事实推理链
const counterfactualReasoning = `
## 反事实推理（Counterfactual Thinking）

在做出关键决策（投票、刀人、用药、开枪、查验）前，你应该在 internal_thought 中进行
反事实推理——思考 2~3 条「如果 X 则 Y」的可能性路径：

- "如果 5 号是狼人，那他第 2 轮的发言策略就说得通了"
- "如果 3 号是预言家，为什么他的查验逻辑和票型不一致？"
- "如果昨晚守卫守了 7 号，狼人可能换了刀口"

这不需要独立工具或额外输出。在你自然思考的过程中融入反事实分析即可。
它帮助你避免单一假说锁定，提升决策质量。
`
```

**注入位置**：`prompt.go` line ~82（`gameMindset` 末尾），在 `hardBans` 之前。
**不改变** system prompt 整体结构（§128 要求），仅追加一个自然语言段。

#### 2. 不改动的部分

- **不新增工具**：反事实推理通过自然语言指令引导 LLM 在现有 `internal_thought` / `speak_with_thought` 中产出
- **不新增字段**：产出内容自然流入 `HeartThought`（§119 协议层隔离）或 `LastDecisionSummary`
- **不新增前端组件**：推理内容通过现有 HistoryDrawer「🤖 独白」sub-tab 可见（仅 spectator）
- **不修改后端逻辑**：纯 prompt 层改动

#### 3. 开关

无需独立开关——如果需要禁用，从 `gameMindset` 中移除该段即可。
考虑到 Token 成本极低且不影响核心逻辑，默认启用。

### 测试验证

- `go build ./...` 通过
- `go test ./agent/wwplayer/... ./game/werewolf/... -count=1` 通过
- System prompt 输出验证：新段落出现在 `gameMindset` 之后、`hardBans` 之前

## U2: 即刻原班重开（Fast Restart）

### 设计理念

当前游戏结束后进入冷却期 → 重启投票阶段（5 分钟窗口，≥ 2/3 同意）。
流程冗长——「想继续但要走流程」的尴尬。

即刻原班重开：结算页顶部增加「⚡ 即刻原班重开」按钮，单击直接以 ≥ 50% 同意即可快速重开，
跳过 5 分钟等待窗口。不同意则走原有慢路径。

### 核心价值

- 消除「想继续但要等」的体验断裂
- 人类玩家主导节奏（无需等 Agent 投票）
- 复用现有 `restartGameLocked`，工程量极低

### 实现方案

#### 1. 后端：Fast Restart 模式

**文件**：`ServerGo/game/werewolf/engine_restart_vote.go`

新增 `FastRestart` 字段到 `GameState`（或 `WerewolfRoom` 的 restart vote 相关状态）：

```go
// RestartVoteState 扩展
type RestartVoteState struct {
    // ...existing fields...
    FastRestart bool `json:"-"` // §20260811-01 U2: 快速重开模式
}
```

**修改 `EvaluateRestartVoteLocked`**（`engine_restart_vote.go:173`）：

快速模式下降低门槛：
- 标准模式：`yesCount >= ceil(eligible * 2/3) + 1`
- 快速模式：`yesCount >= ceil(eligible * 1/2) + 1`（简单多数）

**新增入口**：`Action_FastRestartVote`（`room_action.go` 或 `room_restart_vote.go`）

```go
// §20260811-01 U2: 即刻原班重开
func (m *WerewolfManager) Action_FastRestartVote(roomID, userID string) *errcode.Error {
    r, err := m.lockRoomBriefly(roomID)
    if err != nil { return err }
    defer r.mu.Unlock()

    seat := r.State.SeatOf(userID)
    if seat == NoSeat { return errcode.New(30001, "not a player") }

    // 如果还在 PhaseRestartVote，直接投 yes
    if r.State.Phase == PhaseRestartVote {
        return restartVoteLocked(r, seat, "yes")
    }

    // 如果还在冷却期或 PhaseGameOver，强制进入 restart vote + fast mode
    // ...
}
```

**WS 帧**：`game.werewolf_fast_restart`（人类玩家专用）

```json
{ "room_id": "xxx" }
```

**WS 处理**（`ws/game_service.go`）：
- 校验：必须是房间内玩家（非观众）
- 调用 `Action_FastRestartVote`

#### 2. 前端：SettlementModal 快速重开按钮

#### 3. Bot 行为

Bot 在收到 `game.settlement` 后自动投 yes（复用现有 `RestartVoteBotLocked` 逻辑）。
快速模式下降低门槛 = Bot 自动投票 + 1 个人类点击 = 即可达到简单多数。

- 玩家身份（非观众）

## U3: 投票阶段「半公开计票」（Semi-Public Vote Count / Vote Suspense）

### 设计理念

当前投票结果实时推送——投票一结束就显示完整票型（谁投了谁 + 得票数）。
缺少「屏息」时刻——狼人杀的高光之一是「开票」瞬间的紧张感。

半公开计票：投票结束后 3 秒内只显示「谁投了谁」，不显示得票数；
3 秒后自动揭晓完整票型。

### 核心价值

- 增加投票阶段的戏剧张力
- Agent 必须根据「谁投了谁」+「已有证词」反推得票情况（心智模型）
- 纯前端视觉层改动，不改变任何后端逻辑或数据

### 实现方案

#### 1. 配置开关

**后端**：`ServerGo/config/werewolf.go`（或对应配置结构体）

```go
// §20260811-01 U3: 投票半公开计票
VoteSuspense        bool `json:"vote_suspense"`         // 默认 false
VoteSuspenseDelayMs int  `json:"vote_suspense_delay_ms"` // 默认 3000
```

**下发**：`ClientGameState` 新增字段

```go
VoteSuspense        bool `json:"vote_suspense,omitempty"`
VoteSuspenseDelayMs int  `json:"vote_suspense_delay_ms,omitempty"`
```

#### 2. 前端：投票悬念逻辑

**文件**：`ClientWeb/src/components/werewolf/DayControlPanel.tsx`

当前实时票数渲染（lines 412-421）：

```tsx
{gameState.votes && Object.keys(gameState.votes).length > 0 && (
  <div className="tally">
    <h5>实时票数</h5>
    <ul>
      {Object.entries(gameState.votes).map(([k, v]) => (
        <li key={k}>#{parseInt(k, 10) + 1} → {v} 票</li>
      ))}
    </ul>
  </div>
)}
```

改造为：

```tsx
// §20260811-01 U3: 半公开计票
const [suspenseActive, setSuspenseActive] = useState(false);
const [suspenseVotes, setSuspenseVotes] = useState<Record<string, number> | null>(null);

// 检测投票结束 → 触发悬念
useEffect(() => {
  if (!gameState.vote_suspense) return;
  // 投票阶段结束后（phase 切换或 vote 完成标记）
  if (gameState.phase === 'vote' && /* all voted */) {
    setSuspenseActive(true);
    setSuspenseVotes(gameState.votes); // 暂存完整票型
    const timer = setTimeout(() => {
      setSuspenseActive(false);
    }, gameState.vote_suspense_delay_ms || 3000);
    return () => clearTimeout(timer);
  }
}, [/* dependencies */]);

// 渲染
{gameState.votes && Object.keys(gameState.votes).length > 0 && (
  <div className="tally">
    <h5>{suspenseActive ? '🗳 投票已结束…' : '实时票数'}</h5>
    {suspenseActive ? (
      // 悬念态：只显示谁投了谁，不显示票数
      <ul className="vote-suspense">
        {Object.entries(gameState.votes).map(([k, _v]) => (
          <li key={k}>#{parseInt(k, 10) + 1} → ?</li>
        ))}
      </ul>
    ) : (
      // 正常态：完整票型
      <ul>
        {Object.entries(gameState.votes).map(([k, v]) => (
          <li key={k}>#{parseInt(k, 10) + 1} → {v} 票</li>
        ))}
      </ul>
    )}
  </div>
)}
```

#### 4. 复用路径

- **HistoryDrawer 时间轴**：悬念不应用到历史记录——历史记录始终显示完整票型
- **观战者视图**：观战者同样经历悬念（与玩家一致的体验）
- **狼人夜间投票**：不适用悬念（狼人投票是内部的，已在 NightActionPanel 有独立展示）

### 约束

- 悬念期间 `votes` 数据仍在 `game.state` 中下发（不改变后端），前端选择性渲染
- 不影响 `FinishVote` / `TallyVotes` / `EmitVoteResult` 等后端逻辑
- 不影响 Agent 行为（Agent 通过 GameContext 直接获取票型，不经过前端悬念）

### 测试验证

- `tsc --noEmit` 通过
- `npm run build` 通过
- 手动测试：创建房间 → 投票结束 → 3 秒悬念动画 → 揭晓完整票型
