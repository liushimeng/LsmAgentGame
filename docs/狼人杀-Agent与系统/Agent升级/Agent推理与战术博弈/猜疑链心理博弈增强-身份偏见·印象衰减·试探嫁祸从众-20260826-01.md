## 二、核心设计:四个新模块

### 2.1 模块 1:身份偏见 `RolePrior`

**文件**:`ServerGo/game/werewolf/role_prior.go`(新建,≤ 300 行)

#### 动机

真人玩家对每个座位天然有"角色先验分布",来源于:

- **神职先验**:上一局哪些座位被验证过是预言家/守卫 → 本局同座位 **30% 概率仍为该阵营**
- **身份轮转先验**:13 人局角色卡池对称 → 任何座位是狼先验 ≈ 4/13 ≈ 31%
- **自我保护先验**:自己绝对排除(prior=0)
- **死亡先验**:已死玩家的身份由法官公布 → 直接 hard-set 100%

#### 数据结构

```go
// RolePriorSingle 一条身份先验条目。
type RolePriorSingle struct {
    TargetSeat   int     `json:"target_seat"`
    RoleGuess    string  `json:"role_guess"`
    PriorProb    float32 `json:"prior_prob"`    // 0~1
    EvidenceKind string  `json:"evidence_kind"` // "uniform" | "historical_role" | "death_revealed" | "self"
    Note         string  `json:"note"`          // ≤40 字来源说明
    ComputedAt   int64   `json:"computed_at"`
}

// RolePriorTable 房间级 + per-bot 视图(与 HypothesisTable 同形)。
//
// §92a 锁约束:所有方法 *Locked 变体。
// §135 spectator 隔离:玩家仅看自己 bot 的,观战者看全部。
type RolePriorTable struct {
    Seat     int               `json:"seat"`
    Entries  []RolePriorSingle  `json:"entries"`
    ComputedAt int64            `json:"computed_at"`
}

// RolePriorStore 房间级先验存储。
type RolePriorStore struct {
    tables map[int]*RolePriorTable
}
```

#### 计算入口

```go
// computeRolePriorForSeatLocked 在持锁路径调用(StartAgentsLocked 末尾、
// 每局 Day 1 第一次 LLM 调用前)。
//
// 输入:房间状态 + Agent 人格向量 + 历史 reputation。
// 输出:每个目标座位的 RolePriorSingle 列表。
//
// 算法:
//   1. 初始化均匀分布:13 个 role × 12 目标 = 156 条 prior=1/N
//   2. 应用死亡公开(若 X 已死且身份已揭晓) → 该角色 prior=1.0,其他角色 prior=0
//   3. 应用历史轮转(若本局沿用上一局座位) → 同角色 prior 提升 30%
//   4. 应用 self-exclusion(target == self) → 自身所有角色按已知身份 hard-set
//   5. 应用人格向量(TrustTendency) → 多疑者 prior 整体提高 10%
//
// 不调用 LLM,纯计算。
```

### 2.2 模块 2:记忆印象 `ImpressionMemory`

**文件**:`ServerGo/game/werewolf/impression_memory.go`(新建,≤ 400 行)

#### 动机

假说表是"我猜 X 号是 Y"(身份层),印象表是"我对 X 号的整体观感"(人格层)。
两者正交,不可互相替代。

| 维度 | 假说表 | 印象表 |
|------|--------|--------|
| 粒度 | 一条身份猜测 | 一位玩家的多维评分 |
| 取值 | role_guess + confidence 0-100 | 5 维评分 0~1 |
| 衰减 | UpdatedAt | DecayHalfLifeHours(默认 48h) |
| 写入触发 | LLM `📊 [...]` JSON 段 | **服务端自动聚合**(本文 §三) |

#### 数据结构

```go
// ImpressionDims 5 维印象评分(0~1,越高越正面)。
type ImpressionDims struct {
    Trust       float32 `json:"trust"`        // 信任度:ta 说的我信多少
    Competence  float32 `json:"competence"`   // 能力评估:ta 推理是否到位
    Sincerity   float32 `json:"sincerity"`    // 真诚度:ta 是不是在玩心理战
    Cooperation float32 `json:"cooperation"`  // 合作意愿:ta 是否愿意站我这边
    Threat      float32 `json:"threat"`       // 威胁感:ta 对我多危险
}

// ImpressionEntry 单条印象(per bot × per target)。
type ImpressionEntry struct {
    TargetSeat   int            `json:"target_seat"`
    Dims         ImpressionDims `json:"dims"`
    LastUpdateMS int64          `json:"last_update_ms"`
    EventCount   int            `json:"event_count"`     // 累积观察次数
    SampleEvents []string       `json:"sample_events"`   // ≤5 条最近观察的简短描述
}

// ImpressionMemory per bot 的印象集合。
type ImpressionMemory struct {
    Seat      int               `json:"seat"`
    Entries   []ImpressionEntry `json:"entries"`
    UpdatedAt int64             `json:"updated_at"`
}

// ImpressionStore 房间级印象存储。
type ImpressionStore struct {
    tables map[int]*ImpressionMemory
}
```

#### 衰减算法

```go
// DecayHalfLifeHours 默认 48h — 模拟"人记忆会模糊"。
//
// 公式:dims[i] = dims[i] * 0.5^(elapsed_hours / DecayHalfLifeHours)
// 衰减仅对 Trust / Sincerity / Cooperation 三个软维度生效;
// Threat 因为是"危险感"应该累计,**不衰减**。
// Competence 衰减半衰期 24h(短期能力观察易过期)。
```

### 2.3 模块 3:情绪→推理权重桥 `EmotionReasoningBridge`

**文件**:`ServerGo/game/werewolf/emotion_reasoning_bridge.go`(新建,≤ 200 行)

#### 动机

当前 emotion.go 影响发言风格,**不**影响推理。
本模块做"情绪驱动的认知偏差":

- `wary` 情绪 → 假说表所有 confidence **下限钳制**到 60(疑者偏疑)
- `guilty` 情绪 → 自身所有对外假说 confidence **上限钳制**到 50(撒谎者心虚)
- `irritated` 情绪 → 高估 Threat 维度 1.5x
- `confident` 情绪 → 假说表 confidence 倾向锚定(不轻易改)
- `excited` 情绪 → Trust / Cooperation 维度评分提升 1.3x

#### 接口

```go
// EmotionReasoningWeights 是情绪对推理的修正向量。
type EmotionReasoningWeights struct {
    HypothesisConfidenceFloor int            // 假说 confidence 下限
    HypothesisConfidenceCeil  int            // 假说 confidence 上限
    ThreatMultiplier          float32        // Threat 维度的倍率
    TrustMultiplier           float32        // Trust / Cooperation 倍率
    StabilityBias             float32        // 0~1,越大越不轻易改假说
}

// ApplyEmotionToHypothesisLocked 给定当前 emotion,返回修正后的 confidence。
//
// 严格 §92a:调用方持 r.mu。
func ApplyEmotionToHypothesisLocked(baseConfidence int, emotion string) int {
    w := weightsForEmotion(emotion)
    c := baseConfidence
    if w.HypothesisConfidenceFloor > 0 && c < w.HypothesisConfidenceFloor {
        c = w.HypothesisConfidenceFloor
    }
    if w.HypothesisConfidenceCeil > 0 && c > w.HypothesisConfidenceCeil {
        c = w.HypothesisConfidenceCeil
    }
    return c
}
```

### 2.4 模块 4:博弈工具 `probe / frame / follow_crowd`

**文件**:`ServerGo/agent/wwplayer/tools_psychology.go`(新建,≤ 350 行)

#### 动机

当前 Agent 只有被动工具(`speak` / `interject` / `vote`)。
本模块新增 3 个**主动博弈工具**,让 Agent 能"测试对手"。

| 工具 | 语义 | 频率限制 | 实现路径 |
|------|------|---------|---------|
| `probe_player` | 试探 — 在发言中向特定玩家抛一个"陷阱问题",观察回应 | 每天 1 次 / 目标 | LLM 在 speak 文本里加 1 句试探;后端解析后注入目标 bot 下轮 prompt 高优问题 |
| `frame_player` | 嫁祸 — 主动把怀疑引向第三方"X 像悍跳",为狼队做掩护 | 每天 1 次 | LLM 在 speak 文本里加 1 句嫁祸;后端记录到 RumorGraph(hop=0)+ ImpressionMemory(目标 Threat +0.2) |
| `follow_crowd` | 从众 — 公开表达跟随某玩家的怀疑(可真心可假意) | 每天 1 次 | LLM 在 speak 文本里加 1 句跟票声明;后端记录到 commitment_ledger(承诺)+ ImpressionMemory(目标 Trust +0.1) |

### 5.4 §92a 锁约束

- 所有 `*Store` 的方法均为 `*Locked` 变体。
- 公开变体(测试用):`*Locked` 命名一致,加 `r.mu.Lock()`/`Unlock()` 一层。
- `BuildClientStateWithRoom` / `BuildAgentContext` / `phaseWatchdogTick` 已持 `r.mu`,直接调 `*Locked` 即可。

### 5.5 §92a 反模式自检

- **不得**在 `*Locked` 方法内调 `r.mu.Lock()` → §92a 自死锁。
- **不得**在 handler 里用 `time.Sleep` 等阻塞调用 → 阻塞 LLM 调用链。
- **不得**写 `chat_message` 表 → §119 隔离。
- **不得**在 `BotTranscript.PublicToolUse` 暴露 target_seat → 泄露推理链给对手。
