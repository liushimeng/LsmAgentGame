## U1: 模型能力雷达图（§10.5 T11）

### 动机

管理员和观众缺乏直观的模型能力对比视角。当前 `Leaderboard()` 仅返回 games/wins/win_rate/avg_tokens/net_coins 6 个标量，无法展现「一个模型擅长狼人还是好人」「发言效率如何」等多维能力。

### 设计

**后端** — 新增 `ModelRadarStats` 聚合结构，在 `ModelLogService` 中扩展：

```go
type ModelRadarStats struct {
    ProviderID    string  `json:"provider_id"`
    AgentName     string  `json:"agent_name"`     // JOIN llm_provider 取展示名
    Games         int64   `json:"games"`
    // 5 维能力（归一化到 0~100）
    WinRate       float64 `json:"win_rate"`        // 总胜率 × 100
    WolfWinRate   float64 `json:"wolf_win_rate"`   // 狼人胜率 × 100（仅狼人局）
    GoodWinRate   float64 `json:"good_win_rate"`   // 好人胜率 × 100（仅好人局）
    TokenEff      float64 `json:"token_eff"`       // 效率 = 胜率 / avg_tokens（归一化）
    CoinPerGame   float64 `json:"coin_per_game"`   // 每局平均金币（归一化到 ±500 映射 0~100）
    SampleOK      bool    `json:"sample_ok"`       // Games >= 8
}
```

**API** — `GET /api/admin/llm/radar`（需登录 + admin 权限），返回 `ModelRadarStats[]`。

**查询** — 单次 GROUP BY provider_id，利用 `SelfPortraits` 已有的 wolf/good 分支聚合，额外算 token 效率和金币均值。

**前端** — 新增 `ModelRadarChart.tsx`（~150 行），使用 SVG 绘制五角雷达图（不引入第三方图表库，项目无 echarts/recharts 依赖）。挂在模型管理页面和大厅排行榜旁。

### 风险

- **极低**：纯读操作，零游戏逻辑变更
- **§130 接线**：新增 API + router 注册 + 前端 fetch 三处同步
- **§121 数据形状**：返回 `ModelRadarStats[]` 直接数组，不包装

## U2: 发言质量评估增强（§10.4 T7）

### 动机

当前 `InfluenceTracker` 只有 4 个维度（跟票率/关注度/发言参与/存活），缺少对「发言质量」的客观度量。§120 公平性要求公式不含 LLM 判断信号，但**客观行为信号**（发言长度、工具使用密度、`speak_with_thought` 使用率）是合法输入。

### 设计

在 `InfluenceTracker` 新增第 5 维度 **Insight（洞察力）**，权重从现有四维度中重新分配：

| 维度 | 旧权重 | 新权重 | 变化 |
|------|--------|--------|------|
| Persuasion 跟票率 | 40 | 35 | -5 |
| Attention 关注度 | 25 | 20 | -5 |
| Presence 发言参与 | 20 | 18 | -2 |
| Survival 存活加成 | 15 | 12 | -3 |
| **Insight 洞察力** | **0** | **15** | **+15** |

**Insight 计算公式**（全部客观信号）：
- `longSpeakRatio`：发言字数 > 50 字的比例（鼓励深度发言），对数归一，上限 8 次
- `thoughtRatio`：使用 `speak_with_thought` 的次数占总发言比例（鼓励心口不一策略）
- 各占 Insight 权重的 60%/40%

**数据来源**：`r.recentSpeeches` 已有 `Text` 和 `HasHeartThought` 字段，无需新增数据结构。

### 风险

- **中低**：权重重分配影响所有座位的影响力分数，但变化幅度 ≤ 5 分
- **§120 公平性**：Insight 仅使用客观行为信号（字数、工具使用），不含 LLM 判断
- **§92a**：所有改动在 `RecalculateInfluenceLocked` 锁内，不新增锁
- **Agent prompt 同步**：`InfluenceBlock` 公式说明文案必须更新（权重变化）

## U3: 观众押注竞猜系统（§10.1）

### 动机

观众目前只能被动观看，缺乏参与感。押注系统让观众在每轮投票阶段预测「谁会被放逐」，增加观战趣味性的同时，押注行为本身不泄露任何信息给玩家（§119 协议层隔离）。

### 设计

**数据模型** — 新表 `t_lsm_game_spectator_bet`：

```sql
CREATE TABLE t_lsm_game_spectator_bet (
    id          CHAR(36) PRIMARY KEY,
    room_id     CHAR(36) NOT NULL, INDEX idx_room_round (room_id, round),
    user_id     CHAR(36) NOT NULL,
    round       INT NOT NULL,           -- 投票轮次(day_number)
    target_seat INT NOT NULL,           -- 预测被放逐的座位号
    amount      INT NOT NULL,           -- 押注金额 10~100
    settled     TINYINT(1) DEFAULT 0,   -- 是否已结算
    result      VARCHAR(16) DEFAULT '', -- 'win'/'lose'/''
    payout      INT DEFAULT 0,          -- 赢得金额
    created_at  DATETIME(3)
);
```

**WS 帧协议**：
```
客户端→服务端: game.werewolf_bet { room_id, target_seat, amount }
服务端→客户端: game.werewolf_bet_ack { seat, amount, round }
             game.werewolf_bet_result { round, winners[], pot, actual_target }
```

**结算逻辑**：
- 押注窗口：`PhaseVote` 开始后 30 秒内（人类操作）
- 结算时机：`EmitVoteResult` 后自动触发
- 赔率：固定赔率 1:N（N = 押中人数占总押注人数的比例，最低 1.5x）
- 未押中：50% 销毁 + 50% 滚存到下一局奖池
- **关键约束**：押注信息对**玩家不可见**；不触发 bot 唤醒

**后端**：~300 行（模型 + service + WS handler + 结算 hook）
**前端**：~200 行（`SpectatorBetPanel.tsx` + CSS，仅观战者可见）

### 风险

- **中等**：涉及新表 + WS 帧 + 结算 hook
- **§119 协议层隔离**：押注信息仅推给观战者，不入 `game.state` 公开字段
- **§130 接线**：`EmitVoteResult` 后结算 hook + 新 WS 帧注册 + 前端组件接入三处同步
- **§133 EconTier**：独立常量 `werewolf.bet_destroy_rate = 50`，不与道具经济耦合
- **§121 数据形状**：`bet_ack` 和 `bet_result` 必须核对后端 struct tag

## U4: 音效反馈系统（§10.3 T3）

### 动机

狼人杀是高度情绪化的游戏，当前前端完全无声。关键事件（投票、死亡、天黑天亮、道具命中）缺少听觉反馈，降低沉浸感。

### 设计

**架构**：纯前端，Web Audio API + CSS `prefers-reduced-motion` 友好。

**新增文件**：
- `ClientWeb/src/hooks/useSoundEffects.ts` — 音效 hook，管理音量、开关、播放队列
- `ClientWeb/src/assets/sounds/` — 音效资源目录（4 个基础音效，用 Web Audio API 合成，无需外部文件）

**7 类基础音效**（按事件类型）：

| 事件 | 音效描述 | 触发时机 |
|------|---------|---------|
| 天黑 | 低沉钟声 + 环境音下降 | `DayNightOverlay` night 阶段 |
| 天亮 | 清脆鸟鸣 + 环境音上升 | `DayNightOverlay` dawn 阶段 |
| 投票放逐 | 沉重鼓点 | `vote_result` WS 帧 |
| 玩家死亡 | 倒地声 | `all_dead_list` 变更 |
| 道具命中 | 弹射/爆炸音 | `prop_used` activity |
| 发言气泡 | 轻微弹出声 | 新 chat_message 到达 |
| 身份揭晓 | 翻牌声 | `RolePubliclyRevealed` 变更 |

**实现方式**：Web Audio API `OscillatorNode` + `GainNode` 合成简单音效（无需 mp3/ogg 文件），每个音效 ~20 行代码。用户可通过设置面板调节音量/关闭。

**配置**：localStorage 持久化 `sound_enabled` + `sound_volume`（0~1）。

### 风险

- **极低**：纯前端，零后端改动
- **`prefers-reduced-motion`**：检测到减少动画偏好时自动禁用
- **§136 跨游戏约束**：音效 hook 放 `shared/utils/` 或 `hooks/`（跨游戏共享），不放狼人杀目录
