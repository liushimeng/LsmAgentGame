# 狼人杀 7 人局: 游戏结束后「重新开始」投票 (2026-07-10)

> 需求: 一局狼人杀 `Status=over` 后不要立刻拆除, 让玩家 (人类 + 7 个 Agent)
> 在 5 分钟内对「原地重开一局」进行投票, 通过后由服务端保留所有聊天数据、
> 用同一批 seat 重新发牌开局; 不通过则 5 分钟到时后清理房间。

## 1. 背景与不变量

- 现有 `PhaseGameOver` 状态瞬间触发, watchdog 在 5s tick 调
  `EmitGameOver` + `onGameOver` 回调把 DB `t_lsm_game_room.status` 改为 `over`,
  此后房间无法再被任何客户端交互。
- `t_lsm_game_chat_message` 表保存历史 chat; `ChatHistoryQueue` (§115) 保存
 房间 500K 滚动 chat context。重启动期间**所有 chat 必须保留**:
   1. `t_lsm_game_chat_message` — 通过原有 ChatService 不变路径持续 append。
   2. `ChatHistoryQueue` — 保留原 room 引用 + ReadPointer, 不重置 `nextSeq`、
       `messages`, 不重置 bot 的 `readPointers`。新一局开局后 BotContext 初始
       WindowFor 仍能拿到上一局的尾部 0~N 条作为审计上下文(被压缩淘汰的
       自然淘汰, 未淘汰的保留)。
- 「重开」的本质 = 原 7 个 seat 不动、Agent 不重置、`GameState` 全字段
  由 `StartGame` 重置后立即推进到 `PhasePreWolves`, 玩家 UI 在客户端不卸载。

## 2. 阶段机扩展

新增一个 `Phase`: `PhaseRestartVote`, enum 值排在 `PhaseGameOver` 之前。

| 字段 | 内容 |
|---|---|
| `Phase.String()` | `"restart_vote"` |
| `IsNight()` | false (不阻塞发言) |
| 进入条件 | `checkWinner()` 返回 true 后, 房间内**至少 2 个存活/出场座位** (单局 < 2 玩家直接走 `advanceToPostOver`) |
| 退出条件 (同意侧) | 累计 ≥ floor(N_voters*2/3)+1 同意票 (默认简单多数); 服务端调 `restartGameLocked` → `StartGame(seed)` → `PhasePreWolves` |
| 退出条件 (拒绝侧) | 累计 ≥ ceil(N_voters/2)+1 反对票; 或 5 分钟 deadline 到且没达成多数同意 → 走关闭路径 (原 Behavior) |
| 服务端状态字段 (in `GameState`) | `RestartVoteDeadlineAt time.Time`; `RestartVoteYes map[Seat]bool`; `RestartVoteNo map[Seat]bool`; `RestartVoteDone bool` |

## 3. 配置

`ServerGo/config/werewolf.go` 新增 `WerewolfConfig.RestartVote`:

| 字段 | 默认 | 说明 |
|---|---|---|
| `Enabled` | `true` | 是否启用重开投票 (false 时游戏结束直接走 status=over) |
| `DeadlineSec` | `300` | 投票窗口秒数 (5 分钟) |
| `YesQuorumNumerator` | `2` | 通过比例的分子 |
| `YesQuorumDenominator` | `3` | 通过比例的分母 (同意 ≥ 2/3 + 1 票即通过) |
| `MinPlayers` | `2` | 至少需要 N 名玩家入座过, 否则不进入投票直接关闭房间 |

## 5. 后端实现要点

### 5.1 engine.go

- `PhaseRestartVote` 常量 + `Phase.String()` "restart_vote" +
   `isActingPhase("restart_vote") → false` (因为不需要 LLM 决策, 见 §6.1 的特殊处理)。
- `GameState` 加 4 字段 (§ 2)。
- `checkWinner()` 之后由 manager (`m.finalizeGameOverLocked`) 检测
   `cfg.Werewolf.RestartVote.Enabled && len(r.Seats) >= MinPlayers` → 进入
   `PhaseRestartVote`; 否则保持现 Behavior。

### 5.2 room.go

- 新增 `restartVoteLocked(r, userID, choice string) *errcode.Error` —
  caller 必须持 `r.mu`; 检查 phase/voter-seat, 写 `RestartVoteYes/No/Abstain`,
  调 `evaluateRestartVoteLocked(r)`; 后者根据 §2 退出条件触发:
   - 通过 → 调 `restartGameLocked(r)` (见 5.3)
   - 拒绝/timeout → 调 `forceCloseRoomLocked(r)` (EmitGameOver + onGameOver)
- 新增 `restartVoteDeadlineTick(r)` (在 phaseWatchdog goroutine 中, 每 5s
  检查 deadline; 到点视为 timeout 走关闭路径)。
- `Action_RestartVote(roomID, userID, choice string) (*WerewolfRoom, *errcode.Error)`
  public 入口, 锁标准模式 (mirror Action_DayVote)。

### 5.3 restartGameLocked = 用新 StartGame 重置 + 复用 seats

```go
func (m *WerewolfManager) restartGameLocked(r *WerewolfRoom) *errcode.Error {
    oldSeats := r.Seats
    oldChatQueue := r.chatQueue
    // 1. 清理运行时状态 (Players / Phase / DayNumber)
    //    但保留: r.Seats, r.chatQueue, r.chatQueue.readPointers,
    //    r.AgentNames, r.lobbyBotSeats, BotAgents 引用
    r.State = NewGame(time.Now().UnixNano())
    for seat, uid := range oldSeats {
        if uid != "" {
            r.State.Seats[seat] = uid
            r.State.PlayerByID[uid] = Seat(seat)
        }
    }
    r.State.IsReady = func() bool { ... } // 7 人在座 → true
    // 2. 调 StartGame 等价的 helper: 发牌 + 进 PhasePreWolves
    if err := r.State.DealAndStart(); err != nil { return err }
    // 3. 强制重置 chatQueue 字节累计 (但不 pop messages),
    //    ReadPointers 不动; 给所有 bot 推 game.state
    // 4. wakeAllAgentsLocked 唤醒所有 bot
    return nil
}
```

**关键**: `r.chatQueue` (500K 共享队列) **不重置**; 上一局被淘汰的消息保留
作为 BotContext 的历史回顾。

### 5.4 phaseWatchdog 集成

- `watchdogActingSeat("restart_vote") → -1` (无 actingSeat, 由玩家主动投票)
- deadline 到期 / 多数达成 → 派发 **`evaluateRestartVoteLocked`** (manager 派,
  非 dispatchQuarantinedSkipLocked)

### 5.5 SkipPhaseAction / dispatchQuarantinedSkipLocked

- `SkipPhaseAction("restart_vote", anyRole) → ("", 0)` (无 single-bot 跳过路径)
- `dispatchQuarantinedSkipLocked` 对 `restart_vote` 直接 no-op + INFO 日志
  (依赖 watchdog 5-min deadline)

## 6. Agent 工具

### 6.1 PhaseRestartVote 在 BuildTools 暴露什么

Bot 在 restart_vote 阶段依然需要被 wake: 系统把 GameContext phase 推到
"restart_vote" 后, bot 的 system prompt 会被 `buildAgentContextLocked` 注入
一段「Game Over, 可投票重开一局」+ 上一局 winner。
BuildTools 仅暴露:

- `restart_vote` (description: "投票是否原地重开一局。choice=yes 同意;no 反对;abstain 弃权。可在 phase=restart_vote 内随时投票;超过多数或 deadline 到时会自动结算。")
- `idle_think`

不暴露 speak / interject / whisper / 任何夜间 / 白天工具。

### 6.2 ToolRunner

```go
type ToolRunner interface {
    ...
    RestartVote(choice string) (string, error)
}
```

Manager `restartVoteLocked` 校验 choice ∈ {"yes","no","abstain"}, 写入
`RestartVoteYes/No/Abstain`。

### 6.3 Agent 行为约束 (system prompt)

注入到 `bot.prompt.go` forRestartVote 段落: 「上一局已结束, 阵营结果为
wolf/good; 现在你可以投票决定是否原地重开。同意会立即复用本座位、上一局的
聊天记录保留 (含你上一局的所有思考), 立即发牌开始新一局。反对则本房间将关闭
清理。请在 5 分钟内投票; 多数 (≥ 2/3) 同意即通过。」
