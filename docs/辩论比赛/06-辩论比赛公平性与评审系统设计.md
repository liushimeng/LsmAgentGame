# 辩论比赛 — 公平性与评审系统设计

> 本文档描述辩论比赛的**公平性保障机制**、**评审系统**、**评分体系**、**防偏见设计**。

## 1. 公平性原则

### 1.1 核心原则

| 原则 | 说明 |
|------|------|
| **机会均等** | 双方/多队发言时间、发言次数严格相等 |
| **信息对称** | 所有 Agent 看到相同的辩题和公开信息 |
| **模型中立** | 模型分配随机，不偏向任何一方 |
| **评审独立** | 3 个裁判独立评审，互不可见 |
| **透明可溯** | 所有评分附带理由，可追溯 |

### 1.2 公平性约束清单

| 约束 | 实现方式 |
|------|----------|
| 发言时间均等 | 引擎严格控制每队总时长相等 |
| 发言顺序公平 | 交替发言 + 阶段内轮换 |
| 模型能力均衡 | Fisher-Yates 洗牌 + 立场平衡 |
| 裁判独立性 | 独立 goroutine + 独立 Memory |
| 信息隔离 | 裁判不可见其他裁判评分 |
| 防止串通 | Agent 之间无私下通信通道 |

## 2. 模型分配公平性

### 2.1 分配算法

```go
// FairModelAssignment 公平模型分配
// 目标：
// 1. 每队内模型不重复
// 2. 正反方模型能力均值大致相等
// 3. 裁判模型与辩方不同
// 4. 随机性（Fisher-Yates 洗牌）
func FairModelAssignment(
    teamCount, agentsPerTeam int,
    judgeCount int,
    availableModels []string,
    modelWinRates map[string]float64, // 历史胜率（可选）
) (teamAssignments map[int]map[int]string, judgeAssignments []string) {

    // Step 1: Fisher-Yates 洗牌
    shuffled := make([]string, len(availableModels))
    copy(shuffled, availableModels)
    rand.Shuffle(len(shuffled), func(i, j int) {
        shuffled[i], shuffled[j] = shuffled[j], shuffled[i]
    })

    // Step 2: 按历史胜率排序（平衡模式）
    if modelWinRates != nil {
        sort.SliceStable(shuffled, func(i, j int) bool {
            return modelWinRates[shuffled[i]] > modelWinRates[shuffled[j]]
        })
    }

    // Step 3: 蛇形分配（平衡正反方实力）
    // 强-弱-弱-强 交替分配，确保双方总实力均衡
    teamAssignments = make(map[int]map[int]string)
    for t := 0; t < teamCount; t++ {
        teamAssignments[t] = make(map[int]string)
    }

    // 蛇形分配：第 1 轮正序，第 2 轮逆序
    idx := 0
    for a := 0; a < agentsPerTeam; a++ {
        if a%2 == 0 {
            for t := 0; t < teamCount; t++ {
                teamAssignments[t][a] = shuffled[idx%len(shuffled)]
                idx++
            }
        } else {
            for t := teamCount - 1; t >= 0; t-- {
                teamAssignments[t][a] = shuffled[idx%len(shuffled)]
                idx++
            }
        }
    }

    // Step 4: 分配裁判（使用与辩方不同的模型）
    usedModels := make(map[string]bool)
    for t := 0; t < teamCount; t++ {
        for a := 0; a < agentsPerTeam; a++ {
            usedModels[teamAssignments[t][a]] = true
        }
    }

    var candidates []string
    for _, m := range shuffled {
        if !usedModels[m] {
            candidates = append(candidates, m)
        }
    }

    // 如果候选不足，允许重复
    for j := 0; j < judgeCount; j++ {
        if j < len(candidates) {
            judgeAssignments = append(judgeAssignments, candidates[j])
        } else {
            judgeAssignments = append(judgeAssignments, shuffled[j%len(shuffled)])
        }
    }

    return teamAssignments, judgeAssignments
}
```

### 2.2 分配验证

```go
// ValidateAssignment 验证模型分配的公平性
func ValidateAssignment(teamAssignments map[int]map[int]string, judgeAssignments []string) error {
    // 1. 每队内不重复
    for teamID, agents := range teamAssignments {
        seen := make(map[string]bool)
        for _, model := range agents {
            if seen[model] {
                return fmt.Errorf("team %d has duplicate model: %s", teamID, model)
            }
            seen[model] = true
        }
    }

    // 2. 裁判与辩方不重复
    usedByTeams := make(map[string]bool)
    for _, agents := range teamAssignments {
        for _, model := range agents {
            usedByTeams[model] = true
        }
    }
    for _, jm := range judgeAssignments {
        if usedByTeams[jm] {
            return fmt.Errorf("judge model %s is also used by a team", jm)
        }
    }

    // 3. 裁判之间不重复
    seenJudges := make(map[string]bool)
    for _, jm := range judgeAssignments {
        if seenJudges[jm] {
            return fmt.Errorf("duplicate judge model: %s", jm)
        }
        seenJudges[jm] = true
    }

    return nil
}
```

## 3. 发言公平性

### 3.1 时间控制

| 规则 | 实现 |
|------|------|
| 每队总时间相等 | 引擎严格计时，超时自动截断 |
| 阶段内时间均等 | 每阶段每队分配相同时间 |
| 自由辩论交替 | 发言权严格交替，一方落座另一方即刻接续 |
| 阶段轮换 | 每阶段发言顺序轮换（第一阶段正方先，第二阶段反方先） |

### 3.2 字数控制

| 阶段 | 字数上限 | 处理方式 |
|------|----------|----------|
| 立论 | 500 字 | 超出自动截断 + 警告 |
| 驳论 | 400 字 | 超出自动截断 + 警告 |
| 质询提问 | 50 字 | 超出自动截断 |
| 质询回答 | 100 字 | 超出自动截断 |
| 自由辩论 | 80 字/次 | 超出自动截断 |
| 总结 | 600 字 | 超出自动截断 + 警告 |

### 3.3 发言顺序算法

```go
// GetSpeakingOrder 获取当前阶段的发言顺序
// 规则：交替 + 轮换
func GetSpeakingOrder(phase string, teamCount int, round int) []int {
    order := make([]int, teamCount)

    // 基础顺序
    for t := 0; t < teamCount; t++ {
        order[t] = t
    }

    // 轮换：每阶段偏移一位
    offset := round % teamCount
    rotated := make([]int, teamCount)
    for t := 0; t < teamCount; t++ {
        rotated[t] = order[(t+offset)%teamCount]
    }

    return rotated
}
```

## 4. 评审系统设计

### 4.1 3 裁判制

| 属性 | 说明 |
|------|------|
| 裁判数量 | 3 个（固定单数） |
| 独立性 | 独立 goroutine + 独立 Memory + 独立 LLM 调用 |
| 同时评审 | 3 个裁判同时开始评审 |
| 投票机制 | 多数决（2/3） |
| 分歧处理 | 取中位数分数 |

### 4.2 评分维度

| 维度 | 权重 | 说明 |
|------|------|------|
| 论证质量 | 20% | 论点清晰、论据充分、论证有力 |
| 逻辑严谨 | 20% | 逻辑链条完整、无漏洞 |
| 语言表达 | 20% | 表达清晰、语言优美、有说服力 |
| 团队配合 | 20% | 队友配合默契、论点一致互补 |
| 反驳效力 | 20% | 反驳精准、有效瓦解对方论点 |

### 4.3 评分计算

```go
// ComputeFinalScore 计算最终得分
func ComputeFinalScore(judgeScores []JudgeScore, teamCount int) []TeamFinalScore {
    results := make([]TeamFinalScore, teamCount)

    for teamID := 0; teamID < teamCount; teamID++ {
        // 收集 3 个裁判对该队的评分
        var totalScores []float64
        dimensions := map[string][]float64{
            "argument_quality":       {},
            "logic_rigor":            {},
            "language_expression":    {},
            "team_coordination":      {},
            "rebuttal_effectiveness": {},
        }

        for _, js := range judgeScores {
            for _, r := range js.Rankings {
                if r.TeamID == teamID {
                    totalScores = append(totalScores, r.TotalScore)
                    dimensions["argument_quality"] = append(dimensions["argument_quality"], r.Scores.ArgumentQuality)
                    dimensions["logic_rigor"] = append(dimensions["logic_rigor"], r.Scores.LogicRigor)
                    dimensions["language_expression"] = append(dimensions["language_expression"], r.Scores.LanguageExpression)
                    dimensions["team_coordination"] = append(dimensions["team_coordination"], r.Scores.TeamCoordination)
                    dimensions["rebuttal_effectiveness"] = append(dimensions["rebuttal_effectiveness"], r.Scores.RebuttalEffectiveness)
                }
            }
        }

        // 取中位数（3 个值的中位数 = 排序后的第 2 个）
        sort.Float64s(totalScores)
        medianScore := totalScores[len(totalScores)/2]

        // 各维度取均值
        dimAverages := map[string]float64{}
        for dim, scores := range dimensions {
            sort.Float64s(scores)
            dimAverages[dim] = scores[len(scores)/2] // 中位数
        }

        results[teamID] = TeamFinalScore{
            TeamID:            teamID,
            TotalScore:        medianScore,
            DimensionScores:   dimAverages,
        }
    }

    return results
}
```

### 4.4 胜方判定

```go
// DetermineWinner 判定胜方
func DetermineWinner(judgeScores []JudgeScore, teamCount int) (winnerTeamID int, bestDebaterSeat int) {
    // 1. 统计各裁判认定的胜方
    winVotes := make(map[int]int)
    for _, js := range judgeScores {
        winVotes[js.WinnerTeamID]++
    }

    // 2. 多数决
    maxVotes := 0
    for teamID, votes := range winVotes {
        if votes > maxVotes {
            maxVotes = votes
            winnerTeamID = teamID
        }
    }

    // 3. 最佳辩手投票
    bestDebaterVotes := make(map[int]int)
    for _, js := range judgeScores {
        for _, r := range js.Rankings {
            if r.TeamID == winnerTeamID {
                bestDebaterVotes[r.BestDebater]++
            }
        }
    }

    maxBestVotes := 0
    for seat, votes := range bestDebaterVotes {
        if votes > maxBestVotes {
            maxBestVotes = votes
            bestDebaterSeat = seat
        }
    }

    return winnerTeamID, bestDebaterSeat
}
```

### 4.5 多队模式评审

**双队模式**：
- 直接比较两队总分，高分者胜

**三队模式**：
- 按总分排名（1-3 名）
- 同时评出最佳辩手

**四队模式（BP 制）**：
- 按阵营排名（政府方 vs 反对方）
- 阵营内再排名（上院 vs 下院）
- 评出最佳辩手

**五队模式**：
- 按总分排名（1-5 名）
- 评出最佳辩手

## 5. 防偏见设计

### 5.1 裁判防偏见

| 措施 | 说明 |
|------|------|
| 模型隔离 | 裁判使用与辩方不同的模型 |
| 匿名评审 | 裁判不知道哪个模型对应哪个队伍 |
| 独立评审 | 3 个裁判互不可见彼此评分 |
| 维度评分 | 强制按 5 维度分别打分，避免印象分 |
| 评语要求 | 每个评分必须附带具体理由 |

### 5.2 辩方防作弊

| 措施 | 说明 |
|------|------|
| 无私下通信 | Agent 之间无 whisper 通道 |
| 信息隔离 | 只能看到公开发言，不可见对方内部思考 |
| 阶段隔离 | 只能在当前阶段发言，不能预发后续阶段内容 |
| 字数限制 | 严格字数上限，防止灌水 |

### 5.3 系统防操纵

| 措施 | 说明 |
|------|------|
| 模型随机分配 | 每次创建房间随机分配模型 |
| 分配验证 | 创建时验证分配公平性 |
| 评分异常检测 | 检测异常评分（如全 10 分或全 1 分） |
| 审计日志 | 所有操作可追溯 |

## 6. 异常处理

### 6.1 评分异常

| 异常 | 处理 |
|------|------|
| 裁判超时 | 使用默认中位数评分（5 维度均 5 分） |
| 裁判连续失败 | 隔离该裁判，剩余裁判评审 |
| 2 个裁判失败 | 使用唯一有效评分 |
| 3 个裁判均失败 | 使用 fallback 评分（均 5 分），标记为异常 |
| 评分分歧过大 | 取中位数，记录分歧 |
| 全相同评分 | 正常处理（可能确实表现接近） |

### 6.2 发言异常

| 异常 | 处理 |
|------|------|
| Agent 发言为空 | 视为放弃本轮，自动切换下一位 |
| Agent 发言过短（< 10 字） | 允许但记录，影响评分 |
| Agent 连续 3 次失败 | 隔离该 Agent，该队剩余 Agent 继续 |
| Agent 发言超时 | 自动截断，进入下一位 |

### 6.3 模型异常

| 异常 | 处理 |
|------|------|
| LLM 调用超时（90s） | 使用 fallback 模板发言 |
| LLM 返回非法 JSON | 重试 1 次，仍失败用 fallback |
| LLM 返回空内容 | 视为放弃发言 |
| Provider 不可用 | 切换到备用 Provider |

// FallbackSpeech 生成 fallback 发言
func FallbackSpeech(role, stance, phase string) string {
    templates := map[string]map[string]string{
        "opening_argument": {
            "pro": "我方坚定认为正方立场成立。首先，从逻辑上看...其次，从事实上看...综上，我方坚持正方立场。",
            "con": "我方坚决反对正方观点。首先，对方的论点存在逻辑漏洞...其次，事实表明...综上，我方坚持反方立场。",
        },
        "rebuttal": {
            "pro": "对方刚才的论点存在明显问题。第一...第二...因此，我方坚持认为正方立场更为合理。",
            "con": "对方刚才的论述不能成立。第一...第二...因此，我方坚持认为反方立场更为合理.",
        },
        // ... 其他阶段
    }

    if phaseTemplates, ok := templates[phase]; ok {
        if speech, ok := phaseTemplates[stance]; ok {
            return speech
        }
    }
    return "我方坚持己方观点，由于技术原因暂时无法详细阐述。"
}
