# 辩论比赛 — 超级管理员强制解散房间设计

> 2026-08-31 §20260831-12 — 新增超级管理员强制解散辩论房间功能。
>
> 需求背景：超级管理员以观战者或其他身份进入辩论房间后，可强制解散房间，相关资源自动释放；
> 点击后弹出二次确认框，防止误操作。

## 1. 现状分析

### 1.1 辩论游戏架构独立性

辩论比赛（`game/debate`）与其他 5 款游戏（象棋/国际象棋/军棋/斗地主/德州扑克/狼人杀）
**架构完全独立**：

| 维度 | 其他 5 款游戏 | 辩论比赛 |
|------|-------------|---------|
| 房间管理器 | `GameService` 统一管理 | 独立 `DebateManager` |
| WS 服务 | `ws.GameService` | 独立 `ws.DebateService` |
| 房间 DB 表 | `t_lsm_game_room` + `t_lsm_game_player` | 独立 `t_lsm_game_debate_room` 等 |
| 管理员强制解散 | `DELETE /api/admin/rooms/:id`（通用） | ❌ 未接入 |

### 1.2 已有的解散能力

- **房主解散**：`DELETE /api/games/debate/rooms/:id` → `DebateManager.Disband()`
  - 仅房主可操作，校验 `CreatedBy == callerUserID`
  - 停止 Agent + 引擎 → 设 GameOver → 从内存 map 删除
- **通用超管解散**：`DELETE /api/admin/rooms/:id` → `RoomService.ForceDisbandRoom()`
  - 操作 `t_lsm_game_room` / `t_lsm_game_player` 表
  - 调用 `GameService.RemoveRoomState()` + `BroadcastRoomRemoved()`
  - **对辩论房间无效**（辩论不走这些表/manager）

### 1.3 已有的通用组件

- `AdminDisbandButton`（`components/ui/AdminDisbandButton.tsx`）
  - 超管判定：`userType >= 3`
  - 二次确认：`ConfirmModal`
  - 调用：`forceDisbandRoom(roomId, reason)`
  - 目前用于 5 款游戏的大厅房间卡片

## 2. 设计目标

1. **超级管理员可在辩论房间内强制解散** — 不论身份是房主、观战者还是未加入，均可操作
2. **资源完整释放** — Agent goroutine 停止、引擎停止、内存房间删除、WS 订阅者全部退出
3. **二次确认** — 点击按钮后弹出确认框，需再次确认才执行
4. **与现有架构风格一致** — 对齐狼人杀/德州扑克等游戏的超管解散模式
5. **前端双入口** — 房间内按钮 + 大厅房间卡片按钮

## 3. 后端设计

### 3.1 API 端点

```
DELETE /api/admin/debate/rooms/:room_id?reason=...
```

**权限**：`userType >= UserTypeSuper`（超级管理员）

**请求参数**：
- `room_id`：路径参数，辩论房间 ID
- `reason`：查询参数，解散原因（可选，默认 "admin force disband"）

**响应**：
```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "room_id": "debate_abc123",
    "reason": "admin force disband",
    "removed_at": "2026-08-31T12:00:00Z",
    "spectators": 5
  }
}
```

**幂等性**：房间不存在时返回 200 + `message: "room already absent"`（对齐通用 `ForceDisbandRoom` 语义）。

### 3.2 DebateManager 新增方法

在 `room_manage.go` 中新增 `ForceDisband` 方法：

```go
// ForceDisband 超级管理员强制解散房间(不校验房主身份)。
//
// 与 Disband 的区别:
//   - Disband: 仅房主可调用,校验 IsOwner
//   - ForceDisband: 超管可调用,不校验身份,参数多一个 reason
//
// 资源释放顺序:
//   1. 停止 Agent goroutine(辩手 + 裁判 + 解说)
//   2. 停止引擎阶段机
//   3. 设 PhaseGameOver + closed
//   4. 从 rooms map 删除
//   5. 触发 onRoomRemove 钩子
func (m *DebateManager) ForceDisband(roomID, reason string) (spectators int, ok bool)
```

> 复用现有 `Disband` 的 teardown 路径，去掉 `IsOwner` 校验，增加 reason 参数。

### 3.3 WS 广播帧

新增 `debate.room_removed` 帧（对齐通用 `game.removed` 的命名空间）：

```json
{
  "type": "debate.room_removed",
  "payload": {
    "room_id": "debate_abc123",
    "reason": "admin force disband",
    "removed_at": "2026-08-31T12:00:00Z"
  }
}
```

**DebateService 新增方法**：
```go
// BroadcastRoomRemoved 向所有订阅者推送 debate.room_removed 帧,
// 然后取消所有订阅(对齐 hub.BroadcastRoomIncludingSpectators + UnsubscribeRoomAll)。
func (s *DebateService) BroadcastRoomRemoved(roomID, reason string)
```

### 3.4 接入 main.go

在 `main.go` 的 `DebateManager` 初始化区，注入 `onRoomRemove` 钩子：

```go
debateMgr.SetOnRoomRemove(func(rid string, reason string) {
    debateWsSvc.BroadcastRoomRemoved(rid, reason)
})
```

> 现有 `onRoomRemove` 钩子签名为 `func(roomID string)`，需要扩展为带 reason 参数，
> 或新增独立的 `onForceRemove` 钩子。为最小改动，采用新增 `onForceRemove` 方案。

### 3.5 持久化处理

辩论房间使用 `t_lsm_game_debate_room` 表持久化。强制解散时：

- **内存侧**：`DebateManager.ForceDisband()` 已清理所有内存状态
- **DB 侧**：更新 `t_lsm_game_debate_room` 状态为 `force_closed`，记录 reason
  - 不硬删除，保留审计痕迹（与通用 `ForceDisbandRoom` 硬删除不同，因辩论表是
    历史对局查询的数据源，删除会导致「历史战绩」页面缺记录）

## 4. 前端设计

### 4.1 useDebate hook 新增处理

在 `useDebate.ts` 的 WS `on` 回调中新增 `debate.room_removed` 分支：

```ts
case 'debate.room_removed': {
  if (p.room_id !== roomId) return;
  const reason = (p.reason ?? 'room removed') as string;
  // 上报全局错误(toast 提示用户)
  reportGlobalError({ 
    message: `房间已被管理员解散:${reason}`, 
    severity: 'warning' 
  });
  // 重置 store
  reset();
  // 跳转回大厅
  setTimeout(() => navigate('/debate'), 100);
  break;
}
```

### 4.2 房间内超管按钮

在 `DebateHostControls.tsx` 中增加超级管理员入口：

- **位置**：房主控制面板下方 / 或独立的管理员面板
- **可见条件**：`userType >= 3`（超管）
- **按钮文案**：`⛔ 强制解散`
- **二次确认**：复用 `ConfirmModal`
- **调用 API**：`adminForceDisbandDebateRoom(roomId, reason)`

> 即使当前身份是观战者（非房主），超管也能看到按钮。
> 房主 + 超管双重身份时，同时显示「房主解散」和「超管强制解散」两颗按钮。

### 4.3 大厅房间卡片按钮

在 `DebateLobbyPage.tsx` 的房间卡片渲染中，接入 `AdminDisbandButton`：

- 复用现有 `AdminDisbandButton` 组件
- 超管才能看到
- 解散成功后从 rooms 列表移除该房间
- 走 `debateService.forceDisband(roomId)` 端点（辩论专用，新增）

### 4.4 新增 API 方法

在 `ClientWeb/src/api/admin.ts` 中新增辩论专用方法（或在 `api/debate.ts` 中新增 admin 方法）：

```ts
// 超级管理员强制解散辩论房间
// DELETE /api/admin/debate/rooms/:room_id?reason=...
export async function adminForceDisbandDebateRoom(
  roomId: string,
  reason = 'admin-force-disband',
): Promise<{ room_id: string; reason: string; removed_at: string; spectators: number }>
```

## 5. 完整交互流程

```
超级管理员在房间内
    │
    ▼
点击「⛔ 强制解散」按钮
    │
    ▼
弹出 ConfirmModal 二次确认
    │
    ├─ 取消 → 关闭弹窗,无操作
    │
    └─ 确认 → 调用 DELETE /api/admin/debate/rooms/:id
              │
              ▼
         后端 DebateManager.ForceDisband()
              │
              ├─ 1. 停止所有 Agent goroutine
              ├─ 2. 停止阶段引擎
              ├─ 3. 标记房间 closed
              ├─ 4. 从内存 map 删除
              ├─ 5. 更新 DB 状态(force_closed + reason)
              └─ 6. 广播 debate.room_removed 帧
                        │
                        ▼
                   所有订阅者收到帧
                        │
                        ├─ 超管本人:跳转大厅 + toast 提示
                        └─ 其他观众:跳转大厅 + toast 提示
```

## 6. 权限校验双保险

| 层级 | 校验 | 位置 |
|------|------|------|
| 前端 UI 层 | `userType >= 3` 才渲染按钮 | `DebateHostControls` + `AdminDisbandButton` |
| HTTP API 层 | `userType >= UserTypeSuper` | `AdminAPI.ForceDisbandDebateRoom` |
| 服务层 | 无额外校验(API 层已保证) | `DebateManager.ForceDisband` |

> 与通用 `ForceDisbandRoom` 保持一致的双保险模式。

## 7. 错误处理

| 场景 | 状态码 | 处理 |
|------|--------|------|
| 房间不存在 | 200 (message: "room already absent") | 前端 toast 提示,跳转大厅 |
| 无权限 | 403 | 前端 toast 显示「需要超级管理员权限」 |
| 未登录 | 401 | 重走登录弹层 |
| 服务器内部错误 | 500 | 前端显示错误详情 |

## 9. 测试要点

1. **超管在房间内解散**：超管进入房间 → 点击强制解散 → 确认 → 房间消失 → 跳转大厅
2. **超管在大厅解散**：超管在大厅 → 点击房间卡片的强制解散 → 确认 → 房间从列表消失
3. **普通用户看不到按钮**：普通用户进入房间 → 无「强制解散」按钮
4. **普通用户接收通知**：超管解散房间 → 普通用户收到 toast + 自动跳转
5. **幂等性**：连续点击两次解散 → 第二次返回 room already absent → 无报错
6. **资源释放**：解散后确认 Agent goroutine 已停止（无后续 LLM 调用日志）
7. **DB 状态**：解散后 `t_lsm_game_debate_room` 状态正确更新
