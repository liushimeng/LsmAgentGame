# 辩论比赛 — 房间创建与配置设计

> 本文档描述辩论比赛的**房间创建流程**、**配置选项**、**辩题池管理**、**队伍配置**。

## 1. 房间创建流程

### 1.1 创建流程

```
用户点击「创建辩论房间」
    ↓
弹出创建配置弹窗（RoomCreateModal）
    ↓
用户选择/配置：
  ① 辩题（从池中选择 or 手动输入）
  ② 辩论模式（双队/三队/四队/五队）
  ③ 队伍配置（每队人数、立场）
  ④ 阶段参数（发言时长、字数限制）
  ⑤ 模型分配（自动/手动）
  ⑥ 裁判配置（3 个裁判模型）
  ⑦ 观众设置（是否允许聊天、是否展示 Agent 思考）
    ↓
提交创建请求 → 后端创建房间
    ↓
创建者自动成为房主 + 进入观战
    ↓
房主点击「开始比赛」→ Agent 就位 → 比赛开始
```

## 2. 辩题池设计

### 2.1 辩题分类

| 分类 | 说明 | 示例 |
|------|------|------|
| `classic` | 经典辩论题 | 人性本善/本恶、温饱是/不是谈道德的必要条件 |
| `policy` | 政策型辩题 | 安乐死应该/不应该合法化、碳排放税应该/不应该征收 |
| `value` | 价值型辩题 | 集体利益 vs 个体自由、通才 vs 专才 |
| `tech` | 科技伦理题 | AI 利大于弊/弊大于利、AI 创作是否享有版权 |
| `education` | 教育类辩题 | 大学高中化让青春更/不值得 |
| `divergent` | 发散性议题 | 如何平衡效率与公平、未来 10 年最大的挑战 |
| `custom` | 用户自定义 | 手动输入 |

### 2.2 辩题数据结构

```go
type DebateTopic struct {
    ID            string `json:"id" gorm:"primaryKey"`
    Text          string `json:"text"`           // 辩题文本
    Type          string `json:"type"`           // classic/policy/value/tech/education/divergent/custom
    Category      string `json:"category"`       // 细分分类
    ProPosition   string `json:"pro_position"`   // 正方立场描述
    ConPosition   string `json:"con_position"`   // 反方立场描述
    Background    string `json:"background"`     // 辩题背景说明
    Keywords      string `json:"keywords"`       // 关键词（JSON 数组）
    Difficulty    int    `json:"difficulty"`     // 难度 1-5
    UsageCount    int    `json:"usage_count"`    // 使用次数
    AvgRating     float64 `json:"avg_rating"`    // 平均评分
    CreatedAt     int64  `json:"created_at"`
    IsOfficial    bool   `json:"is_official"`   // 是否官方题库
}
```

## 3. 队伍配置

### 3.1 模式配置矩阵

| 模式 | 队伍数 | 每队人数 | 总 Agent 数 | 立场分配 |
|------|--------|----------|-------------|----------|
| `two_team` | 2 | 3-4 | 6-8 | 正方 + 反方 |
| `three_team` | 3 | 3 | 9 | 正方 + 反方 + 中立 |
| `four_team` | 4 | 2 | 8 | 政府上院 + 政府下院 + 反对上院 + 反对下院 |
| `five_team` | 5 | 2 | 10 | 5 个不同角度 |

### 3.2 队伍数据结构

```go
type TeamConfig struct {
    TeamID    int          `json:"team_id"`
    Stance    string       `json:"stance"`     // pro/con/neutral/angle1-5
    StanceLabel string     `json:"stance_label"` // 显示名称
    Agents    []AgentConfig `json:"agents"`
}

type AgentConfig struct {
    SeatID   int    `json:"seat_id"`
    Role     string `json:"role"`     // first/second/third/fourth
    RoleName string `json:"role_name"` // 一辩/二辩/三辩/四辩
    ModelKey string `json:"model_key"`
}
```

### 3.3 立场分配

**双队模式**：
- 队伍 0 → 正方（pro）
- 队伍 1 → 反方（con）

**三队模式**：
- 队伍 0 → 正方（pro）
- 队伍 1 → 反方（con）
- 队伍 2 → 中立（neutral）

**四队模式（BP 制）**：
- 队伍 0 → 政府上院（gov_upper）
- 队伍 1 → 政府下院（gov_lower）
- 队伍 2 → 反对上院（opp_upper）
- 队伍 3 → 反对下院（opp_lower）

**五队模式**：
- 队伍 0-4 → 5 个不同角度（angle_1 到 angle_5）

## 5. 模型分配配置

### 5.1 自动分配

- 系统从 8 个可用模型中随机分配
- 保证每队内模型不重复
- 裁判使用与辩方不同的模型
- 正反方模型能力均衡

### 5.2 手动分配

- 用户可为每个 Agent 指定模型
- 用户可为每个裁判指定模型
- 系统校验：裁判模型不得与辩方重复

### 5.3 分配约束

| 约束 | 说明 |
|------|------|
| 每队内不重复 | 同一队伍内尽量使用不同模型 |
| 裁判独立 | 裁判模型与辩方不同 |
| 立场平衡 | 正反方模型数量相等 |
| 最少模型数 | 至少需要 5 个可用模型（4 辩方 + 1 裁判） |

## 7. 房间状态机

```
Filling（等待开始）
  ↓ 房主点击开始
Preparation（准备阶段）
  ↓ 30s 后自动
OpeningArgument（立论）
  ↓ 所有一辩发言完毕
Rebuttal（驳论）
  ↓ 所有二辩发言完毕
CrossExamination（质询）
  ↓ 质询时间用尽
CrossExamSummary（质询小结）
  ↓ 小结完毕
FreeDebate（自由辩论）
  ↓ 双方时间用尽
ClosingArgument（总结陈词）
  ↓ 总结完毕
Judging（评审）
  ↓ 3 份评分收齐
Result（公布结果）
  ↓ 30s 后
GameOver（结束）
```
