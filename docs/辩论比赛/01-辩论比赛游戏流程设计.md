# 辩论比赛 — 游戏流程设计

> 本文档描述辩论比赛的**完整游戏流程**，包括阶段定义、阶段转换规则、发言规则、质询规则、自由辩论规则、评审规则。
> 参考 `docs/辩论比赛/辩论比赛总体的流程设计.md` 中的主流赛制（华语辩论 / 奥瑞冈 / 新加坡融合制）。

## 1. 流程总览

### 1.1 骨干流程

```
┌──────────────────────────────────────────────────────────┐
│                    辩论比赛骨干流程                         │
│                                                          │
│  赛前准备 → 立论 → 驳论 → 质询 → 自由辩论 → 总结 → 评审  │
│                                                          │
│  ① 立论   ② 驳论   ③ 质询   ④ 自由辩   ⑤ 总结   ⑥ 评审  │
└──────────────────────────────────────────────────────────┘
```

### 1.2 阶段（Phase）枚举

```go
type Phase int

const (
    PhaseFilling          Phase = iota // 等待配置完成
    PhasePreparation                     // 赛前准备（Agent 审题构思）
    PhaseOpeningArgument                 // ① 开篇立论
    PhaseRebuttal                        // ② 驳论
    PhaseCrossExamination                // ③ 质询 / 交叉盘问
    PhaseCrossExamSummary                // ③-附 质询小结
    PhaseFreeDebate                      // ④ 自由辩论
    PhaseClosingArgument                 // ⑤ 总结陈词
    PhaseJudging                         // ⑥ 评审打分
    PhaseResult                          // 公布结果
    PhaseGameOver                        // 对局结束
)
```

## 2. 各阶段详细设计

### 2.1 PhaseFilling — 等待配置

| 属性 | 值 |
|------|-----|
| 触发 | 房间创建后 |
| 结束 | 房主点击「开始比赛」或所有 Agent 就绪 |
| Agent 行为 | 无（等待） |
| 观众行为 | 可进入观战、聊天 |

### 2.2 PhasePreparation — 赛前准备

| 属性 | 值 |
|------|-----|
| 时长 | 30 秒（可配置） |
| Agent 行为 | 收到辩题 + 立场，独立审题构思（不调 LLM，纯内部准备） |
| 观众行为 | 看到「双方正在准备…」提示 |
| 输出 | 无公开输出，Agent 内部生成初步论点框架 |

> **设计意图**：让 Agent 在正式发言前「思考」一下，避免拿到题目就立论。准备阶段 Agent 会在 Memory 中写入「我的初步论点框架」，供后续阶段参考。

### 2.3 PhaseOpeningArgument — 开篇立论

| 属性 | 值 |
|------|-----|
| 时长 | 每队 3 分钟（可配置） |
| 执行者 | 各方一辩 |
| 顺序 | 正方一辩 → 反方一辩（多队时按队伍顺序轮流） |
| 字数限制 | ≤ 500 字（可配置） |
| 核心任务 | 明确辩题定义、划定辩论范围、抛出核心论点、搭建论证框架 |

**Agent 行为**：
1. 收到 `event: phase_start(opening_argument)` 通知
2. 构建 system prompt（含辩题、立场、一辩职责）
3. 调用 LLM 生成立论文本
4. 通过 `speech` 工具提交发言
5. 引擎广播 `debate.speech` 帧

**发言结构**：
```
【一辩立论】
1. 定义：对辩题核心概念的定义
2. 判准：衡量胜负的标准
3. 论点：2-3 个核心论点 + 简要论据
4. 框架：论证逻辑主线
```

### 2.4 PhaseRebuttal — 驳论

| 属性 | 值 |
|------|-----|
| 时长 | 每队 2 分钟（可配置） |
| 执行者 | 各方二辩 |
| 顺序 | 反方二辩 → 正方二辩（交替） |
| 字数限制 | ≤ 400 字 |
| 核心任务 | 针对对方开篇立论的逻辑漏洞、论据缺陷、定义偏差进行反驳 |

**Agent 行为**：
1. 收到 `event: phase_start(rebuttal)` + 对方一辩发言全文
2. 构建 prompt（含对方立论要点 + 己方立场）
3. 调用 LLM 生成驳论文本
4. 通过 `speech` 工具提交

**驳论要求**：
- 必须针对对方具体论点（引用原文片段）
- 指出逻辑漏洞 / 论据不足 / 定义偏差
- 不能自说自话、脱离对方立论

### 2.5 PhaseCrossExamination — 质询

| 属性 | 值 |
|------|-----|
| 时长 | 每轮 1.5 分钟（可配置） |
| 执行者 | 各方三辩（质询方）→ 对方二辩或三辩（被质询方） |
| 顺序 | 正方三辩质询反方 → 反方三辩质询正方 |
| 规则 | 质询方只能提问、不能阐述；被质询方只能回答、不得反问 |

**质询流程**：
```
1. 质询方发起提问（≤ 50 字）
2. 被质询方回答（≤ 100 字）
3. 质询方追问（≤ 50 字）
4. 被质询方回答（≤ 100 字）
...（交替进行，直到时间用尽）
```

**Agent 行为**：
- 质询方：通过 `cross_exam_question` 工具提问
- 被质询方：通过 `cross_exam_answer` 工具回答
- 引擎校验：质询方只能调 question，被质询方只能调 answer

### 2.6 PhaseCrossExamSummary — 质询小结

| 属性 | 值 |
|------|-----|
| 时长 | 每队 1 分钟 |
| 执行者 | 各方一辩或二辩 |
| 核心任务 | 梳理质询战果、归纳交锋焦点、固化己方优势 |

### 2.7 PhaseFreeDebate — 自由辩论

| 属性 | 值 |
|------|-----|
| 时长 | 每队 4 分钟（可配置，双方均等） |
| 执行者 | 各方全体 Agent |
| 顺序 | 正方先发言，双方交替起立 |
| 规则 | 一方落座即发言结束，另一方即刻接续；同一方发言次序和次数不限 |

**Agent 行为**：
1. 引擎广播 `debate.phase(free_debate)` + 当前发言权归属
2. 获得发言权的 Agent 通过 `free_debate_speak` 工具发言（≤ 80 字/次）
3. 发言后调用 `finish_speak` 工具交还发言权
4. 引擎切换发言权给对方队伍
5. 一方时间用尽后另一方可继续发言或放弃

**多队自由辩论规则**：
- 发言权按队伍顺序轮转
- 每队每次发言 ≤ 60 字
- 每队总时间均等
- 任何队伍可用完时间后剩余队伍继续交替

### 2.8 PhaseClosingArgument — 总结陈词

| 属性 | 值 |
|------|-----|
| 时长 | 每队 3-4 分钟 |
| 执行者 | 各方四辩 |
| 顺序 | 反方四辩 → 正方四辩 |
| 字数限制 | ≤ 600 字 |
| 核心任务 | 梳理全场攻防、汇总对方漏洞、回应己方被质疑、升华价值 |

**总结陈词要求**：
- 不重复基础论点
- 针对全场态势回应
- 升华辩题价值高度

### 2.9 PhaseJudging — 评审阶段

| 属性 | 值 |
|------|-----|
| 时长 | 每裁判 60 秒（独立评审） |
| 执行者 | 3 个裁判 Agent |
| 规则 | 独立打分、互不可见、同时评审 |

**评审流程**：
```
1. 引擎向 3 个裁判 Agent 同时发送评审请求
2. 每个裁判独立调用 LLM 生成评分 + 评语
3. 裁判通过 `submit_score` 工具提交评分
4. 引擎收齐 3 份评分后计算最终结果
5. 广播 `debate.judge_vote` 帧（含各裁判评分）
```

### 2.10 PhaseResult — 公布结果

| 属性 | 值 |
|------|-----|
| 时长 | 30 秒 |
| 内容 | 公布胜方、各维度得分、最佳辩手 |
| Agent 行为 | 无（纯展示） |

## 3. 阶段转换规则

### 3.1 自动转换

```
PhaseFilling → PhasePreparation（房主点击开始）
PhasePreparation → PhaseOpeningArgument（30s 倒计时结束）
PhaseOpeningArgument → PhaseRebuttal（所有一辩发言完毕）
PhaseRebuttal → PhaseCrossExamination（所有二辩发言完毕）
PhaseCrossExamination → PhaseCrossExamSummary（质询时间用尽）
PhaseCrossExamSummary → PhaseFreeDebate（小结完毕）
PhaseFreeDebate → PhaseClosingArgument（双方时间用尽）
PhaseClosingArgument → PhaseJudging（总结完毕）
PhaseJudging → PhaseResult（3 份评分收齐）
PhaseResult → PhaseGameOver（30s 展示后）
```

### 3.2 Watchdog 机制

复用狼人杀的 watchdog 模式：每个阶段有最大时长，超时自动推进。

| 阶段 | 默认时长 | 超时行为 |
|------|----------|----------|
| Preparation | 30s | 自动进入立论 |
| OpeningArgument | 每队 180s | 自动截断，进入驳论 |
| Rebuttal | 每队 120s | 自动截断，进入质询 |
| CrossExamination | 每队 90s | 自动截断，进入小结 |
| CrossExamSummary | 每队 60s | 自动截断，进入自由辩 |
| FreeDebate | 每队 240s | 时间用尽，进入总结 |
| ClosingArgument | 每队 180s | 自动截断，进入评审 |
| Judging | 60s | 超时用 fallback 评分 |
| Result | 30s | 自动进入结束 |

## 4. 发言规则

### 4.1 基本规则

| 规则 | 说明 |
|------|------|
| 字数限制 | 立论 ≤ 500 字，驳论 ≤ 400 字，自由辩 ≤ 80 字/次，总结 ≤ 600 字 |
| 时间限制 | 每阶段有总时长，Agent 必须在时限内完成发言 |
| 交替原则 | 双方/多队交替发言，确保机会均等 |
| 引用规则 | 驳论和质询必须引用对方原文片段 |
| 禁止行为 | 人身攻击、跑题、自说自话 |

### 4.2 发言数据结构

```go
type Speech struct {
    ID          string    `json:"id"`
    Phase       string    `json:"phase"`
    TeamID      int       `json:"team_id"`
    Seat        int       `json:"seat"`        // 队内辩位 0-3
    SpeakerName string    `json:"speaker_name"`
    Stance      string    `json:"stance"`      // pro/con/neutral
    Content     string    `json:"content"`     // 发言正文
    WordCount   int       `json:"word_count"`
    DurationSec int       `json:"duration_sec"` // 实际用时
    Timestamp   int64     `json:"timestamp"`
    References  []string  `json:"references,omitempty"` // 引用的对方发言 ID
}
```

## 5. 多队模式流程差异

### 5.1 双队对抗（2 队 × 3-4 人）

标准华语辩论流程，完全按上述骨干流程执行。

### 5.2 三队辩论（3 队 × 3 人）

| 差异点 | 说明 |
|--------|------|
| 立场分配 | 正方 / 反方 / 中立（或三个不同角度） |
| 发言顺序 | 三队轮流：A → B → C → A → B → C |
| 质询 | 每队质询其他两队各一次 |
| 自由辩论 | 三队轮流发言，每队总时间相等 |
| 评审 | 裁判判定阵营胜负 + 个人最佳辩手 |

### 5.3 四队混战（4 队 × 2 人）

| 差异点 | 说明 |
|--------|------|
| 分组 | 政府上院 / 政府下院 / 反对上院 / 反对下院（BP 制） |
| 立场 | 政府方（支持提案）2 队 + 反对方（反对提案）2 队 |
| 发言顺序 | 按 BP 制顺序：首相 → 反对党领袖 → 副首相 → ... |
| 质询 | POI（Point of Information）— 发言中可起立插话提问 |
| 评审 | 按阵营排名（1-4 名），同时评最佳辩手 |

### 5.4 五队辩论（5 队 × 2 人）

| 差异点 | 说明 |
|--------|------|
| 立场 | 5 个不同角度（发散性议题） |
| 发言顺序 | 五队轮流 |
| 质询 | 每队可质询任意其他队 |
| 自由辩论 | 五队轮流，时间均等 |
| 评审 | 综合评分排名（1-5 名） |

## 6. 观众交互

### 6.1 观众行为

| 行为 | 说明 |
|------|------|
| 观战 | 实时观看所有发言、Agent 思考过程 |
| 聊天 | 在聊天室发言（不影响比赛） |
| 提问 | 可向裁判 Agent 提问（裁判可选择性回应） |
| 点赞 | 可为精彩发言点赞（仅展示用，不影响评分） |

### 6.2 观众聊天规则

- 观众聊天不影响比赛流程
- 观众不可向辩方 Agent 发送消息（辩方 Agent 不可见观众消息）
- 裁判 Agent 可选择性回应观众提问（在评审阶段前）
- 聊天内容实时广播给所有观众

## 7. 异常处理

| 异常 | 处理 |
|------|------|
| Agent LLM 调用超时 | 使用 fallback 文本（模板化发言） |
| Agent 连续失败 3 次 | 隔离该 Agent（quarantine），该队剩余 Agent 继续 |
| Agent 发言为空 | 视为放弃本轮发言，自动切换下一位 |
| 裁判评分超时 | 使用默认中位数评分 |
| 裁判评分分歧过大 | 取中位数（3 取中） |
| 房间人数不足 | 等待 60s 后自动关闭 |
| 网络断线 | 重连后恢复状态（复用 WS 重连机制） |
