# 辩论比赛游戏 — 总体架构设计

> 本文档是辩论比赛游戏系统的**总体架构设计**，描述系统定位、核心概念、技术选型、模块划分、数据流与接口契约。
> 详细设计见同目录下的专题文档（Agent 设计 / 游戏流程 / 房间配置 / 界面交互 / 工具与记忆 / 公平评审）。

## 1. 系统定位与核心概念

### 1.1 产品定位

辩论比赛游戏是一个 **AI Agent 驱动的自动化辩论平台**。与人类玩家只能观战和聊天的狼人杀不同，辩论比赛的**全部参赛角色均由 Agent 扮演**，人类玩家以「观众」身份观看比赛、在聊天室插话、与 Agent 互动。

| 维度 | 狼人杀 | 辩论比赛 |
|------|--------|----------|
| 参与主体 | 人类 + Agent 混合 | **纯 Agent 参赛**，人类仅观战 |
| 核心玩法 | 身份隐藏 + 投票淘汰 | 论证质量 + 逻辑交锋 |
| 胜负判定 | 屠边 / 放逐 | 裁判 Agent 投票评审 |
| 信息结构 | 不对称（身份隐藏） | 对称（题目公开、立场公开） |
| 交互模式 | 夜间行动 + 白天发言 | 阶段制发言 + 质询 + 自由辩论 |

### 1.2 核心概念

| 概念 | 说明 |
|------|------|
| **辩题（Topic）** | 辩论的核心议题，支持经典正反辩题、发散性议题、政策型辩题 |
| **立场（Stance）** | 队伍在辩题上的持方：正方 / 反方 / 中立 / 多角度 |
| **队伍（Team）** | 由 2-4 个 Agent 组成的辩论队，共享立场 |
| **辩位（Role）** | 队内分工：一辩（立论）、二辩（驳论）、三辩（质询/小结）、四辩（总结） |
| **裁判（Judge）** | 3 个评审 Agent，独立打分投票，单数保证必出结果 |
| **阶段（Phase）** | 辩论流程的各个环节：立论 → 驳论 → 质询 → 自由辩论 → 总结 → 评审 |
| **发言（Speech）** | Agent 在某个阶段的正式发言，有字数和时间限制 |
| **质询（CrossExam）** | 一方对另一方的提问交锋环节 |
| **评审（Judging）** | 3 个裁判 Agent 独立评审、投票决定胜负 |

### 1.3 辩论模式

| 模式 | 队伍数 | 每队人数 | 适用场景 |
|------|--------|----------|----------|
| **双队对抗** | 2 队 | 3-4 人 | 经典正反辩论 |
| **三队辩论** | 3 队 | 3 人 | 多角度议题（正/反/中立） |
| **四队混战** | 4 队 | 2 人 | BP 式议会制辩论 |
| **五队辩论** | 5 队 | 2 人 | 多元立场发散性议题 |

> **分组规则**：3 队及以上时，按立场分为 2 大阵营（支持方 vs 反对方 / 多角度），评审按阵营胜负 + 个人表现综合评定。

## 2. 技术架构

### 2.1 技术栈

| 层级 | 技术 | 说明 |
|------|------|------|
| 后端 | Go + Gin | REST API + 房间管理 |
| 实时通信 | gorilla/websocket | WSS 39002 推送辩论进程 |
| 数据库 | MariaDB + GORM | 房间、发言、评审记录 |
| LLM 驱动 | Anthropic 协议 | 8 个 Provider，统一接口 |
| Agent 框架 | in-process goroutine | 复用狼人杀 Agent 架构模式 |
| 前端 | React 18 + TypeScript + Vite | 观战界面 + 聊天室 |
| 状态管理 | zustand | 辩论状态 store |
| 3D/2D | @react-three/fiber + drei | 辩论舞台可视化 |

## 3. 数据流设计

### 3.1 辩论生命周期

```
创建房间 → 配置辩题/模式/队伍 → 开始比赛
    ↓
阶段循环：
  立论阶段 → 驳论阶段 → 质询阶段 → 自由辩论 → 总结阶段
    ↓
评审阶段（3 裁判独立打分）
    ↓
公布结果 → 复盘总结 → 房间关闭/重开
```

### 3.2 Agent 驱动流

```
房间创建（含 agent_seats）
   ↓
StartGame（队伍坐满）
   ↓ 对每个 Agent（辩方 + 裁判）
go Agent.Run(ctx)
   ↓
观察 room.agentEvents channel（phase 切换 / 轮到该 Agent）
   ↓ 轮到我
构建 system + messages + tools → provider.Chat → 解析 tool_use
   ↓
DispatchTool → DebateManager.Action_* / SendBotSpeech
   ↓
把 tool_result 写回 memory，继续循环
   ↓
房间结束 → ctx 取消 → goroutine 退出
```

### 3.3 实时推送流

```
Agent 发言 → engine.BroadcastSpeech → WS 推送
    ↓
前端 useDebate hook 接收 → store 更新 → UI 渲染
    ↓
观众看到实时发言 + Agent 思考面板
```

## 5. 公平性设计

### 5.1 模型分配公平

- **随机分配**：创建房间时，系统自动将 8 个可用模型随机分配给各 Agent 座位
- **不重复原则**：同一队伍内尽量使用不同模型（Fisher-Yates 洗牌）
- **裁判独立**：3 个裁判使用与辩方不同的模型，避免利益冲突
- **立场平衡**：正反方模型能力均值大致相等（按历史胜率平衡）

### 5.2 发言顺序公平

- **交替发言**：正反方交替，确保双方发言机会均等
- **阶段内轮换**：每阶段发言顺序轮换（第一阶段正方先，第二阶段反方先）
- **时间均等**：每队总发言时间严格相等

### 5.3 评审公平

- **3 裁判制**：单数投票，必出结果
- **独立评审**：裁判 Agent 独立打分，互不可见
- **多维度评分**：论证质量 / 逻辑性 / 语言表达 / 团队配合 / 反驳效力
- **去掉极端分**：3 取中位数（或加权平均）

## 6. 不做的事（边界）

- ❌ 不做人类玩家参赛（人类仅观战 + 聊天）
- ❌ 不做实时语音/视频（纯文本辩论）
- ❌ 不做 Agent 跨房间持久化记忆
- ❌ 不做 Agent 之间的私下协商（所有交互在辩论流程内）
- ❌ 不做观众投票决定胜负（仅裁判 Agent 评审）
- ❌ 不做多模态（纯文本 + 可选生成的配图）
