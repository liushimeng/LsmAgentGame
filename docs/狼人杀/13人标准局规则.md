>   - `MaxPlayers` 常量 12 → **13**(数组尺寸上界)

> 兼容:**完整保留** 12 人局(`werewolf_12`)与 7 人局(`werewolf_7`)引擎代码,仅 default branch 切到 13 人。

本文档描述**狼人杀 13 人标准竞技局** —— 4 狼 + 4 神 + **5 民**(自 2026-07-10 §13 起为默认 werewolf 房间人数)。引擎位于 `ServerGo/game/werewolf/`,前端位于 `ClientWeb/src/components/werewolf/`。平台实现以服务端权威为准,所有身份判定 / 技能结算 / 胜负裁决均在服务端。

---

> **设计目标**:多 1 个好人平民让好人阵营规模优势更大(9 好 vs 4 狼),倒逼 4 狼提高夜间协同与白天欺骗能力;为后续「更大规模 Agent 模拟实验」铺垫(13 是 Agent 并发压力下一个水位)。

## §1 角色构成

13 人标准竞技局角色配置(固定牌组,发牌前随机洗牌, 默认 werewolf 房间):

| 角色 | 数量 | 阵营 | 缩写 |
|---|---|---|---|
| 狼人 Werewolf | 4 | 狼人阵营 | 4 狼 |
| 预言家 Seer | 1 | 好人阵营 · 神职 | 神 |
| 女巫 Witch | 1 | 好人阵营 · 神职 | 神 |
| 猎人 Hunter | 1 | 好人阵营 · 神职 | 神 |
| 白痴 Idiot | 1 | 好人阵营 · 神职 | 神 |
| **平民 Villager** | **5** | 好人阵营 | **5 民** |

> **合计**:4 狼 + 4 神 + **5 民 = 13 人**。
> 上表是**固定牌组** `StandardDeck13()`,其中**不含**丘比特 / 守卫 / 第三方阵营。
> ⚠️ **注意**:随机牌组 `RandomDeck13()` 是另一条路径,**会**从 `godRolePool` 发出守卫等扩展神职(见 §2.4)。
> 「不设守卫」仅指固定牌组,不适用于随机牌组。守卫完整规则见 [`狼人杀守卫角色设计.md`](狼人杀守卫角色设计.md)。详细角色能力见 §3。
> 牌组由后端 `StandardDeck13()` 给定,与 `StandardDeck12()`(werewolf_12 专用)、7 人局 `StandardDeck()` 并存,按 `game_kind` / `SeatCount` 分支加载。
> 对比 12 人局:**仅多 1 平民**(好人 8→9, 好人:狼人 9:4 — 好人阵营规模优势更大, 倒逼 4 狼提高夜间协同)。

### 2.4 关键常量

- `const MaxPlayers = 13` — 数组尺寸上界,贯穿 `cards/engine/room/view` 的所有 `[MaxPlayers]` 数组与 `for i<MaxPlayers` 循环。
- `const NoSeat Seat = -1`(空刀 / 弃权 / 放弃开枪 的哨兵值)。
- `func StandardDeck13() []Role` — 返回 13 张固定牌组:
  ```go
  RoleWerewolf×4, RoleSeer, RoleWitch, RoleHunter, RoleIdiot, RoleVillager×5
  ```
- `func AssignRoles13(seed int64, userIDs [MaxPlayers]string) [MaxPlayers]Role` — 13 座全满才发牌。
- 随机牌组 `RandomDeck13()` 固定 4 狼 + 1 预言家,再从活动神职池 `godRolePool` 随机选 2~3 名神职。**当前 `godRolePool` 含 6 名完整实现的神职:女巫、猎人、白痴、守卫、骑士、猎魔人**(代码 `var godRolePool = []Role{RoleWitch, RoleHunter, RoleIdiot, RoleGuard, RoleKnight, RoleDemonHunter}`)。
- **实现状态分级**(§134 起)。`godRolePool` 中的角色分两类,发牌前必须明确其状态:

  | 状态 | 角色 | 含义 |
  |---|---|---|
  | ✅ **完整实现** | 女巫 / 猎人 / 白痴 / 守卫 / 骑士 / 猎魔人 | 引擎阶段 + `Action_*` + Agent 工具 + 人类 UI 全链路可玩 |

  > **§134 / §198 / §猎魔人 硬约束**:进入 `godRolePool` 的角色**要么完整实现,要么移出卡池**,二者必居其一。
  > 「半实现」是最坏状态 —— 玩家持有无效身份,好人阵营等价于少一个神职,而狼人阵营
  > 毫不知情地获得优势。守卫已于 §134 补全、骑士已于 §198 补全、**猎魔人已于 §猎魔人补全**。
  > 剩余 5 名半实现扩展候选(魔术师 / 奇迹商人 / 射梦人 / 乌鸦 / 纯白之女等)已全部移出 `godRolePool`,
  > 新局 `RandomDeck13()` 不再发出。**`godRolePool` 当前活跃 = 6 名完整实现神职:
  > 女巫 / 猎人 / 白痴 / 守卫 / 骑士 / 猎魔人**(详见 [`狼人杀猎魔人角色设计.md`](狼人杀猎魔人角色设计.md))。
- `RoleScarecrow`（稻草人）与 `RolePrince`（定序王子）仅保留枚举值、wire 字符串、阵营/神职判定与显示映射以兼容历史回放、数据库数据和既有帧；二者已从 `godRolePool` 移除,新局 `RandomDeck13()` / `AssignRoles13Random()` 不会再发出。
- 既有 `StandardDeck12()` / `AssignRoles12()` 保留供 `werewolf_12` 专用;既有 `StandardDeck()` (7 张)保留与 `AssignRoles()` 保留,供 `game_kind=werewolf_7` 兼容。

## §3 角色技能

### 3.1 狼人 Werewolf
- **夜间:** 每晚共同睁眼,协商选择击杀任意一名非狼人玩家(4 狼在 `night_wolves` 阶段互看彼此座位,见视图 `BuildWolfPeerView`)。
- **空刀合法:** `wolf_kill(target=-1)` 表示空刀(平安夜)。
- **工具:** `wolf_kill {target: -1|0..12}`(target 枚举 = 存活非狼人玩家 ∪ {-1})。**【改动】原 7 人局不提供空刀 -1,12+ 人局新增**。
- **自爆:** 白天发言阶段 `wolf_suicide` 自爆→死亡(亮身份)→ **遗言**(§20260830-02 新)→ **自爆带走**(可带走 1 人)→进入 `night_wolves`(详见 §8.1)。
- **代码约束:** `NightWolfKill(actor, target)` 校验 actor 必为存活狼人;`target==NoSeat` 为空刀;否则 target 存活、非狼人、非自己。

### 3.2 预言家 Seer
- **夜间:** 每晚查验任意一名非自己的存活玩家,服务端返回该玩家**阵营**(好人 / 狼人,不告知具体身份)。
- **工具:** `seer_check {target}`(filterSelf 存活玩家)。
- **警徽流:** 当选警长后通过 `sheriff_stream` 工具声明验人顺序,死后传递信息(详见 §7)。
- **代码约束:** `NightSeerCheck(actor, target)` 写 `Players[actor].LastSeerCheck `{seat, faction}。

### 3.3 女巫 Witch
- **持有:** 解药 1 瓶 + 毒药 1 瓶,整局各用一次(`Player.WitchAntidoteUsed` / `WitchPoisonUsed`)。
- **工具:** `witch_act {action: "antidote"|"poison"|"none", target?}`,target 可 =-1(解药时自动用狼刀目标)。
- **限制:**
  - 解药与毒药**不能同晚使用**(既有约束,保持不变)。
  - 解药仅对狼杀有效,对白天投票 / 女巫毒杀 / 猎人开枪等其他死亡方式无效。
  - 被当晚毒杀的女巫不能再使用当晚毒药。
- **代码约束:** `NightWitchAct(actor, action, target)` 入口校验互斥。

### 3.4 猎人 Hunter
- **死亡时:** 被狼刀 / 被白天投票放逐 → 可开枪带走任意一名玩家(含放弃=-1)。
- **工具:** `hunter_shoot {target: -1|0..12}`。
- **限制:** 被女巫毒死(`HunterPendingFrom=="poison"`)时**不能开枪**。
- **代码约束:** `HunterShoot()` 入口校验 `PendingFrom != "poison"`。

### 3.5 白痴 Idiot(神职)【新增角色】
- **核心:** 被白天投票放逐时,可**翻开身份牌免予出局**,继续留在场上发言。
- **触发限制:** 仅白天投票放逐最高票时触发(`PhaseVote` → `PhaseIdiotReveal`);夜间死亡 / 被毒 / 被猎人开枪 → 直接死亡,无法翻牌。
- **翻牌代价:** 翻牌后(`Player.IdiotRevealed=true`)失去投票权与被投票权,不能参与放逐 / 警长投票,也不能再次被翻牌翻牌后当天直接进入黑夜。
- **阵营:** 翻牌后身份公开,仍属神职阵营,狼人**屠神必须将白痴击杀**才算屠神成功。
- **工具:** `idiot_reveal {choice: "reveal"|"skip"}`,白痴在 `idiot_reveal` 阶段选择翻牌或放弃。
- **代码约束:** `IdiotReveal(actor, choice)` 校验 actor 为最高票存活白痴;成功后设 `Reveal=true`、重置当天投票、直接进入 `night_wolves`(跳回夜晚)。

### 3.6 平民 Villager
- 无夜间能力,白天靠发言与推理找狼。**默认 13 人局数量 5 人**(12 人历史局 4 人)。

### 3.6b 骑士 Knight(神职)【§198 新增】

> 详见 [`狼人杀骑士角色设计.md`](狼人杀骑士角色设计.md) — 本节为速览。

- **核心技能(白天一次性):** `KnightDuel(actor, target)`。骑士在自己的发言轮(或发言中)可发动决斗翻牌:
  - 若目标阵营 = 狼(`RoleWerewolf`) → **目标出局**(verdict=`execution`,cause=`vote` 因公众裁决语义);
  - 若目标阵营 = 好人(含死亡待复活的非狼) → **骑士自己出局**(verdict=`execution`,cause=`duel` 自决)。
- **使用次数:** 每局限一次。一旦调用 `KnightDuel`(成功或失败),`Player.KnightDuelUsed=true` 锁定技能。
- **发动时机:** 仅 `PhaseSpeak`(白天发言)。其他阶段调 → `ErrValidationFailed`。
- **校验链:** K1-K8 (详见设计文档 §2.2) 与守卫 §134 G1-G5 同一结构。
- **公开身份:** 发动即亮身份(K8)。`RolePubliclyRevealed(actor)` 在 `KnightDuelUsed=true` 时返回 `true`,与猎人开枪、狼自爆、白痴翻牌并列。
- **工具:** Agent 工具 `knight_duel {target: int}`(`target=-1` = 本轮放弃,不消耗机会)。
- **代码约束:** `KnightDuel(actor, target)` 必须先校验阶段、白天存活、`KnightDuelUsed==false`、自己存活、目标存活、`target != actor`;通过后 `killPlayer(target, "vote")` 或 `killPlayer(actor, "duel")` + `KnightDuelUsed=true`。
- **与 §134 守卫的差异:** **不新增阶段**(`PhaseSpeak` 复用)、**不增加 `*_skip` 派发**、**不下传 `KnightDuelUsed` 字段**(前端用 `my_role==='knight' && !player.knight_duel_used` 自决)、**新增 cause=`duel`** 走 `verdictFor → "execution"`。

### 3.6d 猎魔人 DemonHunter(神职)【§猎魔人 新增】

> 详见 [`狼人杀猎魔人角色设计.md`](狼人杀猎魔人角色设计.md) — 本节为速览。

- **核心技能(第 2 晚起每晚可发动):** `NightDemonHunterHunt(actor, target)`。猎魔人在 `PhaseNightDemonHunter`(女巫用药之后、公布死亡之前)狩猎一名存活玩家:
  - 若目标阵营 = 狼(`RoleWerewolf`) → **目标立即死亡**(verdict=`death`,cause=`wolf`,复用狼 cause);
  - 若目标阵营 = 好人 → **猎魔人自己出局**(verdict=`execution`,cause=`demon_hunter_misjudge` 新增死因);
  - 若 `target = -1` → **空过**(本晚不动,合法战术选择)。
- **首夜不可用:** DH1 硬约束 — `DayNumber < 2` 调用一律 `ErrValidationFailed`(枚举端空过)。
- **每晚必发动/空过:** 每晚必须调用 `demon_hunter_hunt`(传 -1 表空过);跨夜不锁定 — 技能可每晚使用,只是身份公开。
- **校验链:** DH1-DH7 (详见设计文档 §2.2):首夜禁用 / 目标存活 / 不狩猎自己 / 空过合法 / 每晚限一次 / 结果立即结算 / 发动即公开。
- **公开身份:** 发动即亮身份(DH7)。`RolePubliclyRevealed(actor)` 在 `DemonHunterHuntUsed=true` 时返回 `true`,作为白名单第 **⑥ 类**(继 ① 终局 / ② 白痴翻牌 / ③ 狼自爆 / ④ 猎人开枪 / ⑤ 骑士决斗 之后)。
- **工具:** Agent 工具 `demon_hunter_hunt {target: int}`(枚举已剔除自己 + 已死;`target=-1` 表空过)。
- **代码约束:** `NightDemonHunterHunt(actor, target)` 必须先校验 `DayNumber>=2`、阶段、`actor==DemonHunterSeat`、存活;通过后 `killPlayer(target, "wolf")` 或 `killPlayer(actor, "demon_hunter_misjudge")` + `DemonHunterHuntUsed=true`。
- **新阶段:** `PhaseNightDemonHunter`(位于 `PhaseNightWitch` 之后、`PhaseDawn` 之前),无守卫或猎魔人已死时跳过;`startNight` 串接猎魔人阶段(`endWitchPhase` 后调 `endDemonHunterPhase`)。
- **watchdog 兜底策略:** 守卫 fallback 兜底守护 / 预言家 fallback 兜底查验 / 女巫 fallback 兜底 skip / **猎魔人 fallback 必须空过**(`target=-1`)— 命中狼的概率太低,误杀好人代价太大。
- **死因新增:** `DeathCauseDemonHunterMisjudge = "demon_hunter_misjudge"`,走 `verdictFor → "execution"`(自决语义,与狼自爆 / 骑士自决对齐)。
- **公开广播:** `EmitDemonHunterHunt` 活动事件公开 actor 与 target,文案分流(命中狼 / 命中好人)与骑士 `EmitKnightDuel` 同构。

### 3.7 神职计数与屠边适配

```
神职 Divine = Seer + Witch + Hunter + Idiot + Knight + DemonHunter (共 5~6)
平民 Plain  = Villager (共 5 在 13 人;12 人历史局 4)
狼人 Wolf   = Werewolf (共 4)
```

> §猎魔人 后,神职池从 5 人扩展到 6 人;随机牌组 2~3 个神职的实际数量视 `godRolePool` 抽取而定。
> 屠边阈值按实际 `DivineCnt / PlainCnt` 动态计算(代码 `refreshCounts()`)。

- `refreshCounts()` 统计 `WolfAliveCnt / GoodAliveCnt / DivineCnt(=神职) / PlainCnt(=Villager)`。
- **屠边阈值:** `DivineCnt==0`(4 神死光) 或 `PlainCnt==0`(**13 人局 5 民死光 / 12 人局 4 民死光**) → 狼人胜。逻辑形状不变。

## §4 阶段流程(Phase)

后端定义于 `ServerGo/game/werewolf/engine.go`,`Phase.String()` 字符串是前后端稳定契约。12 人局阶段枚举如下:

### 4.1 阶段枚举与字符串

| Phase 枚举 | 字符串 | 触发时机 |
|---|---|---|
| PhaseFilling | `filling` | 等待 13 人入座 |

| PhasePreWolves | `pre_wolves` | 首夜发言缓冲期(既有) |
| PhaseNightGuard | `night_guard` | 【§134 新增】夜晚 · 守卫守护(`NightGuardProtect`);仅当牌组含守卫且守卫存活时进入 |
| PhaseNightWolves | `night_wolves` | 夜晚 · 狼人协商刀人(`NightWolfKill`) |
| PhaseNightSeer | `night_seer` | 夜晚 · 预言家查验(`NightSeerCheck`) |
| PhaseNightWitch | `night_witch` | 夜晚 · 女巫用药(`NightWitchAct`) |
| PhaseNightDemonHunter | `night_demon_hunter` | 【§猎魔人 新增】夜晚 · 猎魔人狩猎(`NightDemonHunterHunt`);仅 DayNumber>=2 且本局含猎魔人且存活时进入 |
| PhaseDawn | `dawn` | 黎明 · 公布死亡 + 遗言 + **警徽流结算** |
| PhaseSheriff | `sheriff` | 警长竞选(仅 Day1,既有) |
| PhaseSpeak | `speak` | 白天 · 轮流发言 |
| PhaseVote | `vote` | 白天 · 投票放逐(警长 1.5 票) |
| PhaseIdiotReveal | `idiot_reveal` | 【新增】白痴翻牌结算:投票放逐白痴时触发 |
| PhaseDeathLyric | `death_lyric` | 遗言(LastWords=true 的出局玩家,既有) |
| PhaseHunterShoot | `hunter_shoot` | 猎人死亡后开枪 / 不开枪(既有) |
| PhaseRestartVote | `restart_vote` | 重开局投票(既有) |
| PhaseGameOver | `over` | 对局结束 |

### 4.2 流转简图

```
filling →(满 13 人) pre_wolves → night_guard? → night_wolves → night_seer → night_witch → dawn
dawn → [Day1] sheriff → speak → vote
     → [Day>1] speak → vote
vote →(最高票是白痴)→ idiot_reveal →(翻牌) night_guard?/night_wolves
                              →(放弃翻牌) death_lyric? → hunter_shoot? → night_guard?/night_wolves
vote →(非白痴最高票)→ death_lyric? → hunter_shoot? → night_guard?/night_wolves
     (平票 PK → 仍平 → 无人出局 → night_guard?/night_wolves)
gameover → restart_vote →(通过) 重新发牌
```

> `night_guard?` 表示**条件阶段**:仅当随机牌组含守卫且守卫存活时进入,
> 否则 `startNight()` 直接切到 `night_wolves`(与无女巫时跳过 `night_witch` 同理)。

### 4.3 辅助方法

- `func (p Phase) IsNight() bool` = `PhasePreWolves || PhaseNightGuard || PhaseNightWolves || PhaseNightSeer || PhaseNightWitch`。
- `setPhaseAndDeadline(gs, p)`:(§13 阶段时钟)所有阶段切换统一包装,切换即挂 `PhaseDeadlineAt`。
- `isActingPhase` 白名单(含):`pre_wolves / night_guard / night_wolves / night_seer / night_witch / sheriff / speak / vote / idiot_reveal / hunter_shoot`。

## §5 夜间流程

### 5.1 状态推进

```
night_guard  →(guard_protect, target=-1 空守合法;无守卫/守卫已死则跳过)
night_wolves →(wolf_kill, target=-1 空刀合法)
night_seer   →(seer_check)
night_witch  →(witch_act)
dawn         →(护盾 / 解药 / 同守同救统一结算;checkWinner;未分胜负则 StartDay)
```

> **守卫「盲守」**:守卫在狼刀**之前**行动,因此看不到当晚狼刀目标,必须靠推理预判。
> 这与女巫「可见狼刀」形成策略反差。护盾在 `endWitchPhase` 统一结算,
> 三方行动互不可见。**同守同救**(守卫与女巫救同一人)→ 两者抵消,该玩家仍死亡。
> 完整规则与判定表见 [`狼人杀守卫角色设计.md`](狼人杀守卫角色设计.md)。

平台差异:线下由真人法官手动切换,平台由服务端状态机 + AI 驱动角色自动推进。

### 5.2 狼刀规则

| 规则 | 含义 |
|---|---|
| 合法目标 | 任意非狼人存活玩家 |
| 空刀 | `target = NoSeat(-1)`,当晚无人死亡(平安夜)【新增选项】 |
| 拒绝操作 | target==actor / target 是狼人 / target 已死 |

- 4 狼协商逻辑:每个存活狼人依次被 wake,均可提交 `wolf_kill`;**第一个非 -1 的有效狼刀覆盖 `WolfKillTarget`**。后续狼人再提交非 -1 刀即覆盖前值;提交 -1(空刀)时不覆盖既有非 -1 目标。watchdog 兜底 90s:-1 时若 `WolfKillTarget==NoSeat` 视为狼人协商空刀。

### 5.3 预言家查验

- `seer_check {target: 存活非自己玩家}`。
- 校验通过写 `LastSeerCheck` 后进入 `night_witch`。

### 5.4 女巫用药

| action | target | 备注 |
|---|---|---|
| none | -1 | 默认 |
| antidote | -1(自动用 WolfKillTarget) | 仅在当晚狼刀有效时可用 |
| poison | 存活玩家 | 可与狼刀目标同(同刀同毒,该玩家仍死亡) |

### 5.5 同刀同毒
若狼刀与女巫毒指向同一玩家,该玩家仍正常死亡。`endWitchPhase` 中 `appendUniqueSeat` 去重后写入 `NightDeaths`。

### 5.6 平安夜
狼人空刀 + 女巫不用毒 → `LastNightDeaths = []`,客户端显示「今晚平安夜」。

## §6 白天流程

### 6.1 黎明阶段 `dawn`
- 服务端公布 `LastNightDeaths`(不公布死因 / 身份)。
- 死亡玩家根据 §8.4 遗言规则有 / 无遗言。
- **【新增】警徽流结算:** 若上夜预言家警长`夜间`死亡,本阶段按 §7.3 自动结算警徽归属,广播 `game.sheriff_stream_settle`。

### 6.2 警长竞选 `sheriff`(仅 Day1)
- 候选人报名 `sheriff_candidate{target=自己的座位}`;发言;未参选玩家投票 `sheriff_elect`;平票者二次发言+二次投票,仍平→本局无警长。
- 警长 1.5 票由 `TallyVotes(false)` 以 weight 3:2 整数比实现;警长竞选本身一票一投(`TallyVotes(sheriffMode=true)`)。
- 警长可调整白天发言起点(死左 / 死右 / 警长左 / 警长右)。

### 6.3 轮流发言 `speak`
- 按既定顺序,每位存活玩家依次发言 `speak{text}` + `finish_speak`。
- 当前发言者外的玩家可 `interject`(45s speak 桶) / `whisper`(90s 桶) / `idle_think`。
- 狼人可 `wolf_suicide`(仅限 PhaseSpeak,投票阶段不可自爆;§20260830-02 起自爆
  后有遗言 + 自爆带走权,详见 §8.1)。

### 6.4 投票放逐 `vote`
- 每名存活玩家投一票 `vote{target: -1|0..12}`(-1=弃权)。
- 单一最高票者被放逐;最高票为白痴 → `PhaseIdiotReveal`。
- 平票 → 平票者辩护 + 二次投票;仍平 → 当天无人出局进入黑夜。

## §7 警徽流核心机制

> 警徽流是 12 人竞技局的核心博弈机制,是预言家在无遗言的夜间死亡后,唯一能向全场传递验人信息的方式。
> 实现位置:`ServerGo/game/werewolf/sheriff_stream.go`(新增) + engine / view / agent 三处适配。

### 7.1 数据结构

```go
// GameState 新增字段
SheriffStreams   [2]Seat // [0] 第一警徽流目标,[1] 第二警徽流目标;NoSeat 表示未声明
SheriffStreamsAt [2]int64 // 声明时间(用于前端历史溯源)
```

- 声明:`sheriff_stream{slot: 1|2, target: -1|0..12}`(slot=1 第一,slot=2 第二;target=-1 表示撤回该槽位)。
- 仅预言家警长可生效,非预言家警长死亡后警徽按常规规则(sheriff_successor,见下)处理。

### 7.2 基础规则

- **使用前提:** 仅预言家身份的警长可生效警徽流。
- **声明时机:** 白天发言 / 警长竞选阶段(任意次,后者覆盖前者)。
- **结算时机:** 预言家`夜间`死亡(无遗言)时,下一白天 `dawn` 结算警徽归属,同步广播验人结论。
- **白天出局:** 预言家白天被放逐(有遗言),可口头公布验人结果并自主选择移交对象(`sheriff_successor`),**不走警徽流自动结算**。

### 7.3 标准结算规则

**单警徽流(仅预留一晚验人)**:
- 验出好人(金水) → 警徽移交金水玩家
- 验出狼人(查杀) → 撕警徽(不移交)

**双警徽流(标准)**:
- 双金水 → 移交第一警徽流目标
- 一金一查杀 → 移交金水玩家
- 双查杀 → 撕警徽

**特殊情形**:
- 警徽流目标已提前死亡 / 无声明 → 外置位公认好人;无声明则按撕警徽处理。
- 服务端以**真实验人结果**(`LastSeerCheck` 历史)为准结算,防止假预言家虚假报流。

### 7.4 警徽移交动作

```go
// GameState / Player
SheriffSuccessor Seat // 警长死亡后的警徽继承者( slain 时自动按警徽流计算 / 白天口头指定 )
func (r *WerewolfRoom) SettleSheriffOnDeathLocked(deadSeat Seat, cause string) (successor Seat, ripped bool)
```

- 夜间死亡:若死者为警长且为预言家 → 按 §7.3 结算;否则看 `SheriffSuccessor`(默认=撕,可由玩家在生前 `sheriff_successor` 声明受理)。
- 广播帧 `game.sheriff_stream_settle`:`{dead_seat, successor: -1|0..12, ripped: bool, reason, stream_targets[2], stream_factions[2]}`。

### 7.5 工具

- `sheriff_stream {slot: 1|2, target: -1|0..12}` — 预言家警长在 speak / sheriff / 任意白天阶段声明 / 撤回警徽流(暴露给警长,仅限 PhaseSpeak / PhaseSheriff / PhaseDawn)。
- 警徽流结算服务端自动触发,无需玩家工具。

## §8 特殊规则

### 8.1 自爆(§20260830-02 起:遗言 + 带走)

> 完整设计:[`狼人杀自爆遗言与带走设计-20260830-02.md`](../狼人杀-角色设计/狼人杀自爆遗言与带走设计-20260830-02.md)

- 仅 `PhaseSpeak` 发言阶段;投票阶段不可自爆。
- 出局:身份公开(③白名单);**有遗言**(新规则,配置 `werewolf.suicide_take_enabled`
  默认 true;false 回退旧「无遗言直接入夜」行为)。
- **自爆带走 `suicide_take`**(新阶段):自爆狼遗言结束后,可选择带走一名存活玩家
  (人类 WS 帧 `game.werewolf_suicide_take` / Agent 工具 `wolf_suicide_take`,
  `target=-1` 放弃);watchdog 兜底永远放弃(不随机带走)。
- 被带走者:`DeathCause=suicide_take`,`verdict=death`,身份**不公开**;
  `DayNumber≤2` 有遗言;若为猎人 → 可反枪(`HunterPendingFrom="suicide_take"`),
  反枪结算后入夜。
- 全链路:`speak →(自爆)→ death_lyric(自爆狼)→ suicide_take →(目标死亡)→
  [death_lyric 目标] → [hunter_shoot 反枪] → advanceDay → night`。
  自爆终止白天,`DayNumber` 在入夜时递增(修复旧实现不递增的天数编号缺陷)。

### 8.2 猎人开枪

| 死亡来源 | 可否开枪 | HunterPendingFrom | 身份是否公开 |
|---|---|---|---|
| 狼刀 | ✅ | wolf(§135 起真实接线,黎明遗言后进开枪阶段) | 开枪则公开 |
| 白天放逐 | ✅ | vote | 开枪则公开 |
| 女巫毒杀 | ❌ | 不置 HunterPendingShoot | ❌ 保密 |
| 自爆 / 同守同救被判死 | ❌ | — | — |

- 猎人可选择不开枪 `hunter_shoot{target=-1}` → **不亮身份**(§135)。
- 实际开枪(`target != NoSeat`)置 `Player.HunterFired = true`,进入身份公开白名单。
- 被枪杀者的身份**不公开**;开枪带走已翻牌白痴 → 白痴直接死亡,计入神职死亡数。

> **§135 修复记录**:此前 `HunterPendingShoot` 仅在白天投票放逐两条路径置位,
> 狼刀死的猎人**从未**获得开枪机会 —— `HunterPendingFrom=="wolf"` 分支与
> `HunterShoot` 的 poison 拒绝分支都是为一条永不执行的路径写的死代码。

### 8.2b 身份公开规则(§135 核心)

**普通死亡出局,死者身份牌全程不翻开。** 法官只公布「几号玩家死亡」+ 处决/死亡决断,不报角色。
全场仅 4 类事件公开身份,由 `GameState.RolePubliclyRevealed(seat)` **单点判定**:

| # | 事件 | 判定字段 |
|---|---|---|
| ① | 终局复盘 | `Status == "over"` |
| ② | 白痴白天翻牌 | `Player.IdiotRevealed` |
| ③ | 狼人白天自爆 | `DeathCause == "suicide"` |
| ④ | 猎人实际开枪 | `Player.HunterFired` |

三条下发通道全部走同一白名单:WS 视图 `BuildClientState`(`players[].role`)、
死亡列表 `publicRoleName()`(`all_dead_list_verbose` / `dead_list` / `last_night_deaths_verbose`)、
REST 房间详情 `GetPublicPlayerStates`。

> ⚠️ **禁止**在任何视图层重新引入 `!p.Alive → RoleRevealed = true`。该分支曾使女巫毒药
> 沦为免费验人、狼刀预言家后的悍跳博弈价值归零。回归测试见
> `ServerGo/game/werewolf/engine_reveal_fairness_test.go`(R-01..R-14)。

### 8.3 白痴翻牌(详见 §3.5)
- 仅 `PhaseVote` 最高票时触发 → `PhaseIdiotReveal`。
- 翻牌选择 `idiot_reveal{choice:"reveal"}` → `Players[seat].Revealed=true`,当天无人出局,直接 `night_wolves`。

## §9 胜负判定(屠边)

### 9.1 触发点

服务端在以下时机调 `checkWinner()`:
`endWitchPhase` / `FinishVote` / `WolfSuicide` / `SuicideTake`(§20260830-02)/ `HunterShoot` / `IdiotReveal`(新增触发点)。

### 9.2 判定规则

```go
func (gs *GameState) checkWinner() (winner string) {
    r := gs.refreshCounts()
    switch {
    case r.WolfAliveCnt == 0:            Winner = "good"  // 放逐全部 4 狼
    case r.DivineCnt == 0:               Winner = "wolf"  // 屠神(预+女巫+猎+白痴=4)
    case r.PlainCnt == 0:                Winner = "wolf"  // 屠民(13 人局 5 民 / 12 人局 4 民)
    }
    return
}
```

- 狼人阵营胜:屠神(4 神死光) 或 屠民(4 民死光)。
- 好人阵营胜:放逐全部 4 名狼人。
- 逻辑形状与 7 人局同,神职数从 3 增为 4(加入白痴)、平民从 2 增为 4、狼从 2 增为 4。

### 9.3 结算

- `Status="over"`, `Phase=PhaseGameOver`,广播 `game.over{winner, status, all_reveal=true}`。
- 客户端展示阵营胜负 + 全部身份。

| 首夜发言缓冲期 | 120s(pre_wolves) | 12 bot 公开试探 / 抢身份(7 人 120s 已验证,12 人沿用) |
| Phase Watchdog 警告 | 60s | 同 phase + actingSeat 超 60s WARN |
| Phase Watchdog 强制跳过 | 90s | 超 90s 自动 skip |
| Agent LLM HTTP 最小间隔 | 8s | 12 bot 串行 wake 间隔(【注意】12×8s=96s,需关注 deadline 与并发) |
| Agent speak 限流 | 45s | 单 bot 两次公开(含 interject)最小间隔 |
| Agent whisper 限流 | 90s | 单 bot 两次私聊最小间隔 |
| 遗言阶段单座位截止 | 30s | 与 7 人同 |

### 13.2 房间级 LLM 并发配置

`LsmAgentGame.conf.example`:

```json
"werewolf": {
    "room_llm_concurrency": 12,   // 【改动】原 8 → 12(需 ≥ bot 数以支撑 12 bot 房)
    "phase_deadline_sec": {
        "pre_wolves":360, "speak":360, "vote":360, "sheriff":240,
        "idiot_reveal":240, "hunter_shoot":240, "dawn":8,
        "night_wolves":240, "night_seer":240, "night_witch":240
    }
}
```

> `room_llm_concurrency` 需 ≥ 最大 bot 数(12),避免 12 bot 房间信号量瓶颈。

### 13.3 Agent 限流(同 7 人)

- 同 bot 两次 interject / speak 走同一令牌桶;speak 限流 45s,whisper 90s。
- pre_wolves 阶段 SpeakLimiter 缩到 30s、LLMCallLimiter 缩到 4s(既有)。
- 13 人全 AI 房,LLMCallLimiter=8s 时全员串行 13×8=104s,建议评测阶段观察 `speak`/`vote` 阶段 deadline(360s 宽松)。

## §16 Agent 法官(主持人)与死亡语义(2026-07-10 新增)

13 人局在保留全部既有子系统基础上,新增两个**叠加层**:

### §16.1 Agent 法官

详见 [`docs/狼人杀-重构方案/主持人Agent重构设计.md`](狼人杀-重构方案/主持人Agent重构设计.md)。要点:

- 法官**不是身份牌**,是身份牌之外的系统角色;
- 默认 `judge_mode="ai"` 启动 LLM 法官(`AgentJudge`);真人房间可切 `judge_mode="human"`;LLM 不可用时回退 `judge_mode="auto"`(沿用 host driver 路径);
- 工具集:`announce` / `prompt_actor` / `summary` / `declare_cause` / `idle_silent`;
- 法官不参与投票 / 夜间行动 / 胜负,只做"公开宣告 + 流程引导 + 死因宣告";
- 13 人局所有阶段切换都触发 `judgeWake`(phaseWatchdogTick 末尾填 `JudgePendingAnnounce`);
- 前端 `JudgePanel.tsx` 显示法官最近宣告 + quarantine 徽章。

### §16.2 死亡语义区分

详见 [`docs/狼人杀-角色设计/狼人杀死亡语义设计.md`](狼人杀死亡语义设计.md)。要点:

| 死亡方式 | `cause` | `verdict` | 中文 |
|---|---|---|---|
| 投票放逐 | `vote` | `execution` | 处决 |
| 白痴放弃翻牌 | `vote` | `execution` | 处决 |
| 狼人自爆 | `suicide` | `execution` | 处决 |
| 被自爆带走 | `suicide_take` | `death` | 死亡(§20260830-02) |
| 狼刀 | `wolf` | `death` | 死亡 |
| 女巫毒杀 | `witch_poison` | `death` | 死亡 |
| 猎人反杀 | `hunter` | `death` | 死亡 |

- 玩家 Agent prompt / 法官宣告 / 前端徽章 / DeadPlayerJSON 全部用「处决 / 死亡」术语,不用「杀 / 放逐 / 出局」;
- 引擎 `Player` 新增 `DeathCause` / `DeathVerdict` 字段,`killPlayer` 内部自动算 verdict;
- `DeadPlayerJSON` / `LastNightDeathsVerbose` 视图透出;
- `speak_dedup` 之后过 `normalizeDeathTerms` 二次清洗。
