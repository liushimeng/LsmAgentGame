# 狼人杀13人局 — 创建房间时玩家自选角色（优化和解决方案）

> 日期：2026-08-06 · 编号：20260806-03 · 状态：已实现
> 关联：`docs/狼人杀-Agent与系统/狼人杀Agent设计.md`、CLAUDE.md §15/§134/§198

## 1. 需求

`创建狼人杀房间` 弹窗当前只能选择「哪些座位是 AI + 各 AI 用什么模型 + 法官模式」，
**角色身份完全由引擎随机发牌**（`AssignRoles13Random` 种子确定性洗牌）。
在「主要房间由 Agent 组成」的场景下，用户（房间创建者）希望：

1. 为**自己（人类座位）**指定角色：狼人 / 预言家 / 女巫 / 猎人 / 白痴 / 守卫 /
   骑士 / 猎魔人 / 平民 / **随机**（默认）。
2. 为**每个 AI 座位**指定角色（同一组可选项，默认随机）。

典型玩法：人类固定拿预言家，12 个 AI 随机；或人类拿狼人练习悍跳；
或指定某个 AI 固定拿女巫观察其用药策略。

## 2. 现状分析

### 2.1 发牌链路（改造前）

```
RoomCreateModal.tsx                     POST /api/games/werewolf/rooms
  agent_seats: [{seat, model_key}]  →   createRoomRequest{AgentSeats []AgentSeatConfig}
                                            │ AgentSeatConfig{Seat, ModelKey}
                                            ▼
                              service.CreateRoomWithAgents (room_service_crud.go)
                                            │ RegisterAgentSeats → ws.GameService
                                            ▼
                  ws.GameService.RegisterAgentSeats (game_service.go:190)
                      ManagerAddPlayerAt(bot seats) + SetSeatModelKey
                      SyncSeat → werewolfMgr.JoinGame(human)  ← 人类随机空位
                                            ▼
              13/13 满 → tryStartWithHumanWaitLocked（人类等待窗口）
                       → State.StartGame() (engine.go:572)
                                            ▼
              AssignRoles13Random(gs.Seed, gs.Seats)  ← 唯一发牌点
```

### 2.2 关键约束

- **13 人随机牌组**（`RandomDeck13`, cards.go:356）：固定 4 狼 + 1 预言家 +
  从 `godRolePool`（女巫/猎人/白痴/守卫/骑士/猎魔人 6 选 2~3）随机抽神职，
  其余补平民。**牌组组成是平衡性契约，不能因自选角色而改变**——若允许
  「3 个座位都指定狼人」则牌组必须有 ≥3 狼，否则无解。
- 身份保密：角色只在发牌后按座位下发给本人（view.go 已脱敏），
  自选角色**仅创建者在发牌前知道"我要了什么"，其他玩家/Agent 不可见**，
  不破坏博弈公平性（等同于线下局"我要预言家"的熟人局玩法）。
- **重开局**（§117 `restartGameLocked`）原地复用座位重发牌——自选偏好
  应跨局保留（房间级设置），否则重开后创建者丢失自己的角色选择。
- §92a：`sync.Mutex` 不可重入，所有被持锁路径调用的函数必须 `*Locked` 变体。
- §134/§198 教训：**卡池是契约**——UI 上可选的角色必须全链路实现
  （当前可选集 = 狼人 + 6 神职 + 平民，共 9 个，全部已实现，不含已退役角色）。

### 2.3 设计取舍：「组成守恒的座位置换」而非「任意组局」

拒绝方案 A（任意指定 N 个角色，引擎改牌组组成）：破坏 13 人标准竞技局
平衡性，且多个指定同一限量角色（预言家仅 1 张）时无解，需复杂冲突仲裁。

采用方案 B（**偏好注入 + 牌组内座位置换**）：

1. 引擎照常 `RandomDeck13(seed)` 生成牌组（组成不变）。
2. 对**每个带偏好的座位**（按座位号升序，先到先得的确定性顺序）：
   - 偏好 = `random` / 空 → 跳过；
   - 偏好角色在牌组中有**未被其他偏好预留**的牌 → 把该座位发到的牌与
     一张匹配的牌**交换**（swap），该座位拿到偏好角色；
   - 牌组中无该角色（如本局随机牌组没抽到骑士，但座位指定骑士）→
     **降级为随机**并记日志（Warn），不报错不开局失败。
3. 多座位指定同一限量角色：升序第一个得到满足，其余降级随机。

效果：牌组多重集合在发牌前后**完全一致**（swap 不改变多重集），
平衡性契约不变；指定操作天然幂等、可单测。

### 3.3 ws 层接线

`ws/game_service.go`：
- `RegisterAgentSeats` 从 `AgentSeatConfig.Role` 收集 `map[int]string`，连同
  creator pref 在入座循环**之前**调 `werewolfMgr.SetSeatRolePrefs`。
- 接口实现 `SetSeatRolePrefs(gameKind, roomID, prefs, creatorPref)`：非狼人杀忽略；
  创建者偏好按「调用时 r.Seats 中的人类座位」解析——由于调用点在
  `RegisterAgentSeats`（bot 已入座、人类未 SyncSeat）**之前**，创建者座位尚未
  确定，故 creatorPref 以 `pendingCreatorRolePref` 暂存，`JoinGame` 人类入座成功后
  立即回填到 `seatPreferredRoles[humanSeat]`。

### 3.4 发牌注入算法（cards.go，纯函数）

```go
// ApplyPreferredRoles 在洗牌完成后按座位偏好做"牌组内座位置换"。
// 不变式:返回的 roles 与输入是同一多重集(swap-only)。
func ApplyPreferredRoles(roles *[MaxPlayers]Role, prefs map[int]Role) {
    if len(prefs) == 0 { return }
    // 确定性顺序:座位号升序
    order := sortedSeatKeys(prefs)
    reserved := make(map[int]bool) // 已被偏好占用的"牌位"下标
    for _, seat := range order {
        want := prefs[seat]
        if want <= RoleUnknown || want == RoleMagician /* retired */ { continue }
        if roles[seat] == want { reserved[seat] = true; continue } // 已命中
        // 找一张未被预留、不在"已满足偏好座位"上的匹配牌交换
        for i := 0; i < MaxPlayers; i++ {
            if reserved[i] || i == seat { continue }
            if _, isPrefSeat := prefs[i]; isPrefSeat && roles[i] == prefs[i] { continue }
            if roles[i] == want {
                roles[i], roles[seat] = roles[seat], roles[i]
                reserved[seat] = true
                break
            }
        }
        // 找不到 → 降级随机(记日志由调用方负责)
    }
}
```

注意与 `AssignRoles13Random` 末尾「第 13 人强制平民」的交互：该强制交换在
`assignRolesImpl` 之后执行，会把偏好座位上的非平民牌换走。修法：
**偏好注入放在最末**（`StartGame` 中 `AssignRoles13Random` 返回后统一调用），
即覆盖「第 13 人强制平民」——若创建者恰好是第 13 人且指定了非平民，
以**用户显式选择优先**（自选需求 > 牌组尾位平民这条软约定），
牌组多重集仍守恒（swap-only），仅「尾位必平民」约定被该座位豁免。

## 5. 边界与降级

| 场景 | 行为 |
|---|---|
| 全 AI 房（agentCount=13，创建者观众） | 创建者无座位 → 不显示「我的角色」；`creator_role` 忽略 |
| 牌组中无所选角色（如指定骑士但本局未抽到） | 该座位降级随机；`logger.Warn` 记录 seat+role |
| 多座位抢同一限量角色 | 座位号升序先到先得，其余降级随机 |
| 重开局（§117） | `seatPreferredRoles` 保留在 room 上，每局 `StartGame` 重新注入 → 偏好跨局生效 |
| 人类等待窗口期间 | 创建者入座时（JoinGame）回填 pending 偏好；等待窗口结束后 `StartGame` 正常注入 |
| 非法角色名 | `CreateRoomWithAgents` 校验失败 → `ErrValidationFailed`，弹窗内联红条（§7.1） |
| 老客户端（不带 role 字段） | `omitempty` 零值 = 全随机，行为与改造前完全一致 |

## 6. 测试

- `cards_preferred_roles_test.go`：
  - P-01 单座位指定命中（预言家）后牌组多重集不变
  - P-02 指定角色不在牌组 → 降级随机，多重集不变
  - P-03 两座抢同一角色 → 升序先得，另一座降级
  - P-04 偏好座位已命中 → no-op
  - P-05 与「尾位强制平民」交互：第 13 人指定狼人可生效且多重集守恒
  - P-06 全偏好（13 座全指定）结果仍是合法多重集
- `room_service_crud` 既有测试不受影响（role 字段可选）。

## 7. 安全与公平性

- 自选角色**不下发**给其他玩家：`ClientGameState` 不含偏好字段，
  Agent 的 `GameContext` 也不注入（他座偏好 = 未知信息），博弈公平性与随机局一致。
- 角色名白名单服务端强校验（`DisallowUnknownFields` + 白名单），前端拼错字段名
  会 400（§132 教训）。
- 仅创建入口（房间创建瞬间）可指定；开局后无任何 API 可改角色（引擎无此路径）。
