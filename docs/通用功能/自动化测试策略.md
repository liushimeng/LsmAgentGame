## 2. 工具速查

### 2.1 Web 端:GoWebDebugTool(默认推荐)

```bash
# 启动
cd go-web-debug-tool && ./GoWebDebugTool -d

# 新建页面
curl -X POST http://localhost:28999/NewChromePage \
  -H "Content-Type: application/json" \
  -d '{"url":"https://127.0.0.1:39001"}'

# 点击 / 输入 / 截图 / Console / Network
curl -X POST http://localhost:28999/ControlChromePage \
  -d '{"page_id":"p_xxx","action":"click","selector":"#login-btn"}'

curl -X POST http://localhost:28999/LookChromePageInfo \
  -d '{"page_id":"p_xxx","info":"screenshot"}'
```

完整 API + 错误码见 `CLAUDE.md §30.3`–`§30.7`。常见动作(`/NewChromePage` / `/ControlChromePage`
`action=click|input_text|navigate|wait|scroll|close_tab`)可直接覆盖 5 款游戏
的所有 UI 路径。

### 2.2 后端单元测试

```bash
cd ServerGo && go test -count=1 ./...
```

包含 `engine_test.go` / `wallet_service_test.go` 等,无须任何外部依赖。

### 2.3 后端集成 / 冒烟

```bash
# 健康检查
bash rebuild_restart_app.sh

# 钱包 HTTP 端到端
bash scripts/smoke/test_wallet_api.sh
bash scripts/smoke/test_wallet_db_consistency.sh
bash scripts/smoke/test_wallet_ws.sh

# 钱包 i18n 字段三语对齐
node scripts/smoke/test_wallet_i18n.js
```

> 集成测试(`wallet_service_integration_test.go`)用 `go test -tags walletintegration ./service/`。

## 6. 历史教训(为什么禁止 Python 测试脚本)

`auto_test.py` / `auto_test_v2.py` 自 2026-07-03 删除前,曾让 Agent 付出 4 次修复成本:

| 报告 | 失败项 | 根因类别 |
|------|--------|----------|
| `TestReport/_20260703_031500.md` | 1 | chromedp + React 19 合成事件差异 |
| `TestReport/_20260703_104448.md` | **18** | **全部源自脚本**:路径错 13 + 瞬时状态 2 + 错误码 3 |
| `TestReport/_20260703_104448.md`(再审计) | 6 | **全部源自脚本**:SSL + 重试 + 错误码 |
| `TestReport/_20260703_105200.md` | 0 | 已修复 |

**经验**:

1. **Python 测试脚本的脆弱性集中在三块**:路径漂移(后端路由改了脚本不跟)、证书校验
   (`websocket-client` 的 `sslopt` 字典契约)、错误码覆盖不全。Go `httptest` / `go test`
   直接调用 handler 是**编译期**保证类型,远胜 Python 字符串拼 URL。
2. **Web 渲染验证只能靠真实 Chrome**(或 CDP 抽象)——Python selenium 不能解决 WebGL
   / React 合成事件 / `data-testid` 命中问题。**`go-web-debug-tool` 是项目内的正解**。
3. **每次"修脚本"都是净负债**:修复后仍要跑真实 e2e 才能确认服务端无回归,等于
   "二次劳动"。直接 `go test` 把测试代码放在后端仓库,本身就是后端的回归网。

## 7. 例外:何时仍可临时使用 Python / 独立工具

下列场景**仅作为一次性诊断手段**,不是测试代码,必须**不落库**:

| 场景 | 推荐做法 | 落库? |
|------|----------|--------|
| 临时验证某个 HTTP 端点响应 | `curl -k https://127.0.0.1:39001/...` | ❌ |
| 临时模拟 WS 客户端收发一帧 | `wscat -c wss://... --no-check` | ❌ |
| 一次性导出 DB 数据 / 脚本查询 | `mysql -h 127.0.0.1 -u superuser lsmDB -e "..."` | ❌ |

这些命令在排查问题时由 Agent 临时执行,完成后**不应**沉淀为 `.py` / `.sh` 文件。
如确需沉淀,放进 `scripts/smoke/` 下并加 `test_` 前缀 + 在 PR 描述里说明,经 review 后方可入库。

## 10. 落地 checklist(每个 Agent 必查)

接到"测试 / 验证 / 跑一下 / e2e / 自动化"任务时,按顺序检查:

- [ ] 是 Web 端 UI 验证?→ 用 `go-web-debug-tool`,**不要**造 Python 脚本
- [ ] 是后端业务逻辑?→ 在 `ServerGo/` 加 `*_test.go` + `go test ./...`
- [ ] 是后端冒烟?→ 调 `bash scripts/smoke/test_wallet_*.sh` 或 `bash rebuild_restart_app.sh`
- [ ] 是 WS 帧协议?→ 在 `ServerGo/ws/` 或 `ServerGo/game/<kind>/` 加 `*_test.go`
- [ ] 已在仓库里看到 `auto_test*.py`?→ **不要恢复使用**,按 §4 走 `git log` 找原因

如以上五项均不匹配任务,说明任务定义模糊,**回退给用户确认**而不是自创第四类。
