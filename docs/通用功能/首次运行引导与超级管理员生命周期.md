# 首次运行引导与超级管理员生命周期设计

> 2026-08-25 开源首次部署体验优化。目标:开源仓库 clone 之后,运维**无需手工拷贝/改写
> 任何配置模板**,一条 `./rebuild_restart_app.sh` 即可完成首次部署;同时保证超级管理员
> (root)凭据**永不硬编码于源码**,且在其历史使命完成后自动禁用。

## 1. 需求背景

| # | 需求 | 实现要点 |
|---|------|---------|
| 1 | 首次运行无配置文件时自动回写生成 `LsmAgentGame.conf`,所有字段(数据库等)带默认值 | `config.ensureRuntimeConfigFile` + `applyDefaults` 补齐 DB 默认值 |
| 2 | 无超级管理员时通过配置文件随机生成超管 `用户名` + `密码`,回写 conf 供运维登录部署 | `main.go` 首次种子时随机生成并 `PersistToFile` 回写 |
| 3 | 数据表已有用户记录后:超管功能禁用,conf 回写 `disable`;登录/注册鉴权**不读** conf 中的超管账密 | `SeedRootUserIfEmpty` no-op 判定 + conf 回写 `"disable"` |
| 4 | 多国语言 README 给出首次安装部署运行步骤入口 | README.md / README.en.md / README.ja.md 「快速开始」段 |

## 2. 配置文件自动引导(首次运行)

**解析顺序**(`config.Load()`,维持既有行为):

1. `$LSM_CONF`(绝对路径,测试/CI 用)
2. `./LsmAgentGame.conf`
3. `./LsmAgentGame.conf.example`

**回写生成规则**(`ensureRuntimeConfigFile`,幂等,绝不覆盖已有文件):

- 只有 `.example` → 逐字节拷贝为 `LsmAgentGame.conf`(保留注释);
- 两者都没有 → 从代码内默认值 `synthesizeDefaultConfig()` 同时生成两份。

**DB 默认值**(2026-08-25 新增于 `applyDefaults`,仅当字段为空时填充,不影响存量部署):

| 字段 | 默认值 |
|------|--------|
| `db.host` | `127.0.0.1` |
| `db.port` | `3306` |
| `db.name` | `lsmDB` |
| `db.user` | `root` |
| `db.password` | 空(必须由运维填写 —— 唯一无法给出安全默认值的字段) |

> 注:生成的 conf 中 `jwt.secret` / `llm.endpoint` / `db.password` 仍为空/占位;
> `jwt.secret` 为空时服务**拒绝启动**(2026-08-25 安全加固,Fatal)。运维只需填写这三项。

## 3. 超级管理员生命周期

```
            ┌──────────────────────────────────────────────┐
            │ 启动 → cfg.server.root_account 解析            │
            └──────────────────────────────────────────────┘
                     │                          │
        t_lsm_game_user 表为空(首次)          表中已有用户记录
                     │                          │
   随机生成 root_account = "lsm_root_<rand>"   cfg 回写:
   随机生成 root_password (20位强随机)          root_account = "disable"
   随机生成 root_invite_code (16位)             root_password = "disable"
                     │                          │ (root_invite_code 保留,
   SeedRootUserIfEmpty 落库                     │  注册流程仍需邀请码)
   conf 回写生成的凭据 ──→ 运维从 conf 读到       │
   明文账密并首次登录                             │
                     ▼                          ▼
         后续重启:表中已有用户 → 自动 disable
```

### 3.1 首次启动(空用户表)

- `root_account` 为空或 `"disable"` → 生成 `lsm_root_<8位随机>`(用户名也随机,防扫描);
- `root_password` 为空或 `"disable"` → `util.RandomStrongPassword(20)`;
- 种子落库(`SeedRootUserIfEmpty`)成功后,把**生成的明文凭据回写进 conf**
  (`cfg.PersistToFile`),运维直接打开 `LsmAgentGame.conf` 即可读到;
- 日志输出:`dev_mode=true` 输出明文一次;非 DevMode 仅输出 SHA-256 指纹(凭据以 conf 为准)。

### 3.2 非首次启动(用户表已有记录)

- `SeedRootUserIfEmpty` 返回 `created=false`(no-op);
- 若 conf 中 `root_account != "disable"`,回写:

```json
"server": {
  "root_account":  "disable",
  "root_password": "disable"
}
```

- `"disable"` 是**字面哨兵值**:再遇到空库(如删库重装)时,引导逻辑识别到 `"disable"`
  不会把 `"disable"` 当账号种子,而是重新随机生成;
- **登录/注册鉴权不读 conf 超管账密**:`AuthService.Login/Register` 只走数据库
  bcrypt 校验 + 全员强制 CAPTCHA(2026-08-25 已删除全部旁路),conf 中的
  `root_account` / `root_password` 仅在**首次种子**这一个启动瞬间被消费,
  之后对鉴权链路零影响 —— 写成 `"disable"` 后不存在任何"配置文件直登"路径。

### 3.3 保留项

- `server.root_invite_code` **不**被 disable(注册邀请码是持续需要的);
  为空时首次启动随机生成并同样回写 conf。
- `server.dev_mode` 不参与鉴权,仅控制日志详细度。

## 4. 首次部署标准步骤(README 同步入口)

```bash
# 1. 克隆 + 子模块
git clone <repo> && cd LsmAgentGame
git submodule update --init --recursive

# 2. 准备依赖:MariaDB/MySQL 运行于 127.0.0.1:3306

# 3. 首次启动(无需手工建配置文件)
./rebuild_restart_app.sh
#    - 自动生成 LsmAgentGame.conf(全默认值)
#    - jwt.secret 为空会 Fatal → 编辑 conf 填入强随机串后重跑

# 4. 打开 LsmAgentGame.conf:
#    - 填 db.password;
#    - 首次启动若为空库,root 凭据已随机生成并回写到 server.root_account/root_password,
#      用它登录 https://127.0.0.1:39001;
#    - 下一次重启时 root 凭据自动变为 "disable"(使命完成)。

# 5. LLM Agent 功能:登录后在 /admin/models 为各模型填入真实 api_key
#    (存储于 t_lsm_game_llm_provider,不落 conf)。
```

## 5. 涉及文件

| 文件 | 改动 |

## 6. 安全边界

- 随机 root 凭据只以两种形态存在:conf 文件(0600 权限,gitignore)与 bcrypt 哈希(库);
- 非 DevMode 日志不落明文;
- conf 回写使用 `PersistToFile`,LLM provider api_key 段照旧剥离;
- 任何时刻登录都需要 CAPTCHA + bcrypt,不存在 conf 直登后门。
