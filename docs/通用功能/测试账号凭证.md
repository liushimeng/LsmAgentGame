## 3. 配套 JSON 文件（不入库）

仓库根目录提供:

```
test_account.json    # 4 个账号的 machine-readable 副本(已在 .gitignore 中排除)
```

由于包含明文密码,`test_account.json` 已被 `.gitignore` 排除。Agent
启动时若文件不存在,请按以下流程重新生成(在已经有一个测试账号注册成功的
环境基础上):

```bash
# 1. 用 §1.1 中列出的账号 + 你自己设置的密码,登录开发库并触发一次注册/登录
# 2. 把账号 + 密码 JSON 序列化,写到仓库根目录的 test_account.json
# 3. 后续 Agent 启动可直接 JSON.parse 该文件
```

## 4. Agent 自动化脚本消费方式

```javascript
// Node.js / 浏览器自动化测试场景
import accounts from './test_account.json' assert { type: 'json' };
for (const { account, password } of accounts.accounts) {
  await fetch('https://127.0.0.1:39001/api/auth/login', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ account, password }),
  });
}
```

## 5. 安全注意事项

- **密码不出现在任何 git 跟踪的文件中**(包括本文件 / CLAUDE.md / 任何脚本)。
- **生产环境禁用 AgentBypassAccounts**:显式设置 `cfg.Server.DevMode=false`。
- **定期轮换**:测试账号的密码应在每个开发环境初始化后由运维自定义,
  不应长期复用同一组密码。
- **本文件不应包含真实生产凭据或对外公开凭据**;若发现违规,
  立即轮换密码并 git filter-branch 清除历史。

> ⚠️ 密码含 `;` 的 `test_04` 在 shell / curl 单引号外层或 `JSON.stringify`
> 嵌入时不会出问题,但若嵌入到 `eval "$(echo ...)"` 等命令替换里必须先做转义。
