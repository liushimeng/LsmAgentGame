## 2. 登录流程（全员强制 CAPTCHA）

1. `POST /api/captcha` → 返回 `{captcha_id, svg, expires_at}`。
2. 识别 svg 中的验证码文本（自动化用 OCR / 调试工具读取）。
3. `POST /api/auth/login` 携带 `{account|phone, password, captcha_id, captcha_answer}`。

## 3. 配套 JSON 文件（不入库）

仓库根目录提供:

```
test_account.json    # 账号的 machine-readable 副本(已在 .gitignore 中排除)
```

由于包含明文密码,`test_account.json` 已被 `.gitignore` 排除。Agent
启动时若文件不存在,请自行注册测试账号并按相同 schema 重新生成。

## 4. Agent 自动化脚本消费方式

```javascript
import accounts from './test_account.json' assert { type: 'json' };
for (const { account, password } of accounts.accounts) {
  const cap = await fetch('https://127.0.0.1:39001/api/captcha', { method: 'POST' }).then(r => r.json());
  // 识别 cap.data.svg 中的验证码文本 → captchaAnswer
  await fetch('https://127.0.0.1:39001/api/auth/login', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ account, password, captcha_id: cap.data.captcha_id, captcha_answer: captchaAnswer }),
  });
}
```

## 5. 安全注意事项

- **密码不出现在任何 git 跟踪的文件中**(包括本文件 / CLAUDE.md / 任何脚本)。
- **无认证旁路**：任何环境（含 `DevMode=true`）登录都必须过 CAPTCHA。
- **定期轮换**:测试账号的密码应在每个开发环境初始化后由运维自定义,
  不应长期复用同一组密码。
- **本文件不应包含真实生产凭据或对外公开凭据**;若发现违规,
  立即轮换密码并 git filter-branch 清除历史。

> ⚠️ 密码含 `;` 的 `test_04` 在 shell / curl 单引号外层或 `JSON.stringify`
> 嵌入时不会出问题,但若嵌入到 `eval "$(echo ...)"` 等命令替换里必须先做转义。
