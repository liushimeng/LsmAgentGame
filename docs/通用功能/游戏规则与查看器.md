# 游戏规则与 RulesViewer 设计规范

> 本文档是「游戏规则 Markdown 文件 + Web 端规则说明弹窗」的事实来源。
> 任何 Agent（`Claude Code` / `Kilo Code` / `OpenCode` / `pi` / `OpenClaw` 等）
> 在新增 / 修改游戏规则、添加新游戏、或调整 `RulesViewer` 弹窗时，**必须**先阅读本文档并按其中的规范实施。

---

## 1. 目标与适用范围

| 范围     | 内容                                                         |
| -------- | ------------------------------------------------------------ |
| 适用游戏 | 当前 5 款：中国象棋、国际象棋、中国军棋、斗地主、德州扑克  |
| 未来扩展 | 狼人杀等新游戏落地时，**必须**沿用本文档定义的目录、命名、组件契约 |
| 不适用   | 联机调试页面、登录页、钱包页面等非游戏对局页（不需要规则弹窗） |

**核心原则**：

1. **规则 Markdown 是真相来源**。代码逻辑、UI 提示、AI 客服、玩家教程都以此为准。
2. **Web 端通过 `RulesViewer` 弹窗直接渲染 Markdown**。不写第二份 HTML / TSX 复刻。
3. **新游戏接入成本 ≤ 3 个文件**：`public/rules/<kind>.md` + `GameKind` 联合类型 + `GameInfoPanel` 一行按钮。

## 2. 文件目录与命名规范

### 2.1 Markdown 源文件（两份，互为同步）

| 位置                                  | 用途                              | 同步方式                       |
| ------------------------------------- | --------------------------------- | ------------------------------ |
| `<repo-root>/<游戏名>规则.md`（中文名） | 玩家面向、纯人工阅读的源文件       | **人工维护**                   |
| `ClientWeb/public/rules/<kind>.md`    | Vite dev server 与生产构建打包    | **手动 `cp` 同步**（见 §6.2）   |

> ⚠️ **禁止**只维护其中一份。`public/rules/` 是构建产物，但仓库内只放 md 文件不增加 bundle 体积（~10KB × 5 ≈ 50KB）。

**文件命名规范**：

- 仓库根目录使用**中文文件名**（如 `中国象棋规则.md`、`扑克牌类型-斗地主规则.md`），便于在 `ls` 时一眼识别。
- `public/rules/` 目录下使用 **`<kind>.md`**（小写 ASCII），与 `game_kind` 枚举一一对应：
  - `xiangqi.md` / `chess.md` / `junqi.md` / `doudizhu.md` / `texasholdem.md`
- 未来新增游戏的 `kind` 命名沿用此约定（`werewolf.md`、`go.md` …）。

### 2.2 Markdown 内容结构

每份规则文件**必须**包含：

1. **一级标题**：`# <游戏名>规则`（不带「完整规则说明」「完整版」等冗词）。
2. **引言块引用**（`>` 开头）：用 1-3 句话说明规则来源、平台权威范围、与官方规则的差异。
3. **目录**：`## 目录` + 12 以内的二级章节列表，每条带 `#锚点` 链接。
4. **章节正文**：使用 `## 二级标题` + `### 三级标题`，避免四级以下。
5. **章节末尾引用块**（`>` 开头）：标注实现位置（`ServerGo/game/<kind>/`、`ClientWeb/src/components/<kind>/`）。

**表格规范**：

- **必须**使用标准 Markdown 表格语法（`| 列 | 列 |` + `| --- | --- |` 分隔行）。
- 列数 ≤ 6 列；超出时分拆成两张表或拆出子章节。
- 单元格内允许 `**粗体**` / `` `code` ``，**不允许**嵌套表格或代码块。

**列表规范**：

- 无序列表用 `-`（不混用 `*`）。
- 有序列表用 `1. 2. 3.`，数字必须连续（GitHub 风格渲染才正确）。
- 列表项文字 ≤ 60 字；超长项改成段落。

## 3. 组件契约

### 3.1 文件组织

| 文件                                                | 职责                                                  |
| --------------------------------------------------- | ----------------------------------------------------- |
| `ClientWeb/src/rules/gameRules.ts`                  | `GameKind` 联合类型 + `GAME_ACCENT` 配色 + `rulesUrl()` |
| `ClientWeb/src/rules/renderMarkdown.tsx`            | 纯 React 节点渲染器（无外部依赖）                    |
| `ClientWeb/src/components/common/DraggableModal.tsx` | 通用可拖拽弹窗（无业务耦合）                          |
| `ClientWeb/src/components/rules/RulesViewer.tsx`    | 业务组件：拉 md + 渲染 + 错误处理                    |
| `ClientWeb/src/components/rules/RulesButton.tsx`    | 业务组件：自包含「规则说明」按钮 + 弹窗                |
| `ClientWeb/src/styles/globals.css`（末尾追加）      | `.md-root` / `.md-table` / `.rules-button` 样式       |

### 3.2 `GameKind` 联合类型

```ts
// ClientWeb/src/rules/gameRules.ts
export type GameKind = 'xiangqi' | 'chess' | 'junqi' | 'doudizhu' | 'texasholdem';
```

**新增游戏**时，**必须**：

1. 在联合类型里追加 `'werewolf'` 等。
2. 在 `GAME_ACCENT` 里加一行配色。
3. 在 i18n `types.ts` + 三语言 locale 里加 `rules.title.<kind>`。

### 3.3 `RulesViewer` Props

```ts
interface RulesViewerProps {
  kind: GameKind;          // 必填
  open: boolean;           // 受控
  onClose: () => void;     // 受控
  titleKey?: TKey;         // 可选,默认走 rules.title.<kind>
  width?: number;          // 默认 760
  height?: number;         // 默认 600
}
```

**不要**修改 `RulesViewer` 来承载游戏特定内容。它只渲染 Markdown。

### 3.4 `RulesButton` Props

```ts
interface RulesButtonProps {
  kind: GameKind;
  className?: string;
  testId?: string; // 默认 rules-button-<kind>
}
```

按钮**自包含** `useState(open)` —— 调用方不需要任何额外状态管理。

## 4. 接入流程（5 步 = 5 分钟）

新增一款游戏时（例如狼人杀）：

1. **写规则 Markdown**：在仓库根目录创建 `狼人杀规则.md`（中文文件名）。
2. **同步到构建产物**：`cp 狼人杀规则.md ClientWeb/public/rules/werewolf.md`。
3. **扩联合类型**：
   - `ClientWeb/src/rules/gameRules.ts`：`type GameKind` 加 `'werewolf'`，`GAME_ACCENT` 加一行。
4. **加 i18n**：
   - `ClientWeb/src/i18n/types.ts`：加 `'rules.title.werewolf': string;`。
   - `ClientWeb/src/i18n/locales/{zh-CN,en,ja}.ts`：加对应翻译。
5. **接入 GameInfoPanel**：在侧栏「认输 / 退出房间」一行后追加：
   ```tsx
   <RulesButton kind="werewolf" />
   ```

无需修改 `RulesViewer` / `DraggableModal` / `renderMarkdown`。

## 5. UI / UX 规范

### 5.1 视觉风格

- **对齐 `settlement-overlay` / `settlement-modal`**：项目内已有的弹窗视觉语言（深色面板、圆角、阴影）。
- **每款游戏一个强调色**：弹窗头部左侧 4px 边框 + 头部渐变背景使用 `GAME_ACCENT[kind]`。
- **拖拽光标**：header 上 `cursor: grab`；按下时 `setPointerCapture`，避免鼠标离开 header 后丢失。
- **关闭方式**：
  - 右上角 `✕` 按钮（`data-testid="draggable-modal-close"`）。
  - 背景蒙层点击。
  - `Esc` 键。
  - 三者**必须**都可用。

### 5.2 Markdown 渲染样式

由 `ClientWeb/src/styles/globals.css` 末尾的 `.md-*` 样式统一管理：

| 元素       | 关键样式                                                   |
| ---------- | ---------------------------------------------------------- |
| `h1`       | 20px + 底部 1px 分割线                                     |
| `h2`       | 16px + 左侧 3px `var(--accent)` 强调条                     |
| `h3`       | 14px，半透明文字色                                         |
| `table`    | 1px 边框 + sticky thead + 偶数行 zebra + hover 高亮        |
| `code`     | 行内：深色背景 + 1px 边框；块：`<pre>` 12.5px              |
| `blockquote` | 左侧 3px 灰色强调 + 半透明背景                            |

**不要**在 `.md-*` 样式里写 `color: white` 这类绝对色值；统一走 CSS 变量（`var(--text)` / `var(--card)`）。

### 5.3 性能与可访问性

- **模块级缓存**：`RulesViewer` 在 `fetch` 成功后把文本写进 `Map<url, string>`，二次打开零延迟。
- **CDP 友好**：`RulesButton` 默认带 `data-testid="rules-button-<kind>"`，`DraggableModal` 容器带 `data-testid="draggable-modal"`，关闭按钮带 `data-testid="draggable-modal-close"`。
- **键盘可达**：弹窗的 `Esc` 关闭、`role="dialog"` + `aria-modal="true"` 已实现；后续如需 trap focus，升级到 `focus-trap-react`。
- **无外部依赖**：渲染器是项目自带的 ~80 行代码，避免引入 `marked` / `react-markdown`（+200KB+ bundle）。

## 6. 维护流程

### 6.1 修改规则文本

1. 编辑仓库根目录的中文 Markdown（`中国象棋规则.md` 等）。
2. 同步 `cp` 到 `ClientWeb/public/rules/<kind>.md`。
3. 提交；commit message 用 `docs(<kind>): 更新 <kind> 规则`。
4. **不要**直接改 `public/rules/` 下的副本 —— 会和源文件漂移。

### 6.2 自动化同步（建议后续接入）

```bash
# 仓库根目录 scripts/sync_rules.sh
for kind in xiangqi chess junqi doudizhu texasholdem; do
  cn_name=$(case $kind in
    xiangqi) echo "中国象棋规则.md";;
    chess) echo "国际象棋规则.md";;
    junqi) echo "中国军棋规则.md";;
    doudizhu) echo "扑克牌类型-斗地主规则.md";;
    texasholdem) echo "扑克牌类型-德州扑克.md";;
  esac)
  diff -q "$cn_name" "ClientWeb/public/rules/$kind.md" >/dev/null || \
    cp "$cn_name" "ClientWeb/public/rules/$kind.md"
done
```

> 当前未自动化；手动 `cp` 是规范的过渡方案。

### 6.3 渲染器升级路径

如果 Markdown 写法扩展（内嵌 HTML、脚注、目录自动生成等），**不要**先扩展 `renderMarkdown.tsx` 的特例。改用 `react-markdown` + `remark-gfm`：

```bash
cd ClientWeb && npm i react-markdown remark-gfm
# 然后:
#   1) RulesViewer.tsx 替换 renderMarkdown(md) 为 <ReactMarkdown>{md}</ReactMarkdown>
#   2) 删除 src/rules/renderMarkdown.tsx
#   3) 同步本节文档的"组件契约"
```

> `+~80KB` 的 bundle 增长可接受；只要新语法确实被需要才升级。

## 7. 失败模式与兜底

| 场景                       | 行为                                                                          |
| -------------------------- | ----------------------------------------------------------------------------- |
| `fetch /rules/<kind>.md` 404 | 弹窗内显示红色错误卡片 + 「请刷新页面或联系管理员」+ 实际 HTTP code         |
| `fetch` 网络中断            | 同上，外加 `error.message` 文本                                               |
| Markdown 解析失败           | 当前实现只渲染已知语法，**不抛错**（解析器对未知语法降级为段落）            |
| RulesViewer 嵌入到非对局页  | 仍可工作；按钮位置由调用方决定                                              |
| 移动端                     | `DraggableModal` 限制 `maxWidth: calc(100vw - 16px)` + `maxHeight: calc(100vh - 16px)`，在小屏自适应 |
