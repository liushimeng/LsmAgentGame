# 国际化(i18n)与服务器命名规则

> 本文件是 Agent 自动加载的规则补充,配合根目录 `CLAUDE.md` 使用。
> 涉及多语言文案、language 字段、服务器文件命名时,先读本文件。

## 1. 多国语言(i18n)

### 1.1 支持的语言

| 代码 | 含义 | 标签 |
|---|---|---|
| `zh-CN` | 中文(**默认**) | 中文 |
| `en` | 英语 | English |
| `ja` | 日语 | 日本語 |

前后端必须保持一致:
- 前端:`ClientWeb/src/i18n/index.ts` 的 `SUPPORTED` / `DEFAULT_LANG` / `LANG_LABELS`。
- 后端:`ServerGo/service/user_service.go` 的 `SupportedLanguages` / `DefaultLanguage`。

新增/删除语言时,**两端同时改**,否则服务器会拒绝前端无法识别的值。

### 1.2 前端架构(自建,无第三方依赖)

- `src/i18n/types.ts` — `Dict` 接口,定义全部翻译 key(扁平 `'区块.名称'`)。新增文案先在此加 key,三份字典立即变成类型错误,强制补齐。
- `src/i18n/locales/{zh-CN,en,ja}.ts` — 三份字典,均 `: Dict`,key 完全一致。
- `src/i18n/index.ts` — `translate(lang, key, vars?)`,占位符形如 `{id}`;缺失 key 回退默认语言,再回退 key 本身。
- `src/store/i18n.store.ts` — zustand + persist 到 `localStorage['lsm.lang']`:
  - `setLang(lang)`:本地立即生效;**已登录**则后台 `PATCH /api/user/language` 落库(失败仅告警,不回滚)。
  - `applyServerLang(lang)`:登录/注册成功后由 `auth.store` 调用,用服务器值覆盖本地。
- `src/hooks/useT.ts` — `const t = useT(); t('key', { id })`。组件内一律用 `t()`,**禁止**新增硬编码用户可见文案。
- `src/components/layout/LanguageSwitcher.tsx` — 标题栏工具栏的语言下拉,未登录也可用。

### 1.3 偏好持久化流程

- 游客:语言存 `localStorage['lsm.lang']`,刷新保留。
- 登录:服务器 `t_lsm_game_user.language` 为准;login/register/refresh 响应携带 `language`,前端 `applyServerLang` 覆盖本地 → 换浏览器登录也保留。
- 登出:不清除本地语言。

### 1.4 相关接口

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| GET | `/api/user/profile` | 是 | 返回 `{user_id, account, language}` |
| PATCH | `/api/user/language` | 是 | 请求 `{language}`,非法值回 `20001` |

login/register/refresh 的 `data` 额外含 `language` 字段。

### 1.5 数据库

`models.TLsmGameUser.Language`:`varchar(10) NOT NULL DEFAULT 'zh-CN'`。
靠 `db/db.go` 的 `AutoMigrate` 自动加列并对存量行回填默认值(数据自动补全)。

## 2. 服务器文件命名规则(补充 CLAUDE.md §3)

- **测试文件**:以 `test_` 前缀且 `_test.go` 后缀 → **`test_<topic>_test.go`**。
  - 同时满足项目「`test_*` 前缀」要求与 Go「`_test.go` 才被识别为测试」的约束。
  - 例:`service/test_user_service_test.go`。
- **临时 / 数据补全文件**:以 `temp_` 前缀 → **`temp_<topic>.go`**。
  - 用于一次性数据迁移/补全脚本或临时辅助代码。
  - 例:`temp_backfill_language.go`(如需把空 language 行刷成 `zh-CN`)。
  - 完成其用途后应及时清理。
- 上述规则不适用于 `models/`(模型文件仍用 `t_lsm_game_*.go`)。

### 1.6 游戏 i18n key 命名空间

各游戏使用独立的 key 命名空间，前缀格式为 `<game>.*`：

| 游戏 | 命名空间 | 示例 |
|------|---------|------|
| 象棋 | `xiangqi.*` | `xiangqi.game.start` |
| 国际象棋 | `chess.*` | `chess.game.check` |
| 军棋 | `junqi.*` | `junqi.game.battle` |
| 斗地主 | `doudizhu.*` | `doudizhu.game.bid` |
| 德州扑克 | `texasholdem.*` | `texasholdem.game.fold` |

> `texasholdem.*` 命名空间随第 5 款游戏引入，新增/删除游戏时同步更新此表。

## 3. 新增一条 UI 文案的标准流程

1. 在 `src/i18n/types.ts` 的 `Dict` 加 key。
2. 在三份 locale 文件补齐对应翻译(zh-CN 为权威源)。
3. 组件中 `const t = useT();` 后用 `t('your.key')` 渲染。
4. `npx tsc --noEmit` 确认无缺漏 key,`npm run build` 通过。
