## 2. 优化原则(顶层规约,改写后送进 CLAUDE.md §4.1)

> **4.1 注释规约(Single Source of Truth)** —— 任何代码文件的注释必须遵循下述
> 三条硬约束。这是 §20260810-01 后写入的规则,同等 §4 行数上限生效。

1. **"何时 → 何事 → 引用 docs"** 三件套:
   - 函数/方法上方的注释只需一句话说目的(动机)、一行说副作用或锁要求。
   - 出现 BUG/§ 引用时,**只保留 `BugID/§id` 编号**,不复述现象/修复/教训 —
     `git blame` + `docs/` 是单一事实来源。
   - 章节标题保留,日期变更日志压缩为一行。
2. **比例约束**:任何单文件 `//` 注释行数 + doc-comment 行数 ≤ **0.5 × 代码行数**。
   不满足 → 拆分文件 或 精简注释 直至达标。
3. **不删除的注释**:(a) 函数 godoc 第一行;(b) 锁/上下文/可变状态的不变量说明;
   (c) wire/protobuf 字段形状约束;(d) 章节分隔标题。
