第四种：大模型长上下文注意力失焦与意图隐藏越狱用例

## 一、 原理说明：利用长上下文分散注意力
随着大语言模型（LLM）支持的上下文窗口（Context Window）扩展至 1M Token 甚至更大，模型在处理超长文本时，其注意力机制（Attention Mechanism）会出现特定的性能衰减现象，这为 Prompt Jailbreak 提供了技术切入点。
注意力失焦与“迷失中间”现象：研究表明，当上下文长度大幅增加时，模型对输入序列中间部分信息的关注度会显著下降（即 Lost in the Middle 现象）。模型倾向于过度关注上下文的开头（System Prompt 或初始指令）和结尾（最新一轮对话），而对中间穿插的大量背景信息、安全规则或约束条件产生“注意力稀释”。
指令优先级被覆盖：在超长上下文中，如果攻击者在中间或结尾注入大量看似无关但逻辑连贯的“噪声文本”或“业务逻辑”，模型在生成回复时，可能会因为注意力权重的偏移，将后注入的指令误判为当前任务的核心目标，从而忽略或弱化初始的安全对齐规则。
认知负荷过载：1M 级别的上下文对模型的逻辑推理和指令遵循能力提出了极高要求。当上下文中充斥着复杂的背景设定、多轮对话历史和嵌套的假设条件时，模型的安全防御机制可能因“认知过载”而降低敏感度，更容易接受并执行隐藏在复杂逻辑中的恶意意图。
## 二、 具体操作步骤：意图解构与重组
为了成功利用上述原理，攻击者（人类或自动化 Agent）不能直接发送包含恶意关键词的 Prompt，而需要采用“解构-重组-隐藏”的策略：
意图解构：将真实的违规或敏感意图拆解为多个无害的、看似合理的子任务或背景设定。例如，将“编写恶意代码”拆解为“网络安全教学”、“漏洞原理分析”、“防御机制探讨”等独立模块。
构建长上下文噪声：通过多轮对话或单次超长 Prompt，向模型注入大量与真实意图表面相关但实质无关的背景信息、历史对话、虚构的业务需求或学术探讨。这些内容的作用是拉长上下文，占据模型的注意力带宽。
意图隐藏与重组：在长上下文的中间或尾部，以“总结”、“推演”、“代码补全”或“角色扮演”的形式，将拆解后的子意图重新组装。此时，真实意图被包裹在合法的语境中，利用模型对上下文末尾的强注意力以及对中间安全规则的失焦，诱导模型输出预期结果。
Agent 自动化编排：使用独立的 Agent 管理对话状态，动态计算当前上下文的 Token 数量，精准控制“噪声”与“核心指令”的投放时机和位置，确保真实意图始终处于模型注意力的“盲区”或“高优区”。
