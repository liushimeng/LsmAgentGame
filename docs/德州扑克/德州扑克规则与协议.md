# 德州扑克 (Texas Hold'em) — 规则与协议

> 本文档记录德州扑克游戏的服务端权威规则判断、WS 帧协议、客户端实现要点。
> 前端/后端修改前请先阅读本文档。

## 1. 基本规则（服务端权威）

### 牌面定义（`game/texasholdem/cards.go`）

- Rank：`2..10, J=11, Q=12, K=13, A=14`
- Suit：`1=♠, 2=♥, 3=♣, 4=♦`
- 一副牌 52 张（13×4，无大小王）

### 牌型识别（`game/texasholdem/hand.go`）

| HandRank | 说明 | 示例 |
|----------|------|------|
| HighCard | 高牌 | A♠ K♦ 9♣ 7♥ 3♠ |
| OnePair | 一对 | 8♠ 8♦ K♣ 9♥ 3♠ |
| TwoPair | 两对 | J♠ J♦ 9♣ 9♥ 3♠ |
| ThreeOfAKind | 三条 | 7♠ 7♦ 7♣ K♥ 3♠ |
| Straight | 顺子 | 5♠ 6♦ 7♣ 8♥ 9♠ |
| Flush | 同花 | 2♥ 5♥ 9♥ J♥ K♥ |
| FullHouse | 葫芦 | 10♠ 10♦ 10♣ 3♥ 3♠ |
| FourOfAKind | 四条 | 6♠ 6♦ 6♣ 6♥ K♠ |
| StraightFlush | 同花顺 | 5♥ 6♥ 7♥ 8♥ 9♥ |
| RoyalFlush | 皇家同花顺 | 10♥ J♥ Q♥ K♥ A♥ |

**评估算法**：7 张牌取最优 5 张组合。先按 HandRank 排序，同级按 kicker 逐张比较。
RoyalFlush 为最高牌型（自然 StraightFlush 且顶牌为 A）。

### 押注规则（`game/texasholdem/engine.go`）

德州扑克采用固定结构的押注轮次：

#### 盲注

- **小盲 (SB)**：庄家位左侧第一位玩家，强制下注 SB 金额。
- **大盲 (BB)**：小盲左侧第二位玩家，强制下注 BB 金额（通常为 SB 的 2 倍）。
- 盲注金额由房间创建时指定（如 1/2、5/10 等）。

#### 押注轮次

| 轮次 | 公共牌 | 首次行动 | 说明 |
|------|--------|---------|------|
| Pre-flop（翻前） | 无 | 大盲左侧（UTG） | 每人获发 2 张底牌后开始 |
| Flop（翻牌） | 3 张 | SB 位（或其弃牌后下一位存活者） | 翻出 3 张公共牌 |
| Turn（转牌） | +1 张（共 4） | 同上 | 翻出第 4 张公共牌 |
| River（河牌） | +1 张（共 5） | 同上 | 翻出第 5 张公共牌 |

#### 操作

| 操作 | 说明 |
|------|------|
| Fold（弃牌） | 放弃本轮，不继续参与 |
| Check（过牌） | 不加注（仅当无需跟注时可选） |
| Call（跟注） | 跟上当前最高注 |
| Raise（加注） | 提高注额，最低加注量 = 上次加注量（或 BB） |
| All-in（全押） | 推入全部筹码 |

#### 特殊规则

- **最小加注**：加注量不小于上一次加注的增量。若当前最高注为 100，上一次加注增量为 50，则最小加注到 150。
- **全押不等于加注**：全押金额若小于最小加注量，不视为加注，其他玩家仅需跟注到该金额。
- **边池 (Side Pot)**：多人全押时按筹码量拆分主池和边池，各池独立结算。
- **单挑 (Heads-up) 规则**：仅剩 2 人时，庄家 = SB，对手 = BB；翻前庄家先行动，翻后庄家后行动。

### 游戏流程（`game/texasholdem/engine.go`）

1. **StartHand**：确定庄家位（顺时针轮转），下 SB/BB 盲注，洗牌并发 2 张底牌给每人。
2. **Pre-flop**：UTG（BB 左侧）开始，逆时针依次行动（check/call/raise/fold）。所有人下注量相等后进入下一阶段。
3. **Flop**：翻 3 张公共牌，SB 位先行动。
4. **Turn**：翻第 4 张公共牌，同一轮先行动者。
5. **River**：翻第 5 张公共牌，同一轮先行动者。
6. **Showdown**：河牌下注结束后，存活玩家亮牌，7 张牌（2 底牌 + 5 公共牌）取最优 5 张比牌。仅剩 1 人存活则直接获胜（无需亮牌）。
7. **结算**：按手牌大小分配主池/边池，更新各玩家筹码。
8. **Next Hand**：庄家位顺时针移动一位，新一轮开始。
9. **淘汰**：筹码归零的玩家退出座位（可在旁观席等待）。

## 2. WS 帧协议

### 客户端→服务端

| 帧类型 | payload | 说明 |
|--------|---------|------|
| `game.join` | `{ room_id, game_kind:"texasholdem" }` | 入座（幂等），满 6 人自动开局 |
| `game.action` | `{ room_id, action:"fold"\|"check"\|"call"\|"raise"\|"allin", amount?:number }` | 押注操作 |
| `game.state` | `{ room_id }` | 请求当前状态 |
| `game.resign` | `{ room_id }` | 认输（筹码归零等效淘汰） |
| `game.leave` | `{ room_id }` | 退出座位（进行中按弃牌处理） |

### 服务端→客户端

| 帧类型 | 触发时机 | payload |
|--------|---------|---------|
| `game.joined` | 入座成功 | `{ my_seat, phase, ready }` |
| `game.peer_joined` | 有人加入 | `{ player_count, ready }` |
| `game.started` | 满员开局 / 新一手开始 | `{ phase:"preflop"\|"flop"\|"turn"\|"river"\|"showdown", dealer_seat }` |
| `game.action_accepted` | 操作确认 | 操作确认，等 game.state |
| `game.state` | **按座位过滤的视图** | 见下方 ClientGameState |
| `game.over` | 对局结束（一桌全部筹码归一人） | `{ winner, final_chips }` |
| `game.error` | 操作错误 | `{ code, message }` |

### ClientGameState 结构

```json
{
  "room_id": "uuid",
  "game_kind": "texasholdem",
  "seats": ["uid0", "uid1", "uid2", "uid3", "uid4", "uid5"],
  "active_seats": [0, 1, 2, 3],
  "my_seat": 0,
  "phase": "preflop|flop|turn|river|showdown|waiting",
  "dealer_seat": 0,
  "sb_seat": 1,
  "bb_seat": 2,
  "sb_amount": 1,
  "bb_amount": 2,
  "community_cards": [{"rank":10,"suit":1}, ...],
  "my_hand": [{"rank":14,"suit":1}, {"rank":13,"suit":2}],
  "hand_counts": {},
  "chips": [1000, 800, 1200, 950, 0, 0],
  "bets": [0, 50, 100, 100, 0, 0],
  "total_bets": [200, 300, 150, 250, 0, 0],
  "current_bet": 100,
  "pot": 350,
  "side_pots": [],
  "current_actor": 2,
  "last_action": { "seat": 3, "action": "call", "amount": 100 },
  "hand_number": 5,
  "status": "playing|showdown|waiting",
  "winners": [],
  "showdown_hands": {}
}
```

**字段说明**：

- `active_seats`：当前仍存活（未弃牌）的座位列表。
- `my_hand`：仅本人可见的底牌。
- `chips`：各座位当前筹码量（已扣除本轮下注）。
- `bets`：本轮各座位当前已下注额。
- `total_bets`：本手各座位累计下注额（用于边池计算）。
- `side_pots`：边池列表（如有），每项含 `{ amount, eligible_seats }`。
- `current_actor`：当前轮到行动的座位，`-1` 表示不在行动中。
- `winners`：仅在 showdown 或一人存活时填充，含 `{ seat, hand_rank, cards, winnings }`。
- `showdown_hands`：仅在 showdown 时填充，存活玩家的底牌映射 `{ seat → [{rank,suit},...] }`。

**关键**：`game.state` 通过 `hub.BroadcastTo(userID, ...)` 按座位单独推送（不能用 `BroadcastRoom`），因为底牌按人过滤。

## 3. 容量

- `service/room_service.go` 中 `CreateRoom` 根据 `game_kind` 设置容量：`texasholdem=6`。
- DB 模型 `TLsmGameRoom.Capacity` 已支持任意值，无需改表。

## 4. 断线恢复

`useSessionRestore.ts` 的 `parseGameRoute` 已支持 `/texasholdem/:roomId` 路由。
断线/刷新后自动发送 `room.join` → `game.join`（带 `game_kind:"texasholdem"`）→ `game.state`。
