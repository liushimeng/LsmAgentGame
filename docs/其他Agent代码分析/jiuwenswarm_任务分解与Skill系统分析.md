# JiuwenSwarm 任务分解与 Skill 系统分析

> 分析日期: 2026-08-13
> 源码路径: `/usr/local/LsmGitOpenSource/jiuwenswarm`
> 分析目的: 提取任务分解与 Skill 自演进设计模式,为狼人杀 Agent 决策链优化提供参考

## 1. 任务规划系统

### 1.1 核心机制

JiuwenSwarm 的任务规划采用**动态待办清单**模式:

```
用户复杂需求 → Agent 调用 todo_create 拆解为子任务
    → 每完成一个子任务 → todo_modify 更新状态
    → 用户中途插入新需求 → todo_modify 在合适位置插入
    → 随时 todo_list 掌握全局进度
```

### 1.2 工具集

| 工具 | 说明 |
|------|------|
| `todo_create` | 创建初始待办清单(覆盖式) |
| `todo_modify` | 修改/删除/取消/追加子任务 |
| `todo_list` | 列出所有待办事项及状态 |
| `todo_get` | 获取指定子任务详情 |

### 1.3 任务状态机

```
pending → in_progress → completed
                     → cancelled
```

### 1.4 持久化

任务以 JSON 持久化至 `workspace/todo/{session_id}/todo.json`,按会话隔离,支持并发安全读写。

### 1.5 动态干预

关键特性: 支持用户**动态打断**当前任务流,插入新需求。系统借助智能体中断恢复与任务调度能力灵活响应。

## 2. Skill 自演进系统

### 2.1 技能定义

Skill 是**可安装、可管理、可复用的能力包**:

```
┌───────────────────────────────────────────────┐
│               智能体 (Agent)                   │
│                                               │
│   基础能力: 对话/文件操作/网络搜索/代码执行     │
│                                               │
│   ┌───────────────────────────────────────┐   │
│   │           技能层 (Skills)              │   │
│   │                                       │   │
│   │   ┌───────────┐ ┌───────────┐        │   │
│   │   │ gitcode-pr│ │pptx-craft │ ...    │   │
│   │   │  Git操作   │ │  PPT制作  │        │   │
│   │   └───────────┘ └───────────┘        │   │
│   │                                       │   │
│   │   可安装/可卸载/可扩展                  │   │
│   └───────────────────────────────────────┘   │
└───────────────────────────────────────────────┘
```

### 2.2 技能来源

| 来源 | 说明 | 特点 |
|------|------|------|
| 内置技能 | 系统内置核心技能 | 与产品版本一致 |
| SkillNet | 通用 AI 技能管理平台(开源) | 可匿名使用 |
| ClawHub | 企业技能库(应用商店) | 需 CLI Token |
| SwarmSkills | 团队/集群技能库 | 无需额外配置 |
| 本地导入 | 用户自建技能文件 | 完全自定义 |

### 2.3 技能目录结构

```
skill_name/
├── SKILL.md           # 技能定义(YAML frontmatter + 正文)
├── references/        # 参考文档(可选)
└── scripts/           # 辅助脚本(可选)
```

### 2.4 技能自演进机制

**核心创新**: 技能不是静态的,而是**越用越强**:

1. **使用记录**: 每次技能执行的结果被记录
2. **模式识别**: 识别成功/失败模式
3. **自动优化**: 基于历史数据调整技能参数
4. **版本迭代**: 技能文件自动更新

### 2.5 Symphony 技能编排

Symphony 是 JiuwenSwarm 的**技能编排与分发**系统:

```
用户需求 → 意图识别 → 技能检索 → 技能编排 → 执行 → 反馈
                │           │           │
                ↓           ↓           ↓
           ┌─────────┐ ┌────────┐ ┌──────────┐
           │路由分类  │ │向量检索│ │任务分解   │
           │(NLU)    │ │(Skill) │ │(Planning)│
           └─────────┘ └────────┘ └──────────┘
```

### 3.2 团队生命周期

- 每个成员可运行在不同进程/机器
- 通过 WebSocket/HTTP 通信
- 团队记忆通过共享存储同步

## 4. 与狼人杀 Agent 的对比

| 维度 | JiuwenSwarm | 狼人杀 Agent |
|------|-------------|--------------|
| **任务分解** | 动态待办清单(todo_create/modify) | 无(单轮决策) |
| **技能系统** | 可安装/可演进的 Skill 包 | 固定工具集(tools.go) |
| **多 Agent 协作** | Team Manager + 成员角色 | 每座独立 goroutine |
| **意图识别** | NLU 路由 + 技能检索 | 隐式(阶段驱动) |
| **知识共享** | 团队记忆 + 标签系统 | §131 按 model_key 隔离 |
| **动态干预** | 支持用户打断插入 | 无(阶段线性推进) |

## 5. 可借鉴的设计模式

### 5.1 动态任务分解 → 狼人杀「多步决策链」

**问题**: 当前 Agent 每轮只做一步决策(如 speak 或 vote),无法规划「先发言建立信任→再投票」的多步策略。

**借鉴**: 引入内部「决策待办」:
```
Phase: speak
  → Agent 内部规划:
    1. [pending] 发言建立预言家形象
    2. [pending] 暗示 5 号可能是狼
    3. [pending] 对 3 号的质疑做出回应
  → 按序执行,每步完成后更新状态
```

**实现思路**: 在 `GameContext` 新增 `DecisionPlan []string` 字段,
Agent 在首轮 LLM 调用时生成计划,后续轮次按计划执行。

### 5.2 Skill 自演进 → 狼人杀「策略模板演进」

**问题**: Agent 每局从零开始,无法积累「什么策略在什么局面下有效」。

**借鉴**: 将成功策略封装为「策略模板」:
```
strategy_templates/
├── seer_day1_announce.md    # 预言家 Day1 公开查验结果
├── wolf_fake_seer.md        # 狼人悍跳预言家
├── witch_save_self.md       # 女巫首夜自救
└── villager_vote_majority.md # 平民跟票策略
```

每局结束后,根据胜负结果更新模板的「有效性分数」,
下次遇到类似局面时优先选择高分模板。

### 5.3 蜂群协作 → 狼人杀「狼队战术分工」

**问题**: 虽然已有 §20260810-10 WolfPackRole 分工,但缺乏动态调整机制。

**借鉴**: 引入「战术会议」模式:
```
NightWolves 阶段:
  → 狼王发起战术会议(wolf_whisper)
  → 各狼提交自己的观察和建议
  → 狼王综合后分配角色(hype/charger/hook/deep)
  → 角色分配结果注入下一轮 GameContext
```

### 5.4 意图识别路由 → 狼人杀「阶段内策略路由」

**问题**: 当前阶段内 Agent 行为完全由 LLM 自由决定,缺乏结构化引导。

**借鉴**: 引入阶段内策略路由:
```
Phase: speak (白天发言)
  → 路由判断:
    - 如果是预言家且有查杀 → 走「announce_check」策略
    - 如果是狼人且被怀疑 → 走「defend」策略
    - 如果是平民且信息不足 → 走「gather_info」策略
  → 注入对应策略模板到 prompt
```

## 6. 关键教训

1. **任务要可分解** —— 复杂决策拆为多步,每步可追踪可回滚
2. **技能要可演进** —— 静态工具集无法适应变化的博弈环境
3. **协作要结构化** —— 不是「大家都说话」,而是有角色有分工
4. **路由要分层** —— 先识别意图,再选策略,最后执行
5. **知识要共享** —— 个人经验要能沉淀为团队知识
