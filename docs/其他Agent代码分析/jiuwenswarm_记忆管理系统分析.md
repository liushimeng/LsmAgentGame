# JiuwenSwarm 记忆管理系统分析

> 分析日期: 2026-08-13
> 源码路径: `/usr/local/LsmGitOpenSource/jiuwenswarm`
> 分析目的: 提取记忆管理设计模式,为狼人杀 Agent §131 持久化记忆优化提供参考

## 1. 架构总览

JiuwenSwarm 的记忆系统采用**三层架构**:

```
┌─────────────────────────────────────────────────┐
│                  用户 / Agent                    │
│                                                  │
│  ┌──────────────┐  ┌──────────────┐  ┌────────┐ │
│  │ 会话内即时    │  │ Dreaming     │  │ Team   │ │
│  │ 写入         │  │ 后台离线提取  │  │ 协同   │ │
│  └──────┬───────┘  └──────┬───────┘  └───┬────┘ │
│         └─────────────────┼──────────────┘      │
│                           ↓                      │
│         ┌─────────────────────────────────┐      │
│         │   MemoryIndexManager(索引层)    │      │
│         │  文件监控 / 混合检索 / 按需读取  │      │
│         └─────────────────────────────────┘      │
└─────────────────────────────────────────────────┘
```

## 2. 记忆文件结构

采用**纯 Markdown 文件存储**,Agent 通过文件工具直接操作:

```
{workspace_dir}/memory/
├── MEMORY.md               # 长期记忆(决策/偏好/持久事实)
├── USER.md                 # 用户档案(个人信息)
├── YYYY-MM-DD.md           # 每日会话记录
└── DREAMING.md             # Dreaming 离线提取结果
```

### 2.1 MEMORY.md (长期记忆)

- **用途**: 存储决策、偏好、持久性事实
- **更新**: Agent 通过 write/edit 文件工具写入
- **特点**: 跨对话持久,极少变动

### 2.2 USER.md (用户档案)

- **用途**: 存储用户姓名、职业、爱好、位置等
- **特点**: 帮助 Agent 个性化服务

### 2.3 YYYY-MM-DD.md (每日日志)

- **用途**: 记录日常笔记和运行上下文
- **特点**: 每天一页,追加写入

## 3. 三种写入机制

### 3.1 会话内即时写入

Agent 对话中根据需要即时调用文件工具:

| 信息类型 | 写入目标 | 操作方式 |
|----------|----------|----------|
| 决策/偏好/持久事实 | MEMORY.md | write/edit |
| 用户个人信息 | USER.md | write/edit |
| 日常笔记 | YYYY-MM-DD.md | write/edit |

### 3.2 Dreaming 睡时整理

**核心创新**: 闲时周期性扫描历史会话,调用 LLM 提取值得长期保留的内容。

| 模式 | 抽取目标 | 输出 |
|------|----------|------|
| `agent` | 用户偏好/背景/关注领域 | DREAMING.md(单文件,≤50条) |
| `code` | 调试根因/API 边界/设计决策 | coding_memory/consolidated_{hash}.md |

**工作机制**:
- **定时触发**: 每隔 `interval_seconds` 检查,启动后 120s 首次扫描
- **忙碌退避**: Agent 处理请求时跳过,下一周期再试
- **增量扫描**: checkpoint 记录已处理 session,不重复处理

### 3.3 Agent Team 协同提取

在多智能体场景下:
- 每个成员拥有**独立个人记忆**
- 团队共享**团队记忆**(TEAM_MEMORY.md)
- Leader 在每个 round 结束后**自动提取**团队记忆

**团队记忆标签系统**:

| 标签 | 含义 |
|------|------|
| `[decision]` | 团队决策:为何选 A 不选 B |
| `[lesson]` | 经验教训:什么有效/什么导致返工 |
| `[member]` | 成员特长:谁擅长什么 |
| `[context]` | 项目背景:业务约束/截止日期 |

## 4. 记忆检索机制

### 4.1 混合检索策略

```
Query ──► Embed ──► Vector Search ──┐
                                    ├─► Merge ──► Results
Query ──► FTS5 Search ──────────────┘
```

- **向量检索权重**: 0.7 (语义匹配)
- **全文检索权重**: 0.3 (关键词匹配)
- **混合分数**: `score = 0.7 * vectorScore + 0.3 * textScore`

### 4.2 核心组件

```
MemoryIndexManager
├── Config (配置)
├── Embedding Provider (向量化)
└── SQLite Database
    ├── chunks (分块)
    ├── files (文件索引)
    ├── embedding_cache (缓存)
    ├── chunks_fts (FTS5 全文索引)
    └── chunks_vec (vec0 向量索引)
```

### 4.3 记忆模式配置

| 配置值 | 说明 |
|--------|------|
| `builtin` | 仅内置记忆(默认) |
| `external` | 仅外接记忆(LTM/Mem0/OpenViking) |
| `both` | 内置+外接并存 |
| `none` | 全部关闭 |

## 5. 与狼人杀 Agent §131 的对比

| 维度 | JiuwenSwarm | 狼人杀 Agent (§131) |
|------|-------------|---------------------|
| **存储格式** | Markdown 文件系统 | DB mediumtext (t_lsm_game_agent_memory) |
| **记忆粒度** | 长期/用户/日志/Dreaming 四层 | 单一 MEMORY.md 四段固定标题 |
| **写入方式** | Agent 主动工具调用 + Dreaming 自动 | 每局结束 LLM 异步迭代 |

| **团队记忆** | 个人+团队双层,标签系统 | 按 model_key 隔离,无团队层 |
| **角色感知** | 无(通用 Agent) | §20260812-04 按角色子段选取 |

## 6. 可借鉴的设计模式

### 6.1 Dreaming 离线整理 → 狼人杀「赛后自动复盘」

**借鉴点**: 当前 §131 的记忆迭代只在每局结束时触发一次。可引入「空闲 Dreaming」——
当房间无人类在线且 bot 空闲时,自动回顾近 N 局记忆,提取模式化教训。

**实现思路**:
```
coolingWatchdog(§129) 检测到无人类在线
  → 触发 Dreaming goroutine
    → 读取近 3 局的 MEMORY.md + judge_summary
    → LLM 提取「跨局模式」(如:某模型在 Day3+ 总是投票偏保守)
    → 写入 MEMORY.md 新增 "## 跨局模式识别" 段
```

### 6.2 混合检索 → 狼人杀「按需注入」

**借鉴点**: 当前全量注入 4000 runes,大量无关信息浪费 token。可改为:
- 关键决策(投票目标/查验结果) → 始终注入
- 一般教训 → 仅在相关阶段注入(如预言家教训只在 night_seer 注入)
- 历史模式 → 仅在终局前注入

### 6.3 标签系统 → 狼人杀「教训分类」

**借鉴点**: 团队记忆的 `[decision]/[lesson]/[member]/[context]` 标签可映射为:
- `[strategy]` 决策策略
- `[mistake]` 失误教训
- `[model_pattern]` 其他模型特点
- `[game_context]` 特定局面处理

### 6.4 4 级压缩处理器 → 狼人杀「分层压缩」

**借鉴点**: 当前只有单一的 `CompressHistoryLocked` + `Prune`。可引入:
1. **工具结果压缩**: tool_result > 1000 字时摘要(如道具列表)
2. **对话历史压缩**: > 100 条时 LLM 摘要(已有,可增强)
3. **轮次级压缩**: 连续同阶段对话 > 5 轮时折叠
4. **循环检测压缩**: 连续相同工具调用折叠

## 7. 关键教训

1. **记忆文件即数据源** —— Markdown 文件是唯一事实来源,索引层只做检索加速
2. **增量优于全量** —— Dreaming 的 checkpoint 机制避免重复处理
3. **压缩是多级的** —— 不同类型的内容需要不同的压缩策略
4. **检索要分层** —— 不是所有记忆都需要每次都注入
5. **团队记忆需要标签** —— 无标签的记忆无法被有效检索和过滤
