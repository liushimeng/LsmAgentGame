## §3 设计目标与边界

### 3.1 目标

| 目标 ID | 描述 | 验收标准 |
|---------|------|---------|
| **G1** | 主标题区**始终**显示"已运行 X 分 Y 秒" | `WerewolfGamePage` mount 后即可见，不依赖 phase |
| **G2** | 一个**一眼可见**的"📜 历史"按钮 + 点击打开抽屉 | 进入对局 page 后第一屏可见（不需滚动到 0.6fr 左栏底部） |
| **G3** | 抽屉内渲染 4 类历史：📜 时间轴 / 🤖 BotTranscript / ⚰ 死亡事件 / 🏆 整局总结 | 抽屉 Tab 计数显示数据量（"📜 时间轴 23"） |
| **G4** | 13 人局布局在 1280×720 / 1440×900 / 1920×1080 三档下都**不出现隐藏的关键按钮** | 全局自检：`ActionButtons` 命中区 ≥ 44 × 44 px |

### 3.2 不在范围（边界）

- ❌ 不新增 HTTP API（仅下发已存在的 `gameStartedAt` 字段）
- ❌ 不修改 12/7 人局代码
- ❌ 不修改后端 Agent / LLM 任何驱动逻辑
- ❌ 不做移动端 PWA 改造（仅响应式断点）
- ❌ 不重做 FactionDrawer，只在它上面新增第 4 个 Tab

## §4 房间运行时间显示

### 4.1 数据契约

**后端最小改动（`view.go` + `room.go`）**：

```diff
// view.go:36 ClientGameState
+   GameStartedAt int64 `json:"game_started_at,omitempty"`  // Unix 秒;0 = 未开始
```

```diff
// room.go:2017（BuildClientState 头部，已存在的 gameStartedAt 直传）
-   // 当前赋给 agent.GameContext 的 GameStartedAt 字段
+   // 同样塞进 ClientGameState,让前端有时间戳
+   out.GameStartedAt = r.gameStartedAt
```

### 4.2 渲染规则

| 场景 | 显示 |
|------|------|
| `game_started_at == 0`（未开始） | `⏱ —` |
| `status === 'over'` | `⏱ 已结束 (整局 12 分 34 秒)` |
| `status === 'playing'` | `⏱ 已运行 12 分 34 秒`（每 1s 重算） |

格式 = `{HH:}MM:SS`，超过 1 小时显示 `HH:MM:SS`。
- **G1 实现**：在 `werewolf-main-header` 标题右侧增加 `.werewolf-main-header__sub` 的第二行（共用现有 CSS），同时 `ww-status-bar__row` 第一位置增一个 `__clock-room` chip（颜色比阶段倒计时更柔：rgba(193,154,86,0.18) 弱背景）。

### 4.3 组件新文件

- `ClientWeb/src/components/werewolf/RoomRunningClock.tsx`（60 行）
  - Props: `gameStartedAt: number | undefined`、`status: string`
  - 内部 1s `setInterval`（同 FactionDrawer 模式），窗口可见性 API 暂停以省电

### 4.4 旧字段兼容性

- `game_started_at` 缺省时前端按 "⏱ —" 显示（即 12/7 人局历史数据回放也不崩）

## §5 历史记录侧边栏

### 5.1 设计原则

> **不新建抽屉**：在 `FactionDrawer` 已有的 380px 右侧抽屉加第 4 个 Tab（"📜 历史"）。
> 边角代价最小：复用 ESC 关闭、tab 切换、`nowMs` 自维护。

### 5.2 4 个 Tab 结构（"📜 历史"Tab 内容）

```
📋 任务         (原有)
🤖 Agent        (原有)
👥 玩家         (原有)
🆕 📜 历史       (新增)  ←—— active 时显示
  ┌────────────────────────────────────┐
  │ 子标签(分段控件)                    │
  │ [⏱ 时间轴] [🤖 独白] [⚰ 死亡] [🏆 总结]│
  ├────────────────────────────────────┤
  │ ⏱ 时间轴 (默认):                    │
  │  按 day 顺序展示已发生事件:          │
  │  · 发言(seat, 摘要)                  │
  │  · 投票(seat, target)                │
  │  · 夜间死(seat, cause)               │
  │  · 警徽流(slot, target)              │
  │  · 白痴翻牌(seat)                    │
  │  · 遗言(seat, spoken/skipped)        │
  │  · 阶段切换(phase / day)             │
  │  每条带相对时间"[D1 03:12]"           │
  │ 顶部小筛选: ☑ 显示夜 ☑ 显死亡        │
  │                                       │
  │ 🤖 独白(sub):                        │
  │  遍历 bot_contexts,点击展开          │
  │  心口不一(heart_thought) 折叠面板     │
  │  last_llm_latency_ms / avg / calls    │
  │  仅 spectator 可见                    │
  │                                       │
  │ ⚰ 死亡(sub):                         │
  │  遍历 all_dead_list_verbose[]          │
  │  列: seat / role / 死因 / verdict / day│
  │  + 警徽继承                          │
  │                                       │
  │ 🏆 总结(sub):                         │
  │  judge_summary 整段                    │
  │  + modelMemories[] (按模型 key 折叠)  │
  └────────────────────────────────────┘
```

### 5.3 数据来源（已有，无需新 API）

| 子面板 | 已有字段 |
|--------|---------|
| ⏱ 时间轴 | `phase_extra.dead_list` + `all_dead_list_verbose` + `recentSpeeches[chatSvc]` + 阶段切换通过观察 `phase` delta |
| 🤖 独白 | `game.state.bot_contexts[]` |
| ⚰ 死亡 | `game.state.all_dead_list_verbose[]` + `sheriff_successor` |
| 🏆 总结 | `game.state.judge_summary` + `game.state.judge_model_memories` |

> **时间轴** 完整方案需要服务端 `phase_change_log[]`，但**第一版可纯前端拼**:`useState` 监听 `phase` / `day` 变化增条目;`recent_speeches` 通过 chat 路由 `chat.message` 帧累积（频道=`room_${roomId}`）。
> 若需要更可靠时间轴，再单独 P1 提需求；不在本设计范围。

### 5.4 入口按钮 — **3 入口 / 互不冲突**

| 入口 | 位置 | 显示条件 |
|------|------|---------|
| A **主入口** | `werewolf-main-header` 右侧 (主标题旁) | **永远显示** |
| B **快捷入口** | 房间信息面板 (`WerewolfGamePage` 0.6fr 左栏) header 行的"R📚 500K"左边 | 永远显示 |
| C **操作按钮组** | `GameInfoPanel` 第 5 块 (规则+退出) 增加第三个按钮 | 永远显示 |

> **设计权衡**：A 是顶层 sticky 标题上 + ESC 关闭的抽屉，对 13 人局 UI 提占用最小（仅 +44px 宽按钮）。
> B / C 是冗余入口，照顾习惯下划点开信息面板的用户。

### 5.5 抽屉 UI 规范

- 抽屉宽 = `min(380px, 30vw)`（沿用 FactionDrawer 现有规范）
- ESC 关闭
- 子 tab（5.2）用 `.faction-drawer__subtabs` 横向 chips（与主 tab 同款）
- 时间轴每条 ≥ 36px 行高，便于触屏点击展开
- 数据量 > 50 时虚拟滚动（`IntersectionObserver` + 简单 placeholder，第一版可只做 200 条硬上限）

## §6 13 人局布局空间优化

### 6.1 主标题瘦身

```diff
- 🐺 狼人杀13人局游戏主界面
+ 🐺 狼人杀 · 13人局
```

- 节省 ~80px 字符宽度 → 中栏宽 1.8fr 在 1280px 时不再挤压
- `font-size: 20px → 18px`；sticky 不变

### 6.2 状态条"总时间"抢占首位置（§4.2）

```diff
.ww-status-bar__row { gap: 8px; }
+ .ww-status-bar__clock-room { /* 浅橙色弱背景,与阶段倒计时区分 */ }
```

### 6.3 主面板"中栏"压缩

- `board-container` 的子元素默认 `gap: var(--ww-gap)` = 10px；→ 13 人局时改为 6px
- `WerewolfTable` 在 `<1280px` 下每个 seat 卡的 `min-width` 缩到 110px（原 130px）

### 6.4 触控热区 44 × 44

新建 token：

```css
:root {
  --ww-touch-target: 44px;
}
.ww-button, .btn {
  min-height: var(--ww-touch-target);
  min-width: var(--ww-touch-target);
}
```

应用范围：`werewolf-game` 作用域下所有按钮 / .seat-chip / .info-block button。

### 6.5 中栏（1.8fr）滚动策略

- `<1024px`：竖排（已有，§6.4）
- `1024-1599px`：三栏比例 0.5:1.5:1（左更窄，中更宽）
- `≥1600px`：保持 0.6:1.8:1

## §11 风险与回滚

| 风险 | 缓解 |
|------|------|
| `game_started_at` 缺省 → 前端显示"⏱ —" | 不崩；UX 友好退化 |
| 时间轴 phase delta 拼装漏状态 → 列表有空段 | 第一版时间轴不强求覆盖 100%；只保证有 phase 切换就有条目 |
