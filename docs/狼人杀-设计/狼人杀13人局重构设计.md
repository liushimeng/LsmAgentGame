## §1 业务目标与范围

| 目标 | 说明 |
|------|------|
| 13 人标准 Agent 局 | 4 狼 + 4 神（预 / 女巫 / 猎 / 白痴）+ **5 民** = 13 |
| 全员 Agent 验证 | 所有 13 个座位均为 Agent，人类仅作观战者，验证 Agent 并发稳定性 |
| 全栈兼容 | 引擎 / 视图 / Agent / 配置 / 前端 / WS 帧 全链路对齐 13 人 |
| 保留 12 人局 | 现有 `werewolf_12` 完整保留，新增独立 13 人实现 |

### 1.1 不在范围
- ❌ 不新增角色（不引入守卫 / 丘比特 / 第三方阵营）
- ❌ 不修改 12 人局代码（仅新增/扩展）
- ❌ 不修改 Agent 驱动基础设施（ToolRunner / 500K 队列 / parallel_think / 5 类既有子系统）

## §2 角色构成（13 人）

| 角色 | 数量 | 阵营 | 缩写 |
|---|---|---|---|
| 狼人 Werewolf | 4 | 狼人阵营 | 4 狼 |
| 预言家 Seer | 1 | 好人 · 神职 | 神 |
| 女巫 Witch | 1 | 好人 · 神职 | 神 |
| 猎人 Hunter | 1 | 好人 · 神职 | 神 |
| 白痴 Idiot | 1 | 好人 · 神职 | 神 |
| **平民 Villager** | **5** | 好人 | **5 民** |

> **合计**：4 狼 + 4 神 + 5 民 = **13 人**
> **对比 12 人**：+1 平民，好人阵营从 8→9，好人：狼人 → 9：4

### 2.1 屠边阈值变化

12 人局屠边阈值：`Divine==0`(屠神 4) / `Plain==0`(屠民 4)
**13 人局屠边阈值**：`Divine==0`(屠神 **4**，神职数不变) / `Plain==0`(屠民 **5**，+1)

```go
func (gs *GameState) checkWinner() (winner string) {
    r := gs.refreshCounts()
    switch {
    case r.WolfAliveCnt == 0:  return "good"  // 放逐全部 4 狼
    case r.DivineCnt == 0:     return "wolf"  // 屠神(4 神死光)
    case r.PlainCnt == 0:      return "wolf"  // 屠民(5 民死光) ← 13 人局变化
    }
    return
}
```

> `DivineCnt` 上限 = 4 / `PlainCnt` 上限 = 5 —— 由牌组给定，代码无需硬编码阈值，
> 只要 `refreshCounts()` 按真实存活统计，屠边判定自然适配。

## §3 核心数值改动（12→13）

### 3.1 常量层

| 项 | 12 人 | 13 人 | 改动方式 |
|---|---|---|---|
| `MaxPlayers` | 12 | **13** | 改常量（通用） |
| `StandardDeck` / 牌组 | 12 张 | 13 张 | 新增 `StandardDeck13()` |
| `AssignRoles` | `[12]Role` | `[13]Role` | 改签名（或泛化） |
| 房间容量 cap | 12 | **13** | config 驱动 |
| `room_llm_concurrency` | 12 | **13** | 配置（并发信号量需 ≥ 13 bot） |

### 3.2 数组尺寸依赖

所有 `[MaxPlayers]` 数组自动扩 1（`Players` / `Votes` / `LastWordsUsed` / `NightDeaths` 等）。
任何 `for i:=0; i<MaxPlayers; i++` 自动适配。

### 3.3 座位枚举 / 0-indexed 一致性

- 座位号：`0..12`（13 座）
- 玩家编号（UI）：`1..13`
- 前端 13 等分圆（12 是 12 等分 = 每座 30°，13 ≈ 27.69°）
- `sheriff_stream` / `idiot_reveal` 工具参数 target 枚举 `-1|0..12`

## §4 服务端改动清单

### 4.1 `cards.go`（牌组 + 常量）

```go
const MaxPlayers = 13  // 12 → 13

// 新增
func StandardDeck13() []Role {
    return []Role{
        RoleWerewolf, RoleWerewolf, RoleWerewolf, RoleWerewolf, // 4 狼
        RoleSeer, RoleWitch, RoleHunter, RoleIdiot,             // 4 神
        RoleVillager, RoleVillager, RoleVillager, RoleVillager, RoleVillager, // 5 民
    }
}
// 12 人牌组保留：func StandardDeck12() []Role { ... }
```

> **兼容**：既有 `StandardDeck12()` 引用（12 人局房间）保持不变。

### 4.2 `engine.go`（阶段 / 胜利判定）

- `checkWinner()` —— 不需要改代码，只要 `refreshCounts()` 按真实牌组统计 `PlainCnt`，
  阈值 5 自动适配。保留 Double-check：`PlainCnt` 初始化 = 5。
- 阶段枚举 —— 不变（与 12 人完全相同，不新增 / 删除阶段）
- `isActingPhase` —— 不变
- 狼刀/查验/用药/投票/白痴翻牌 —— 逻辑复用，只扩展数组尺寸（`MaxPlayers=13`）

### 4.3 `room.go`（房间 + 配置）

- `StartAgentsLocked` —— bot 数从 12→13（依赖 `len(r.BotAgents)`，自动适配）
- `buildAgentContextLocked` —— `MySeat / SpeakTurn / TurnActingSeat` 逻辑不变（基于循环）
- `watchdogActingSeat` —— 不变（基于 phase 分支，不写死人数）
- `AgentEvents` per-seat channel —— 不变

### 4.4 `view.go`（客户端状态广播）

- `BuildClientState` —— 数组字段随 `MaxPlayers` 自动扩
- `PlayerBrief` 编号 → `1..13`，座位 `0..12`
- `max_seat` 字段 → 13

### 4.5 `service/room_service.go`（房间创建 + Agent 分配）

- `game_kind == "werewolf"` 默认人数 → 13（或新增 `werewolf_13` 配置项）
- `if int64(len(agentSeats)) > 13` 校验
- Agent 模型随机分配 `Fisher-Yates` —— 不变（8 模型对 13 座位：允许重复不够时降级轮询）

### 4.6 Agent 模块（`ServerGo/agent/`）

**几乎不改**。Agent 是"按座位驱动"的，bot 数由房间给定。唯一需要确认：
- `BuildTools(phase, seat, role, ...)` —— target 枚举从 room 拉存活列表，自动 0..12
- `BuildUserPrompt` 的「玩家档案」循环 0..12 —— 自动适配

## §6 Agent / LLM 改动

### 6.1 System Prompt

`BuildSystemPrompt` 新增 13 人局分支：

```
你是一个狼人杀 13 人标准竞技局的 AI 玩家。
【游戏规则摘要】
- 13 人局：4 狼人 + 1 预言家 + 1 女巫 + 1 猎人 + 1 白痴 + 5 平民
- 狼人阵营胜：屠边——杀光所有神职（4），或杀光所有平民（5）
- 好人阵营胜：放逐全部 4 名狼人
...
【你的座位号】{seat}（0-12）
【你的玩家编号】{seat+1}（1-13）
```

> 12 人分支保留，由房间配置 `MaxPlayers` 切换。

### 6.2 User Prompt / Context

- 存活玩家列表 `0..12` —— 自动适配
- 玩家档案编号 —— 自动适配

### 6.3 工具定义

不新增工具。`wolf_kill` target 枚举 -1|0..12；`sheriff_stream` target -1|0..12；
`hunter_shoot` target -1|0..12 —— 动态生成。

### 6.4 限流 / 配额调整

- `LLMCallLimiter` 保持 8s 默认（13×8=104s, speak/vote deadline 360s 充足）
- `speak` 令牌桶 45s / `whisper` 90s —— 不变
- `room_llm_concurrency` → 13（配置，需 ≥ 13 bot 数）
- `Pre_wolves` 阶段 `SpeakLimiter` 缩到 30s / `LLMCallLimiter` 缩到 4s —— 不变

### 6.5 并发Semaphore

- `roomLLMConcurrency = 13`（LsmWebGame.conf 默认）—— 13 bot 同时至少 1 个可发 LLM
- `parallel_think` per-bot worker 上限 = 2；总并发上限 ≤ 13×2 = 26，但受 `roomLLMConcurrency=13` 约束 → 实际 ≤ 13

## §10 风险与回滚

| 风险 | 缓解 |
|---|---|
| `MaxPlayers=13` 改通用常量，影响既有 12 人局 | 12 人局走独立配置 `werewolf_12`，由房间级 `MaxPlayers` 覆盖全局常量 |
| 数组尺寸不一致（部分硬编码 12） | 全量 grep `MaxPlayers`，消除魔法数字 |
| 前端座位布局椭圆参数耦合 | `WEREWOLF_SEATS` 常量驱动 13 等分 |
| LLM 并发 13×2 > semaphore | `roomLLMConcurrency=13` 硬上限兜底 |
| 13 人局平衡性（好人 9 vs 狼 4 偏优势） | 可配置牌组；本次产品目标是 "好人多 1" 场景验证 |

**回滚**：恢复 `MaxPlayers=12` + 删除 `StandardDeck13()` + 12 人 LsmWebGame.conf 默认即可。
