> **变更动机**：当前实现已经支持人类通过 WS 帧发起所有主要动作（vote / wolf_kill / seer_check / witch_act / shoot / sheriff / idiot_reveal / sheriff_stream / restart_vote），前端
> `NightActionPanel` / `DayControlPanel` / `IdiotRevealPanel` / `SheriffStreamPanel` / `HunterShootInline` 也已渲染对应的人类操作按钮。但仍存在四类缺失：
>
> 1. **遗言 (Last Words)** — `Action_LastWords` / `Action_SkipLastWords` 已存在于 `room.go`，但**没有 WS 帧入口**，也没有前端面板。
> 2. **「轮到我了」UX** — `phase_extra` 有 `phase_deadline_at`，但 `PhaseClock` 只是"全局倒计时"，没有给"我"单独的"⏱ 还剩 23 秒"的醒目提示 + 自动 skip 警告。
> 3. **公平性 / 可玩性** — 13 人局 8 种模型 LLM 耗时差异 4-12s 不等（§120），人类却必须在 120-300s 内完成多个串行动作；发言倒计时、投票倒计时、警徽流倒计时没有针对人类的单独计时与超时兜底。
> 4. **座位标识 / 操作面板始终可见** — 人类座位下方应该有常驻"轮到我了"高亮 + 操作面板；当前依赖玩家自己"凑过去"看 NightActionPanel，体验不直接。

### 1.2 后端：人类支持基础设施

- `Player.IsBot bool`（`engine.go:95`）— 标记座位为 AI bot
- `hasHumanPlayer(gs)`（`engine.go:1537`）— 检测房间内是否有人类
- `cfgPhaseDeadlineSec(phase, seatCount, isHuman ...bool)`（`engine.go:1489`）— **已支持人机 deadline 区分**：
  - 全 AI 时 phase_deadline 默认 360-480s
  - 有真人时压缩到 120-180s
- `phase_extra.phase_deadline_at`（`view.go:165`）— 已下发绝对截止时间，前端可渲染倒计时
- `Action_*` 内部检查 `Roles[seat] == RoleXxx` —— **不检查 IsBot**，人类以正确角色入座即可调用

### 1.4 公平性问题

| 维度 | 现状 | 改进 |
|------|------|------|
| 人类 vs AI 决策时间 | AI LLM 调用耗时 4-12s + 多轮；人类 5-120s 不等 | 已在 `cfgPhaseDeadlineSec` 区分人机（120-180s vs 360-480s） |
| 发言时间 | `LLMCallLimiter` 30s 人类无此限流 | 需为人类添加"单段发言最长 N 秒"硬约束（避免真人拖时间） |
| 警徽流 | 无单独 deadline | 应有 "预言家警长" 警徽流声明窗口 ≤ 60s |
| 自爆狼 | speak 阶段任意时刻自爆，无确认 | 需弹窗二次确认（防止误触） |
| 投票投票/放逐 | `DayVote` 投完即可，不强制发言 | 允许"只发言不投票"流程保持现有不变 |
| 遗言 | 30s 截止（`DeathLyricDefaultDeadlineSec`） | OK；但人类**没法主动提交**，必须修 |
| 异步操作 | 所有 `Action_*` 是同步 in-memory，无并发风险 | OK |

### 1.5 §127 已有基础

`engine.go:1273-1276` 注释 "§127 人机区分": 当房间存在真人玩家(isHuman=true)时, acting phase 的 deadline 缩短为更合理的值,避免人类等待过久。这意味着 §127 的 cfg 配置已经存在,只需确认配置项默认值合理。

## §2 设计目标与边界

### 2.1 目标

| ID | 描述 | 验收标准 |
|----|------|---------|
| **G1** | 人类在所有需要操作的阶段都能看到"轮到我了"专属倒计时 + 操作面板 | 进入对局第一屏可见 `MyTurnIndicator` 组件；非自己回合时隐藏 |
| **G2** | 遗言（PhaseDeathLyric）有 WS 帧 + 前端面板 | 人类死者能看到 textarea + 「发送遗言」+ 「放弃遗言」按钮 |
| **G3** | 公平性：人类 deadline 已按 `hasHumanPlayer` 区分；新增「30s 警告」+ 「再不动就 skip」提示 | PhaseClock 接近 deadline 时人类专属指示器变红 + 弹 toast 警告 |
| **G4** | 自爆狼、投白痴放逐、警徽流等"高风险"操作二次确认 | 弹 ConfirmModal，误触可取消 |
| **G5** | 真人房间「发言」阶段人类可主动结束发言 | `DayControlPanel` 在 speak 阶段、`my_seat === speak_turn_seat` 时显示「⏭ 结束发言」按钮，调用 `game.werewolf_finish {action:"speak"}` |
| **G6** | 公平性：人类发言有 30s 单段硬上限（与 `LLMCallLimiter` 对齐） | 人类发言超过 30s 时按钮变灰，提示"已达单段发言上限" |
| **G7** | 配置可调：人类阶段 deadline、发言时长上限、警徽流窗口等 | `LsmAgentGame.conf.example` 新增 5 项 werewolf 人类配置 |
| **G8** | 不破坏现有 7/12 人局 / 全 AI 房间 | 所有改动在 `hasHumanPlayer == false` 路径上完全 no-op |

### 2.2 不在范围（边界）

- ❌ 不修改 `Action_*` 内部业务逻辑（仅扩展遗言 WS 帧 + 人类 deadline 警告）
- ❌ 不修改 AI 驱动基础设施（ToolRunner / agentRunner / 500K 队列 / parallel_think）
- ❌ 不修改 7 / 12 人局代码
- ❌ 不修改观战者 / 法官 / 重开局投票 / 遗言以外的子系统
- ❌ 不重做 NightActionPanel / DayControlPanel（仅做增量增强 + 新增 MyTurnIndicator / LastWordsPanel）

## §3 后端改动清单（WS 帧 + Action 扩展）

### 3.1 新增 WS 帧：`game.werewolf_last_words`

**目的**：让人类遗言有入口。

**文件**：`ServerGo/ws/game_service.go`（仿 `handleWerewolfRestartVote` 模式）

```go
// handleWerewolfLastWords 处理人类玩家的遗言提交 / 放弃。
// 客户端→服务端:
//   { "room_id": "uuid", "choice": "speak"|"skip", "text": "..." }
// 仅 phase=death_lyric 且 DeathLyricCurrent=seat 的人类死者可操作。
// 观战者不可操作；bot 走 Action_LastWords / Action_SkipLastWords 自身路径。
func (s *GameService) handleWerewolfLastWords(c *Client, env Envelope) {
    var req struct {
        RoomID string `json:"room_id"`
        Choice string `json:"choice"`           // "speak" | "skip"
        Text   string `json:"text,omitempty"`   // 仅 speak 时有意义
    }
    if err := json.Unmarshal(env.Payload, &req); err != nil || req.RoomID == "" {
        s.sendError(c, env.Seq, 20001, "invalid game.werewolf_last_words payload")
        return
    }
    if s.rejectIfSpectator(c, env, req.RoomID) {
        return
    }
    var (*WerewolfRoom, *errcode.Error)
    switch req.Choice {
    case "speak":
        r, e = s.werewolfMgr.Action_LastWords(req.RoomID, c.UserID, req.Text)
    case "skip":
        r, e = s.werewolfMgr.Action_SkipLastWords(req.RoomID, c.UserID)
    default:
        s.sendError(c, env.Seq, 20001, "unknown last_words choice: "+req.Choice)
        return
    }
    if e != nil {
        s.sendError(c, env.Seq, e.Code, e.Message)
        return
    }
    s.hub.BroadcastRoom(req.RoomID, Envelope{
        Type: "game.action_accepted",
        Payload: mustMarshal(map[string]any{
            "room_id":   req.RoomID,
            "game_kind": "werewolf",
            "by":        c.UserID,
            "action":    "last_words_" + req.Choice,
        }),
    })
    s.broadcastWerewolfState(req.RoomID)
}
```

**注册**：在 `case "game.werewolf_..."` switch 增加 `"game.werewolf_last_words"` → `handleWerewolfLastWords`。

### 3.2 `Action_LastWords` / `Action_SkipLastWords` 校验强化

**文件**：`ServerGo/game/werewolf/room.go:3663`

现有实现已经校验 `seat == DeathLyricCurrent`。**只需确认**：人类调此 Action 时不会触发 `Action_*` 锁外副作用（已确认，Action_LastWords 内只调 `gs.SayLastWords` / `gs.SkipLastWords`，无 bot 限定）。

### 3.3 `Action_*` 内的人类"二次确认"后端信号

**不变**：当前 `Action_WolfSuicide` 等没有"二次确认"概念，第二次提交就生效。**前端**用 ConfirmModal 拦截即可。

### 3.4 `phase_extra` 增字段（人类专属）

**文件**：`ServerGo/game/werewolf/view.go`

```diff
type PhaseExtra struct {
    ...
+   // 2026-07-21 §人类玩家: 标记当前 acting 阶段是否轮到当前座位玩家。
+   // 仅当 hasHumanPlayer(gs) == true 时填；false 时填 false。
+   MyTurnNow bool `json:"my_turn_now,omitempty"`
+
+   // 2026-07-21 §人类玩家: 轮到我的剩余秒数（phase_deadline_at - now）。
+   // 仅当 my_turn_now=true 时填；前端 MyTurnIndicator 直接渲染。
+   MyTurnRemainingSec int `json:"my_turn_remaining_sec,omitempty"`
}
```

**填充**：在 `BuildClientStateForUserID` / `BuildClientStateWithRoom` 末尾加：

```go
mySeat := gs.SeatOf(userID)
extras.MyTurnNow = false
extras.MyTurnRemainingSec = 0
if hasHumanPlayer(gs) && mySeat >= 0 {
    switch gs.Phase {
    case PhaseNightWolves:
        // 狼阶段所有狼人都要投票
        if gs.Roles[mySeat] == RoleWerewolf && gs.AliveSeat(mySeat) {
            extras.MyTurnNow = !gs.WolfVoteCast[mySeat]
            if !gs.PhaseDeadlineAt.IsZero() {
                extras.MyTurnRemainingSec = int(time.Until(gs.PhaseDeadlineAt).Seconds())
            }
        }
    case PhaseNightSeer:
        if mySeat == gs.TurnActingSeat {
            extras.MyTurnNow = true
        }
    case PhaseNightWitch:
        if mySeat == gs.TurnActingSeat {
            extras.MyTurnNow = true
        }
    case PhaseSpeak:
        if mySeat == gs.SpeakTurnSeat {
            extras.MyTurnNow = true
        }
    case PhaseVote:
        extras.MyTurnNow = !gs.Players[mySeat].Voted
    case PhaseSheriff:
        if gs.SheriffSeat == NoSeat {
            // 第一轮：所有存活玩家举手
            extras.MyTurnNow = !gs.Players[mySeat].HasSpoken
        }
    case PhaseIdiotReveal:
        if gs.DayEliminated == mySeat {
            extras.MyTurnNow = true
        }
    case PhaseHunterShoot:
        if gs.Roles[mySeat] == RoleHunter {
            extras.MyTurnNow = true
        }
    case PhaseDeathLyric:
        if gs.DeathLyricCurrent == mySeat {
            extras.MyTurnNow = true
        }
    }
    if extras.MyTurnNow && extras.MyTurnRemainingSec == 0 && !gs.PhaseDeadlineAt.IsZero() {
        extras.MyTurnRemainingSec = int(time.Until(gs.PhaseDeadlineAt).Seconds())
    }
}
```

> **关键**：`MyTurnNow` 只对 `IsBot == false` 的座位填 true。换言之：**只有人类能"轮到"自己**；bot 永远不在 `MyTurnNow` 范围（避免误展示）。

## §5 公平性与可玩性约束

### 5.1 时间维度

| 阶段 | 全 AI deadline | 真人 deadline | 真人单段硬上限 | 说明 |
|------|---------------|--------------|---------------|------|
| pre_wolves | 480s | **180s** | n/a | 缓冲期 |
| speak | 420s | **180s** | **30s** (单段发言) | 人类超过 30s 提示"已达单段上限"但允许继续(避免误打断) |
| vote | 360s | **120s** | n/a | 真人 120s 充裕 |
| sheriff | 300s | **120s** | n/a | 参选 + 投票 |
| hunter_shoot | 300s | **120s** | n/a | 单一决策 |
| night_wolves | 300s | **120s** | n/a | 4 狼投票,120s 充裕 |
| night_seer | 300s | **120s** | n/a | 单一决策 |
| night_witch | 300s | **120s** | n/a | 单一决策 |
| idiot_reveal | 300s | **120s** | n/a | 翻牌/放弃 |
| dawn | 8s | 8s | n/a | 切换态 |
| death_lyric | 30s | 30s | n/a | 每段 30s |

> **§127 已有实现**：`cfgPhaseDeadlineSec` 已支持人机区分（`defaultPhaseDeadlineSec` 表中 `human=true` 缩到 120-180s）。本次仅**确认**配置默认值合理，**不修改**逻辑。

### 5.2 单段发言硬上限

- 新增 `cfgWerewolfHumanSpeakHardLimitSec`（默认 30s）
- 前端在 speak 阶段从 `nowMs - mySpeakStartAt` 计算；超过 30s 时发言 textarea 仍可输入但提交按钮变灰 + tooltip "已达单段发言上限,请点'结束发言'"
- 故意不做"强制禁言"：人类可能想输入长文；只阻止提交避免无限延后

### 5.3 自爆狼确认

- 前端 ConfirmModal 拦截（§4.5）
- 自爆一旦执行不可撤销（现有 `Action_WolfSuicide` 立即 kill）；二次确认是产品层防御

### 5.4 投票按钮禁用

- `phase_extra.my_turn_now === false` 时：所有操作按钮 disabled + tooltip "请等待其他玩家投票/上一位行动"
- 警长票权、弃票、self-vote 等规则校验与全 AI 房间完全一致

### 5.5 旁观 vs 参与

- `my_seat === -1`（观战者）→ MyTurnIndicator 不渲染 + 所有操作面板隐藏
- `my_seat >= 0 && !alive`（死者）→ 操作面板隐藏（除了遗言阶段）
- `my_seat >= 0 && alive`（存活玩家）→ 按 phase 显示对应操作

## §9 风险与回滚

| 风险 | 缓解 |
|------|------|
| `phase_extra.my_turn_now` 计算错误 → 真人看到错误指示器 | 单元测试覆盖所有 11 个 phase；与 `TurnActingSeat` / `SpeakTurnSeat` 字段交叉验证 |
| 自爆误触 | ConfirmModal 强制二次确认（默认开启） |
| 遗言 WS 帧被 bot 误调 | `Action_LastWords` 内部已校验 `DeathLyricCurrent == seat`，bot 不会触发 |
| 真人 deadline 误压到 0 | `cfgPhaseDeadlineSec` 兜底表 + `acting-phase floor` 校验 |
| MyTurnIndicator 与 PhaseClock 重叠 | 布局：MyTurnIndicator 在 PhaseClock 下方 16px gap |
| 跨语言 key 缺失 | t() 兜底 `key` 字符串；类型检查 ts 不会报错但运行期不崩 |

**回滚**：
- 后端：`revert` 提交即可（无 DB migration；纯 in-memory + WS 帧）
- 前端：`<MyTurnIndicator>` / `<LastWordsPanel>` 是新增组件，删除 import 即生效
