## 一、P0 级阻塞：无可用 LLM API Key

### 1.1 现象

创建 1 人 + 12 AI 的狼人杀房间时，前端弹窗底部红色错误条提示：

> 创建失败,请检查网络或重试;详细错误请查看页面顶部红色提示。

页面顶部红色提示：

> no usable LLM API key configured. AI agent seats cannot be filled

### 1.2 后端错误码

```
POST /api/games/werewolf/rooms
→ code: 30016
→ message: "no usable LLM API key configured; AI agent seats cannot be filled"
```

### 1.3 根因定位

**数据库 LLM Provider 全部使用占位 Key**：

| Provider 数量 | 表 | endpoint | enabled | api_key_hint |
|---|---|---|---|---|
| 10 个 | `t_lsm_game_llm_provider` | `http://127.0.0.1:29000/Anthropic` | 全部 1 | sk-d... / sk-e... 等 |

10 个 Provider（Qwen / Kimi / DouBao / DeepSeek / GLM / MiniMax / MeiTuan / Xiaomi / Tencent / Kwail）均已注册且 enabled=1，但 API Key 为 seed 默认占位值，调用 LLM 代理（`127.0.0.1:29000`）时鉴权失败。

### 1.4 验证链路

1. ✅ LLM 代理服务可达：`http://127.0.0.1:29000/Anthropic` 返回 `{"error":"Unauthorized","message":"missing Authorization header"}`
2. ✅ 远程代理也可达：`http://8.130.85.252:29000/Anthropic`（配置文件中配置的 endpoint）
3. ✅ 前端 `GET /api/llm/models` 返回 10 个模型（不含 key）
4. ❌ 所有 Provider 的 `api_key_enc` 为 seed 占位值（DB-first 模式，首次启动空 DB 时自动 seed 8 个占位 key，另外 2 个为后续手动添加的占位）

### 1.5 影响范围

**全部 10 项未覆盖项（P0-A ~ P2-5）均因无法创建房间而无法测试**，与上一轮报告（`自动化测试报告_20260811_220139_无问题.md`）结论一致——环境阻塞问题仍未解决。

## 五、环境阻塞解决方案建议

### 5.1 立即解决方案（开发环境）

在 Web 端 Admin 面板（`/admin/models`）为每个 Provider 填入真实 API Key，或通过 SQL 直接更新：

```sql
-- 示例：更新一个 Provider 的 API Key（需先经过 AES-256-GCM 加密）
-- 推荐走 Web 端 Admin 面板，由后端统一加密
```

### 5.2 测试环境优化建议

1. **开发环境默认配置真实 Key**：`LsmAgentGame.conf` 中至少配置 1-2 个真实可用的 LLM API Key，确保基本测试可进行
2. **降级模式**：当无可用 LLM Key 时，允许创建「全人类房间」或「Mock Agent 模式」（Agent 不调 LLM，按预定义脚本行动），用于前端 UI 测试
3. **错误提示优化**：当前错误 `no usable LLM API key configured` 对普通用户不够友好，建议区分「管理员配置问题」和「网络临时故障」

### 5.3 建议新增「前端 UI 专项测试」通道

Agent 对局测试依赖 LLM Key，但前端 UI 测试（创建房间弹窗、角色选择、道具商店、个人中心等）不需要 LLM。建议：
- 新增「UI 专项测试」模式，跳过 Agent 依赖
- 或在开发环境提供 Mock Agent 模式（后端模拟 Agent 行为，不调真实 LLM）

## 六、本轮新增发现

### 6.1 前端登录状态持久化机制

- **token 存储**：`localStorage.lsm.token`（HTTP service 读取）
- **auth state 存储**：`localStorage.lsm.auth`（zustand persist）
- **初始化流程**：页面加载时 zustand persist 从 `lsm.auth` 恢复，然后 `hydrateFromStorage()` 校验 `lsm.token` 是否存在，存在则设置 `isAuthenticated=true`
- **结论**：登录状态持久化逻辑正确，与 `CLAUDE.md` 中 auth 模块设计一致

### 6.2 创建房间 API 严格校验

- `POST /api/games/werewolf/rooms` 使用 `DisallowUnknownFields`（§84b 规范）
- 传错字段名（如 `max_seats` 不存在）直接返回 20001 `invalid body: json: unknown field "max_seats"`
- **结论**：API 严格校验正常工作，符合 §84b 规范

### 6.3 DB-first LLM Provider 加载

- 10 个 Provider 全部从 DB 加载（不再从配置文件读取）
- `t_lsm_game_kv.llm_api_key_master` 为主密钥（AES-256-GCM 加密 API Key）
- **结论**：§118 模型管理系统数据层正常工作
