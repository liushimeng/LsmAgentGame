- 结果：Bot 注册成功但永远不会被驱动决策；**§B8 bot 回合 watchdog 因为 onHandStarted 内的 `markTurnLocked` 流程走不到也可能不启动**

`startTexasBotWatchdog`（`game_service_texas_bot.go:367-379`）有日志但级别是 `Debug`（默认不输出）；`texasBotWatchdogTick` 中的 `texasholem bot turn watchdog forcing fold` 是 `Warn` 级 —— **8+ 分钟应该出现 ≥12 次**。

server log 完整搜索 `texasholem bot turn watchdog forcing fold`：**0 命中**。说明 watchdog 没启动，或启动后房间被当作 gone 立即退出。

注意：`BotTurnInfo` 要求 `startedAt` 非零。`markTurnLocked` 在 `JoinGame` 自动 StartHand 路径里**被调用**（line 366），应设置 startedAt。但若 watchdog 因房间检查逻辑直接退出，可能 never 出现 fold 日志。

## 五、发现的缺陷

### 🐛 P0-NEW-R（复发阻断，本轮新发现）

**位置**：`ServerGo/game/texasholem/room.go:354-371` `JoinGame` 函数内自动 StartHand 路径

**问题**：`JoinGame` 在 `r.IsReady() && r.State.Street == PhaseWaiting` 时调用 `StartHand`，但**未调用 `m.onHandStarted(roomID)` 回调**。该回调是触发 `broadcastTexasHoldemState` + `go s.ProcessBotTurn` 的唯一入口。

**对比**：`runHandOverEpilogue` 内的延迟 goroutine（`room.go:445-453`）正确调用 `m.onHandStarted`，仅 `JoinGame` 自动开首手路径缺失。

**影响**：当 Bot 通过 REST `POST /api/games/texasholem/rooms` 创建房间（agent_seats>0）时：
1. Bot 用户落库 ✅
2. Bot 入座到 in-memory 房间 ✅
3. `IsReady()` true → 自动 `StartHand` ✅
4. **缺失** `onHandStarted` 回调 → Bot 永远不被驱动决策
5. 人类 creator 后续 WS join 时 `started=false`（已被消耗），不触发 `go s.ProcessBotTurn`
6. watchdog（§B8）应在 `timeoutSec+10s = 40s` 后强制 fold，但本轮 8+ 分钟也未触发 —— 待进一步确认是否 watchdog 本身也未启动

**修复建议**（不自动改业务代码，仅建议）：

- **方案 A（推荐）**：在 `JoinGame` 自动 StartHand 路径后（`room.go:368` 之后，释放 r.mu 之前或之后），同样调用 `m.onHandStarted(roomID)`，与 `runHandOverEpilogue` 路径对齐。注意 onHandStarted 回调内会再 `WithRoomLocked`，必须**在 r.mu 释放之后**调用（参照 §B6 死锁修复）。
- **方案 B（备选）**：在 `registerTexasHoldemAgentSeats` 中，调用 `JoinGame` 之后显式 `go s.ProcessBotTurn(roomID)`，与 `handleTexasHoldemJoin` 的 `started=true` 分支对齐。
- **方案 C（兜底）**：把 watchdog `startTexasBotWatchdog` 调到 `JoinGame` 自动 StartHand 路径中强制启动（即使没有回调，watchdog 5s tick 应能兜底 force-fold）。

### 🐛 P1-X（弱 bug，附带记录）

**位置**：`ClientWeb/src/pages/TexasHoldemGamePage` 房间信息面板手牌计数渲染

**问题**：界面显示「第 {} 手 #1」—— `{hand_number}` 模板字面量未被替换。

**影响**：纯显示 bug，不影响游戏逻辑。
